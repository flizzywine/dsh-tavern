# 剧本游标设计

剧本游标表示“下一轮正文默认注入哪个剧本切块”，不是 Agent 当前阅读到的位置。

## 剧本模式的双锚点

剧本模式通过候选项生成和正文生成两个锚点，把实际游玩持续锚定在剧本走向上，同时保留玩家选择和临场创作的自由度。

- 后台 Agent 在候选任务中查看当前及后续剧本，为玩家提出符合剧情方向、但不是唯一答案的行动建议。
- 前台 Agent 同样查看足够的剧本上下文，把玩家最终选择自然写入既定走向，而不是只依赖候选项转述剧本。
- 两者围绕同一个剧本游标紧密配合。候选项负责为下一步探路，正文负责让实际发生的剧情落地。
- 剧本约束的是关键事件、因果关系和长期方向，不要求复述原文，也不固定对白、动作和局部实现方式。

候选项与正文不能只看一个孤立切块。默认上下文应覆盖游标附近足够的连续剧本；后台 Agent 在候选任务中还可以按需查询其他切块。阅读范围与游标位置相互独立。

## 持久化后台 Agent

后台 Agent 随游玩会话持续存在，状态结算与候选生成复用同一个子会话；服务重启后仍通过保存的 Session ID 继续。

- 人物卡、候选任务和稳定世界书放在靠前的稳定上下文中，利于缓存复用。
- 每轮只追加最新正文，并重新注入最新 Guide、人物姿势和剧本窗口；本轮权威状态覆盖子会话中的旧动态状态。
- 后台 Agent 保留自己的状态结算、剧本查询、推理和候选历史，前台 Agent 不接收这些中间过程。
- 长上下文直接复用 DSH Session 的原生压缩机制，dsh-tavern 不维护第二套摘要或压缩规则。
- 自由故事与剧本模式都复用后台 Session；只有剧本候选任务会获得剧本读取工具。

候选框和 DSH 原生子代理入口都可以打开该会话，查看历次查询、推理和候选输出。

## 游标职责

游标是剧情进度的最低水位线，也是主动控制节奏的推进器。它避免自由发挥长期停留在同一阶段，但不代表 Agent 最远看到了哪里。

## 核心规则

1. 前台 Agent 与后台候选任务可以前后阅读任意剧本块；阅读不改变游标。
2. 每次正文成功提交后，游标自动前进一块。
3. 后台 Agent 只能在候选任务中通过独立的 `tavern_point_script` 工具跳转游标；`tavern_read_script` 保持只读。
4. `point` 只能保持或向前跳：`next = max(current, requested)`。
5. 读取失败、候选失败或没有 `point` 时，候选流程不改变游标。
6. 末块正文提交后进入“剧本结束”位置，不再重复注入末块。

## 回退例外

“回退本轮”会恢复该回合提交前的完整剧本状态，用于重新生成同一轮正文。这是交易回滚，不属于游戏内的游标后退；重新提交后仍只前进一次。

## 原因

阅读位置只是研究上下文的临时状态。如果把“最后阅读位置”当成游标，Agent 在查看前文伏笔后就会让剧情倒退。因此阅读与推进必须分离。
