# 剧本游标设计

剧本游标表示“下一轮正文默认注入哪个剧本切块”，不是 Agent 当前阅读到的位置。

## 剧本模式的双锚点

剧本模式通过候选项生成和正文生成两个锚点，把实际游玩持续锚定在剧本走向上，同时保留玩家选择和临场创作的自由度。

- 候选 Agent 查看当前及后续剧本，为玩家提出符合剧情方向、但不是唯一答案的行动建议。
- 正文 Agent 同样查看足够的剧本上下文，把玩家最终选择自然写入既定走向，而不是只依赖候选项转述剧本。
- 两者围绕同一个剧本游标紧密配合。候选项负责为下一步探路，正文负责让实际发生的剧情落地。
- 剧本约束的是关键事件、因果关系和长期方向，不要求复述原文，也不固定对白、动作和局部实现方式。

候选项与正文不能只看一个孤立切块。默认上下文应覆盖游标附近足够的连续剧本；候选 Agent 还可以按需查询其他切块。阅读范围与游标位置相互独立。

## 游标职责

游标是剧情进度的最低水位线，也是主动控制节奏的推进器。它避免自由发挥长期停留在同一阶段，但不代表 Agent 最远看到了哪里。

## 核心规则

1. 正文与候选 Agent 可以前后阅读任意剧本块；阅读不改变游标。
2. 每次正文成功提交后，游标自动前进一块。
3. 候选 Agent 只能通过显式 `point` 跳转游标。
4. `point` 只能保持或向前跳：`next = max(current, requested)`。
5. 读取失败、候选失败或没有 `point` 时，候选流程不改变游标。
6. 末块正文提交后进入“剧本结束”位置，不再重复注入末块。

## 回退例外

“回退本轮”会恢复该回合提交前的完整剧本状态，用于重新生成同一轮正文。这是交易回滚，不属于游戏内的游标后退；重新提交后仍只前进一次。

## 原因

阅读位置只是研究上下文的临时状态。如果把“最后阅读位置”当成游标，Agent 在查看前文伏笔后就会让剧情倒退。因此阅读与推进必须分离。
