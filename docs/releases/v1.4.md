# v1.4 发布记录

v1.4 主要整理了酒馆的后台运行链路，并继续补齐人物卡生态与 Android 的实际使用体验。本版重点不是增加更多操作入口，而是让变量结算、人物设计、人物卡脚本和会话恢复各自承担清晰的职责，在断线、刷新、切换对话或服务重启后能够更可靠地继续工作。

## 主要更新

### 重构 MVU 后台结算链路

- 使用明确的 Session 信号和 SSE 通知唤醒浏览器脚本任务，减少固定轮询造成的等待；浏览器断线重连后会重新同步任务状态并继续尚未完成的结算。
- 浏览器先确认接收任务，再执行人物卡脚本；变量写入只能归属于发起它的当前结算事件，避免旧任务、重复事件或其他脚本误写本轮变量。
- 将变量、姿势等结算结果作为一次效果原子提交；任务在提交前中断时不会留下部分写入，服务重启后会根据持久记录对未完成结算进行核对和恢复。
- 正文重新生成会先取消仍在运行的旧结算，避免旧任务稍后返回并覆盖新正文对应的状态。
- 修复 MVU 初始化失败没有正确传到前台、下载失败后错误重跑初始化、后台已经完成但前台仍显示“结算中”等问题。
- MVU 运行依赖改为随 Tavern 内置，减少外部资源加载失败；兼容 Windows 换行差异，并修复分块读取请求体时可能破坏 UTF-8 中文的问题。
- 增加有边界的 MVU 加载、资源校验和变量拒绝诊断，失败时尽量保留真正的错误原因，方便通过诊断包定位问题。
- 资源库读取不再长期占用实时连接，降低人物卡库、世界书库与后台结算相互堵塞的概率。

### 人物设计与状态结算正式解绑

- 人物设计不再依附于 MVU 或人物姿势结算，普通人物卡与 MVU 人物卡都可以使用。
- 现有后台 Agent 在发现需要补全重要人物时，直接加载人物设计 Skill 并完成设计，不再额外创建一层人物设计 Agent。
- 人物设计使用独立的生成阶段和采样策略，不再沿用变量结算所需的低温度；设计档案、姿势和 MVU 变量分别保存、分别提交。
- 人物设计档案按当前对话持久化，并显示在右侧“酒馆状态”中，便于确认后台实际设计了哪些人物。
- 普通卡获得的是人物设计与档案复用能力，不会因此自动获得 MVU 变量或状态栏。

### 补强人物卡脚本、手机界面与动态世界书

- 将 YAML、Vue、Vue Router、Lodash、Zod、jQuery、jQuery UI、Tailwind 和 Font Awesome 等常见浏览器依赖随 Tavern 打包，减少人物卡因外部 CDN、网络环境或宿主缺少全局对象而启动失败。
- 补充 Tavern Helper 常用运行接口、正则读取与交互消息桥接，让依赖这些能力的人物卡前端能够在 DSH Tavern 中继续工作。
- 人物卡自带的手机界面可以嵌入右侧“酒馆状态”，不必始终漂浮在正文上；切换对话后会重新挂载，图标资源也会在嵌入后正确加载。
- 补齐手机消息的交互动作和持久写入链路。卡片脚本生成的手机回复可以写回当前 Chat 的插件数据，刷新后继续读取，而不混入剧情正文或 MVU 变量继承。
- 常驻世界书条目与关键词触发条目在查看和注入时明确区分；常驻内容进入稳定上下文，动态条目仍按触发规则召回。
- 新增对动态世界书模板的原生投影：支持常驻 EJS 控制器根据当前变量运行，并通过 `getwi(...)` 读取被当作资料库使用的条目；模板失败时只跳过该控制器，不把模板源码发给正文模型。
- 普通小说正文不再无条件放入 iframe，只有确实包含人物卡交互前端的消息才进入隔离渲染。

> 人物卡脚本的实现方式差异很大。本版补齐的是一组常用宿主能力，不代表所有 SillyTavern 插件、手机或数据库脚本都已完整兼容。

### DSH Session、Agent 与会话恢复

- 人物卡信息和世界书上下文会记录进 DSH Session 轨迹，预设仍采用请求时投影，便于随时切换。
- Tavern 状态以只读、可重建的形式投影到 Agent 工作区，让前后台 Agent 能按需读取当前资源与会话状态。
- 修复 DSH 版本变化后的 Session 历史读取，并恢复卡片 Agent 所需的基础文件工具；前台、后台与卡片 Agent 按职责获得不同的工具集合。
- 修复服务重启或迁移后重复 Tavern 前缀导致对话空白，以及切换对话后候选项、手机界面或正在进行的 MVU 状态没有恢复的问题。
- 修复 DSH Desktop 2.0.5 中重新生成正文后界面仍保留旧正文的问题。

### Android 实验性支持与一键安装

- Android 安装改为以 `android/setup.sh` 为主的一键流程：自动下载或更新、安装依赖、配置 Profile、校验、启动，并在失败时回滚。
- 用户可以直接在 DSHA 的“终端”粘贴一条命令完成安装；不会使用终端时，也只需把同一段完整指令交给 Agent 执行，不再让 Agent 临时拆解安装步骤。
- 适配官方 DSHA 运行环境及不同宿主版本，支持缺少 `curl` 的环境，并自动配置所需的远程预设。
- 酒馆入口使用带宿主认证的地址，不再依赖裸端口；补充入口缺失时的修复与更新能力。
- 支持从 Android Download 目录导入人物卡；未授予文件访问权限时提供明确提示和系统文件选择器作为备选。
- 安装和桌面更新会保留 Tavern 所需依赖，避免更新过程先停止服务或覆盖依赖后导致安装失败。

Android 仍属于实验性支持。不同系统、DSHA 版本、网络和后台限制可能影响安装或运行，不能按 Windows、macOS 和 Linux 正式支持的标准承诺可用性。

## 界面与文档改进

- 精简游玩区操作：保留“生成候选项”“重新生成正文”和“更多”的清晰层级，移除正文下方无实际用途的复制、点赞、点踩和分支按钮。
- 用户画像入口统一移动到右侧栏；关闭场景生图时隐藏对应操作，同时保留已有配置。
- 优化预设库的复制与默认选择说明，减少“当前预设”和资源副本之间的混淆。
- 新增完整的 GitHub Pages 用户手册和产品概览，按酒馆生态兼容、游玩模式、卡片模式和高级功能组织，并配有公开演示截图与可下载样例。
- 本地诊断包、Playwright 输出和分析资料不再误提交到仓库。

## 其他修复

- 修复 ComfyUI 工作流中通过 rgthree 节点间接连接 Seed 时无法识别随机种子的问题。
- 修复人物卡库等资源读取超时后错误显示为“0 张人物卡”的相关连接争用问题。
- 修复插件更新时依赖目录被破坏，以及 Windows 环境因换行字节不同而把可执行 MVU 资源误判为损坏的问题。
- 修复场景截图、查看子 Agent 等界面行为干扰当前游戏 MVU 所有权的问题。
- 完善候选项、回退、重新生成和失败恢复期间的忙碌状态与错误反馈。

## 重要变更

### 兼容模式已停用

- 原“兼容模式”已从设置、初始化、RPC、历史读取和恢复入口中移除，不再提供重新启用方式。
- 旧兼容会话和归档数据不会被主动删除，但不能继续生成；请使用当前原生游玩链路重新开始游戏。
- “支持导入和运行部分酒馆资源”不等于恢复兼容模式，也不代表完整复制 SillyTavern 的可变历史和全部插件环境。

## 升级提示

- 更新后请重启 Tavern，并刷新已经打开的浏览器页面，以加载新的后端、前端脚本和内置依赖。
- Android 用户建议重新执行文档中的一键安装命令，让脚本同步 DSHA 入口、Profile 和依赖。
- 使用复杂人物卡脚本时，如界面能够显示但某个按钮或数据操作仍无响应，请导出诊断包，并说明人物卡名称、操作入口和复现步骤。
- 本版不会自动改写已导入的人物卡、世界书或旧对话；人物设计档案、手机插件数据和 MVU 状态仍按各自的数据边界保存。
