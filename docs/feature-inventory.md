### 相同功能按认知深度分层介绍

- **酒馆生态兼容：** 将人物卡、世界书、预设导入和正则、MVU、前端美化统一介绍；先讲支持能力，再讲状态栏掉格式时转 MVU 的可选处理。可导入、可编辑与可执行分别说明，不用“全面兼容”代替具体边界，也不重新引入兼容模式入口。
- **历史回忆：** 程序可以从早期就提供能力，但用户通常到长局才体会其价值，因此放在高级功能中的长局章节，不要求先懂历史检索才能开始玩。
- **先完整介绍初步游玩，再介绍卡片模式：** 开局、候选、重写、回退、Guide、状态查看与剧本游玩属于同一组初步游玩内容，中间不插入工作台教程。随后介绍对话修改资源和从素材制卡；卡片模式仍是核心功能，不归入高级功能。
- **偏好与文风：** 先用当前局的剧情指导解决眼前需求，再按需编辑预设等资源；跨局长期偏好的画像留在高级章节。画像入口仅在右侧栏，新用户不需要在开局前知道或选择画像。
- **后台人物设计：** 与“修改人物卡中不喜欢的内容”分开介绍。它是当前游戏中的后台能力，按需设计、补全和复用重要人物；不要求玩家进入工作台逐个手写人物，也不是长期用户画像。
- **互联网搜索：** 在高级章节单独介绍用途、开关与生效范围，不与历史回忆混用：前者查外部资料，后者找回当前游戏中已经发生的剧情。
- **文生图：** 属于后置的高级功能，即使界面可见，也不提前进入新手教程。文字游玩完全不依赖生图，详细渠道参数只在需要时展开。

## 一、酒馆生态兼容

先回答“原来在酒馆使用的资源，在这里能用到什么程度”。具体操作链接到同一份功能文档，不重复维护教程。

| 酒馆资源或能力 | 当前支持 | 需要说明的边界 |
| --- | --- | --- |
| 人物卡 | 导入 PNG / JSON，查看与编辑，导出 JSON | 支持卡片格式不等于支持卡内全部第三方脚本；不宣称支持 PNG 导出。 |
| 世界书 | 导入、编辑和关联；支持常驻背景与按规则召回 | 保留字段不等于完整复现原酒馆的全部触发语义。 |
| 预设 | 导入、选择、编辑提示词与正则，用于游玩正文 | 按 DSH Tavern 的方式应用，效果可能与原酒馆不同；无需预设也能开始。 |
| 正则 | 使用人物卡及预设中的受支持正则处理与美化内容 | 按具体规则、作用位置与运行支持判断效果。 |
| MVU | 后台变量结算、更新回执与右侧常驻状态栏 | 需要人物卡具备相应结构和资源，不保证任意卡或脚本自动适配。 |
| 前端美化 | 正文内 HTML 展示与人物卡状态面板 | 展示 HTML 不等于实现所有浏览器脚本和酒馆宿主接口。 |

先展示这些支持能力，再提供“状态栏掉格式时转为 MVU”的按需说明，不作为开局前置课程。已关闭的“兼容模式”不列入其中，也不使用“所有酒馆资源完全兼容”的笼统承诺。

## 二、游玩模式

按界面和操作讲解，不先解释后台机制。每个界面区域配截图，标明入口、可执行的动作及结果。

### 开始第一局

- 导入 SillyTavern PNG / JSON 人物卡，从人物卡库直接开局。
- 默认无需导入外部预设；模型服务仍需要先配置。
- 有多个开场白的卡，可以预览并选择开场。
- 设置玩家称呼，并可在后续游玩中修改称呼。
- 同一人物卡可以创建多次独立游戏，保留各自对话。
- 没有绑定剧本时自由游玩；绑定剧本的卡在新开局时自动按剧本推进，不需要额外学习一种操作模式。

### 认识游玩界面

- 正文区：阅读当前故事与人物卡带来的展示内容。
- 输入区与候选区：输入自己的行动，或选择候选后修改、发送。
- 右侧面板：认识剧情指导、人物状态与更新结果的入口；高级面板只提供相关文档链接，不要求新手逐项配置。

### 基础操作与自由游玩

- 自由输入行动、对白或剧情要求。
- 独立生成行动候选和场景变化；点击候选填入输入框，可修改后再发送。
- 重新生成候选，也可附上要求重新生成。
- 通过同一个“重新生成正文”入口重写当前正文，指导意见可留空。
- 从“更多”菜单回退当前回合或压缩上下文。
- 添加、查看和删除持续生效的剧情指导（界面名称 Guide）。
- 查看右侧人物状态与本轮更新结果；继续历史对话，或导出纯对话文本。

### 右侧状态与更新结果

- 查看后台总结的人物姿势等场景信息。
- 支持的 MVU 人物卡可在右侧常驻展示状态栏，并随状态更新。
- 查看后台结算状态，失败时可单独重试；这里只解释看到的结果与可执行操作。

### 跟随剧本游玩

- 绑定小说、故事大纲或剧本，按当前剧情附近的片段推进；玩家仍可偏离原文行动。
- 查看剧本进度与当前参考片段。

这里介绍最短导入、绑定和新开局路径；世界书、预设等完整资源编辑在下一节卡片模式中展开。

### 历史对话与故事导出

- 继续、重命名或移除游玩对话；与卡片工作台历史分开管理。
- 将玩家与角色正文导出为纯对话 TXT，不混入推理和工具轨迹。

边界：回退与重写不等于完整的任意历史节点分支管理；多开场预览也不等于所有历史正文版本都可以自由切换。

## 三、卡片模式

### 认识工作台与资源入口

- 认识卡片 Agent 对话区、任务入口和资源引用方式。
- 认识人物卡库、世界书库、剧本库与预设库，区分查看、引用到对话和绑定到人物卡。
- 继续、重命名或移除工作台对话；与游玩历史分开管理。

### 通过对话制作和修改内容

- 阅读、分析和修改现有人物卡，调整不喜欢的设定，保留希望继续使用的内容。
- 同样可以通过对话修改世界书、外部预设与剧本，而不只是修改人物卡。
- 从小说、剧本或素材中抽取人物与相关设定，制作新人物卡。
- 把多个资源引用进当前工作台对话，作为讨论和创作材料。
- 保留导入原版，日常编辑工作版；有恢复人物卡原版的 Agent 工具。
- 也可以从想法空白开始，与卡片 Agent 讨论并制作内容。

卡片模式与游玩模式并列为核心能力，在初步游玩介绍完成后紧接介绍，不归入高级功能。无需先学习复杂字段或自行编写提示词；先讨论修改范围、确认后写入，不同资源的生效范围按对应说明处理。

按需延伸：状态栏经常掉格式时，可转换为独立 MVU 版；正文、正则或美化异常时，可将相关记录交给 Agent 调试。文风提炼、Skill、自定义工具和插件在后面的高级功能中单独介绍。

### 人物卡库

- 导入、查看、编辑、导出 JSON、重命名文件和删除人物卡。
- 编辑角色描述、性格、情境、开场白、备选开场白、对话示例等字段。
- 管理人物卡的世界书与剧本绑定。
- 查看卡内正则、Tavern Helper 脚本与 MVU 相关资源；查看扩展内容不代表执行所有脚本。

### 世界书库

- 统一查看独立世界书与人物卡内置世界书。
- 导入、导出、编辑条目及启用状态，管理与人物卡的绑定。
- 在卡片对话中引用世界书，交给 Agent 修改。
- 常驻背景与按关键词命中的条目按各自规则参与游玩。

### 剧本库

- 导入 TXT、Markdown、JSON、EPUB 素材（人物卡内直接导入剧本入口为 TXT、Markdown、EPUB）。
- 在资源库查看工作版；通过卡片 Agent 修改正文，支持重命名、删除、引用到卡片对话。当前查看页不是直接编辑正文的文本编辑器。
- 将剧本与人物卡绑定或解绑。

### 预设库

- 导入、选择、查看、导出、重命名和删除外部预设。
- 编辑预设提示词、正则和可切换条目的启用状态，或交给卡片 Agent 修改。

定位：预设库服务游玩，用于调整文风、叙事方式与写作规则，不再标为实验性。不导入外部预设也能直接开始；本节讲资源库里的查看、选择与编辑操作，不作为开局必经步骤；内置系统提示词另在高级功能介绍。导入的酒馆预设在 DSH Tavern 中应用，效果可能与原酒馆不同。

## 四、高级功能

把隐藏机制和按需使用的能力逐项讲清楚，每项独立成页。先讲它解决什么问题、何时值得了解，再讲入口、条件和影响范围；不堆在一个“深度定制”条目里。

### 历史回忆与长局连续性

- 世界书按规则提供相关背景，玩家不必每轮重复粘贴设定。
- 前台与非生图后台任务可按需检索当前游戏的历史正文，再读取命中轮次附近的原文。
- 提供上下文压缩入口，协调前台和后台的压缩。

对外用语：可以说“按需找回前文细节”，不能承诺“永不失忆”“无限上下文”。历史检索属于系统能力，不应要求新用户学习工具调用。

### 状态栏掉格式时转为 MVU

- 已在兼容性章节介绍正则、MVU 与前端美化支持，本节针对正文内状态栏反复掉格式的情况。
- 通过卡片 Agent 转为独立 MVU 版，把变量更新与状态展示分开，检查转换后的状态与更新结果。
- 正常工作的卡无需转换；这不是开局前置步骤，也不等于保证所有第三方脚本兼容。

### 用户画像：复用长期偏好

- 从右侧“用户画像”面板进入卡片 Agent，通过分批访谈建立长期游玩与写作偏好。
- 原始回答、分析与已确认画像分开保存；新草案不会自动覆盖已确认版本。
- 在用户画像面板查看实际生效文本、偏好维度和原始回答。
- 直接修改已确认偏好，或交给卡片 Agent 继续调查、修订。
- 跨人物卡复用画像；仅在右侧“用户画像”面板设置新游戏默认是否启用，默认关闭。开场准备不显示画像，也不提供单局覆盖。
- 当前游戏使用开局时冻结的画像版本，之后修改画像不会悄悄改写正在玩的游戏。

状态：已有入口、持久化和测试，不再是单纯待办。不要照搬旧 TODO 中“可随时切换当前局”“删除任意画像记录”等尚未在本次入口核对中确认的表述。

### 后台人物设计：为当前游戏补全重要人物

- **用途：** 重要人物需要登场、补全或提前储备时，后台可建立完整人物方案；已有档案优先复用、补充，避免反复重造同一人物。
- **设计内容：** 身份、剧情作用、动机、内在矛盾、性格、外貌、行为与说话方式、关系立场、默认衣着及后续剧情可能性。
- **使用方式：** 属于 MVU 后台结算中的按需能力，没有单独的玩家操作按钮；后台先保存完整档案，再按当前人物卡的变量结构提交对应人物字段。
- **本局独立：** 人物档案和变量属于当前对话，不修改导入人物卡的原版；同一卡的新对话可以有不同的人物设计。完整档案不作为额外设计说明注入前台正文 Agent。
- **边界：** 需要匹配当前卡可用的 MVU 结构与校验规则，不承诺任意普通卡都自动获得人物库；只为有持续剧情价值的重要人物按需建档，不给每个路人强制建档。
- **设计不是剧情事实：** 可以设计人物的稳定性格、外貌与默认形象；是否在场、当前位置、关系进展及已经发生的事件仍以正文为准，不能把未来可能性写成既成事实。

这一项独立于卡片工作台的“按个人喜好改卡”，也独立于“用户画像”。展示时可配一组演示：人物出现 → 后台设计并结算 → 卡片状态中出现对应人物信息；具体展示取决于该卡的状态栏。

### 互联网搜索：按需查阅外部资料

- **用途：** 前台与后台 Agent 可在任务需要时搜索外部资料，辅助处理需要现实信息的内容；不是检索本局聊天记录，也不表示每轮一定搜索。
- **入口：** 酒馆设置 → 开启联网搜索。默认关闭，由用户选择是否允许。
- **生效范围：** 开启后新建的游戏，其前台与后台 Agent 都可以按需使用搜索；权限在开局时固定，之后修改设置不改变已有游戏。卡片工作台不继承这个游玩开关。
- **条件与边界：** 搜索工具由 DSH 提供，实际可用性依赖宿主搜索能力及网络；联网不保证内容真实或最新，外部资料仍需判断。该功能不是“模型换成联网模型”，也不能替代世界书中的故事设定。

### 前后台模型分工

- 前台使用 DSH 模型配置；后台可选独立模型，或在开局时跟随前台。
- 说明当前实际使用的后台模型，以及设置对新局的影响，不作为开局前置课程。

## 附录：文档站的呈现方式

文档站只设“酒馆生态兼容、游玩模式、卡片模式、高级功能”四个顶层产品部分，同时提供完整功能索引供查阅：左侧按这四部分分组，中间当前功能说明，右侧本页导航。游玩模式和卡片模式以界面、操作和可用内容为主；高级功能下逐项解释隐藏机制与按需能力。辅助指南不占第五个产品分类。当前 `index.html` 已实现这套纯文字布局；原宣传页保留在 `product.html`，不再承担完整手册的职责。

- **首页先说明能复用什么，再帮助开始。** 首屏简要介绍酒馆生态兼容，并提供开始游玩的入口；完整功能索引保留全部主题，熟悉产品的用户可直接定位，不必顺序学习。
- **目录按模式和认知阶段展开。** 酒馆生态兼容排第一，其后先完整介绍初步游玩，再介绍卡片模式，不把两者交错排列。两种模式都是核心功能；状态栏转换、长局记忆及各项高级功能按需阅读，高级功能仍各有独立入口。帮助入口始终可达。
- **每页只讲一个任务。** 导入、绑定、引用、生效范围这类容易混淆的动作明确区分；相邻任务用相关链接串起来。
- **高级功能也要直接可见。** 用户画像、后台人物设计、互联网搜索、模型分工、系统提示词、文风 Skill、工具插件和文生图分别列为导航项，各自按需展开；不再挤进“长期偏好与深度定制”一个条目里。
- **技术感来自明确操作和事实。** 使用界面中的真实名称、操作步骤、效果截图、条件与限制，不把内部架构术语塞进每个页面。
- **页面与产品能力分开。** 索引页、FAQ、渠道配置页属于文档主题，不作为新增功能计数；未写正文的条目不伪装成可访问链接。

### 每个功能页的固定内容

1. **用途：** 一两句话说明它解决什么问题。
2. **在哪里：** 当前界面的入口路径；Agent 能力则给出一句实际提问示例。
3. **怎么用：** 最短可复现步骤，包括必要前置条件。
4. **看到什么：** 实际结果与截图；如有保存、确认、重试，说明成功标志。
5. **影响范围：** 当前回合、当前对话、新开局或全局；是否产生模型费用，是否改写或删除数据。
6. **限制与相关功能：** 常见误解、支持边界、相邻文档链接。

- 已关闭的兼容模式，包括旧兼容会话的访问和继续生成；保留磁盘数据不等于仍能使用。
