## 用户阅读顺序：从开始玩，到按需发现高级功能

排序依据是“用户什么时候看得见、用得上、能理解”，不是功能有多强大，也不是源码模块顺序。产品主体是文字游戏，先介绍文字游玩及相关创作能力；用户画像与文生图均属于后置的可选高级功能，不进入新手主线。画像只在右侧栏建立、修改和开启，开场准备与工作台起始任务均不展示。以下九组是默认导航顺序，不是必须全部完成的学习路线。

| 顺序 | 用户此时的想法 | 文档目录与组内顺序 |
| --- | --- | --- |
| 1. 开始玩 | 我怎么开始第一局？ | 简短介绍 → 安装与模型配置 → 导入人物卡 → 选择开场和玩家称呼 → 输入第一条行动 / 选择候选 → 认识当前游玩界面。完整安装细节按平台展开，画像、预设、后台模型都不是前置课。 |

### 相同功能按认知深度分层介绍

- **角色状态：** 前几轮只说明“这里能看状态，更新失败可以重试”；制作复杂人物卡时才展开 MVU 变量、脚本和转换过程。
- **历史回忆：** 程序可以从早期就提供能力，但用户通常到长局才体会其价值，因此放在长局章节，不要求先懂历史检索才能开始玩。
- **人物卡：** 开始只讲导入、选卡和开场；人物设计、字段编辑、世界书及扩展留到创作阶段。
- **偏好与文风：** 先用当前局的剧情指导解决眼前需求；画像和预设放在高级章节。画像入口仅在右侧栏，新用户不需要在开局前知道或选择画像。
- **文生图：** 属于后置的高级功能，即使界面可见，也不提前进入新手教程。文字游玩完全不依赖生图，详细渠道参数只在需要时展开。

## 一、开始游戏

- 导入 SillyTavern PNG / JSON 人物卡，从人物卡库直接开局。
- 默认无需导入外部预设；模型服务仍需要先配置。
- 有多个开场白的卡，可以预览并选择开场。
- 设置玩家称呼，并可在后续游玩中修改称呼。
- 同一人物卡可以创建多次独立游戏，保留各自对话。
- 没有绑定剧本时自由游玩；绑定剧本的卡在新开局时自动按剧本推进，不需要额外学习一种操作模式。

## 二、决定故事怎么发展

- 自由输入行动、对白或剧情要求。
- 独立生成行动候选和场景变化；点击候选填入输入框，可修改后再发送。
- 重新生成候选，也可附上要求重新生成。
- 一键重新生成当前正文，或填写具体意见后重写。
- 回退当前回合。
- 添加、查看和删除持续生效的剧情指导（界面名称 Guide）。
- 绑定小说、故事大纲或剧本，按当前剧情附近的片段推进；玩家仍可偏离原文行动。
- 查看剧本进度与当前参考片段。

边界：回退与重写不等于完整的任意历史节点分支管理；多开场预览也不等于所有历史正文版本都可以自由切换。

## 三、保持长局连续性与查看状态

- 后台总结人物姿势等场景信息，右侧查看。
- 支持 MVU 人物卡的后台变量结算，以及常驻右侧、随状态更新的状态栏。
- 显示后台结算状态，失败时可单独重试。
- 世界书按规则提供相关背景，玩家不必每轮重复粘贴设定。
- 前台与非生图后台任务可按需检索当前游戏的历史正文，再读取命中轮次附近的原文。
- 提供上下文压缩入口，协调前台和后台的压缩。

对外用语：可以说“按需找回前文细节”，不能承诺“永不失忆”“无限上下文”。历史检索属于系统能力，不应要求新用户学习工具调用。

## 四、让故事更符合个人偏好

- 从右侧“用户画像”面板进入卡片 Agent，通过分批访谈建立长期游玩与写作偏好。
- 原始回答、分析与已确认画像分开保存；新草案不会自动覆盖已确认版本。
- 在用户画像面板查看实际生效文本、偏好维度和原始回答。
- 直接修改已确认偏好，或交给卡片 Agent 继续调查、修订。
- 跨人物卡复用画像；仅在右侧“用户画像”面板设置新游戏默认是否启用，默认关闭。开场准备不显示画像，也不提供单局覆盖。
- 当前游戏使用开局时冻结的画像版本，之后修改画像不会悄悄改写正在玩的游戏。

状态：已有入口、持久化和测试，不再是单纯待办。不要照搬旧 TODO 中“可随时切换当前局”“删除任意画像记录”等尚未在本次入口核对中确认的表述。

## 五、为剧情生成插画

- 配置后手动为剧情生成场景插画，不会每轮自动收费生成。
- 根据目标正文与可用人物、场景资料整理画面；插画不替代或改写剧情正文。
- 直接重画，或填写意见后重画。
- 查看同一段剧情的多张插画版本，打开大图。
- 选择日系插画、写实摄影、水彩、水墨等风格，并补充自定义描述。
- 按渠道设置尺寸、分辨率或画面比例。
- 在支持的渠道中，将已生成图片明确绑定为指定人物的造型参考；可取消绑定。
- 查看生图进度、取消任务；失败时重试，图片生成成功但保存失败时可单独重试保存。
- 配置生图渠道、连接检查，以及部分渠道的模型列表读取。

当前渠道目录包含：OpenAI Images 及同协议中转、Google Gemini 原生、Gemini 聊天兼容中转、Grok、Seedream、Qwen-Image、NovelAI、ComfyUI、SD WebUI / Forge。渠道入口存在不等于任意模型、中转地址都兼容，也不代表本次已逐家实测。

边界：生图默认需配置并开启，可能产生额外费用；造型参考依渠道能力开放，需确认向目标服务发送图片，不保证锁脸。ComfyUI / WebUI 连接已有服务，不负责安装模型和节点。

## 六、通过对话制作和修改内容

- 从想法空白开始，与卡片 Agent 讨论并制作内容。
- 从小说、剧本或素材中制作人物卡。
- 阅读、分析和修改现有人物卡。
- 修改剧本、世界书与外部预设。
- 把多个资源引用进当前工作台对话，作为讨论和创作材料。
- 将人物卡转换为独立的 MVU 版本，把状态栏展示与正文生成分离，并使用 Tavern 内置候选。
- 游玩中遇到正文、正则或美化问题，可把相关游戏记录交给卡片 Agent 调试。
- 保留导入原版，日常编辑工作版；有恢复人物卡原版的 Agent 工具。
- 高级用户可通过 Agent 提炼样文文风，保存可复用 Skill，并创建自定义工具或插件。

边界：有文风提炼和 Skill 保存能力，不等于已有完整的可视化文风库；“转换后绝对不会掉格式”不宜作为宣传承诺。

## 七、管理人物卡、世界书、剧本和预设

### 人物卡库

- 导入、查看、编辑、导出 JSON、重命名文件和删除人物卡。
- 编辑角色描述、性格、情境、开场白、备选开场白、对话示例等字段。
- 管理人物卡的世界书与剧本绑定。
- 查看卡内正则、Tavern Helper 脚本与 MVU 相关资源；查看扩展内容不代表执行所有脚本。

### 世界书库

- 统一查看独立世界书与人物卡内置世界书。
- 导入、导出、编辑条目及启用状态，管理与人物卡的绑定。
- 在卡片对话中引用世界书，交给 Agent 修改。
- 常驻背景与按关键词命中的条目按各自规则参与游玩。

### 剧本库

- 导入 TXT、Markdown、JSON、EPUB 素材（人物卡内直接导入剧本入口为 TXT、Markdown、EPUB）。
- 在资源库查看工作版；通过卡片 Agent 修改正文，支持重命名、删除、引用到卡片对话。当前查看页不是直接编辑正文的文本编辑器。
- 将剧本与人物卡绑定或解绑。

### 预设与系统提示词

- 导入、选择、查看、导出、重命名和删除外部预设。
- 编辑预设提示词、正则和可切换条目的启用状态，或交给卡片 Agent 修改。
- 查看与编辑内置系统提示词，单项或整套恢复默认、导入导出。

定位：预设库服务游玩，用于调整文风、叙事方式与写作规则，不再标为实验性。不导入外部预设也能直接开始；仍将其放在高级使用中，不作为新手必经步骤。导入的酒馆预设在 DSH Tavern 中应用，效果可能与原酒馆不同。

## 八、日常使用与扩展

- 游玩与卡片工作台历史分开管理；继续、重命名或移除对话。
- 将玩家与角色正文导出为纯对话 TXT，不混入推理和工具轨迹。
- 导出 Session、MVU、生图相关日志，便于反馈问题；分享前检查私人剧情。
- 联网搜索可选开启；前后台是否可用在新游戏建立时固化。
- 前台使用 DSH 模型配置；后台可选独立模型，或在开局时跟随前台。
- 安装、更新与数据持久保存；支持界面检查更新。
- Windows / macOS 桌面入口，Windows / macOS / Linux 命令行运行；Android 为实验性方案。
- 保留 DSH 插件与用户扩展组合能力，更新时保护用户配置与自定义内容。

平台和模型管理依赖 DSH，不应全部宣传为 Tavern 自建能力。GitHub Pages 只承载介绍与指南，不托管实际游戏服务。

- 完整可视化文风库：仍有待办，不能与已有文风提炼 Skill 混同。

- “15 秒一轮”“绝对不掉格式”“永不失忆”“保证破限”“保证锁脸”：需要条件和证据，不能写成通用保证。
- 生图所有渠道、Android、完整真实用户流程：本次不是逐项实测验收。

## 十一、文档站的呈现方式

文档站以“开始玩”作为默认阅读起点，同时提供完整功能索引供查阅：左侧按用户阅读顺序分组，中间当前功能说明，右侧本页导航。保留现有宣传页作为可选产品首页，但不以它承载全部使用说明。本轮只整理内容，不改网页布局。

- **首页先帮助开始，也能查找。** 首屏给出开局路径；完整功能索引保留全部主题，熟悉产品的用户可直接定位，不必顺序学习。
- **目录按认知阶段折叠。** 默认展开开始玩与眼前操作；人物设计、MVU 转换、长局记忆按需展开。用户画像、文生图与深度定制放在后面的高级功能区，默认折叠，不与基础文字玩法并列推荐。帮助入口始终可达，不因排在后面而难以找到。
- **每页只讲一个任务。** 导入、绑定、引用、生效范围这类容易混淆的动作明确区分；相邻任务用相关链接串起来。
- **技术感来自明确操作和事实。** 使用界面中的真实名称、操作步骤、效果截图、条件与限制，不把内部架构术语塞进每个页面。
- **页面与产品能力分开。** 索引页、FAQ、渠道配置页属于文档主题，不作为新增功能计数；未写正文的条目不伪装成可访问链接。

### 每个功能页的固定内容

1. **用途：** 一两句话说明它解决什么问题。
2. **在哪里：** 当前界面的入口路径；Agent 能力则给出一句实际提问示例。
3. **怎么用：** 最短可复现步骤，包括必要前置条件。
4. **看到什么：** 实际结果与截图；如有保存、确认、重试，说明成功标志。
5. **影响范围：** 当前回合、当前对话、新开局或全局；是否产生模型费用，是否改写或删除数据。
6. **限制与相关功能：** 常见误解、支持边界、相邻文档链接。

## 十二、完整性核对与不收录项

这份清单以当前可识别的用户能力为范围，不以服务端函数数量衡量完整性。下面是后续维护时的核对位置。

| 来源 | 已覆盖的目录 | 重点核对 |
| --- | --- | --- |
| `TavernSidebar`、开局选择器 | A、B、H、N | 开场选择、称呼、工作台七类起始任务、历史与更新；无画像选项 |
| `CandidateAction`、`CandidateQuestion`、正文渲染 | B、M | 独立候选、填入输入框、重写、回退、思考、后台轨迹 |
| `TavernStatusPanel`、`TavernMvuReceipt`、压缩操作 | C、D、H | 进度与片段、Guide、姿势、变量前后值、重试与调试 |
| 用户画像界面及画像工具 | E | 访谈、草案与确认、实际生效文本、开局快照 |
| `SceneIllustration`、生图设置、渠道目录 | F、G | 启用、出图、重画、版本、参考授权、取消与保存恢复 |
| 四个资源库及字段编辑器 | I、J、K、L | 导入 / 导出格式、编辑和只读区别、绑定与引用、删除范围 |
| 工作台工具与内置 Skill | H、M | 读卡与原始扩展、游戏调试、资源修改、恢复卡、文风与工具扩展 |
| 酒馆设置、系统提示词、导出与错误中心 | L、M、N | 生效范围、DSH 依赖、纯正文与日志区别 |
| 安装器、管理命令与 README 安装说明 | A、N | 平台入口、启停、升级、持久化与备份边界 |

不收录为可用功能：

- 已关闭的兼容模式，包括旧兼容会话的访问和继续生成；保留磁盘数据不等于仍能使用。
- 仅剩内部接口的预设转换 / bypass plan 管理，不据此编写“方案库”教程。
- 只有服务端接口、没有核实用户入口的独立操作，例如图片删除，不冒充已有按钮。
- 未确认的任意历史分支、局内画像自由切换、画像记录删除、完整可视化文风库。
- 尚未验证的所有酒馆插件兼容性、云同步、自动备份恢复，以及无限记忆、绝对不掉格式等承诺。

新增功能时同时补充“目录项、真实入口、影响范围、限制、截图”；失去入口或停用的功能应移出使用目录，而不是保留一篇无法操作的教程。
