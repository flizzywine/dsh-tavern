# 功能盘点与产品介绍网页大纲

核对日期：2026-09-03。

用途：作为产品功能介绍网页的内容底稿，不是已经发布的宣传页，也不代表本次逐项完成真实模型、真实供应商和各平台验收。

依据：当前界面入口、服务端实现和测试。README 与 TODO 可能滞后，不能仅凭待办勾选状态判断功能是否存在。本次补跑用户画像、历史检索、绘图风格、造型参考的 19 项测试，全部通过。

## 一、开始游戏

- 导入 SillyTavern PNG / JSON 人物卡，从人物卡库直接开局。
- 默认无需导入外部预设；模型服务仍需要先配置。
- 有多个开场白的卡，可以预览并选择开场。
- 设置玩家称呼，并可在后续游玩中修改称呼。
- 同一人物卡可以创建多次独立游戏，保留各自对话。
- 没有绑定剧本时自由游玩；绑定剧本的卡在新开局时自动按剧本推进，不需要额外学习一种操作模式。

## 二、决定故事怎么发展

- 自由输入行动、对白或剧情要求。
- 独立生成行动候选和场景变化；点击候选填入输入框，可修改后再发送。
- 重新生成候选，也可附上要求重新生成。
- 一键重新生成当前正文，或填写具体意见后重写。
- 回退当前回合。
- 添加、查看和删除持续生效的剧情指导（界面名称 Guide）。
- 绑定小说、故事大纲或剧本，按当前剧情附近的片段推进；玩家仍可偏离原文行动。
- 查看剧本进度与当前参考片段。

边界：回退与重写不等于完整的任意历史节点分支管理；多开场预览也不等于所有历史正文版本都可以自由切换。

## 三、保持长局连续性与查看状态

- 后台总结人物姿势等场景信息，右侧查看。
- 支持 MVU 人物卡的后台变量结算，以及常驻右侧、随状态更新的状态栏。
- 显示后台结算状态，失败时可单独重试。
- 世界书按规则提供相关背景，玩家不必每轮重复粘贴设定。
- 前台与非生图后台任务可按需检索当前游戏的历史正文，再读取命中轮次附近的原文。
- 提供上下文压缩入口，协调前台和后台的压缩。

对外用语：可以说“按需找回前文细节”，不能承诺“永不失忆”“无限上下文”。历史检索属于系统能力，不应要求新用户学习工具调用。

## 四、让故事更符合个人偏好

- 在卡片工作台中，通过分批访谈建立长期游玩与写作偏好。
- 原始回答、分析与已确认画像分开保存；新草案不会自动覆盖已确认版本。
- 在用户画像面板查看实际生效文本、偏好维度和原始回答。
- 直接修改已确认偏好，或交给卡片 Agent 继续调查、修订。
- 跨人物卡复用画像；可设置新游戏默认是否启用，也可在开局时单局选择。
- 当前游戏使用开局时冻结的画像版本，之后修改画像不会悄悄改写正在玩的游戏。

状态：已有入口、持久化和测试，不再是单纯待办。不要照搬旧 TODO 中“可随时切换当前局”“删除任意画像记录”等尚未在本次入口核对中确认的表述。

## 五、为剧情生成插画

- 配置后手动为剧情生成场景插画，不会每轮自动收费生成。
- 根据目标正文与可用人物、场景资料整理画面；插画不替代或改写剧情正文。
- 直接重画，或填写意见后重画。
- 查看同一段剧情的多张插画版本，打开大图。
- 选择日系插画、写实摄影、水彩、水墨等风格，并补充自定义描述。
- 按渠道设置尺寸、分辨率或画面比例。
- 在支持的渠道中，将已生成图片明确绑定为指定人物的造型参考；可取消绑定。
- 查看生图进度、取消任务；失败时重试，图片生成成功但保存失败时可单独重试保存。
- 配置生图渠道、连接检查，以及部分渠道的模型列表读取。

当前渠道目录包含：OpenAI Images 及同协议中转、Google Gemini 原生、Gemini 聊天兼容中转、Grok、Seedream、Qwen-Image、NovelAI、ComfyUI、SD WebUI / Forge。渠道入口存在不等于任意模型、中转地址都兼容，也不代表本次已逐家实测。

边界：生图默认需配置并开启，可能产生额外费用；造型参考依渠道能力开放，需确认向目标服务发送图片，不保证锁脸。ComfyUI / WebUI 连接已有服务，不负责安装模型和节点。

## 六、通过对话制作和修改内容

- 从想法空白开始，与卡片 Agent 讨论并制作内容。
- 从小说、剧本或素材中制作人物卡。
- 阅读、分析和修改现有人物卡。
- 修改剧本、世界书与外部预设。
- 把多个资源引用进当前工作台对话，作为讨论和创作材料。
- 将人物卡转换为独立的 MVU 版本，把状态栏展示与正文生成分离，并使用 Tavern 内置候选。
- 游玩中遇到正文、正则或美化问题，可把相关游戏记录交给卡片 Agent 调试。
- 保留导入原版，日常编辑工作版；有恢复人物卡原版的 Agent 工具。
- 高级用户可通过 Agent 提炼样文文风，保存可复用 Skill，并创建自定义工具或插件。

边界：有文风提炼和 Skill 保存能力，不等于已有完整的可视化文风库；“转换后绝对不会掉格式”不宜作为宣传承诺。

## 七、管理人物卡、世界书、剧本和预设

### 人物卡库

- 导入、查看、编辑、导出 JSON、重命名文件和删除人物卡。
- 编辑角色描述、性格、情境、开场白、备选开场白、对话示例等字段。
- 管理人物卡的世界书与剧本绑定。
- 查看卡内正则、Tavern Helper 脚本与 MVU 相关资源；查看扩展内容不代表执行所有脚本。

### 世界书库

- 统一查看独立世界书与人物卡内置世界书。
- 导入、导出、编辑条目及启用状态，管理与人物卡的绑定。
- 在卡片对话中引用世界书，交给 Agent 修改。
- 常驻背景与按关键词命中的条目按各自规则参与游玩。

### 剧本库

- 导入 TXT、Markdown、JSON、EPUB 素材（人物卡内直接导入剧本入口为 TXT、Markdown、EPUB）。
- 查看与编辑工作版，重命名、删除、引用到卡片对话。
- 将剧本与人物卡绑定或解绑。

### 预设与系统提示词

- 导入、选择、查看、导出、重命名和删除外部预设。
- 编辑预设提示词、正则和可切换条目的启用状态，或交给卡片 Agent 修改。
- 查看与编辑内置系统提示词，单项或整套恢复默认、导入导出。

定位：预设库服务游玩，用于调整文风、叙事方式与写作规则，不再标为实验性。不导入外部预设也能直接开始；仍将其放在高级使用中，不作为新手必经步骤。导入的酒馆预设在 DSH Tavern 中应用，效果可能与原酒馆不同。

## 八、日常使用与扩展

- 游玩与卡片工作台历史分开管理；继续、重命名或移除对话。
- 将玩家与角色正文导出为纯对话 TXT，不混入推理和工具轨迹。
- 导出 Session、MVU、生图相关日志，便于反馈问题；分享前检查私人剧情。
- 联网搜索可选开启；前后台是否可用在新游戏建立时固化。
- 前台使用 DSH 模型配置；后台可选独立模型，或在开局时跟随前台。
- 安装、更新与数据持久保存；支持界面检查更新。
- Windows / macOS 桌面入口，Windows / macOS / Linux 命令行运行；Android 为实验性方案。
- 保留 DSH 插件与用户扩展组合能力，更新时保护用户配置与自定义内容。

平台和模型管理依赖 DSH，不应全部宣传为 Tavern 自建能力。GitHub Pages 只承载介绍与指南，不托管实际游戏服务。

## 九、不要列为当前正式卖点

- 兼容模式：已停用，网页不再提供开启方法。
- 任意历史节点的完整剧情分支管理：本次未核实完整入口与状态语义。
- 完整可视化文风库：仍有待办，不能与已有文风提炼 Skill 混同。
- 通吃所有酒馆插件、手机插件或数据库：不能根据底层桥接接口存在就作此承诺。
- “15 秒一轮”“绝对不掉格式”“永不失忆”“保证破限”“保证锁脸”：需要条件和证据，不能写成通用保证。
- 生图所有渠道、Android、完整真实用户流程：本次不是逐项实测验收。

## 十、网页结构建议

目标是完整介绍，但不让用户按顺序学习全部功能。

1. **首页：导入一张卡，开始你的故事。** 一张整体界面图、简短定位、开始使用按钮。突出自由游玩、剧本、对话制卡、插画四种结果，而不是铺满功能名。
2. **快速开始。** 配置模型 → 导入人物卡 → 选择开场 → 输入或点选下一步；其他内容可跳过。
3. **游玩指南。** 候选、重写、回退、剧情指导、剧本、状态与长局连续性。
4. **个性化与插画。** 长期偏好、开局选择、绘图与重画；高级渠道参数折叠。
5. **创作与资源。** 卡片 Agent、从小说制卡、四个资源库、MVU 转换。
6. **高级使用。** 预设、系统提示词、文风 Skill、模型分工、联网、插件。
7. **安装与常见问题。** 平台差异、更新、数据位置、TXT 导出、反馈问题。

每个功能统一采用“能帮你做什么 → 最短操作 → 截图或例子 → 必要限制”。主文用“剧情指导”“长期偏好”“角色状态”等日常用语，再注明现有界面名称。

截图保留左侧入口、中央操作和右侧结果之间的关系；细节局部图作为补充。新功能应重新截图，不默认旧 README 图片仍准确。
