DSH Tavern 功能清单（纯文本审阅版）
整理日期：2026-09-17
对应版本：v1.9，包含此后已合入的更新。
用途：重新整理教学文档的内容底稿。本清单按用户任务分类，不把每个按钮单独算作一项功能，也不包含待开发需求。

一、入门与运行
1. 提供游玩模式和卡片工作台：前者进行文字游戏，后者制作、修改和管理资源。
2. 支持 Windows、macOS Desktop，以及 Windows、macOS、Linux 命令行运行；Android 支持独立 APK 或通过 DSHA 使用。
3. 在 DSH 设置中配置文字模型的服务地址、密钥和模型。
4. Desktop 的“打开 DSH 终端”位于设置窗口顶部；在“桌面设置”的 Profile 中选择 tavern。
5. 支持启动、停止、重启和检查更新。文档网站只提供说明，不运行游戏。

二、开始与继续游玩
1. 导入 PNG 或 JSON 人物卡，从人物卡库新建游戏。
2. 预览并选择人物卡提供的开场白，设置玩家称呼。
3. 同一张人物卡可创建多局独立游戏，分别保存对话与状态。
4. 自由输入行动、对白和剧情要求。
5. 生成行动候选；点击候选填入输入框，修改后再发送。
6. 重新生成候选，可附加要求。
7. 重新生成当前正文，可填写修改意见。
8. 从“更多”进入“编辑正文”，手动修改当前可编辑正文。
9. 回退本轮；没有本轮完整正文时，回退目标可能是上一轮完整对话，应查看按钮中的目标轮次。
10. 回退直接执行，不弹确认框；生成或相关后台任务进行时不可回退。
11. 回退后可通过“撤销回退”恢复正文与状态；新的操作可能使恢复点失效，不是无限次撤销。
12. 对符合条件的末尾失败或停止回复，提供清理未完成回复的操作。
13. 使用 Guide 添加、查看和删除持续生效的要求（正文、候选和变量结算都会参考）。
14. 查看正文、推理与工具轨迹；内部恢复事件不作为剧情展示。
15. 继续、重命名和移除历史游戏；导出玩家输入与故事正文为 TXT。

三、剧本游玩
1. 导入小说、大纲或剧本，与人物卡绑定；新开局使用绑定剧本。
2. 按剧情附近的剧本片段提供参考，玩家仍可以自由行动。
3. 右侧显示剧本块的实际内容、当前游标和总块数。
4. 一次列出 10 个剧本块，默认尽量让当前块位于列表中间。
5. 输入“剧本块号”，点击“跳转到”浏览指定位置；“回到当前”返回当前游标附近。
6. 使用左右翻页按钮浏览前后剧本块。
7. 点击指定块的“切换游标位置”，手动指定后续剧情参考位置。
8. 浏览和翻页不修改游标。只能在空闲时切换，修改在下一轮生效；之后 Agent 仍可按原有逻辑调整位置。
9. 新导入剧本按约 500 个中文汉字的软预算分块，可为保持段落完整稍微超过；已有剧本不会仅因更新程序而自动重新分块。

四、人物状态与后台处理
1. 前台生成剧情，后台处理状态、变量和相关辅助任务。
2. 查看本轮后台处理状态及更新结果。
3. 支持 MVU 人物卡的变量更新、更新回执和常驻状态栏。
4. 后台结算失败时可单独重试，不必重新生成整段正文。
5. 提供停止后台任务的操作。
6. 后台可按需设计、补全和复用本局重要人物档案；普通人物卡不会因此自动拥有 MVU 状态栏。
7. 本局人物状态和档案与其他游戏独立，不直接修改导入人物卡原版。

右侧“酒馆状态”面板：操作说明

1. 交给卡片 Agent 调试
用途：正则加载、前端美化、正文生成或人物表现不符合预期时，让卡片 Agent 结合实际游玩记录分析。
操作：点击“交给卡片 Agent 调试”，进入工作台，补充具体问题、发生轮次和预期效果，再发送任务。
结果：任务包含目标人物卡和已关联游玩记录的引用，Agent 可按需读取记录进行排查；点击入口本身不等于已完成修复。

2. Guide（注入上下文）
用途：给当前游戏添加持续的写作要求、剧情走向或数值尺度，例如“多用短句，多写心理活动”“好感度涨得慢一点”。
操作：在文本框输入要求，点击“添加 Guide”；已添加的要求显示在上方列表，可逐条删除。
生效范围：参与后续正文、候选项生成和后台变量结算，不会自动改写已经生成的正文，也不会重算已结算的轮次。它是当前局的指导，不是跨游戏的默认偏好。

3. 人物设计档案 / 设计人物
用途：按玩家要求为本局创建或补充人物档案，并查看已有设计。
操作：空闲时点击“设计人物”，输入设计意见，再点击“开始设计”；也可不填意见，让后台根据当前剧情和已有档案设计。
结果：列表显示人物名称、身份摘要和更新时间；点击人物可展开查看别名及各项设计内容。
状态：执行时显示“设计中…”，失败时可用“重试设计”。生成或后台忙碌时入口不可用。
生效范围：属于本局人物档案，不等于修改人物卡原版，也不代表设计中的未来情节已经发生。

4. 人物姿势
用途：查看本轮结束时人物的位置、动作、姿势及相关场景状态，帮助理解人物当前在做什么。
操作：直接阅读面板内容，无需额外发送请求；首次结算前显示等待提示。
更新方式：由后台的人物姿势结算任务更新；是否更新取决于任务设置及结算结果。这里展示场景状态，不是人物性格档案。

5. 想调整文风？四种入口
“当前故事”：定位到 Guide 输入框，调整本局后续写法。
“长期偏好”：打开用户画像，设置新游戏使用的长期偏好；不会直接改写已有游戏的画像。
“这张人物卡”：交给卡片助手修改卡片中的设定或写作要求，再按应用流程用于当前游戏；不是只修改当前一段正文。
“导入预设”：打开预设库，导入和管理已有预设。外部预设可能增加思考时间和游玩延迟，效果也可能不同于原酒馆。
选择方法：只想影响这一局，用 Guide；想供以后开局复用，用画像；要修改这张卡本身，用卡片助手；已有一套外部提示词方案，再考虑预设。

五、世界书与历史记忆
1. 使用人物卡内置世界书，也可关联独立世界书。
2. 支持常驻背景，以及按受支持的关键词、组合和排除规则召回条目。
3. Agent 可按需检索本局历史，读取相关轮次的原文。
4. 对重复历史召回进行限制；已召回内容设有 10 轮冷却，前台和后台分别管理。
5. 提供上下文压缩，协调前台与后台处理，支持相应的自动压缩设置。
6. 历史检索与压缩用于辅助长局连续性，不保证无限上下文或永不遗漏。

六、卡片工作台
1. 与卡片 Agent 对话，从想法、人物资料或故事素材制作人物卡。
2. 从小说、剧本中抽取人物与相关设定。
3. 用自然语言分析、修改人物卡、世界书、预设和剧本。
4. 将一个或多个资源引用到工作台对话中，作为修改材料。
5. 保留人物卡导入原版与工作版，可通过 Agent 恢复原版。
6. 给人物卡加上 MVU 变量（各开场初值、后台更新规则、状态栏面板），可在副本上改以保留原卡。
7. 调试游玩中的人物表现、正文、正则或状态异常。
8. 调试任务中显示已关联游玩记录的简短引用，Agent 可按需读取记录概览、日志和状态。
9. 工作台对话与游玩对话分别管理，可继续、重命名和移除。
10. “新建人物卡”任务：逐题问答确定角色与开场，可选 MVU 变量和前端美化；美化先在对话中以 HTML 草图预览。

七、资源库
人物卡库：
1. 批量导入 PNG、JSON 人物卡，搜索、筛选、查看、重命名和删除。
2. 编辑人物描述、性格、情境、开场白、备选开场白、对话示例等字段。
3. 查看卡内正则、脚本和 MVU 相关扩展资源。
4. 管理世界书和剧本绑定，导出 JSON 人物卡。

世界书库：
1. 查看独立世界书与人物卡内置世界书。
2. 导入、导出、重命名和删除世界书。
3. 编辑条目内容、触发配置和启用状态，管理人物卡关联。
4. 引用世界书到工作台，交给 Agent 修改。

剧本库：
1. 导入 TXT、Markdown、JSON、EPUB；人物卡内的直接导入入口支持 TXT、Markdown、EPUB。
2. 查看剧本、重命名、删除，与人物卡绑定或解绑。
3. 引用到工作台，由 Agent 修改；剧本查看页不是直接编辑正文的文本编辑器。

预设库：
1. 导入、查看、导出、重命名和删除外部预设。
2. 设置新游戏默认预设；当前游戏的预设在“本局设置”中管理。
3. 编辑提示词条目、角色、内容、启用状态、顺序和所在分段。
4. 编辑预设正则的匹配、替换和相关作用配置。
5. 默认可不使用外部预设。外部预设可能显著增加思考时间和游玩延迟，效果也可能不同于原酒馆。

八、个性化与提示词
1. 通过 Guide 调整当前局的剧情方向、文风和额外要求。
2. 在“系统提示词”中查看、编辑可管理的内置提示词。
3. 导入、导出提示词配置，单项或整套恢复默认。
4. 程序更新保留用户自行保存的系统提示词修改。
5. 通过用户画像访谈整理长期游玩偏好，区分原始回答、草案和已确认画像。
6. 查看、修订已确认画像，设置新游戏是否默认启用；默认关闭。
7. 游戏使用开局时的画像版本，后续画像修改不会自动改写已有游戏。
8. 让 Agent 分析样文、提炼文风，并按要求保存为 Skill。

九、模型、搜索与扩展
1. 配置前台文字模型；后台可选择独立模型，或在开局时跟随前台。
2. 在本局设置中开启联网搜索并保存，本局前后台从后续请求起可按需查阅外部资料；切换影响缓存，依赖 DSH 搜索能力。
3. 在 Agent 轨迹中查看模型调用和工具执行过程。
4. 通过工作台使用或创建 Skill、自定义工具和插件；相关能力依赖 DSH。
5. 支持受适配范围内的人物卡正则、HTML 美化和脚本能力，不等于兼容所有酒馆插件及宿主接口。

十、剧情生图
1. 配置并启用生图后，手动为剧情生成插画。
2. 选择绘图风格，添加自定义描述，按渠道设置尺寸或比例。
3. 直接重画，或填写意见后重画。
4. 查看同段剧情的多个图片版本，打开大图。
5. 在支持的渠道中，将图片绑定为人物造型参考，也可解除绑定。
6. 查看生成进度、取消任务、失败重试；生成成功但保存失败时可重试保存。
7. 检查渠道连接，部分渠道支持读取模型列表。
8. 渠道入口包括 OpenAI（gpt-image 及兼容中转）、Google Gemini（官方）、Grok（xAI）、Seedream（火山方舟）、Qwen-Image（阿里百炼）、NovelAI（官方或中转站）、ComfyUI（自建）、SD WebUI / Forge（自建）。
9. 实际模型、参考图和参数能力因渠道而异；本地绘图渠道连接已有服务，不负责安装模型。

十一、诊断、维护与数据
1. 查看运行错误和任务轨迹，导出诊断信息用于反馈问题。
2. 诊断包含与问题相关的会话、后台、MVU、生图及性能信息，并记录相关预设和正则配置。
3. 将关联游玩记录交给调试 Agent 分析。
4. 备份本地数据目录，保留人物卡、资源和游戏记录。
5. 支持检查更新；更新操作与用户资源、提示词自定义内容区分处理。

十二、记忆管理：压缩与历史检索怎样配合

1. 区分三类内容
当前上下文：模型本次直接看到的提示词、近期消息和压缩摘要。
游玩记录：本局已经发生的玩家输入与故事正文，可用于回查细节。
用户画像：跨人物卡复用的长期偏好，不用于保存每局剧情经过。

2. 压缩上下文
用途：对话变长时，将上下文整理成更精简的摘要，减少后续请求携带的内容。
操作：空闲时使用“更多”中的压缩入口；自动压缩按相应设置触发，不需要每轮手动压缩。
前后台：两者上下文独立，酒馆协调压缩并分别报告结果，不能把前台成功当成后台也成功。
结果：压缩影响模型后续直接看到的内容，不等于删除游玩记录。摘要可能遗漏细节，因此仍需要原文检索。
注意：压缩会改变请求上下文，可能影响缓存复用；不建议为了少量文字频繁压缩。失败时先看具体结果，不要连续重复点击。

3. 历史检索工具 tavern_recall_history
用途：找回当前游戏已经发生的细节，例如某个人物说过的话、先前的约定、物品来源。
两种用法：按关键词检索相关轮次；按轮次读取该轮及附近的原文。
玩家操作：通常由 Agent 按需调用，也可直接说“查一下之前和店主约定的时间，再继续剧情”，不需要自己填写工具参数。
限制：每次生成最多召回 6 次；完整正文召回后冷却 10 个剧情轮次，前后台分别管理，避免反复读取同样内容。
边界：工具查询本局已发生的剧情，不搜索互联网，也不能把搜到的旧事件重新当成当前事件演一遍。

4. 推荐的长局使用方式
正常游玩 → 上下文变长时压缩 → 摘要维持主要线索 → 需要细节时检索原文 → 继续当前剧情。
若发现记错，指出人物、事件关键词或大致轮次，让 Agent 回查；不要仅要求它“凭记忆想起来”。
不采用每轮通用删除历史标签的办法；状态栏里可能包含剧情信息，修改旧内容也可能影响缓存。

十三、内置工具：Agent 能替玩家做什么

工具通常由 Agent 根据任务调用；不同模式分配的工具不同，并非所有工具都提供给正文 Agent。

1. 读取剧本：tavern_read_script，按需取得剧本内容，辅助剧本推进或工作台分析。
2. 读取游玩记录：tavern_read_play_chat，供调试工作台读取已关联记录的概览及相关证据；与正文 Agent 回忆剧情的 recall 工具分工不同。
3. 人物卡读写：tavern_read_card、tavern_read_card_raw、tavern_update_card，读取结构化设定或原始卡片，按要求修改。
4. 人物卡检查与恢复：tavern_validate_card、tavern_restore_card，检查卡片结构，按要求恢复导入原版。
5. 世界书读写：tavern_read_worldbook、tavern_update_worldbook，检查并修改世界书内容。
6. 预设读写：tavern_read_preset、tavern_update_preset，检查和修改提示词及相关配置。
   正则库：tavern_read_regex_library，读取用户导入的正则，按要求写入人物卡或预设；正则库本身不生效。
7. 用户画像：tavern_user_profile_read、tavern_user_profile_save_draft、tavern_user_profile_confirm，分别读取、保存草案和确认画像。
8. Skill 保存与资料读取：tavern_save_skill、tavern_read_skill_reference，保存可复用的方法，按需加载配套资料。
9. 调试验证：tavern_test_response，供 Agent 在调试流程中测试响应；不能仅凭一次测试保证所有场景正确。

十四、内置 Skill 与自定义 Skill

Skill 是 Agent 在特定任务中使用的工作方法；工具负责实际读取、保存或执行。玩家一般用自然语言提出任务，不必背工具名。

1. debug-card：诊断卡片游玩异常。
示例：“这局状态栏不刷新，请结合关联记录检查原因。”
结合日志、提示词和状态证据排查，适用于显示异常、结算失败、提示词未生效和生成缓慢。

2. card-to-mvu：给人物卡加上 MVU 变量。
示例：“把这张卡转成 MVU 版，原卡保留。”
写各开场初值、后台更新规则与状态栏面板，按格式约定直接改卡，改完校验；不是所有卡都需要转换。

3. user-profile：建立和修订长期用户画像。
通过分批访谈整理偏好，先出草案，经过确认后保存。具体操作见下一节。

4. create-writing-skill：把引用的写作教学材料整理成场景写作 Skill。
操作：先在“剧本与素材库”引用材料，再明确要求“根据这份材料创建写作 Skill”。单纯导入文件不会自动制作 Skill。
结果：形成包含适用场景和写法的独立 Skill，默认分配给前台，由模型按场景选择；可在 Skill 库管理，并在本局设置中开关写作 Skill。

5. create-skill：创建或改进通用 Tavern Skill。
示例：“把这套检查人物设定的方法做成可重复使用的 Skill。”
整理任务边界、步骤和必要参考资料，供以后复用。

6. advanced-capabilities：创建 Skill、自定义工具或 Cordis 插件等高级扩展。
用户扩展保存到持久数据目录，区分临时加载和重启后仍可用；普通改卡无需使用这一能力。

7. gentle-rewrite：现有人物卡的特定改写流程。
它用于制作独立副本，不是剧情生成或记忆管理功能；具体处理范围应在任务中明确，不能理解为通用的一键修复。

8. create-card：逐题问答从零新建原创人物卡。
从起始任务“新建人物卡”进入。确认设定后创建并校验；选择 MVU 时直接在这张卡上加变量与状态栏，选择美化时先给出 2–3 种 HTML 草图供挑选。草图仅为静态示意，脚本不运行。

9. 自定义 Skill 管理
在 Skill 库查看、调整用途或删除已保存的 Skill。写作 Skill 用于指导表达，不代替人物卡事实、玩家选择或工具权限。

十五、用户画像：保存长期偏好

1. 什么时候使用
希望不同人物卡的新游戏都遵循相似偏好，例如偏好的题材、叙事视角、描写密度、推进速度、人物主动性和不喜欢的套路。
单局临时要求放在 Guide；某个人物的设定写入人物卡；已经发生的剧情由游玩记录和压缩摘要保存。

2. 如何建立
从右侧“用户画像”入口进入访谈。Agent 每次围绕一个小主题提问，可选参考答案，也可自由回答或跳过。
已有画像时可以只修订某部分，不必从头重做问卷。

3. 如何确认
Agent 整理原始回答、偏好分析和拟用于游戏的摘要，先保存并展示草案。
检查有没有误解、推断或不希望长期保留的内容，要求修改后再确认保存。回答问卷不等于确认画像。

4. 如何启用
保存后，在右侧“用户画像”打开“新游戏默认启用”；默认关闭，保存画像不会自动打开开关。
之后的新游戏使用开局时的已确认画像。已有游戏保持原有版本，修改画像不会追溯改变它们。

5. 如何查看和修改
在面板查看实际生效文本、偏好维度及原始回答；可以修改已确认偏好，或让 Agent 继续访谈、形成新草案后确认。
画像记录用户认可的长期偏好，不应把 Agent 的猜测、单局人物设定或暂时情绪直接当成长期结论。

十六、酒馆设置：阅读显示与自动压缩

入口：DSH 设置 → DSH Tavern。

1. 正文分色开关
为引号内的对白和斜体文字分别着色，普通文字保持原色，并保留人物卡已有配色。
勾选后开启，取消勾选后关闭。此设置只影响当前浏览器的显示，不修改剧情、存档或发送给模型的文字。

2. 对白颜色与斜体颜色
分别点击对应色块，选择自己喜欢的颜色，修改即时应用。
未自定义时，默认配色自动适配深浅背景；关闭正文分色时，颜色选择器不可用。
设置保存在当前浏览器，不是跨设备统一设置。

3. 恢复默认配色
点击后清除自定义颜色，恢复随深浅背景适配的默认配色。
没有自定义颜色时按钮不可用；恢复配色与关闭正文分色是两种操作。

4. 手动压缩（默认）
程序不按轮数或百分比自动触发压缩，由玩家在游玩中的压缩入口发起。
适合希望自行决定何时整理上下文的用户。

5. 每 N 轮自动压缩
选择此模式后填写剧情轮数，可设置 1–1000 轮，初始配置为 20 轮。
计数针对剧情轮次，重写同一轮、工具调用和生图不额外计轮。
自动压缩在后台结算后的安全时机执行，协调前台和后台，再继续下一轮。

6. 上下文达到 X% 自动压缩
选择此模式后填写占用阈值，可设置 10–95%，初始配置为 80%。
百分比是相对于模型上下文窗口的估算，不是精确的账单或剩余额度。
模型窗口大小未知时会提示，可改用按轮数压缩。

7. 保存压缩设置
修改模式或阈值后，点击“保存压缩设置”。保存成功后，在下一个安全边界生效，不会立即打断正在生成的正文。
自动压缩不会删除原始剧情记录，但会改变模型直接看到的上下文，并可能影响缓存；阈值不宜设置得过于频繁。
与“正文分色”的浏览器本地设置不同，压缩设置由酒馆保存。
