# Tavern 原生世界书激活设计

> 状态：已实现
> 当前范围：只改 dsh-tavern，不修改 DSH 本体。

## 结论

世界书是创作者编写的确定性上下文规则，不再交给后台 Agent 二次分析。

- 常驻条目随人物卡基本信息进入前台 Agent 的稳定前缀；
- 非常驻条目在上一轮正文完成后按关键词确定性匹配；
- 每轮最多选择 3 个非常驻条目，注入下一轮正文请求一次；
- 只有实际注入的非常驻条目进入 10 个剧情回合冷却；
- 世界书不进入候选生成、姿势结算或后台 Agent Session；
- 匹配和投影全部在本地完成，不产生模型调用和后台等待。

## 运行链路

```text
创建或迁移游玩会话
  → 读取当前绑定世界书
  → 启用的常驻条目按 order 排序
  → 与人物卡基本信息一起固化为稳定前缀

上一轮正文完成
  → 只扫描最新一轮正文
  → 对启用的非常驻条目执行 Tavern 关键词逻辑
  → 排除仍在冷却期的条目
  → 按 order 和原始顺序稳定排序
  → 最多取 3 条，保存为下一轮世界书上下文
  → 姿势结算独立运行

下一轮正文
  → 稳定前缀提供常驻条目
  → 动态上下文只注入上一步选中的非常驻条目
```

候选项与姿势结算不读取 `preparedWorldBookContext`，也不会因共享后台 Session 间接看到世界书正文。

## 常驻条目

满足以下条件的条目进入稳定前缀：

- `enabled !== false`；
- `constant === true`；
- `content` 非空。

常驻条目不受 3 条上限和 10 轮冷却限制。它们按 Tavern `order` 降序、`displayIndex` 与原始顺序稳定排列，并在进入 Agent 前统一解析宏、分离展示内容和清理失败宏。

稳定前缀随 Tavern 对话保存。旧对话的快照版本低于当前版本时，在下一次使用时重建一次；普通回合不重复拼装常驻内容。

## 非常驻关键词匹配

匹配对象仅为最新一轮已提交的 assistant 正文，不读取玩家输入和更早历史。

第一阶段执行以下 Tavern 字段：

- `enabled`、`constant`；
- 普通主关键词和合法正则主关键词；
- `secondaryKeys` 与四种 `selectiveLogic`；
- `caseSensitive`、`matchWholeWords`；
- `order`、`displayIndex`。

四种副关键词逻辑：

| 值 | 语义 |
| --- | --- |
| `0` | `AND_ANY`：至少一个副关键词命中 |
| `1` | `NOT_ALL`：不能全部命中 |
| `2` | `NOT_ANY`：所有副关键词都不能命中 |
| `3` | `AND_ALL`：所有副关键词都命中 |

主关键词必须先命中。超过 3 个条目符合条件时，按 `order` 降序选择前三条，不让模型再次判断相关性。

概率、分组竞争、递归扫描、Timed Effects、向量、Automation、Outlet、人物过滤和精确 `position/depth/role` 注入位置暂时只保留原字段，不伪装成已经执行。

## 十轮冷却

非常驻条目在第 `N` 轮实际注入后，第 `N+1` 至 `N+10` 轮不再注入，第 `N+11` 轮恢复资格。

- 只有最终选中的最多 3 条进入冷却；
- 命中但因上限未入选的条目不进入冷却，下一轮仍可竞争；
- 冷却按稳定条目引用和正文指纹保存；
- 条目正文改变后旧冷却立即失效；
- 剧情回退通过 Story Timeline checkpoint 恢复当时的冷却记录。

## 前台注入

常驻内容位于稳定前缀：

```text
【常驻世界书】
...
```

非常驻内容只进入下一轮正文动态投影：

```text
【本轮世界书上下文】
...
```

动态内容不是玩家可见消息，不写入人物卡，也不进入后台 Agent 历史；下一次正文完成后由新的匹配结果覆盖。

## 失败与兼容

- 未绑定、空世界书或没有关键词命中时，动态上下文为空；
- 世界书文件缺失、损坏或单条规则异常时记录诊断，正文仍可继续；
- 未支持字段继续无损导入、编辑和导出；
- 不设置 Agent fallback，避免把确定性创作意图重新变成概率判断。

## 验收标准

- 世界书处理不产生 `worldbook` Agent operation；
- 正文提交后的后台周期直接进入 `settlement`；
- 常驻条目只在稳定前缀出现；
- 非常驻条目每轮最多注入 3 条；
- 实际注入后冷却 10 轮，第 11 轮恢复；
- 候选、结算和后台 Session 中没有世界书原文；
- 世界书匹配不增加任何模型等待时间。
