# 世界书召回任务设计

> 状态：第一版已实现；待使用真实大型世界书继续调整预算与召回质量。

## 目标

每轮正文生成完成后，由后台 Agent 在结算阶段召回世界书，保存为“下一轮世界书上下文”。下一轮玩家输入或选择候选项时，前台只读取已经准备好的结果并立即生成正文，不再临时启动世界书任务。

设计重点：

- 世界书为空时不运行任务，也不注入世界书区块。
- 已启用条目正文合计不超过 200 字时，由程序直接注入前台，不调用后台 Agent。
- 只有正文合计超过 200 字时，才运行世界书召回任务。
- 常驻条目只提供标题目录，后台 Agent 判断需要后再读取正文。
- 非常驻条目由程序只对最新一轮正文做关键词匹配；命中后也只提供标题，由后台 Agent 判断是否读取正文。
- 条目读取后连续 10 个剧情回合不再进入标题目录；后台 Agent 应复用前文，必要时仍可凭引用或准确标题重读。
- 后台 Agent 输出最少但足够的本轮上下文，不把整本世界书塞给前台。
- 最新一轮正文已经明确的信息不重复注入。
- 空结果是正常且鼓励的；多数回合不需要额外世界书设定时，不应为了完成任务强行输出内容。
- 世界书失败不得阻断正文生成。
- 兼容 SillyTavern 的文件字段，但不复制其复杂运行规则。

## 当前实现

旧 `Context Planner` 中“常驻全文直接注入、非常驻关键词直接注入”的路径已经删除。当前链路为：

```text
上一轮正文完成
  → 程序整理常驻标题目录
  → 程序用最新一轮正文匹配非常驻标题
  → 后台 Agent 执行 worldbook 任务
  → 按需读取常驻或命中的非常驻条目全文
  → 保存下一轮世界书上下文
  → 姿势结算
  → 按需生成候选项
  → 下一轮前台正文直接读取已保存结果
```

切换时必须删除旧的直接注入路径，不能让两套逻辑同时生效。

## 运行规则

### 程序预检

程序先汇总当前人物卡所绑定世界书中所有已启用条目的正文，并按去除首尾空白后的 Unicode 字符数计算总量。一张人物卡最多绑定一份世界书。

| 有效正文总量 | 处理方式 |
| --- | --- |
| 0 字 | 不运行召回任务，不注入世界书区块 |
| 1～200 字 | 不运行召回任务，由程序把全部有效正文直接放入前台的世界书上下文 |
| 超过 200 字 | 运行后台 `worldbook` 召回任务 |

这一步完全由程序判断，不调用模型。直接注入指进入前台 Agent 的提示词上下文，不是追加到玩家可见正文。

### 条目分类

`dsh-tavern` 只使用 `constant` 决定召回路径：

- `constant === true`：常驻条目；只先把标题交给后台 Agent。
- 其他情况：非常驻条目；由程序按关键词匹配。

`enabled === false` 是条目总开关，关闭的条目不参与召回。它不是召回算法参数。

非空的 `keys` 与 `secondary_keys` 统一视为关键词，按“任意一个命中即可”处理。第一版只做不区分大小写的字面包含匹配，不实现概率、组合条件或递归扫描。

以下字段只负责导入、展示、编辑和原样导出，不影响 `dsh-tavern` 的运行结果：

- `position`、`order`、`depth`、`role`
- `probability`、`selective`、`selectiveLogic`
- `caseSensitive`、`matchWholeWords`、`scanDepth`
- `group`、`recursion`、`vectorized`
- 扩展字段及其他 SillyTavern 参数

### 人物卡绑定

- 一张人物卡最多绑定一份世界书。
- 人物卡带有内置世界书时，导入后默认绑定该内置世界书。
- 没有内置世界书的人物卡默认不绑定世界书。
- 用户可以解绑当前世界书，也可以改绑世界书库中的其他世界书。
- 解绑只删除绑定关系，不删除人物卡内置世界书或世界书库文件，以后可以重新绑定。
- 世界书库中的文件不会自动参与游玩，只有当前人物卡绑定的世界书会进入预检和召回。
- 已绑定的世界书不存在或无法读取时，按未绑定处理并记录持久错误，不阻断正文。

### 非常驻关键词匹配

匹配输入只使用宏解析、HTML 分离和展示正则处理后的最新一轮正文。玩家行动已经反映在生成完成的正文中，不再重复输入；更早历史由持续后台 Agent 自己保留，不再由程序每轮重传。

命中条目过多时，程序按以下顺序保留候选：

1. 命中关键词数量更多；
2. 世界书中的原始顺序仅用于稳定结果，不表达优先级。

程序只负责找出候选，不直接决定最终注入内容。

### 已读条目冷却

世界书工具成功返回条目正文后，该条目从之后 10 个剧情回合的常驻和非常驻标题目录中隐藏，第 11 个回合重新出现。隐藏只影响目录推荐，不撤销工具权限：后台 Agent 如果记得条目引用或准确标题，仍可在确实需要核对原文时重读；重读后重新开始 10 轮隐藏期。

冷却状态按人物卡对话保存。条目正文变化时原记录立即失效；正文回退时恢复 checkpoint 中对应的冷却状态。即使本次召回最终失败，只要工具已经成功返回条目，也视为已读。

## 一轮任务顺序

1. 前台使用上次结算保存的世界书上下文生成正文；
2. 正文提交后进入后台结算；
3. 程序统计已启用条目正文总字数：空世界书跳过，1～200 字直接保存，超过 200 字运行召回；
4. 世界书召回保存“下一轮世界书上下文”；
5. 运行姿势结算；
6. 用户需要时再生成候选项；
7. 下一轮玩家输入或点击候选项时，前台直接读取已保存结果。

玩家输入、点击候选项和重新生成候选项都不得临时触发世界书召回。固定开场白视为第 0 轮正文：第一次生成候选项时，先完整执行一次“世界书召回 → 姿势结算 → 候选项生成”。如果用户跳过候选项直接输入行动，则使用当前已保存结果（初始为空），不阻塞正文。

世界书、状态结算和候选项复用现有持久后台 Agent，但属于三种不同任务：

| 任务 | 时机 | 可提交结果 |
| --- | --- | --- |
| `worldbook` | 正文提交后的后台结算开头 | 下一轮世界书上下文 |
| `settlement` | 正文提交后 | 姿势及获准的派生状态 |
| `candidate` | 用户显式触发 | 候选项及获准的剧情点提案 |

不新增独立长期 Agent。每次任务都要携带清晰的任务标记和最新权威状态，不能把另一类任务的旧输出当作本轮结果。

## Worldbook Recall Module

世界书召回应成为一个深 Module，路径解析、格式兼容、关键词匹配、预算、工具权限和结果校验都收进内部。调用方只看一个接口：

```js
const result = await worldbookRecall.recall({
  chat,
  card,
  boundWorldBook,
  basedOn: { branchId, revision }
})
```

返回：

```js
{
  context: '可保存并在下一轮注入前台的设定',
  basedOn: { branchId, revision }
}
```

后台 Agent 的最终回复直接作为 `context`，不要求附带来源、分析过程或其他结构化信息。

`context` 允许为空。空结果表示本轮没有需要额外补充的世界书信息，属于正常成功结果，不视为召回失败。程序和提示词都应鼓励如实返回空结果，避免为了“有所输出”而注入无关设定。

## 工具设计

后台 Agent 在 `worldbook` 任务中只开放一个专用读取工具，不开放通用文件工具。

### `tavern_read_worldbook_entries`

按引用读取本轮标题目录中的条目全文。目录包括全部常驻标题，以及由最新正文关键词命中的非常驻标题。

```js
{
  entries: [
    'entry-3'
  ]
}
```

约束：

- 只能读取本次任务标题目录中的条目，或处于隐藏期且此前已经读取过的条目；
- 处于 10 轮目录隐藏期的已读条目，仍可凭此前出现过的引用或准确标题重读；
- 只读，不允许修改世界书；
- 支持一次读取多条，返回标题、正文和稳定条目引用；
- 超过本轮数量或字符预算时明确报错，不截断成可能误导 Agent 的半条设定。

第一版工程预算建议：最多读取 8 条目录条目、最多调用读取工具 2 次、最终 `context` 最多 2,500 字。具体数值用真实大型人物卡测试后调整。

## 后台任务提示词

建议增加独立的稳定提示词 `worldbook-recall.md`：

```text
你是酒馆后台 Agent。本轮任务是“世界书召回”。

目标：只补充最新一轮正文尚未包含，并且根据当前场景判断，紧接着的后续剧情很可能用到的设定。

输入包括：
1. 最新一轮正文；
2. 常驻条目标题目录；
3. 程序按最新正文关键词命中的非常驻条目标题目录。

执行步骤：
1. 判断最新正文中的场景、人物、地点和事件需要哪些设定。
2. 检查常驻标题和命中的非常驻标题；只有标题可能相关时，才调用读取工具查看全文，不根据标题猜测内容。
3. 阅读后删除仅因词面偶合而命中的非常驻内容。
4. 合并真正相关的事实、约束和背景，压缩重复内容。
5. 直接输出需要注入前台的世界书信息。

要求：
- 只提供后续正文需要知道的设定，不续写剧情。
- 最终回复只包含需要注入前台的信息，不输出条目目录、分析过程、工具说明或无关背景。
- 最新正文已经明确的信息不得重复输出。
- 不为遥远、没有明确剧情迹象、仅在理论上可能用到的内容提前注入。
- 不因为条目是常驻就强行注入；常驻只表示需要主动检查。
- 不使用 position、order、depth、probability 等兼容字段作决定。
- 设定冲突且无法从当前剧情判断时，不自行编造。
- 没有相关内容时输出空内容。空内容是合理且鼓励的结果，很多回合本来就不需要额外设定；不得为了完成任务强行挑选或编造内容。

完成标准：回复已经是可直接注入前台的精简世界书信息。
```

## 前台注入格式

已保存的召回结果在下一轮以单独区块注入前台任务：

```text
【本轮世界书上下文】
...
```

只有 `context` 非空时才添加这个区块。空结果不向前台注入任何世界书区块。

这个区块是上一轮后台结算得到的派生上下文，不写入人物卡，不追加到玩家可见正文，也不成为永久权威状态。下一次正文完成后由新的后台结算覆盖。

## 一致性、缓存与回退

- 结果绑定产生它的剧情 revision、玩家行动、世界书绑定关系和世界书内容摘要。
- 正文重生成完成后重新结算并覆盖下一轮结果；正文回退时恢复 checkpoint 中对应的已准备结果。
- 相同输入和相同世界书版本可以复用缓存，但缓存不是第一版必需能力。
- 召回超时、工具失败、输出非法或后台 Agent 拒绝时，记录可复制错误，前台在“不注入本轮世界书”的情况下继续生成正文。
- 不把工具错误、半条内容或后台分析注入前台。

## 实现落点

1. `worldbook-resource.js` 负责兼容格式投影与编辑写回。
2. `file-resources.js` 负责人物卡与世界书的一对一绑定持久化。
3. `worldbook-recall.js` 负责阈值、关键词、标题目录、读取预算和召回结果。
4. `worldbook-recall.md` 是后台任务的稳定提示词。
5. `index.js` 在正文提交后的后台结算开头执行召回；`turn-orchestration.js` 只读取已保存的下一轮上下文；`context-planner.js` 负责注入。
6. 世界书、状态结算和候选复用同一后台 participant。

后续仅需使用真实人物卡验证并调整读取预算与召回质量。

## 验收标准

- 相关常驻标题会触发按需读取；无关常驻条目不读取、不注入。
- 非常驻条目只有关键词命中后才进入后台候选，词面误命中可被 Agent 丢弃。
- 带内置世界书的人物卡默认绑定它；解绑后不再读取，改绑后只读取新的绑定世界书。
- 解绑不会删除任何世界书数据，重新绑定后可继续使用。
- 空世界书不创建后台任务；有效正文不超过 200 字时不调用模型并直接注入。
- 最新正文已经提供的信息不会被世界书重复注入。
- 遥远或没有明确迹象的潜在设定不会被提前注入。
- 没有需要补充的信息时应优先返回空结果；这是正常成功路径，正文继续生成且不出现空世界书区块。
- 前台只收到整理后的 `context`，不会收到整本世界书、条目 ID、来源说明或后台分析。
- 修改 `order`、`position`、`depth`、概率等兼容字段，不改变召回结果。
- 关闭的条目不参与召回。
- 世界书任务一定在上一轮正文完成后、姿势结算之前运行；本轮正文不得临时触发召回。
- 开场白后的第一次候选生成会完整执行世界书召回、姿势结算和候选生成。
- 回退、正文重生成或迟到结果不会提交到错误 revision。
- 世界书异常不阻断正文，且错误可在界面中持久查看和复制。
- 新旧世界书注入路径不会同时运行。
