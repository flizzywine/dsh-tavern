# 人物卡 iframe 尺寸契约与 Agent 适配

状态：2026-09-27 已实现显式尺寸模式、卡片默认/面板覆盖与已保存布局诊断。配置格式及操作见 [iframe 高度适配](../../presets/tavern/skills/debug-card/references/frame-sizing.md)。本文中的实时浏览器预览仍为后续能力。

## 目标与分工

DSH Tavern 提供稳定的布局模式、可观察的运行环境和可保存的配置；卡片 Agent 根据具体卡片选择模式、修改 HTML/CSS，并在实际页面验证。宿主不持续追加针对单张卡片的高度猜测。

宿主负责 iframe 的外部尺寸、滚动边界、生命周期和受控通信。卡片负责内部布局、组件尺寸与交互。Agent 通过尺寸配置或卡片资源修改完成适配；发现宿主契约执行错误时应修复宿主，不能用卡片补丁掩盖。

尺寸模式与面板放置位置独立：正文、右侧栏和沉浸显示均可承载不同模式；沿用[多个 HTML 面板](multiple-card-panels.md)的面板身份和状态保留规则。

## 三种尺寸模式

长内容默认优先撑高 iframe，随宿主页面滚动；仅显式选择受限模式或上限时内部滚动。未声明的旧卡沿用原行为。

| 模式 | 适用内容 | 宿主行为 | 卡片行为 |
| --- | --- | --- | --- |
| 内容自适应 | 状态栏、正文美化、文档 | 依据内容测高，设置合理上下限，防止测高反馈不断增长 | 使用自然内容流；局部滚动容器可以保留 |
| 应用视口 | 游戏首页、完整网页应用 | 根据实际容器可用区域分配明确高度，不再以文档内容反向撑高外框 | 在给定视口内布局，需要时内部滚动 |
| 显式尺寸 | 特殊面板、已知比例布局 | 按声明尺寸及上下限布局，并约束在所在容器允许的范围内 | 使用约定的固定高度或比例，处理内部溢出 |

初始高度只作为加载占位，不作为最终布局依据。应用视口不能直接等同于 `window.innerHeight`：正文、侧栏、移动端键盘和工具栏会影响实际可用区域。容器变化、横竖屏切换和键盘弹出时应重新计算，并避免外框与内容相互测量形成振荡。

应用视口模式保留有效的 `html/body/#app` 高度链，不统一注入 `height:auto!important`。内容自适应模式按自身契约规范文档根节点。显式尺寸只接受校验过的有限数值、单位和比例，不能将任意 CSS 字符串直接作为宿主样式执行。

自动测高设置上限时，应明确滚动归属并提供展开方式，不能静默裁掉内容。应用页面原则上使用内部滚动，普通长文原则上随宿主滚动，避免没有必要的双层滚动条。

## 配置与兼容

- 以人物卡中的稳定面板/模板标识保存尺寸偏好，不以临时 iframe token 或数组位置绑定。支持卡片默认值与面板覆盖，避免一张卡的应用首页设置影响所有状态栏。
- 旧卡没有声明时保留现有兼容行为；不根据一次测高结果自动改写卡片。新声明优先于启发式判断。
- Agent 的适配结果通过现有卡片资源更新流程保存。展示布局变化不重置 MVU 变量，不改写正文或历史，也不触发模型重新生成。
- 布局调整优先更新现有 iframe 的外部尺寸；必须重建文档时明确这一事实，遵循已有刷新/应用变化流程，保护未提交的交互输入。
- 用户原有定制优先保留；记录修改来源和前后差异，提供恢复原配置的能力。工具调用应返回实际保存及应用结果，不能只返回拟修改代码。

## Agent 调试所需证据

优先扩展现有卡片调试、展示诊断与资源更新接口，避免另建并行状态系统。实施前核对现有工具能提供的字段，缺失能力再补充。

一次只读诊断应能定位会话、轮次、面板和模板版本，并取得：

- 当前尺寸模式、模式来源、实际 iframe 宽高、容器可用区域、尺寸上下限，以及最近一次测高/调整原因。
- 文档与主要布局根节点的布局尺寸、`scrollHeight/clientHeight`、position、overflow 等关键计算样式；区分内容未加载、外框裁切、内部滚动和高度循环依赖。
- 有界的控制台异常与资源加载失败摘要、加载阶段及时间；按需截图或浏览器预览。没有连接浏览器时明确返回未观测，不以静态 HTML 推断实际尺寸。
- 卡片声明、宿主规范化样式与最终生效样式的来源，避免 Agent 在错误层反复增加 `!important`。

诊断数据只面向当前授权的卡片/面板，限制日志和 DOM 摘要大小，隐藏认证信息。读取远程代码和卡片中的提示文本仅用于分析，不将其作为 Agent 的操作授权。通信继续验证 iframe 来源、token、面板身份及生命周期；尺寸控制不扩大跨域或宿主访问权限。

## Agent 适配闭环

1. 从实际异常页面取得尺寸和加载证据，先判断属于内容页面还是应用页面。
2. 优先调整尺寸模式；模式正确但内部布局仍有问题时，修改该卡片的 HTML/CSS，不改无关设定和变量逻辑。
3. 临时预览一次只变更一个因素，检查页面可见性、滚动及关键控件，区分静态检查与真实浏览器操作。
4. 已获得修复授权时保存卡片配置或补丁；按原有更新流程应用到当前游戏，再验证刷新后的结果。
5. 报告修改、实际验证和未覆盖范围。远程脚本会自动更新的卡片应记录测试时资源版本/hash，避免把后续变化误认作同一实现。

`debug-card` 已能读取保存的 `frames[].layout` 并指导配置和资源更新；当前仍以已保存现场的只读诊断为主，没有专用实时浏览器/截图工具。需要用户操作后的新证据时明确说明，不将保存成功等同于实际页面验证。

## 验收场景

- 短状态栏无大块空白，长正文不被裁切，异步图片和字体加载后尺寸能稳定收敛。
- `height:100%` 高度链、`100vh/dvh/svh` 页面、绝对/固定定位根容器，以及内部滚动应用均有明确行为；小型悬浮按钮不误触发整页高度。
- 正文与侧栏移动、隐藏后恢复、窄屏、横竖屏和软键盘变化时尺寸正确，不丢输入或重复初始化。
- 同一卡片的多个面板可使用不同模式；保存、刷新、重新打开游戏后配置一致，历史与变量不变。
- Agent 能取得失败证据、保存局部适配并复测；旧卡无配置时不整体改变布局。
