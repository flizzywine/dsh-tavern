# 高 ROI 酒馆兼容功能

## 目标

先选择实现相对简单、用户能立即感知、又能覆盖大量现有 SillyTavern 人物卡的功能。优先承接酒馆资源与可观察体验，不复制它的整套提示词拼接架构。

当前候选按实施顺序排列：

| 顺序 | 功能 | 兼容收益 | 实现复杂度 |
| --- | --- | --- | --- |
| 1 | 多开场白选择 | 中高 | 低 |
| 2 | 简单正则 UI 美化 | 高 | 中 |
| 3 | Tavern 原生世界书确定性激活 | 高 | 中 |

前两项属于“简单、见效快”；世界书确定性激活优先复刻创作者已经写明的规则，不增加模型等待。

## 1. 多开场白选择

### 用户体验

人物卡同时包含 `first_mes` 和 `alternate_greetings` 时，开始游玩前展示开场白列表。用户预览并选择一条，然后以该开场白创建新会话。

### 第一版边界

- 只在创建新游玩会话时选择；剧情开始后不切换开场白。
- 默认选中 `first_mes`，备选开场白按人物卡原顺序展示。
- 空白条目不显示，正文和宏保持原样。
- 剧本模式使用用户选中的开场白对齐剧本起点。
- 选择结果随会话保存，重新打开时保持一致。

### 价值

这项能力已有标准人物卡字段作为输入，不需要新协议。大量人物卡用备选开场白提供不同关系、地点、时间线或游玩尺度；支持选择后，导入体验会更接近酒馆。

### 验收

- 只有一个有效开场白时不增加选择步骤。
- 多个开场白时能够预览并选择，创建后的第一条消息与选择一致。
- 自由、剧本模式都能使用，且不会破坏历史会话、回退和剧本游标。

## 2. 简单正则 UI 美化

### 用户体验

正文中已经存在常见标签、状态块或结构化片段时，前端用简单正则识别并转换为更清晰的卡片、状态栏或折叠区块。用户无需配置；匹配失败时仍能看到完整原文。

### 第一版边界

- 原始回复作为内部源文本保存；正则命中的片段从可见正文移除，只进入展示投影。
- 先支持静态匹配、捕获组和安全替换模板。
- 单条规则失败只产生诊断，不影响正文与其他规则。
- 输出 HTML 必须过滤；不执行人物卡或预设中的 JavaScript。
- 不处理修改输入、修改提示词或依赖酒馆脚本运行时的正则。
- 候选项等 dsh-tavern 已有原生 UI 的内容继续使用原生能力，不重复翻译。

### 价值

许多酒馆人物卡已经要求模型输出固定标签或状态块。第一阶段直接利用已有输出改善观感，不增加模型调用，也不要求正文模型承担新的格式任务。

### 验收

- 识别成功时 UI 明显改善，命中内容不在正文重复展示；内部源文本仍可用于连续生成和回退。
- 匹配失败、替换模板错误或未知格式时完整显示原文。
- 多条规则互相隔离，浏览器中不执行未授权脚本。
- 使用一批真实人物卡验证，而不是只测试手写示例。

详细设计见[回复展示与状态栏兼容](status-bar.md)。

## 3. Tavern 原生世界书确定性激活

### 用户体验

导入世界书后，常驻条目随人物卡进入稳定前缀；非常驻条目根据最新正文和 Tavern 关键词规则激活，最多三条进入下一轮正文。

### 第一版边界

- 常驻条目按 `order` 进入稳定前缀，不受动态上限和冷却影响。
- 非常驻条目执行主副关键词、四种 `selectiveLogic`、正则、大小写和整词匹配。
- 每轮最多注入三条；实际注入后冷却十个剧情回合。
- 世界书不进入候选、结算或后台 Agent Session。
- 不引入向量数据库，不修改世界书，不让单条失败阻断正文。

### 价值与复杂度

这是人物卡兼容性的关键能力。它把创作者明确设置的激活条件作为权威规则，避免模型二次筛选造成遗漏、剧透和等待；代价是关键词设计不足时不会得到语义模型的自动补救。

### 验收

- 常驻条目只进入前台稳定前缀。
- 非常驻条目相同输入得到相同候选顺序，每轮最多三条。
- 只有实际注入条目进入十轮冷却。
- 世界书处理不创建 Agent operation，也不增加模型等待。
- 不支持的字段原样保存并明确标注，而不是近似执行。

## 实施建议

1. 先恢复“创建会话前选择开场白”，用现有字段和真实人物卡完成浏览器验证。
2. 再建立只读的正文展示管线，从少量安全正则开始，用真实卡片逐步扩充样本。
3. 用真实大型世界书验证确定性激活、稳定前缀预算和十轮冷却，再逐项翻译更多 Tavern 字段。

本阶段不顺手加入任意 HTML、JavaScript、MVU、完整 Tavern Helper 或酒馆动态提示词运行时。只有真实人物卡证明某项缺失能力具有高覆盖率时，再把它加入下一批兼容工作。
