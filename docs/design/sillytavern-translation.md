# SillyTavern → dsh-tavern 翻译设计

## 目标

dsh-tavern 全面承接 SillyTavern 的成熟生态，但不复制其动态拼接超大上下文的底层架构。核心原则是：

> **外部协议兼容，内部架构重写；导入时翻译，运行时原生。**

翻译桥保留酒馆资源的格式、语义和可观察效果，把它们转换为 dsh-tavern 的 Agent、Skill、系统规则、状态、任务和渲染产物。只有无法预先转换的动态行为，才进入受限兼容运行环境。

## 人物卡导入边界

人物卡使用三层数据模型：导入的 PNG/JSON 字节作为不可变原版；完整 JSON 作为可编辑工作 raw；UI、游玩与后台任务使用从工作 raw 实时生成的稳定投影。导出始终读取工作 raw，恢复始终读取不可变原版。

卡片模式优先通过标准字段和世界书工具修改人物卡；正则、脚本、MVU 与未知扩展通过 JSON Pointer 按路径读取和修改。所有修改先校验并暂存，在本轮最终回复成功后一次写回工作 raw。dsh-tavern 的修改历史属于本地元数据，不写入酒馆人物卡。

旧版缩水工作卡首次读取时，从原版重建完整 raw，再覆盖用户已经修改的标准字段；迁移前保留旧工作文件。原版缺失或损坏时，以现有工作卡建立兼容 raw，不阻止人物卡继续使用。

## 统一分析模板

每个酒馆概念都从五个维度分析：

1. **概念**：它是什么。
2. **目的**：它真正解决什么问题。
3. **SillyTavern 实现**：酒馆如何实现这个目的。
4. **dsh-tavern 实现**：在新架构中由什么原生能力承担。
5. **翻译器**：如何把原始资产转换为对应产物。

研究顺序固定为：

```text
研究酒馆概念与真实语义
  → 定义 dsh-tavern 对应产物
  → 选择静态转换、语义转换或沙箱适配
  → 实现翻译器
  → 使用真实资源验证
```

## 案例一：世界书

### 概念

世界书是与人物卡或会话绑定的外部知识集合，由人物、地点、组织、事件、规则和背景设定等独立条目组成。

### 目的

世界书解决的是：**信息总量很大，但当前正文只需要知道其中一小部分。** 它的本质是渐进式披露，不是提示词插入位置本身。

### SillyTavern 实现

酒馆保存常驻、关键词、顺序、位置和深度等条目配置。每轮动态组装提示词时，常驻条目固定进入上下文，其他条目按关键词等条件触发，再插入指定位置。

### dsh-tavern 实现

一个世界书转换为一个仅向后台 Agent 开放的知识 Skill 包：

```text
worldbook/<id>/
├── SKILL.md
├── catalog.md
├── manifest.json
└── entries/
    └── <entry-id>.md
```

后台 Agent 根据玩家输入、最近剧情和紧凑目录渐进读取条目，直接筛选、组织并压缩出本轮正文需要知道的上下文，再注入前台主 Agent。来源条目编号只用于审计和追溯，不是后台任务的主要输出。

常驻条目在会话建立时注入一次，普通条目按需加载。传统插入位置和深度不直接进入主 Agent 的拼接流程，只在必要时转换为优先级、适用范围或召回提示。

### 翻译器

| 酒馆字段或语义 | dsh-tavern 产物 |
| --- | --- |
| 世界书基本信息 | `SKILL.md` 中的用途和召回规则 |
| 条目编号、名称和简介 | `catalog.md` 中的紧凑目录 |
| 条目正文 | `entries/<entry-id>.md` |
| 常驻 | 会话初始化注入标记 |
| 关键词与辅助关键词 | 召回元数据和快速候选提示 |
| 顺序与优先级 | 候选排序和预算取舍依据 |
| 插入位置与深度 | 适用范围、优先级或兼容诊断 |
| 未识别字段 | 保留在 `manifest.json` 并报告兼容状态 |

原始世界书保持不变。翻译器记录源文件哈希、版本、条目映射和诊断，并验证目录完整性、信息召回准确性、加工内容对原始设定的忠实性和失败回退。

## 案例二：预设

### 概念

预设是一组用于控制模型行为的提示词、顺序和参数，通常混合了破限、内容偏好、流程指令、正则和模型配置。

### 目的

兼容用户已有的 SillyTavern 提示词资产，但不复制酒馆每轮动态拼接的运行架构。用户可以直接导入预设、查看条目，并少量选择确实需要的内容。

### SillyTavern 实现

酒馆根据 `prompt_order` 等配置，每轮把预设条目与人物卡、世界书和历史动态拼接。破限、内容偏好、流程控制和格式要求通常共同进入同一个大提示词。

### dsh-tavern 实现

原始 JSON 和工作版完整保留在“外部预设库”，只用于查看、导出和抽取，不能直接激活或进入模型请求。用户在外部预设详情中勾选破限提示词；`extensions.regex_scripts` 中酒馆真正执行的正则默认完整迁移并继承原启用状态，用户可以取消或调整。SPreset 编辑器元数据不作为额外运行规则。保存后形成一份自包含的“破限方案”。

Tavern 全局激活一份破限方案。方案独立保存提示词和正则，删除来源外部预设后仍可运行；切换后从下一次请求开始统一作用于游玩前台、后台、卡片 Agent 和兼容模式。当前只有兼容模式完成适配；游玩模式和卡片模式应选择“不使用破限方案”，否则方案内容可能与原生任务冲突。运行时再把方案投影为内部前、中、后，或在兼容模式下投影为 SillyTavern 消息顺序。普通用户不接触“DSH 预设”或三段结构。每次真实请求另行完整落盘供诊断；正则不改写权威模型原文。

### 翻译器

`Preset Reading` 把不同 JSON 结构翻译为稳定只读视图；抽取器生成自包含破限方案；运行时转换器再按 `prompt_order` 生成内部前、中、后或兼容消息。正则直接保存在方案中但不进入提示词正文；原始回复保持权威，历史展示可以随正则配置重建。脚本、模型参数和空占位条目继续由各自兼容模块处理。权威产品定义见 [外部预设库与破限方案库](./preset-library.md)。

## 案例三：显示正则

### 概念

显示正则从模型输出中提取特定格式的内容，并转换为状态栏、卡片、面板等 HTML 界面。本案例只讨论用于展示的正则；修改输入或提示词的正则需要另行分析。

### 目的

把正文之外的人物状态、地点、时间、变量、装备和任务等信息独立渲染，让用户获得比纯文本更直观的界面。

### SillyTavern 实现

正文模型同时输出小说、特殊标签或 HTML 片段。酒馆用正则从正文中匹配捕获组，再通过替换模板以及其他脚本或工具生成前端界面。正文、数据格式和 UI 因而耦合在一起。

### dsh-tavern 实现

前台主 Agent 只输出正文。独立、持续存在的展示后台子 Agent 读取最新正文、状态和必要上下文，单独生成展示结果并单独渲染。

默认实现是让展示 Agent 和渲染器共同维护一份持续 UI 状态。首次创建界面时输出完整状态，后续每轮只提交经过 schema 校验的增量更新，例如变化字段、删除字段和对应剧情 revision。固定渲染器把更新合并到现有界面，只刷新受影响的部分，不重新生成整套 HTML。

确实需要动态 HTML 的资源，增量结果也必须经过安全处理并放入受限 iframe。更新失败或绑定旧 revision 时丢弃本次变更，不影响已有界面、正文和会话。

### 翻译器

显示正则转换为展示包：

```text
presentation/<id>/
├── schema.json
├── instructions.md
├── renderer.html
├── styles.css
└── manifest.json
```

翻译器读取匹配表达式、捕获组、替换模板和运行条件：

- 捕获组转换为 `schema.json` 字段；
- 正文中的格式要求转换为展示 Agent 的提取规则；
- HTML 替换模板转换为固定渲染器和样式；
- 为每个字段生成增量更新、清除和 revision 校验规则；
- 复杂但兼容的脚本转交 QuickJS 运行环境；
- 无法自动理解的组合由 Agent 生成展示包草稿，再经用户确认；
- 无法安全转换的内容保留原文件并报告诊断。

## 案例四：候选项

### 概念

候选项是正文结束后提供给玩家的下一步行动建议。它不是已经发生的剧情，也不是强制选项。

### 目的

候选项给玩家灵感，降低思考和输入成本，让玩家可以偷懒并保持游玩节奏。玩家可以直接选择、修改或完全忽略，因此它是 dsh-tavern 的核心交互能力。

### SillyTavern 实现

正文模型同时生成故事和特定格式的候选项，再由正则或前端逻辑从正文中提取并单独渲染。正文写作因此同时承担候选设计和格式输出。

### dsh-tavern 实现

候选项是系统内置功能：

1. 前台主 Agent 只生成正文。
2. 正文提交并形成确定的剧情 revision。
3. 持续存在的后台 Agent 执行独立候选任务。
4. 后台 Agent 输出结构化候选项。
5. 程序校验后在候选区域单独渲染。
6. 玩家选择后只填入输入框，仍可修改。

候选失败、超时或结果绑定旧 revision 时，不得影响已经提交的正文。

### 翻译器

候选项不生成新的兼容模块，而是映射到系统内置功能：

| 酒馆内容 | 翻译结果 |
| --- | --- |
| 要求正文输出候选项的提示词 | 从正文规则中移除 |
| 候选标签与格式要求 | 不再保留 |
| 候选显示正则 | 标记为由原生功能替代 |
| 候选数量、类型和风格 | 转换为原生 Candidate Policy |
| 人物或剧本相关约束 | 转换为后台候选任务规则 |
| 无法识别的特殊逻辑 | 保留原文并报告诊断 |

翻译完成后，前台主 Agent 不得继续输出旧格式候选项，避免正文和原生候选区域重复显示。
