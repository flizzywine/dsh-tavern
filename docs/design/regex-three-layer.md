# 正则三层语义备忘

> 状态：三层投影语义已在回复提交链路实现；本文继续作为行为约束。

## 核心认识

一次模型输出不应只有一份同时服务所有用途的文本。DSH 对酒馆正则的承接应明确分成三层：

```text
模型原始输出 R
    ├─ 原始输出层：保存 R，用于审计、排错和重新投影
    ├─ UI 展示层：对 R 执行 markdownOnly 正则，得到玩家看到的内容
    └─ DSH Session 层：对 R 执行 promptOnly 正则，再写入有效 Session，成为后续真实上下文
```

原始输出层不等于 DSH Session 层。原始输出需要留档，但下一轮模型实际读取的，应是经过 `promptOnly` 处理后写入 Session 的版本。

## 两个临时正则开关

人物卡正则、预设正则和全局正则描述规则来自哪里；`markdownOnly` 与 `promptOnly` 描述同一条规则作用到哪一层。

| 配置 | UI 展示层 | DSH Session 层 | 原始输出留档 |
|---|---|---|---|
| 仅 `markdownOnly` | 执行替换 | 保持原内容 | 保留 |
| 仅 `promptOnly` | 保持原内容 | 执行替换 | 保留 |
| 两者都启用 | 执行替换 | 执行替换 | 保留 |
| 两者都不启用 | 两层都执行永久替换语义 | 两层都执行永久替换语义 | 是否另存最初响应，后续决定 |

## 当前案例

模型原始输出包含：

```text
draft_notes + 正文 + HTML 注释形式的后台日志
```

人物卡希望得到：

```text
UI 展示层：正文 + “后台日志已封录”
DSH Session 层：正文 + 完整后台日志，不包含 draft_notes
原始输出层：完整保留模型最初响应
```

因此，后台日志使用 HTML 注释是有意的隐藏状态协议；浏览器不显示注释是正确行为。

## 明确边界

- 右侧栏不属于正则三层语义。不能因为内容是 HTML、`<details>` 或正则替换结果，就自动从正文切走并搬到侧栏。
- UI 展示正则应在聊天原位置产生替换结果；Session 正则应在写入有效上下文前产生替换结果。
- HTML 是内容格式，不是所有权标记。是否属于正文、隐藏状态或独立 UI，不能只靠标签形状推断。
- 为节约上下文而改变人物卡原有消息结构，可能导致格式、状态连续性和正则行为失控。上下文压缩需要另行设计明确协议。

## 后续需要决定

- 多来源正则的执行顺序：全局、预设、人物卡之间如何保持酒馆兼容。
- 正则配置改变后，已经写入 DSH Session 的历史是否需要迁移或重建。
- 两个开关都未启用时，如何同时承接酒馆的永久替换语义与 DSH 的原始响应审计。
- 单条正则失败时如何记录诊断，并保证其他规则和当前会话继续运行。
