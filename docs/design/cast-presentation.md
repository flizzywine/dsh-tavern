# 角色演出：对话头像、立绘差分、配音

整体分层见 [从酒馆到 Galgame：四层演出](tavern-to-galgame.md)。

借鉴 [DSH Tavern Galgame](https://github.com/jerryzmtz/dsh-tavern-galgame) 的效果，在 Tavern 本体实现「谁在说话、什么表情、什么声音」这层多模态基础能力，再通过插件接口开放给插件（例如 Galgame 的舞台）。

## 原则

- **普通 SillyTavern 卡直接能用**：不改卡、不改世界书、不要求正文模型改写格式。
- **默认关闭，一个全局开关**：「舞台设置 › 基础设置 › 对话气泡」，打开后对所有游玩对话下一轮生效。
- **素材沿用 ST 习惯**：主角用卡的 PNG 头像；立绘按 ST 表情包约定（每个角色一个文件夹，文件名就是情绪）。
- **分步建设内置舞台 core**：持续状态之后先接入导演增量事务，再建设核心演出与运行时；本切片不含 Live2D、Spine、口型或新的素材包体系。

## 地基：台词标注

每句台词的说话人和表情，由**后台结算顺带标注**，不让正文模型写格式。

- 结算任务里附一段「本轮台词」：从这一轮正文里按顺序取出引号台词（`“”`、`「」`、`『』`、`""` 等同行成对的引号），编号列出。
- 模型调用 `cast_submit({ lines: [{ n, speaker, emotion }] })`，`n` 是编号，不需要抄原文；`emotion` 取 ST 表情扩展的 28 个情绪名之一（`joy`、`anger`、`neutral`…），方便直接对应 ST 立绘包的文件名。
- 结算工具列表固定在缓存前缀里；是否要标注写在每轮任务文字里，开关不影响缓存。
- 标注结果按「轮次 + 正文版本」保存（与插件的每轮数据同一套存储）：回退、重新生成、编辑后旧标注自然失效，不需要同步；导出、分叉随存档走。
- 只关了姿势、变量结算时，打开台词标注也会运行后台结算。

## 第一步：对话头像

- 一段文字里含有已标注的台词时，这段显示成「头像 + 名字 + 情绪标签 + 原文」的气泡行；旁白段落照常显示。只处理 Markdown 正文，卡片自己的 HTML 界面不动。
- 头像：说话人是卡的角色名时用卡的 PNG 头像；其余人物显示首字圆形头像（颜色按名字固定）。
- 结算完成前正文照常显示，标注到了再换成气泡行。

## 三层：故事、演出数据、呈现

- **故事**（正文、变量、回退、存档）通用，不因演出改变。
- **演出数据**（台词标注、角色素材）也是通用的，只是附在故事上的一份标注，可选、默认关。
- **呈现**才特化：聊天视图照旧；舞台是同一局故事的另一种看法，只读另外两层，不碰游玩流程。缺什么退一步：没有立绘用头像，没有头像用首字，没有标注就按旁白显示。

## 第二步：舞台与角色素材

- **入口**：「舞台设置」里「对话气泡」和「舞台模式」（默认开）都开着时，聊天顶栏右侧有「舞台」按钮，「酒馆状态」里有「全屏舞台」按钮，都打开全屏舞台；侧栏不再绘制舞台或播放演出。
- **舞台状态**：显示最新一轮，按台词逐句翻；标注只负责台词/当前说话人，不再决定人物入退场或立绘表情。人物、表情、背景、音乐由内置导演的已接受增量重建，全屏关闭重开仍读会话保留的状态。省略保持；换轮、刷新、重挂载不是清空。最多三人在场，增员超过容量必须显式退场，不自动挤掉别人。无背景时仅以卡图虚化作视觉降级，不自动选择第一张背景。
- **全屏舞台**：画面铺满页面，点击或方向键翻页、自动播放、Esc 退出；读到最后一句可以直接在舞台里输入下一轮行动。
- **角色素材**（每张卡一份）：人物名可加别名，头像和 28 个情绪的立绘。导入 ST 立绘包 ZIP（单人 `joy.png`…归给主角；多人 `角色名/joy.png`…按文件夹名），也可逐张上传。文件按内容寻址存放，链接可以永久缓存。
- **人物和镜头演出只来自导演**：删除自动入场、呼吸、立绘淡入及说话抬升；一次性动作由下述工具显式安排，系统开启「减少动态效果」时消费事件但不播放。

## 舞台 core（2/N）：独立后台导演

- 生产者是独立后台导演：复用 BackgroundAgentRunner，以 `task: 'stage-director', persistent: false` 为每个正文窗口创建自己的 session，可与结算并行。不挂进 settlementItems，不继承结算历史、人物卡/世界书前缀或结算工具；模型选择沿用本局后台模型设置，不增加设置项。
- 宿主正文流或完成事件独立触发，流式范围见下文；重生成只在正文正式采用后触发。完整 round-body 为 `{chatId,sessionId,turn,key,text}`，不从 UI 或台词标注构造正文。导演规则固定，本次 prepared frame 的玩家输入、人物卡、世界书和状态参考冻结后传入；排除写作规则，不继承结算会话。读取舞台不会触发模型。
- 本切片工具名 `stage_update`，整个增量在工具内一次校验；错误直接返回同一 session，模型可在已有 runner 的工具预算内修正，不重建修复会话。成功后结束，一次提交整批 delta。
- 参数为 `{ sequence, through, done:true, figures?: [{speaker, emotion?, remove?}] | null, background?: string | null, music?: string | null }`。`figures` 是逐人物增量，不是名单替换；省略表情保持，新人物默认平静。人物用清单的完整名称，情绪沿用 ST 名称（入口也归一化中文）；背景/音乐用唯一名称。`null` 分别清人物、清背景、停乐；只交封口字段即保持所有状态。
- 音乐使用既有 CCv3 `data.assets` 中 `type: "music"` 的条目（wav/mp3/ogg/m4a），复用 cast-assets 导入、导出和受限媒体路由，不接收任意 URL。播放仍由已有音乐播放器和玩家开关控制。
- 所有字段先校验；任何一项非法则整批不写，工具返回可修复错误。最终持久化时在既有 Chat Journal 串行边界核对 branchId/revision、当前轮与正文 key、任务存活，再把整批 delta 一次写入按轮数据 owner `dsh-tavern.stage`。不改正文、变量或剧情 revision。已接受的同一正文版本不重复提交；过期/取消返回不可重试结果。
- `castStage` 删除过渡字段 `initialFigures`，返回 `stage: {figures, background, music}`（名称状态）及已解析的 `background` URL、`music: {name,url} | null`。现有会话/同源权限不变；插件只读舞台视图也包含这些字段。
- 一轮最终保存一笔合并增量；流式期间的临时投影不提前写入存档。持续场景变化仍按窗口立即应用，不是逐页持久状态时间线。
- 旧台词标注只用于聊天/配音，不回填成导演数据；首次成功导演提交前舞台状态为空。历史读取只折叠当前正文版本匹配的记录，资源缺失只影响投影，不改记录。已删除 demo 的历史/本轮标注人物推导、第一背景自动选择，没有兼容分支。

## 舞台 core（3/N）：按页一次性演出

- `stage_update` 新增可省略的 `performances` 数组（每窗口最多十二项）：`{at,op:'actor.act.play',actor,motion:'nod'|'jump'}` 或 `{at,op:'screen.play',effect:'shake-1'}`。`actor` 必须是本次人物增量应用后仍在场的完整名称；同页同一目标最多一个短动作，不同页可重复。任何无效项都在工具内拒绝整批，原 session 可修正。
- 宿主用正文非空行建立稳定的 `pages`，`at` 从 1 开始；同一份编号正文用于导演和阅读器。台词标注只给页添加姓名/情绪，不改变地址。这不是按屏幕尺寸计算的像素分页。
- 接纳时一次保存 `{delta,performances}`，持久状态仍按 delta 跨轮折叠、显式清除；performances 只属于源正文的本轮对应页，不进入下一轮 baseline。`castStage.turns[]` 增加 `key`、`pages`、`performances`，读取不生成或写状态。
- 玩家翻回本轮某页即开启新 visit，停留约一秒后播放该页一次；普通重绘/导演通知不重播。连续翻页取消中间页，跳过直接到本轮末页并取消待播及当前短动作，目标页不补播或重新朗读；初次打开、刷新、重开不播放已有事件。新正文到来时，只允许当前尚停留页的事件播放，不补播离开的页。
- 每局一个阅读位置与轻量播放 owner（6/N 起归会话运行时），关闭即释放播放；重新打开不补播已有事件。Web Animations 的短动作完成即释放，不写持久 transform，不影响人物/背景/音乐状态。换页、换局、关闭时取消该 owner 的定时器及动画。
- 最小范围是点头、轻跳和轻震屏；暂不移植演出风格条目、entry/turn/idle/exit 组合、关键帧、音效、跨轮历史导航、统一 runtime 和设置 UI。这些不以未使用的协议或兼容分支提前加入。

## 舞台 core（4/N）：导演流水线

正文还在流式生成时，导演先处理开头几行；正文正式提交后，再完成剩余部分。

- 只观察正在运行的正文 operation 的 text-delta，不把推理或工具参数当正文。首五个完整非空行启动第一窗；其余正文在宿主提交后合成余窗，不循环切窗。短正文只调一次，恰好五行不发空余窗。
- 两窗共用冻结参考、素材清单、前序状态及模型选择；余窗只承接已接受的舞台状态。`sequence` 是窗口序号，`through` 是该窗最后的全局页号，`done:true` 封口当前窗口而非宣告全文结束。三项都必须原样提交；错误及回写已封口页的演出在原会话内修复，不会局部接受。
- 首窗只作内存投影，`castStage` 立即显示；全文提交后核对封口文字、operation、剧情版本、正文 key、素材和前序状态，再经既有 Journal 写锁保存合并的 `{delta,performances,seals,presentationKey}`。转正保留阅读来源，不把首窗演出当新事件重播。失败、取消、换代或关闭时清掉临时投影，不留下半轮存档。
- 含副作用宏、EJS、script/style 或未闭合标签的首窗保守等待宿主最终投影；没有 prepared frame、非流式正文及重生成采用后仍走完整正文窗口。暂不涵盖任意 HTML/模板流式投影、相关性召回、长期导演记忆、跨轮分页或统一演出 runtime。

### 设计理由

`sequence/through/done` 是模型提交与宿主窗口的明确对应关系，不靠模型文字或调用顺序猜测完成范围；页地址前缀一旦接受便不可回写，坏参数直接由工具指出并允许修正。临时投影不持久化，是因为前台正文尚可能取消、失败或改写：此时尚无可供存档绑定的正式正文版本，不能让半轮演出成为下一轮的权威状态。窗口之间冻结参考也避免并行结算改变本次导演的事实基础；这不代表已经测量真实模型审美、长清单效果或缓存命中率。

## 舞台 core（5/N）：一局一份舞台

只保留全屏舞台；同一局只保留一份已接受的画面，关闭重开仍接着使用，不因读取失败清场。

- `createStageRuntimeSessions` 跟随原生会话列表及 binding，首次选中才建立 store，不因组件挂载创建模型任务；已经打开的会话保留到原生列表移除或 binding 替换。插件卸载统一退订并中止在途读取。
- store 只读既有 `castStage`，原子发布 `{data,scene,pending,error}`；后台通知、正文运行状态、宿主视图、设置及重连唤醒读取。每局最多一笔在途请求，期间的新通知合并为下一次读取；可见窗口每五秒只读对账，不自动重导或回写历史。
- 普通刷新和读取失败保留上一份画面；收到确定的新快照才替换。相同场景沿用对象引用，显式清人物会清空；未配置背景仍沿用既有卡图降级。换卡、回退上下文或 binding 替换先撤销旧请求，过期结果不得污染新上下文或另一局。
- 删除 demo 的 `useTavernCastStage` 组件内取数、局部数据写入和每个画面的素材投影；素材编辑完成后也重新读宿主。静态背景与立绘在接受边界统一解析；删除 TavernStageSection、其挂载及小舞台专用状态和样式。入口是聊天顶栏「舞台」和「酒馆状态」的「全屏舞台」；音乐开关和退出放在全屏控制栏；角色素材、声音和舞台样式暂留「酒馆状态」，之后归舞台设置页。
- 本步不修改 `stage_update`、存档、提示词和页号；已有回翻停留后播一次、跳过和刷新不补播的规则不变。全屏阅读与播放资源在关闭时释放，素材管理保留原功能；不宣称已删除整个 `cast-stage.js`；媒体租约、解码资源管理、跨轮历史和完整纯 reducer 也不在本步。

设计理由：Galgame 本质上是横屏的，侧栏却是竖向的一列；把横屏舞台硬塞进去没有带来什么价值，还要同时维护侧栏和全屏两套舞台，维护起来很麻烦，所以只保留全屏舞台。

画面的生命周期属于这局游戏，不属于某次 React 挂载；把读取和接受边界收回会话层，才能让全屏关闭重开仍有已接受的画面，普通刷新和失败读取也不被误当成清场。通知只唤醒、结果仍读宿主，避免把并行任务的通知当作权威剧情；读取失败不生成空场景。先统一静态投影，保留已有阅读和短动作合同，可以在小切片中验证会话隔离与连续性，而不把播放器、设置及资源服务一起重写。

## 舞台 core（6/N）：舞台保持阅读进度

读到哪一页、自动翻页和播放都由这一局的舞台运行时持有；全屏只是它的画面。

- 会话 store 在 `{data,scene}` 旁原子发布阅读位置 `reader:{key,index,visit,mode,auto}`。首次读取只恢复（`refresh`）；同一局收到新正文 key 时回到第一页并以 `live` 开始；翻页是新的 visit（`page`），跳过是不播放的 visit（`skip`）；同 key 的通知保留当前页，正文变短时夹到末页；回退等上下文撤销后重新从恢复开始，visit 编号不回绕。
- 全屏打开时向这一局 `attach` 一个播放器：当前页的一次性演出、朗读、自动翻页和音乐都由它驱动。关闭、换局、binding 替换或会话移除时 `detach`，取消定时器和动画，停止朗读和音乐。再打开回到原来那一页，以恢复模式显示，关闭时还在等待的停留不补播。
- 自动翻页等这一句读完后约 0.4 秒翻页，没有朗读时按文字长度等待，末页停止；关闭重开后自动翻页为关。「朗读」开关仍按浏览器记住，关掉立即停声。
- 删除 demo 的 `cast-stage.js` 及其 include：组件内阅读器 `useTavernStageReader`、`TavernStageFullscreen`/`TavernStageSession` 的播放和音乐副作用。舞台画面与插件 `registerStageView` 输入不变，并入舞台运行时文件；角色素材编辑并入人物呈现模块，仍在「酒馆状态」，之后归舞台设置页。
- 不改宿主 RPC、`stage_update`、存档、提示词或页号；仍只读最新一轮，跨轮翻页、媒体租约和解码管理不在本步。

设计理由：阅读位置和播放资源原先挂在 React 组件上，关掉全屏就丢了位置，回来总是第一页；播放的定时器、朗读和音乐各由组件副作用管理，换局、回退时谁来停也分散在几处。画面已经归这一局（5/N），读到哪一页、在播什么也应该归同一个 owner：位置跟会话走，关闭重开不丢；资源只有一个释放点，换局、回退、移除都走同一条路径。播放器只在有画面挂上时存在，因此没有画面的会话不会出声或占用定时器。

## 舞台 core（7/N）：舞台设置页

舞台的设置有三处家，每处只管一件事，都在侧栏开始页的「其他」里：

- **「舞台设置」**：「基础设置」一组开关，顺序是 对话气泡、配音 ›、舞台模式。一行是图标、短名和右侧开关；带「›」的行点开关以外的地方打开它的页面。
  - 「对话气泡」就是原来设置页里的全局「对话头像」（`castPresentation`），从设置页移到这里。
  - 「配音」是配音服务的全局开关，代替全屏舞台原来的「朗读」开关；「›」打开「配音」页，那一页顶部有返回「舞台设置」的「‹」。对话气泡关着时（没有台词标注），配音开关变灰并说明需要对话气泡。
  - 「舞台模式」是全局开关（设置里的 `stageToggles.stage`，默认开），和参考设计一样需要「对话气泡」：对话气泡关着时它变灰、保留原值，所有卡的舞台都不显示。按卡的舞台开关（`setCardStage` / `cardStage`、卡的 `defaults.stage`）随之删除，卡不再替玩家打开舞台。
  - 装了提供舞台画面的插件时，下面多一行「舞台样式」。
  - 不在游玩对话里时显示「未打开人物卡」和「打开人物卡库」。
- **「舞台素材」**：这张卡的角色素材（立绘、头像、每个人物的声音、导入 ST 立绘包），从「酒馆状态」搬来。舞台关着时也能编辑，聊天里的头像也用它们。
- **「配音」**：配音服务页（渠道、默认声音、旁白声音、开关），和「设置 › 配音」是同一页。
- **「酒馆状态」**只留「全屏舞台」入口。全屏舞台自己不放设置：控制栏保留「♪」快速静音，「朗读」不再单独存在。控制栏恢复换行，窄屏不再挤出屏幕。
- 不改宿主 RPC、存档或插件接口。

设计理由：对齐参考的舞台设计，每件事只有一个设置的家。三个面板的名字、图标、顺序和开关行都照搬参考实现；上游还没有的能力（BGM、音效、环境音、物品、演出组合、入场演出、默认皮肤、自动生成选项、设置向导、模组、素材包）由之后各自的 core 连同它们的行一起加入。

## 第三步：配音

- **一个全局开关**：「舞台设置 › 基础设置 › 配音」，和「配音」页（也在「设置 › 配音」）顶部的「开启配音」是同一个开关，默认关。打开前要在「配音」页选好渠道并填齐设置。
- **渠道**：浏览器朗读（系统语音，零配置）、OpenAI 兼容 `/audio/speech`（OpenAI、硅基流动 CosyVoice、中转）、GPT-SoVITS（api_v2）、MiniMax T2A v2、火山引擎（豆包语音 V3，APP ID + Access Token，音色按 ID 填，复刻音色用 `icl_` 前缀）；插件可用 `speechProvider` 再加。各渠道分别保存设置，Key 存在 DSH 凭据库，改地址必须重填 Key。
- **声音**：每个渠道有默认声音和旁白声音（旁白留空则不念）；每个人物在「舞台素材」里按渠道单独选声音，跟着人物卡走，换渠道不丢。
- **情绪**：gpt-4o 系列把标注的情绪写成语气要求；MiniMax 映射到它的 7 种情绪；火山引擎映射到它的情感枚举（2.0 音色、1.0 多情感音色才认，其余保留音色默认语气）；插件渠道拿到情绪名自己处理。
- **合成与缓存**：宿主侧合成，按「渠道 + 非密钥设置 + 声音 + 情绪 + 文字」内容寻址存进 `speech-cache/`，同一句只付费一次；浏览器朗读在浏览器里合成，不经宿主。
- **在哪里听**：带头像的台词行有朗读按钮（只念引号里的话）；配音开着时全屏舞台翻到哪句念哪句，自动播放时念完再翻页；控制栏只留「♪」快速静音音乐。
- **还没做**：缓存不会自动清理；正文写完自动念整轮。

## 插件接口

已开放（见[插件接口](../plugin-api.md)「演出」与 `registerStageView`）：

- 宿主侧：`getCast({ gameId, turn })` 读某一轮当前版本的台词标注；`onCastAnnotated` 标注保存时通知；`getCastAssets({ gameId })` 读角色素材；`speechProvider` 加配音渠道；`synthesizeSpeech` 按人物声音合成一句。
- 浏览器侧：`getStage`、`watchStage` 读舞台数据；`registerStageView` 换舞台画面，Tavern 保留阅读流程，插件失败时退回内置画面；`speak`、`stopSpeech` 朗读。
