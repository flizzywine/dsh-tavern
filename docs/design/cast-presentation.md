# 角色演出：对话头像、立绘差分、配音

整体分层见 [从酒馆到 Galgame：四层演出](tavern-to-galgame.md)。

借鉴 [DSH Tavern Galgame](https://github.com/jerryzmtz/dsh-tavern-galgame) 的效果，在 Tavern 本体实现「谁在说话、什么表情、什么声音」这层多模态基础能力，再通过插件接口开放给插件（例如 Galgame 的舞台）。

## 原则

- **普通 SillyTavern 卡直接能用**：不改卡、不改世界书。打开「对话气泡」后，正文模型按对白格式写台词（30/N），卡和世界书都不动。
- **默认关闭，一个全局开关**：「舞台设置 › 基础设置 › 对话气泡」，打开后对所有游玩对话下一轮生效。
- **素材沿用 ST 习惯**：主角用卡的 PNG 头像；立绘按 ST 表情包约定（每个角色一个文件夹，文件名就是情绪）。
- **分步建设内置舞台 core**：持续状态之后先接入导演增量事务，再建设核心演出与运行时；本切片不含 Live2D、Spine、口型或新的素材包体系。

## 地基：对白格式

每句台词的说话人和表情，由**正文模型在写这一句时一并写出**（30/N 起；之前由后台结算标注引号）。

- 「对话气泡」开着时，正文模型收到一段对白格式说明：每句台词单独一行，写成 `@bubble:handle|名字|差分|[台词]`，心声写成 `[*心声*]`，旁白照常写。说明附一份说话人名单：本卡「舞台素材」和插件提供的人物，每人一个 handle；差分是 ST 表情扩展 28 个情绪的中文名（开心、生气、平静…），方便直接对应 ST 立绘包的文件名。名单外的人物自己起 handle，同样从这 28 个里选。
- 说明不进每轮上下文，也不写进卡或世界书：它作为一条更新消息放在本轮 Frame 之前，只有内容变了（第一次打开、名单变了、关掉）或模型已经看不到它（回退、压缩之后）才重发，其余回合不动缓存前缀。关掉时发一条撤回说明。
- 宿主和浏览器共用一份解析（`bubble-line.cjs` 的 `parseBubbles`；`domain/dialogue-bubbles.js` 把它的结果对到人物、情绪与配音）。它宽容地读：整行外面的代码引号或强调符、全角分隔符、漏掉的方括号都能读；解析不了的 `@bubble` 行只显示它的台词，从不显示原始标记。差分按英文名或中文名归到 28 个情绪之一，其余一律算平静。
- 一轮的说话人直接从当前显示版本的正文读出，不另存：回退、重新生成、编辑后自然跟着正文走，导出、分叉随正文走。插件读到的 `lines`（`getCast`、`onCastAnnotated`、`watchStage`）形状不变，`quote` 是气泡里的台词；正文提交后通知一次 `onCastAnnotated`。
- 30/N 之前写成的轮次，已存的标注仍给舞台和插件读，编辑时照旧带到新版本，不做迁移；聊天里它们按旁白显示（32/N 起）。

## 第一步：对话头像

- 一行气泡显示成「头像 + 名字 + 情绪标签 + 台词」的说话人行（心声加括号）；旁白段落照常显示。只处理 Markdown 正文，卡片自己的 HTML 界面不动。
- 头像：说话人是卡的角色名时用卡的 PNG 头像；其余人物显示首字圆形头像（颜色按名字固定）。
- 正文还在生成时，一行气泡从它的第一个字起就是说话人行（32/N）。没打开「对话气泡」时显示成「名字：“台词”」，从不显示原始标记。

## 三层：故事、演出数据、呈现

- **故事**（正文、变量、回退、存档）通用，不因演出改变。
- **演出数据**（台词标注、角色素材）也是通用的，只是附在故事上的一份标注，可选、默认关。
- **呈现**才特化：聊天视图照旧；舞台是同一局故事的另一种看法，只读另外两层，不碰游玩流程。缺什么退一步：没有立绘用头像，没有头像用首字，没有标注就按旁白显示。

## 第二步：舞台与角色素材

- **入口**：「舞台设置」里「对话气泡」和「舞台模式」（默认开）都开着时，聊天顶栏右侧有「舞台」按钮，「酒馆状态」里有「全屏舞台」按钮，都打开全屏舞台；侧栏不再绘制舞台或播放演出。
- **舞台状态**：显示最新一轮，按台词逐句翻；标注只负责台词/当前说话人，不再决定人物入退场或立绘表情。人物、表情、背景、音乐由内置导演的已接受增量重建，全屏关闭重开仍读会话保留的状态。省略保持；换轮、刷新、重挂载不是清空。最多三人在场，增员超过容量必须显式退场，不自动挤掉别人。无背景时仅以卡图虚化作视觉降级，不自动选择第一张背景。
- **全屏舞台**：画面铺满页面，点击或方向键翻页、自动播放、Esc 退出；读到最后一句可以直接在舞台里输入下一轮行动。
- **角色素材**（每张卡一份）：人物名可加别名，头像和 28 个情绪的立绘。导入 ST 立绘包 ZIP（单人 `joy.png`…归给主角；多人 `角色名/joy.png`…按文件夹名），也可逐张上传。文件按内容寻址存放，链接可以永久缓存。
- **人物和镜头演出只来自导演**：删除自动入场、呼吸、立绘淡入及说话抬升；一次性动作由下述工具显式安排，系统开启「减少动态效果」时消费事件但不播放。

## 舞台 core（2/N）：独立后台导演

- 生产者是独立后台导演：复用 BackgroundAgentRunner，以 `task: 'stage-director', persistent: false` 为每个正文窗口创建自己的 session，可与结算并行。不挂进 settlementItems，不继承结算历史、人物卡/世界书前缀或结算工具；模型选择沿用本局后台模型设置，不增加设置项。
- 宿主正文流或完成事件独立触发，流式范围见下文；重生成只在正文正式采用后触发。完整 round-body 为 `{chatId,sessionId,turn,key,text}`，不从 UI 或台词标注构造正文。导演规则固定，本次 prepared frame 的玩家输入、人物卡、世界书和状态参考冻结后传入；排除写作规则，不继承结算会话。读取舞台不会触发模型。
- 本切片工具名 `stage_update`，整个增量在工具内一次校验；错误直接返回同一 session，模型可在已有 runner 的工具预算内修正，不重建修复会话。成功后结束，一次提交整批 delta。
- 参数为 `{ sequence, through, done:true, figures?: [{speaker, emotion?, remove?}] | null, background?: string | null, music?: string | null }`。`figures` 是逐人物增量，不是名单替换；省略表情保持，新人物默认平静。人物用清单的完整名称，情绪沿用 ST 名称（入口也归一化中文）；背景/音乐用唯一名称。`null` 分别清人物、清背景、停乐；只交封口字段即保持所有状态。
- 背景和音乐是本卡素材包里的条目（docs/design/asset-library.md「宿主接线」）：CCv3 `data.assets` 的 `background`、`type: "music"` 导入时进本卡素材包，导出时写回原位置；导演只看到条目名称（音乐的灯态见「舞台 core（10/N）：背景音乐」），不接收任意 URL。
- 所有字段先校验；任何一项非法则整批不写，工具返回可修复错误。最终持久化时在既有 Chat Journal 串行边界核对 branchId/revision、当前轮与正文 key、任务存活，再把整批 delta 一次写入按轮数据 owner `dsh-tavern.stage`。不改正文、变量或剧情 revision。已接受的同一正文版本不重复提交；过期/取消返回不可重试结果。
- `castStage` 删除过渡字段 `initialFigures`，返回 `stage: {figures, background, music}`（名称状态）及已解析的 `background` URL、`music`（10/N 起是带内容身份的曲目，或 `null`）。URL 是素材库的媒体租约，按媒体复用。现有会话/同源权限不变；插件只读舞台视图也包含这些字段。
- 一轮最终保存一笔合并增量；流式期间的临时投影不提前写入存档。持续场景变化仍按窗口立即应用，不是逐页持久状态时间线。
- 旧台词标注只用于聊天/配音，不回填成导演数据；首次成功导演提交前舞台状态为空。历史读取只折叠当前正文版本匹配的记录，资源缺失只影响投影，不改记录。已删除 demo 的历史/本轮标注人物推导、第一背景自动选择，没有兼容分支。

## 舞台 core（3/N）：按页一次性演出

- `stage_update` 新增可省略的 `performances` 数组（每窗口最多十二项）：`{at,op:'actor.act.play',actor,motion:'nod'|'jump'}` 或 `{at,op:'screen.play',effect:'shake-1'}`。`actor` 必须是本次人物增量应用后仍在场的完整名称；同页同一目标最多一个短动作，不同页可重复。任何无效项都在工具内拒绝整批，原 session 可修正。
- 宿主用正文非空行建立稳定的 `pages`，`at` 从 1 开始；同一份编号正文用于导演和阅读器。台词标注只给页添加姓名/情绪，不改变地址。这不是按屏幕尺寸计算的像素分页。
- 接纳时一次保存 `{delta,performances}`，持久状态仍按 delta 跨轮折叠、显式清除；performances 只属于源正文的本轮对应页，不进入下一轮 baseline。`castStage.turns[]` 增加 `key`、`pages`、`performances`，读取不生成或写状态。
- 玩家翻回本轮某页即开启新 visit，停留约一秒后播放该页一次；普通重绘/导演通知不重播。连续翻页取消中间页，跳过直接到本轮末页并取消待播及当前短动作，目标页不补播或重新朗读；初次打开、刷新、重开不播放已有事件。新正文到来时，只允许当前尚停留页的事件播放，不补播离开的页。
- 每局一个阅读位置与轻量播放 owner（6/N 起归会话运行时），关闭即释放播放；重新打开不补播已有事件。Web Animations 的短动作完成即释放，不写持久 transform，不影响人物/背景/音乐状态。换页、换局、关闭时取消该 owner 的定时器及动画。
- 最小范围是点头、轻跳和轻震屏；暂不移植演出风格条目、entry/turn/idle/exit 组合、关键帧、音效、跨轮历史导航、统一 runtime 和设置 UI。这些不以未使用的协议或兼容分支提前加入。

## 舞台 core（4/N）：导演流水线

正文还在流式生成时，导演先处理开头几行；正文正式提交后，再完成剩余部分。

- 只观察正在运行的正文 operation 的 text-delta，不把推理或工具参数当正文。首五个完整非空行启动第一窗；其余正文在宿主提交后合成余窗，不循环切窗。短正文只调一次，恰好五行不发空余窗。
- 两窗共用冻结参考、素材清单、前序状态及模型选择；余窗只承接已接受的舞台状态。`sequence` 是窗口序号，`through` 是该窗最后的全局页号，`done:true` 封口当前窗口而非宣告全文结束。三项都必须原样提交；错误及回写已封口页的演出在原会话内修复，不会局部接受。
- 首窗只作内存投影，`castStage` 立即显示；全文提交后核对封口文字、operation、剧情版本、正文 key、素材和前序状态，再经既有 Journal 写锁保存合并的 `{delta,performances,seals,presentationKey}`。转正保留阅读来源，不把首窗演出当新事件重播。失败、取消、换代或关闭时清掉临时投影，不留下半轮存档。
- 含副作用宏、EJS、script/style 或未闭合标签的首窗保守等待宿主最终投影；没有 prepared frame、非流式正文及重生成采用后仍走完整正文窗口。暂不涵盖任意 HTML/模板流式投影、相关性召回、长期导演记忆、跨轮分页或统一演出 runtime。

### 设计理由

`sequence/through/done` 是模型提交与宿主窗口的明确对应关系，不靠模型文字或调用顺序猜测完成范围；页地址前缀一旦接受便不可回写，坏参数直接由工具指出并允许修正。临时投影不持久化，是因为前台正文尚可能取消、失败或改写：此时尚无可供存档绑定的正式正文版本，不能让半轮演出成为下一轮的权威状态。窗口之间冻结参考也避免并行结算改变本次导演的事实基础；这不代表已经测量真实模型审美、长清单效果或缓存命中率。

## 舞台 core（5/N）：一局一份舞台

只保留全屏舞台；同一局只保留一份已接受的画面，关闭重开仍接着使用，不因读取失败清场。

- `createStageRuntimeSessions` 跟随原生会话列表及 binding，首次选中才建立 store，不因组件挂载创建模型任务；已经打开的会话保留到原生列表移除或 binding 替换。插件卸载统一退订并中止在途读取。
- store 只读既有 `castStage`，原子发布 `{data,scene,pending,error}`；后台通知、正文运行状态、宿主视图、设置及重连唤醒读取。每局最多一笔在途请求，期间的新通知合并为下一次读取；可见窗口每五秒只读对账，不自动重导或回写历史。
- 普通刷新和读取失败保留上一份画面；收到确定的新快照才替换。相同场景沿用对象引用，显式清人物会清空；未配置背景仍沿用既有卡图降级。换卡、回退上下文或 binding 替换先撤销旧请求，过期结果不得污染新上下文或另一局。
- 删除 demo 的 `useTavernCastStage` 组件内取数、局部数据写入和每个画面的素材投影；素材编辑完成后也重新读宿主。静态背景与立绘在接受边界统一解析；删除 TavernStageSection、其挂载及小舞台专用状态和样式。入口是聊天顶栏「舞台」和「酒馆状态」的「全屏舞台」；音乐开关和退出放在全屏控制栏；角色素材、声音和舞台样式暂留「酒馆状态」，之后归舞台设置页。
- 本步不修改 `stage_update`、存档、提示词和页号；已有回翻停留后播一次、跳过和刷新不补播的规则不变。全屏阅读与播放资源在关闭时释放，素材管理保留原功能；不宣称已删除整个 `cast-stage.js`；媒体租约、解码资源管理、跨轮历史和完整纯 reducer 也不在本步。

设计理由：Galgame 本质上是横屏的，侧栏却是竖向的一列；把横屏舞台硬塞进去没有带来什么价值，还要同时维护侧栏和全屏两套舞台，维护起来很麻烦，所以只保留全屏舞台。

画面的生命周期属于这局游戏，不属于某次 React 挂载；把读取和接受边界收回会话层，才能让全屏关闭重开仍有已接受的画面，普通刷新和失败读取也不被误当成清场。通知只唤醒、结果仍读宿主，避免把并行任务的通知当作权威剧情；读取失败不生成空场景。先统一静态投影，保留已有阅读和短动作合同，可以在小切片中验证会话隔离与连续性，而不把播放器、设置及资源服务一起重写。

## 舞台 core（6/N）：舞台保持阅读进度

读到哪一页、自动翻页和播放都由这一局的舞台运行时持有；全屏只是它的画面。

- 会话 store 在 `{data,scene}` 旁原子发布阅读位置 `reader:{key,index,visit,mode,auto}`。首次读取只恢复（`refresh`）；同一局收到新正文 key 时回到第一页并以 `live` 开始；翻页是新的 visit（`page`），跳过是不播放的 visit（`skip`）；同 key 的通知保留当前页，正文变短时夹到末页；回退等上下文撤销后重新从恢复开始，visit 编号不回绕。
- 全屏打开时向这一局 `attach` 一个播放器：当前页的一次性演出、朗读、自动翻页和音乐都由它驱动。关闭、换局、binding 替换或会话移除时 `detach`，取消定时器和动画，停止朗读和音乐。再打开回到原来那一页，以恢复模式显示，关闭时还在等待的停留不补播。
- 自动翻页等这一句读完后约 0.4 秒翻页，没有朗读时按文字长度等待，末页停止；关闭重开后自动翻页为关。「朗读」开关仍按浏览器记住，关掉立即停声。
- 删除 demo 的 `cast-stage.js` 及其 include：组件内阅读器 `useTavernStageReader`、`TavernStageFullscreen`/`TavernStageSession` 的播放和音乐副作用。舞台画面与插件 `registerStageView` 输入不变，并入舞台运行时文件；角色素材编辑并入人物呈现模块，仍在「酒馆状态」，之后归舞台设置页。
- 不改宿主 RPC、`stage_update`、存档、提示词或页号；仍只读最新一轮，跨轮翻页、媒体租约和解码管理不在本步。

设计理由：阅读位置和播放资源原先挂在 React 组件上，关掉全屏就丢了位置，回来总是第一页；播放的定时器、朗读和音乐各由组件副作用管理，换局、回退时谁来停也分散在几处。画面已经归这一局（5/N），读到哪一页、在播什么也应该归同一个 owner：位置跟会话走，关闭重开不丢；资源只有一个释放点，换局、回退、移除都走同一条路径。播放器只在有画面挂上时存在，因此没有画面的会话不会出声或占用定时器。

## 舞台 core（7/N）：舞台设置页

舞台的设置有三处家，每处只管一件事，都在侧栏开始页的「其他」里：

- **「舞台设置」**：「基础设置」一组开关，顺序是 对话气泡、配音 ›、舞台模式。一行是图标、短名和右侧开关；带「›」的行点开关以外的地方打开它的页面。
  - 「对话气泡」就是原来设置页里的全局「对话头像」（`castPresentation`），从设置页移到这里。
  - 「配音」是配音服务的全局开关，代替全屏舞台原来的「朗读」开关；「›」打开「配音」页，那一页顶部有返回「舞台设置」的「‹」。对话气泡关着时（没有台词标注），配音开关变灰并说明需要对话气泡。
  - 「舞台模式」是全局开关（设置里的 `stageToggles.stage`，默认开），和参考设计一样需要「对话气泡」：对话气泡关着时它变灰、保留原值，所有卡的舞台都不显示。按卡的舞台开关（`setCardStage` / `cardStage`、卡的 `defaults.stage`）随之删除，卡不再替玩家打开舞台。
  - 装了提供舞台画面的插件时，下面多一行「舞台样式」。
  - 不在游玩对话里时显示「未打开人物卡」和「打开人物卡库」。
- **「舞台素材」**：这张卡的角色素材（立绘、头像、每个人物的声音、导入 ST 立绘包），从「酒馆状态」搬来。舞台关着时也能编辑，聊天里的头像也用它们。
- **「配音」**：配音服务页（渠道、默认声音、旁白声音、开关），和「设置 › 配音」是同一页。
- **「酒馆状态」**只留「全屏舞台」入口。全屏舞台自己不放开关：控制栏保留「♪」快速静音，「朗读」不再单独存在（控制栏的「声音」打开的 CONFIG 只放玩家本机的音量和阅读节奏，见 23/N）。控制栏恢复换行，窄屏不再挤出屏幕。
- 不改宿主 RPC、存档或插件接口。

设计理由：对齐参考的舞台设计，每件事只有一个设置的家。三个面板的名字、图标、顺序和开关行都照搬参考实现；上游还没有的能力（BGM、音效、环境音、物品、演出组合、入场演出、默认皮肤、自动生成选项、设置向导、模组、素材包）由之后各自的 core 连同它们的行一起加入。

## 舞台 core（8/N）：皮肤是数据

舞台长什么样，由一份皮肤文档决定；舞台只认文档里的字段，不认皮肤是哪一个。

- **皮肤文档**（`dsh.skin/1`）：只有数据——颜色、封闭的词、数字和包内文件名，不能写代码、CSS 或网址。校验器是封闭的：未知字段、超出范围的数值、不在列表里的词，或者正文/名牌/控件的文字对比度不够，整份文档被拒收。必填 `schema`、`id`、`label`、`textbox`、`nameplate`、`font`、`textFx`，其余省略就用舞台的默认外观。
  - 校验器在 `lib/domain/stage-skin.js`，宿主和浏览器共用同一份；`stage-skin.schema.json` 是给编辑器和工具看的 JSON Schema 镜像，以校验器为准。
  - 文档包括文字层（文本框和名牌的配色、形状、描边环、字形与排版、逐字揭示、翻页光标、控件行、音效、人物取景、效果外观、HUD、演出模式）和美术层 `art`（设计屏坐标里的框图、名牌图、选项条、按钮、菜单、履历、头像框等）。
  - 美术层的通用部件形状对每个能用它的槽位写法都一样：九宫格 `slice`（`[上,右,下,左]` 或 `{edges}`）、逐帧图集 `frames`、分状态按钮 `buttonArt`；头像框的 `fill`（不透明底色）、框上沿圆弧写的名字（描边、硬投影、压暗带、最小字号）、手机落位 `narrow`；控件行的 `place` 和手机上的 `narrow`。
  - 演出主题的 `levels` / `overlay`、模组选项 `mods` 和 `assets` 不属于这份文档，随各自的功能加入。
- **内置皮肤「经典」**也是一份普通文档，是所有舞台的默认外观。它不指定字体，舞台继续用客户端自己的字体。
- **解释器**（`features/stage-skin.js`）把文档变成舞台根上的变量：文本框的底色、字色、边框、圆角和描边环，名牌的底色、字色、形状和倾斜，正文的字重、字距和行高，控件行的字色与按下/悬停色块（对比度至少 3:1），输入框和发送按钮的配色（强调色对底色、按钮字对强调色至少 4.5:1）。玩家的字号和文字排版设置仍然优先。
- 全屏舞台用「经典」画出来；文本框、名牌、正文、控件和输入框的样式里不再有自己写死的颜色，只读这些变量。名牌不再按人物换色（之前的人物色相），表情标签跟随名牌的字色。
- 今天的舞台画出文本框、名牌、正文、控件行和输入框这几部分；其余字段已经是合法的皮肤数据，由之后各自的画面部件读取。美术层要用皮肤包里的图片，随「皮肤素材和切换」一起接上。
- 不改宿主 RPC、存档、提示词或插件接口；`registerStageView` 的插件画面不受影响。

设计理由：皮肤是数据而不是代码，才能安全地交换和安装别人做的皮肤：封闭的校验器在入口一次挡住代码、网址和读不清的配色，之后舞台照着数据画，不再重复检查。舞台只通过一个解释器读皮肤，没有按皮肤 id 的分支，所以新皮肤不需要新代码，「经典」也只是第一份数据：它和以后的每一份皮肤走同一条路径，舞台原来写死的配色就可以删掉，不留第二套外观。文档格式整份一次定下来，通用部件的形状（九宫格、逐帧、按钮体）对所有槽位只有一种写法，之后的画面部件按同一份格式接上，不必再改格式。

## 舞台 core（10/N）：背景音乐

舞台的背景音乐有了自己的播放器：循环、按条目音量播放，可以暂停和手动选曲，在聊天和全屏舞台之间切换不重播。

- **只有一个播放器**：页面上一个 BGM 播放器跟随当前选中的这一局，聊天和全屏舞台里都是它在放，开关全屏不会重播或叠播。没有打开的局、这一局舞台模式关着或 BGM 关着时不出声。全屏舞台的运行时只管演出、朗读和自动翻页，不再驱动音乐（代替 6/N 里播放器驱动音乐的那一部分）。
- **播放**：Web Audio 把整首解码成一段缓冲，由音频线程原生循环。条目写了 `loopStart`/`loopEnd`（秒）时前奏只放一次，之后循环这一段；没写时裁掉首尾静音，把约 40 ms 的等功率交叠烘焙进尾部，接缝处没有定时器，也不重新解码。换曲交叉淡化约 1.2 秒；导演停乐淡出 1.2 秒，新曲可以打断淡出；跳过、关掉 BGM、暂停、换局立即停。条目的「音量」（0–1）就是这首的增益。同一首（同一条目、同一份媒体）换了租约地址也只是接着放。浏览器拒绝自动播放时，玩家下一次点击或按键即恢复。
- **面板**：全屏控制栏的「♪ 曲名」和聊天顶栏的同一个按钮（只在舞台模式开着的局显示）打开同一个面板：曲名、「导演选曲」开关、上一首 / 播放暂停 / 下一首、搜索和曲目列表（本卡素材包里亮着的音乐，按绑定顺序再按包内顺序），导演当前的曲目带标记。Esc 或点外面关闭；在舞台上点外面只关闭，不翻页。面板没有音量滑块。
- **导演选曲**：开着时放导演已接受的曲目；手动点一首即关闭，之后导演换曲照常记录但不播放；重新打开立即跳到导演当前的曲目；直接关闭时保留正在放的那首。模式、手选曲目和暂停只按这一局记在本机浏览器（`localStorage`，最多 32 局，默认状态不存），不写卡。手选的曲目从卡的素材包中消失后回到跟随导演；租约失效时先重读一次列表，再失败才显示「载入失败」。
- **BGM 开关**：「舞台设置 › 基础设置」在「舞台模式」下多一行「BGM」，对所有卡生效，默认开（酒馆设置 `stageToggles.music`）。舞台模式关着时这一行变灰。关掉后不出声，导演收不到音乐清单和音乐说明，导演下一次运行时记录停乐；重新打开后等导演选曲。
- **灯态**：蓝灯音乐每轮都给导演；绿灯只在这一轮已有正文（含已封口的前缀）出现条目名、关键词或其同义词时给，汉字词任意位置命中，拉丁字母和数字词按整词命中；关闭的条目不给，也不在列表里。没命中只是少一个选择，不会停掉正在放的绿灯曲目。绿灯背景同样召回，判断模型补位见「舞台 core（13/N）」。
- **导演的音乐操作**：仍是 `stage_update` 的 `music`：名称换曲，`null` 停乐，省略保持，跨轮持续到停乐。正在放的曲目离开清单（条目关闭或删除、BGM 关闭）时，导演看到的是静音，这一轮记录停乐。有可选曲目或正在放音乐时，导演的本轮上下文多一条 `musicNote`：当前 BGM，省略即保持；有曲目可选时，只在换场或情绪转折处换曲，静音之后在剧情明确恢复配乐处再选；玩家或正文让音乐停下时用 `null` 并保持安静。都没有时不写音乐说明。工具 schema 和系统提示不变；`musicNote` 最长约 330 字节（UTF-8）。
- **宿主接口**：`castStage.music` 改为 `{key,ref,identity,name,pack,url,volume?,loopStart?,loopEnd?}`，`identity` 是条目加媒体哈希；另加 `musicEnabled`。新增 `getStageMusicTracks({sessionId})`，返回本卡全部亮着的音乐（同一形状）。URL 仍是素材库的媒体租约。
- **删除**：舞台运行时经 `tavernMusic`（插件音乐用的 HTMLAudio 播放器）放导演音乐的 demo 路径。`tavernMusic`、`tavernUi.playMusic` 和控制栏上只在插件放音乐时出现的「♪ 音乐」开关留给插件，插件音乐仍随舞台画面关闭而停。
- **不在本步**：响度归一化和混音音量（舞台 CONFIG › 声音）、音效和环境音、演出接管音乐。素材条目编辑界面和「BGM ›」在 11/N。

设计理由：照搬参考实现的 BGM 播放器。音乐跟着这一局走，而不是跟着全屏画面：玩家在聊天和舞台之间来回切，音乐不该每次重头放或两首叠在一起，所以页面上只有一个播放器、一个停止点。循环交给音频线程的原生循环，接缝才不会断，也不靠定时器追赶。手动选曲和暂停是玩家对这一局的临时偏好，不改导演记录，也不写卡，所以只按局记在本机。灯态是素材条目的通用规则：蓝灯常驻，绿灯按正文召回，关闭就不可用；没命中只是少一个选择，不能把正在放的音乐停掉。BGM 关闭和条目消失都按投影降级：导演看到静音，这一轮记下停乐，不改写历史。音乐说明只在有曲可选或正在放时才发，没有音乐的卡不多花一个字节。

## 舞台 core（11/N）：素材条目编辑

玩家可以自己管理舞台用的背景和音乐：新建素材包、上传文件，改名称、灯态、触发词、导演说明和音量，把包给这张卡或所有卡使用，也可以删除。详细说明见 asset-library.md「编辑界面」。

- **「舞台素材」**：顶部是素材库（所有素材包），下面仍是这张卡的角色素材。不在游玩对话里时也能打开素材库，这时只有「全局 / 关闭」。
- **「舞台设置」**：基础设置下面多一节「素材包」，列出这张卡在用的包，「管理」展开成全部素材包。BGM 行多一个「›」，打开这张卡的音乐条目。
- **导演目录**：全局包排在卡自己的包后面。改动立即唤醒用到这个包的对局重读舞台，下一轮导演就看到新的清单。正在播放的曲目被关掉或删掉时，按 10/N 的投影规则降级为静音。
- **宿主接口**：新增 `lib/rpc/asset-library.js` 里的素材包 RPC，以及酒馆设置 `globalEnabledPackIds`（修改用 `globalPack: {packId, enabled}`，一次只改一个包）。存档格式和插件接口不变。

设计理由：照搬参考实现的素材库界面，只保留上游已有的两种素材。素材包只有一个家，就是宿主的素材库：页面只显示它的快照，每次修改都是一次 CAS 发布，所以两个窗口同时改不会互相覆盖。触发词只在玩家写的时候检查，导入的包不会因为后来定的规则突然不能用。状态用「全局 / 本卡 / 关闭」三个字，和条目的蓝灯 / 绿灯 / 关闭分开，不混成一套控制。删除素材包时一起解除所有绑定，卡就不会指向一个已经不存在的包。

## 舞台 core（12/N）：可用演出与每轮上限

「舞台设置 › 基础设置」的「舞台模式」行多一个「›」，在同一个面板里打开「舞台模式」页（「‹」和 Esc 返回，焦点回到「›」）。这一页的设置所有卡共用，导演在每轮开始时读一次并冻结到这一轮。

- **可用演出**（酒馆设置 `stageDimensions`，默认全开）：按组列出导演能用的命令——场景与转场（场景 = `background`）、人物（出场 = `figures`，动作 = `actor.act.play`）、效果（画面效果 = `screen.play`）。一组一行，值是「全部 / 部分 n/m / 全部关闭」，展开是这一组的勾选项，点选立即保存。关掉的命令从工具 schema、系统提示和本轮清单里去掉，提交了也会被工具拒绝；它已经设下的状态按「省略保持」留在舞台上。音乐仍由「BGM」开关管。
- **每轮上限**（`stageActionCaps.beat`，默认 6，1–256）：一轮回复里 `screen.play` 最多几次，流式各窗口合计。超出时工具拒绝这一批，导演在同一会话里删去多余的一项再交。这是一份草稿，由「保存」写入；有未保存的修改时页脚吸底，Esc 不离开。
- **宿主接口**：只是酒馆设置的两个新字段，读写走既有的 `getTavernSettings` / `updateTavernSettings`，补丁只写它列出的键。全部开着时工具和提示与之前逐字相同。

设计理由：照搬参考实现的「舞台模式」页，只列上游导演已有的命令。参考实现的「人物动作」上限只管会让人物一直抖的动作，上游只有点头和跳，所以这一行不加。设置放在 `stageToggles` 旁边的酒馆设置里，全局舞台设置只有一个家。

## 舞台 core（13/N）：判断模型与绿灯召回

绿灯条目（背景和音乐）每个窗口按这一轮已有正文召回：条目名、关键词或其同义词出现时提供给导演。「舞台模式」页最上面多一节「判断模型」：配置后，没被正文提到的绿灯条目再问一次判断模型「这条素材适合本轮剧情吗」，把握够的补进清单。

- **灯态**：蓝灯每轮都给，不问判断模型；绿灯被正文提到就给，也不问；其余绿灯问判断模型，概率达到「门槛」的按每类（背景、音乐）概率从高到低取「每类上限」条；关闭的条目不给，也不问。没被召回只是少一个选择，不会换掉当前背景或停掉正在放的音乐。
- **判断模型**（酒馆设置 `stageJudge`，默认「未设置」）：提供方（Jev、OpenAI、OpenAI 兼容）→ 接口地址（只有兼容服务）→ 模型 → API Key，然后是门槛（默认 0.6）、每类上限（默认 8）、超时（默认 1500 毫秒）、附加说明（默认空）。选提供方会填好它的模型和默认环境变量名。这些和「每轮上限」是同一份草稿，由页脚的「保存」写入；兼容服务没填地址、没填模型时「保存」不可点，旁边写原因。未设置或关闭时不读密钥、不发请求，绿灯只按正文召回，导演和以前完全一样。
- **API Key**：一个密码框，可以直接粘贴 API Key，也可以填环境变量的名称。填的是现在能读到的环境变量名，就记为引用（写进 `stageJudge.keyName`）；其他内容都当作密钥本身，存进 DSH 凭据库（每个提供方一个固定名称），不进设置、不回传、不写日志。读取时已存的密钥优先。显示「已配置」或「已配置 · 环境变量 NAME」，可以更换或清除。「测试连接」用未保存的草稿发一个极小的真实请求，只在玩家点的时候发；草稿改了地址或密钥名称时要先保存，已存的密钥不会发到设置里没有的服务器。
- **请求**：判断模型只读这一轮已有的正文（附加说明在最前）和每个候选的一句提问（类别、名称、导演说明，去掉署名和许可片段）；不发玩家输入、旧轮、变量、世界书或人物卡。每次最多 300 题，多了并行；所有批次共用一个超时。任何一批失败、超时、缺答案或概率不合法，这一窗口就只按正文召回，不重试，也不随机补位。日志只有提供方、模型、题数、耗时、固定错误码和用量。
- **宿主接口**：设置走既有的 `getTavernSettings` / `updateTavernSettings`（`stageJudge` 整份写入，缺的字段取默认值或提供方预设）；新增 `getJudgeCredentialStatus {provider,keyName}`、`setJudgeKey {provider,value}`（`null` 清除）、`testJudgeConnection {config?}`，都不返回密钥。

设计理由：照搬参考实现的判断模型和绿灯召回。判断模型只回答「是 / 否」的概率，不写正文、不选演出，所以它可以是一个便宜、快的专用接口，导演仍然只从清单里挑。没配置时什么都不多做，素材条目照样按正文生效；配置后只补正文没提到的绿灯，蓝灯和已命中的不占额度，也不花钱。参考实现的提供方和模型在统一的模型槽里选，上游没有模型槽，所以提供方和模型放回这一节；设置和其他舞台全局设置一样放在酒馆设置里。密钥只进凭据库，测试连接不会把已存的密钥带到草稿里的新地址。

## 舞台 core（14/N）：皮肤成为素材条目

皮肤可以装进素材包了：素材包多了「皮肤」一类，一条皮肤就是一个皮肤文件夹（`skin.json` 和它声明的图片、字体、短音效）。卡的舞台用哪套皮肤，按一个顺序决定：本卡皮肤 → 卡自带 → 素材包默认 → 默认皮肤 → 经典。

- **添加皮肤**：素材包窗口「添加文件 › 皮肤」选一个文件夹。页面只上传 `skin.json` 和它声明的文件（路径相对 `skin.json`），宿主在写入时检查一次：文档合法（`dsh.skin/1`、对比度）、id 与条目一致、声明的文件都在且没有多余文件、图片过媒体检查（SVG 只收惰性的绘图标记）、字体是 16 MiB 以内的 WOFF2、音效不超过 3 秒。之后读取不再检查。存储上是素材包里的一个 bundle：`bundles/skin-<id>/`，条目 `{kind:'skins', bundleKey, entry}`，bundle 有自己的内容哈希。同 id 再添加就整体替换；删除连同文件一起删，id 不再复用。
- **皮肤没有灯**：皮肤条目没有蓝灯/绿灯/关闭，导演不会选它；素材包窗口只显示名称、小样和「包默认」开关。
- **选用顺序**（`lib/domain/stage-skin-choice.js`）：
  - 本卡皮肤：玩家在「舞台设置 › 基础设置 › 本卡皮肤」为这张卡选的（cast.json `skinChoice`，不随卡导出），可选这张卡的素材包里的皮肤，「跟随默认」清除；
  - 卡自带：卡文件里的 `extensions.dsh_tavern.stage.defaultSkin`；
  - 素材包默认：这张卡绑定的素材包里，按绑定顺序第一个声明了默认皮肤的（素材包的 `stageSkin`）；
  - 默认皮肤：「舞台设置 › 基础设置 › 默认皮肤」（酒馆设置 `stageSkin`），可选「全局」素材包里的皮肤；
  - 经典。
  某一步指向的皮肤不在了（素材包删了或解绑、皮肤删了），就跳到下一步；存的选择不改写，皮肤回来后又生效。选择在写入时检查（内置 id，或现在还在的素材包皮肤）。
- **宿主接口**：`addAssetPackSkin {packId, document, files:[{path, uploadId}]}`、`setAssetPackStageSkin {packId, expectedRevision, skin|null}`、`getStageSkins {path?}`（存的选择、这张卡现在用哪套、两个选择器的选项）、`setStageSkin {skin}`、`setCardStageSkin {path, skin|null}`；`castStage` 多返回 `skin`（选中的皮肤文档和它的文件地址，见 15/N）。
- 舞台按皮肤画文本框、名牌、正文、控件和输入框的配色；皮肤里的图片由美术层（15/N）画。

设计理由：照搬参考实现。皮肤和背景、音乐一样是素材包里的条目，才能随素材包安装、分享和删除；它是一个文件夹而不是一张图，所以存成 bundle，写入时一次检查完整个文件夹，读的时候只读。选用顺序从最具体到最一般，每一步都是「有就用，没有或不在了就往下」，所以删素材、解绑素材包都不会让舞台坏掉，也不需要去改写别处存的选择。参考实现的「本卡皮肤」在舞台内的 CONFIG 里，上游舞台没有 CONFIG，所以放在「舞台设置 › 基础设置」，紧跟「默认皮肤」；参考实现的包默认由作者工具写入，上游没有作者工具，所以在素材包窗口里给皮肤条目一个「包默认」开关。

## 舞台 core（15/N）：皮肤美术层

皮肤带 `art` 时，全屏舞台用皮肤自己的图片画文本框、名牌、翻页提示和 AUTO 灯（`src/client/features/stage-skin.js` 的 `stageSkinArt`，样式在 `tavern.css`「stage skin: art」）。坐标都是皮肤设计屏（`art.screen` / `art.screenWidth`）上的像素，舞台按高度缩放，宽度不够时按宽度缩放。

- **文本框**：`art.textbox.images` 的图（旁白可单独一张）；`body` 是框的正文区，`text` 是正文的左右边和中线，`font` / `lines` / `pitch` 定字号、行数和行距，`bottom` 是图离屏幕底边的距离；`align`、`stroke` 可选。
- **名牌**：`art.nameplate` 的位置和大小；有 `image` 时站在皮肤的名牌图上，`slice` 时九宫格拉伸、随名字变长（最多 `grow`），`vertical` 竖排，`fill` 双色字、`shadow` 投影。
- **翻页提示**：`cue` 放在框上某点，或 `inline` 跟在正文末尾；`next` 是图片（`frames` 是逐帧图集），没有图时画一个引擎自带的记号；`bob` / `dip` / `blink` 三种动法。
- **AUTO 灯**：自动翻页时在 `lamp` 处亮起，`frames` / `blink` / `spin` / `swap`（替换翻页提示）。
- **控件和输入框**：控件行是框自己的，在正文区右下角；最后一页的输入框停在框图上方，框多高都不会盖住。
- **手机**（≤640px）：框图按九宫格（`art.textbox.slice`，默认是正文区以外的部分）随行数长高，正文至少 17px、名字至少 14px，控件行在正文下面单独一条。
- **动效**：逐帧用 Web Animations 播放；系统设置「减少动态效果」时不播，停在静止的一帧。
- **皮肤文件**：`castStage` 的 `skin` 是 `{document, base}`，`base` 是这套皮肤 bundle 的租约地址，图片从那里读。租约拿不到时 `base` 为空，舞台只画配色，下一次读取会重试；图片解码失败从 1 秒起按倍数退避重试，最长 30 秒。没有 `art` 或图片还没到时，舞台照常按配色画。

设计理由：照搬参考实现的美术层，只改接缝。参考实现的控件行默认就在框图右下角（`quickMenu.place` 和 `art.textbox.controls` 再把它挪到皮肤指定的位置），上游舞台有同样的控件行，所以也放在框上；上游的输入框在参考实现里没有对应物（参考实现的自由输入在选项里），所以停在框图上方。头像框、`quickMenu` 的落位和图标按钮见 16/N。

## 舞台 core（16/N）：头像框与快捷菜单

皮肤带 `art.portrait` 时，台词页在文本框上画说话人的头像窗口；带 `quickMenu.place` / `icons` 时，控件行按皮肤落位、用皮肤的图标画（`stage-skin.js` 的 `stageSkinPortraitArt`、`stageSkinControlIcons`，样式在 `tavern.css`「stage skin: art portrait」「stage skin: box controls」）。

- **头像窗口**：`art.portrait` 的 `left` / `bottom` / `size` 是设计屏上的正方形，画说话人这一情绪的头像（没有就用人物头像、卡封面）。旁白页和没有头像的人物不画，也不留空框；换说话人直接切换。
- **头像框**：`frame.image` 放在 `left` / `bottom`（图片原尺寸），脸裁进 `window`（默认就是那个正方形）。`round` 裁成椭圆；`front` 框画在脸前面；`glass` 是脸上的一层反光；`back` 是窗口里脸后面的底图；`fill` 是窗口自己的不透明底色（一种颜色，或 `[中心, 边缘]` 径向渐变）；`speaking` 是这句台词正在朗读时换上的框。
- **框上的名字**：`frame.name` 把名字沿框的圆弧写（`arc` 圆心和半径、`span` 弧长、`side` 上弧或下弧）；名字长时先缩小、再收紧字距、再缩到 `min`，最后压进弧长；`ink` 渐变、`stroke` 描边、`shadow` 投影、`bed` 底衬、`engrave` 刻痕保证看得清。名字在框上时，文本框的名牌让开，只留给读屏。
- **手机**（≤640px，`portrait.narrow`）：头像站在框左上角的 `x` / `y`（CSS px，负数在框图上方），宽 `width`，框里的一切按比例缩小；`flow` 决定正文怎么让开（`beside` 留一列、`wrap` 绕开、`below` 从头像下面开始，左边距 `left`）；`name: arc` 保留弧上的名字（最小 `nameMin` px），`below` 改成头像下面一行字。
- **控件行**：`quickMenu.place` 把控件行放在框图的右上角或右下角；`art.textbox.controls` 在宽屏上按设计像素落在框图上（右端在 `x`，顶在 `y`，每个控件 `w` × `size`，间距 `gap`），没有图标的控件在正文列右边换行。手机上 `narrow` 决定控件行的位置：`bottom` 在正文下面单独一条，`top` 在框顶，`edge` 骑在框的上边线上、不占正文的地方。
- **图标按钮**：`quickMenu.icons` 给 ‹（`back`）、自动（`auto`，运行时用 `on` 图）、跳过（`skip`）画皮肤的图标；`quickMenu.button` 是图标底下的按钮图（普通、悬停、开启、禁用四态，`glyph` 是图标在按钮里的位置）。按钮的动作、名字和按键不变；手机上每个图标按钮 44px。
- **输入框**：最后一页的输入框停在框图和头像框两者的上方。

设计理由：照搬参考实现的头像框与控件行，只改接缝。上游舞台的文本框原来没有头像位，参考实现的头像窗口是文本框的一部分，所以只在皮肤声明了 `art.portrait` 时加这一个位置，经典皮肤不变。头像用上游已有的头像来源，按上游对话头像的画法铺满窗口、靠上对齐（上游的头像没有裁切信息）。参考实现的「正在说」是打字中或语音播放中；上游舞台没有打字效果，所以只在朗读这句时换框。参考实现的控件行里没有 ›、页码、BGM、音乐和「退出舞台」，皮肤也没有它们的图标，所以这些控件保持文字，和图标按钮排在同一行；参考实现框上名字让开后名牌缩成语音按钮的位置，上游名牌里没有语音按钮，所以只是隐藏。差分名（`frame.mood`）和半身像（`source: bust`）上游还没有对应的宿主功能，暂不画。

## 舞台 core（17/N）：物品

正文里拿出、递交或特写一件重要物品时，导演可以在那一页把它展示出来：物品的图和名字浮在文本框上方，约 2.8 秒后淡出。

- **素材**：素材包多了「物品」一类（`props`，内容字段 `media` 图片、`tags`），像背景一样一个文件一条、有蓝灯 / 绿灯 / 关闭。绿灯物品和背景、音乐一样按正文召回，判断模型配置后也补位（每类上限单算）。物品不写进导出的卡文件（CCv3 没有它的位置），留在素材库里。
- **开关**：「舞台设置 › 基础设置」在「BGM」下多一行「物品」，对所有卡生效，默认开（酒馆设置 `stageToggles.items`），舞台模式关着时变灰；「›」打开这张卡的物品条目。关掉后导演收不到物品清单和说明，已经安排的物品也不再显示。
- **导演**：本轮有可用物品时，`stage_update` 的 `performances` 多一种 `{at,op:'item.play',item}`，`item` 从本轮上下文的 `items` 清单复制名称，每页至多一件；系统提示多一句什么时候展示。没有可用物品时，工具 schema、系统提示和本轮上下文都不提物品，和以前逐字相同。不在清单里的名字、多余字段、同页两件都在工具内拒绝，导演在原会话修正。物品不是画面效果，不占「每轮上限」；「可用演出」里关掉动作和画面效果也不影响它。
- **播放**：和 3/N 的一次性演出是同一个播放 owner：翻到那一页停留约一秒播一次，跳过、刷新、重开不补播；翻走即取消。这一页的物品图提前在画面里（不可见）加载，图拿不到时只显示名字。「减少动态效果」时只淡入淡出、不移动。物品不挡点击。
- **宿主接口**：`castStage.turns[].performances` 里的 `item.play` 多一个 `image`（这条素材的媒体租约）。按名字对当前亮着的物品条目；条目关掉、删掉或「物品」关闭时，这一项只是不显示，存档不改。
- **不在本步**：获得 / 失去和数量（参考实现要先把卡的背包绑定到 MVU 变量，上游还没有变量绑定）、物品差分、分类图标、避开人脸的落位、履历里的物品记录、皮肤的 `art.item`。

设计理由：照搬参考实现里不依赖变量的那一半——「展示」。参考实现里未绑定背包的卡只能展示，获得 / 失去要等结算核对数量，正文本身不是背包的权威，所以这一步不让导演凭正文声称数量。物品是按页的一次性演出，不是持续状态，所以走 3/N 已有的 `performances` 和播放 owner，不另建第二套播放或历史。开关是全局的一行，和 BGM 一样，按卡的差别来自素材灯态；没有可用物品时一个字节也不多发。

## 舞台 core（18/N）：入场演出

卡自己的素材包里有一段开着的入场演出时，每次打开全屏舞台先在舞台上播它（样例 `examples/stage-entrance/light-tunnel.json` 约 2.6 秒）：光点、光环、从焦点飞出的光线，最后一道白光盖住画面，揭开时舞台已经在下面。

- **素材**：素材包多了「入场演出」一类（`entrances`，内容字段 `entrance`，是一份 `dsh.entrance/1` 文档，没有文件）。只有蓝灯和关闭，导演不用它，也不进导演的素材清单。在素材包「添加文件 › 入场演出」选 JSON 文件添加；写入时检查一次（未知字段、超范围的值整份拒绝），同一份文档再添加还是同一条。列表行显示它的配色，条目页显示一帧静止画面和时长。
- **文档**（`lib/domain/stage-entrance.js`，宿主和浏览器共用）：引擎只画一组通用图元——光点 `light`、光环 `rings`、光线 `streams`、星芒 `flare`、暗角 `vignette`、全屏白光 `flash`；颜色、时长、强度、形状都在文档里。`phases` 按顺序播放：`hold` 段在舞台没准备好时循环；`cover` 段结束时画面被盖住，等舞台画好再交接；之后的段淡出。`skip` 是跳过时的白光和交接时长，`still` 是减少动态效果时那一帧，`reducedMs` 是它的淡出时长。白光和星芒最多一半亮度（光敏保护）。
- **选用**：只看这张卡自己的素材包（全局素材包不会给每张卡都加入场），按绑定顺序、包内顺序取第一条开着的。
- **开关**：「舞台设置 › 基础设置」在「物品」下多一行「入场演出」，对所有卡生效，默认开（酒馆设置 `stageToggles.entrance`），舞台模式关着时变灰；「›」打开这张卡自己素材包里的入场演出条目。
- **播放**：舞台从一开始就画在下面，入场演出从不挡住舞台：舞台准备好后点一下或按翻页键（回车、空格、→、↓、PageDown）直接跳到白光再交接，这一下不会翻页；其余舞台按键等它播完。系统设置「减少动态效果」时只显示一帧静止画面再淡出，没有白光。没有 2D canvas、3 秒内没有第一帧、准备好后迟迟不到白光、白光后 8 秒还没结束，都直接放弃、显示舞台。每次打开舞台播一次；中途改设置等下一次打开才生效。什么也不写：入场演出不属于故事，也不属于某一页的播放。
- **宿主接口**：`castStage` 多返回 `entrance`（`{ref, name, document}`，没有时为 `null`）；`addAssetPackEntrance {packId, name, uploadId}` 添加一条。
- **不在本步**：贴图、逐帧图集、声音、Logo、按卡定制的文字。

设计理由：照搬参考实现的入场演出，只保留不依赖作品素材的那一半。参考实现的入场演出是代码画的，所以这里也存成一份数据文档而不是视频：一套通用图元加时间线，作者只换参数，引擎不认识任何具体作品；文档写入时检查一次，读的时候不再校验。它不挡舞台——舞台始终在下面先画好，白光只是交接；任何一步出问题都是放弃演出而不是卡住。只用卡自己的素材包，是因为入场演出是一张卡的门面，全局素材包给所有卡加同一段不合适；也因此它只有蓝灯和关闭，没有召回。

## 舞台 core（19/N）：音效

正文写到敲门、铃声、玻璃碎裂这类清楚的声响时，导演可以在那一页放一个音效。

- **素材**：素材包多了「音效」一类（`sfx`，内容字段 `media` 音频、`tags`、`volume`），像音乐一样一个文件一条、有蓝灯 / 绿灯 / 关闭，条目页有试听和「音量」。绿灯音效和背景、音乐、物品一样按正文召回，判断模型配置后也补位（每类上限单算）。音效不写进导出的卡文件，留在素材库里。
- **开关**：「舞台设置 › 基础设置」在「BGM」下多一行「音效」，对所有卡生效，默认开（酒馆设置 `stageToggles.sfx`），舞台模式关着时变灰；「›」打开这张卡的音效条目。关掉后导演收不到音效清单和说明，已经安排的音效不再播放，正在响的也停下。
- **导演**：本轮有可用音效时，`stage_update` 的 `performances` 多一种 `{at,op:'sfx.play',sfx}`，`sfx` 从本轮上下文的 `sfx` 清单复制名称；同一页可以放几个不同的音效，同一个只放一次；系统提示多一句什么时候放。没有可用音效时，工具 schema、系统提示和本轮上下文都不提音效，和以前逐字相同。音效不是画面效果，不占「每轮上限」，「可用演出」里关掉动作和画面效果也不影响它。
- **播放**：和 3/N 的一次性演出是同一个播放 owner：翻到那一页停留约一秒播一次，跳过、刷新、重开不补播，停留不到一秒就翻走不播。声音经页面唯一的 AudioContext（和 BGM 同一个）按条目的「音量」播放；这一轮的音效提前解码。响起之后翻页不打断，最长 10 秒，再用 0.5 秒淡出；同时最多 6 个，再多的丢掉。「减少动态效果」不影响音效。关闭舞台时全部停下。
- **宿主接口**：`castStage.turns[].performances` 里的 `sfx.play` 多 `audio`（这条素材的媒体租约）和 `volume`（条目音量，没有时为 1）；`castStage` 多 `sfxEnabled`。按名字对当前亮着的音效条目；条目关掉、删掉或「音效」关闭时，这一项只是不播放，存档不改。
- **不在本步**：环境音（20/N）、混音器和按类的总音量、音效分类、随画面效果自动出的声音（如雷声）、履历里的音效记录。皮肤的界面音效（皮肤文档的 `sfx` 字段）是另一回事，不受这一步影响。

设计理由：照搬参考实现的音效播放：一个页面级的一次性播放器，响起后跨页响完、但有时长上限，避免误标成音效的长音频一直响。音效是按页的一次性演出，不是持续状态，所以和物品一样走 3/N 已有的 `performances` 和播放 owner，不另建第二套播放或历史；声音不交给播放 owner 的取消，是因为翻页切断一声敲门很突兀。开关是全局的一行，和 BGM、物品一样，按卡的差别来自素材灯态；没有可用音效时一个字节也不多发。音量只用条目自己的「音量」：上游还没有全局混音设置。

## 舞台 core（20/N）：环境音

雨声、海浪、人群这类属于一个地点或一种天气的背景声，作为舞台状态一直响着，和 BGM 同时存在。

- **素材**：素材包多了「环境音」一类（`ambience`，内容字段 `media` 音频、`tags`、`volume`），和音乐、音效一样一个文件一条、有蓝灯 / 绿灯 / 关闭，条目页有试听和「音量」。绿灯按正文召回，判断模型配置后也补位。环境音不写进导出的卡文件。
- **开关**：「舞台设置 › 基础设置」在「音效」下多一行「环境音」，对所有卡生效，默认开（`stageToggles.ambience`），舞台模式关着时变灰；「›」打开这张卡的环境音条目。关掉后导演收不到环境音，正在响的立刻停下。
- **导演**：环境音是持续状态，和 `music` 一样：`stage_update` 多一个 `ambience`（清单里的名称，或 `null` 停止），省略即保持；本轮上下文有 `ambience` 清单，`state.ambience` 是正在响的那个。只有本轮有可用环境音、或者正有一个在响（让导演能停掉它）时，工具、系统提示和上下文才提到环境音；否则和以前逐字相同，舞台状态里也没有 `ambience` 这一项（停掉后同样移除）。正在响的条目被关灯、删除或「环境音」关闭时，导演看到的是安静，这一轮记下停止；之后再打开也要等导演重新选。
- **播放**：用 BGM 的播放器（10/N 的循环、条目音量、交叉淡入淡出）另开一路，接在页面唯一的 AudioContext 上，所以和 BGM 同时响。只在全屏舞台打开时播放：跟随舞台状态跨页、跨轮持续，换成别的环境音时交叉淡入，导演停止或条目关灯时 1.2 秒淡出；关闭舞台、关掉「环境音」或「舞台模式」、跳过时立刻停。刷新后打开舞台从状态恢复播放（一次性演出不补播）。同一条目续租的地址不会重播。
- **宿主接口**：`castStage` 多 `ambience`（和 `music` 同形：`key`、`identity`、`name`、`url`、`volume`；没有时为 `null`）和 `ambienceEnabled`。
- **不在本步**：多层环境音同时混合、混音器和按类的总音量、聊天界面里播放环境音、环境音的手动选择面板。

设计理由：环境音和 BGM 一样是持续的舞台状态，所以走同一套增量（省略保持、显式 `null` 才停），不进按页的一次性演出；循环播放、淡入淡出和条目音量已经由 BGM 的播放器实现，这里只是再开一路，而不是另写一个引擎。它只在舞台上响，是因为环境声描述的是舞台上的场景，聊天界面没有场景；BGM 在聊天里继续是 10/N 的既有行为。没有可用环境音时一个字节也不多发，对旧对局和没有环境音的卡零影响。

## 舞台 core（21/N）：配音（上）：Fish 协议渠道

Fish Audio 云端和自己部署的同协议服务用同一个渠道「Fish 协议」，按地址区分，不分云端 / 本地两种。

- **合成**：`POST {服务地址}/v1/tts`，JSON `{ text, reference_id, format: 'wav' }`，`model` 放在同名请求头里。声音（默认声音、旁白声音、每个人物在「舞台素材」里的声音）填参考声音的 ID：Fish Audio 的声音模型 ID，或自建服务上参考音频的名字（一个名字可以对应服务上的多段参考音频）。Fish 不按情绪区分缓存。
- **Key 选填**：留空时请求不带 `Authorization`；填了就发 `Bearer`。Key 只属于保存它时的地址：改了地址、没重填时不报错，新地址照常请求，只是不带旧 Key。
- **模型发现（可选扩展）**：服务可以回答 `GET /v1/info` → `{ models: [{ id, label? }], capabilities: { prepareVoice?: boolean } }`。「配音」页按保存的地址读它，把模型列成「模型（选填）」的候选；模型留空时合成用清单的第一个。回答按地址和 Key 记住；`404` 表示服务不提供，照常按填写的模型（或服务默认）合成；其他失败下次再问。这不是 Fish 官方接口，是给自建服务的约定。
- **预热（可选扩展）**：只有 `/v1/info` 声明 `prepareVoice: true` 时，全屏舞台在配音开着时打开，宿主为这张卡的人物声音和旁白声音各发一次 `POST /v1/warm`（`{ reference_id }`，同样的 `model` 头与鉴权）。不等预热结果，预热失败不影响之后合成这句。没声明就从不请求。
- **配音关着**：不合成、不预热，舞台和台词行不向服务发任何请求。导演完全不知道配音：人物的声音和配音设置都不进导演的工具、提示和上下文（单元测试按字节比较）。
- **宿主接口**：`speech.present()` 的渠道多 `keyOptional`、`discovers`、`prepares`；RPC `speechServiceInfo({ provider })` 返回 `{ models }`，`speechPrepare(sessionId)` 返回 `{ prepared }`。
- **不在本步**：随卡携带的参考音频（每个人物上传几段录音和文字，合成时内联发送）、试听授权与费用确认、缓存清理、流式播放、语音指示 / 情绪标签。

设计理由：配音的渠道、每个人物按渠道的声音、缓存和台词行 / 舞台播放上游已经有了，缺的是一个能接自建服务的通用协议。Fish 的 `/v1/tts` 是云端和常见自建服务共有的形状，所以只加一个渠道，不按地址或模型名猜「这是本地」；服务自己能做什么（列模型、预热）由它在 `/v1/info` 里说，没说就当不支持。Key 选填是因为本机或局域网服务常常不鉴权，不带 Key 的请求不该带一个空的 `Authorization`。

## 舞台 core（22/N）：配音（下）：随卡参考音频

声音克隆类的配音服务只要人物本人的几段录音和它说的原话，就能用这个声音说每一句。同人创作里的人物，服务商不会有现成的声音，所以人物可以自己带参考音频，跟着人物卡走。每个人物有一个「配音来源」：在配好的渠道里选一个；「Fish 协议」提供两种，**声音 ID**（服务上的声音 `reference_id`）和**声音克隆（参考音频）**（人物自己的录音），后者就是这个列表里的一项。

- **配音来源**：人物的 `voiceSource: { provider, clone? }`。`{ provider: 'openai' }` 是那个渠道和人物在那里的声音（`voices[渠道]`，没填用那个渠道的默认声音）；`{ provider: 'fish', clone: true }` 是用参考音频克隆。没有 `voiceSource` 的人物用「配音」页里在用的渠道。「配好的渠道」：浏览器朗读、插件渠道，以及在「配音」页保存过、必填项和 Key 都齐的渠道（`present()` 的渠道带 `configured`）。选了哪个就用哪个：不看录音有没有、另一边填没填，也不自动切换。
- **存放**：参考音频在这张卡的角色素材里（`cast.json` 人物的 `voiceReferences: [{ file, text }]`，音频和立绘一样按内容命名存在 `files/`）。WAV、MP3、OGG、FLAC（按文件头认，不看扩展名），原文 1–500 字；一个人物最多 8 段、合计 8 MB，因为每句都要带上它们。参考音频是渠道用的数据：只有选了声音克隆才用到。
- **界面**：「舞台素材」里每个人物一行，配音开着时有「配音来源」下拉（默认 / 配好的渠道 / Fish 协议 · 声音克隆（参考音频）），后面是这个渠道的声音输入框和「🔊」试听。选了声音克隆时，下面多一块：已有的几段（原文 + 删除），先写原话再选文件；还没有录音时这一块写明缺什么。上传、删除录音都不改配音来源。删掉的那段没有别处引用时文件一并删除。
- **没有录音的声音克隆**：不合成，也不用声音 ID 代替；朗读时报错「「人物」的配音来源是「Fish 协议 · 声音克隆（参考音频）」，还没有参考音频：请在「舞台素材」里为它上传参考音频，或换一个配音来源」（显示在错误记录里）。选的渠道没配好或已不在时同样报错，不换别的渠道。
- **合成**：声音克隆时，`POST /v1/tts` 的请求体是 MessagePack（`content-type: application/msgpack`）`{ text, references: [{ audio, text }], format: 'wav' }`，`audio` 是音频原始字节（bin），不带 `reference_id`。声音 ID 的请求是 JSON，带 `reference_id`。旁白只用「配音」页渠道的旁白声音。参考音频只发给「配音」页保存的服务地址。
- **缓存**：用通用的合成缓存。声音克隆时，缓存键里是这几段参考音频（每段的存储名就是内容哈希，加上原文）：加、删、改一段都会重新合成。其他来源的缓存键里是声音。
- **预热**：舞台打开时只预热用「配音」页渠道声音的人物；声音克隆没有 `reference_id` 可预热。
- **随卡导出、导入**：CHARX 导出把音频写成卡里的文件，`extensions.dsh_tavern.cast.characters[]` 带 `voiceReferences: [{ audio: 'embeded://…', text }]` 和 `voiceSource`；没有参考音频的人物，导出里不写 `voiceReferences`；只有参考音频的卡也会导出成 CHARX。导入（CHARX、DSH 人物卡、卡包）在存进角色素材时按上传的规则校验一次，不合格的那段跳过，导入结果里计 `references` / `skippedReferences`；配音来源照原样导入。
- **接口**：RPC `castAddVoiceReference({ name, text, data })`（`data` 为 base64）、`castRemoveVoiceReference({ name, file })`、`castSetVoiceSource({ name, provider, clone })`（`provider: ''` 回到默认）；角色素材的人物带 `voiceReferences: [{ file, text }]` 和 `voiceSource`。
- **导演**：参考音频和配音来源都不进导演的工具、提示和上下文（单元测试按字节比较）。
- **不在本步**：其他渠道用参考音频、插件接口写参考音频、在页面里试听原始录音、试听授权与费用确认、缓存清理。

设计理由：一个人物只有一个声音，所以「配音来源」是一个选择，不是每个渠道各一套开关；渠道提供几种说话方式就列几项，Fish 的声音克隆只是其中一项，以后别的渠道支持参考音频也照此加一项。参考音频是给声音克隆类后端准备的渠道数据，让没有预设声音的人物（同人创作里很常见）也能用本人的声音说话；放进人物素材，卡分享出去对方接任何同协议服务就能听到同一个声音。不自动切换、不悄悄回退：玩家选了什么就用什么，缺什么就说出来，修起来只要一步。存放和立绘一样按内容命名，导出用 CHARX 里的 `x_dsh_cast` 文件，没有第二套存储或格式；字段形状就是 Fish 内联参考的 `{ audio, text }`。用 MessagePack 是因为 Fish 的内联音频是二进制字段，JSON 只能换成 base64 字符串。编码器只有十几行，只写这种请求用到的类型，不加依赖。

## 舞台 core（23/N）：CONFIG

参考实现的舞台 CONFIG 和它的混音层，取上游现在就有东西可调的那一部分：声音多响、自动翻页多快，由听的人自己决定。

- **入口**：控制栏的「声音」（喇叭图标）打开 CONFIG 的「声音」页；图标同时说明整体状态：全部能听到、部分静音（喇叭少一道波）、全部静音（喇叭带 ×），名字跟着写「声音（已静音）」「声音（部分静音）」。CONFIG 记住上次看的分类，页面刷新前重开回到它。
- **CONFIG 画面**：压暗的舞台上一张不透明的设置页，标题「CONFIG 设置」，左侧分类「声音 SOUND」「文字 TEXT」，右上角 ✕。Esc、✕ 或右键关闭，焦点回到打开它的按钮；开着时焦点留在里面，舞台的翻页键和 Esc 离开舞台都不起作用，**自动翻页暂停**，关上后这一页重新开始等待。手机（宽 ≤ 640，或横握的矮触屏）换成铺满的紧凑布局：标题一行，分类横排，每行标签在上、控件在下。只用舞台的 UI 令牌（`--gal-ui-*`，由皮肤给）画，悬停、选中、滑轨由它们派生。
- **声音 › 音量**：总音量、配音、背景音乐、音效、环境音五层，每行一个静音键、滑条（0–100）和数值；配音一行末尾「▶」试听当前这一句（这一页没有配音时变灰）。静音保留滑条的值，取消静音回到它；拖动一条静音的滑条即取消静音。
- **声音 › 配音倍速**：0.8×–2×（步长 0.1），所有配音按这个倍率播放、音调不变；舞台和聊天里的朗读都生效，正在播放的这一句立即变速。
- **文字 › 阅读**：「自动阅读速度」0.5×–3×（步长 0.1）、「自动模式等待」0–3 秒（步长 0.1 秒）。等待是配音念完后的停顿；没有配音的页按字数的阅读时间加上（等待 − 默认等待）；两者再除以速度。配音总是念完，不加速、不截断。
- **默认值就是之前的样子**：五层都是 100、不静音，配音倍速 1.0×，速度 1.0×、等待 0.4 秒（念完后 0.4 秒；无配音页按字数，至少 1.5 秒、至多 10 秒）。不打开 CONFIG 的玩家听到、看到的和以前一样。
- **混音**：页面唯一的 AudioContext 上，BGM、音效、环境音各自先进本层的增益，再进同一个总音量增益；播放器只多一个可选的 `output`，循环、淡入淡出和条目自己的「音量」都不变。一层听到的响度 = 条目「音量」× 本层 × 总音量。改变时增益在几毫秒内平滑过去，正在响的声音立刻跟着变。配音是浏览器播放的音频（或系统朗读），音量按 配音 × 总音量设；系统朗读从下一句起生效。BGM 在聊天里也按这组音量；插件音乐（`tavernUi.playMusic`）仍由它自己的「♪ 音乐」开关管。
- **保存**：只记在本机浏览器（`localStorage` 的 `dsh-tavern-stage-audio`：每层的值和静音分开存；`dsh-tavern-stage-reading`：`autoWait`、`autoSpeed`、`voiceRate`），读入时按范围和步长收一次。不写存档、卡或酒馆设置，对所有局通用。
- 不改宿主 RPC、存档、提示词、导演或插件接口。
- **不在本步**（之后各自加入）：皮肤自己的 CONFIG 外观（皮肤文档的 `config` 字段）、「界面音效」一层（上游还没有界面音效）、「文字」页的文字速度和预览（上游还没有逐字显示）、字体和字号、「画面」页（本卡皮肤、顶栏按钮、特效质量、帧率、减少动态、光敏保护）、「模组」页、响度归一化和配音时压低 BGM、音效试听。

设计理由：这是参考实现的 CONFIG 和混音器本身，不是另一套设计：模块边界、分类、文案、入口和状态形状都照搬（参考实现的 CONFIG 画面、混音行和「声音」入口、舞台音频状态、阅读节奏），只在上游缺依赖的地方改：滑条用原生 range、说明写在控件下面、试听只有配音、音量默认 100（参考实现另有响度归一化，默认留了余量）、节奏默认是上游原来的 0.4 秒和按字数等待。音量和速度是听的人的习惯，跟设备和耳机走，不跟卡走，所以只记在本机；放在舞台上，是因为只有边听边调才调得准。每层一个增益接在播放器和输出之间，播放器本身不改，不另写第二套播放；一个总音量管所有层，想让所有声音安静只要按一次。CONFIG 开着时暂停自动翻页，和参考实现一样：正在调设置的人不该错过下一句。

## 舞台 core（24/N）：履历

参考实现的舞台履历（BACKLOG），取上游现在就有数据的那一部分：舞台以前只能在最新一轮里退回上一句，现在可以翻回读过的每一页。

- **入口**：控制栏的「履历」、键盘 L、在舞台上滚轮向上。打开时舞台的文字框、控制栏和输入框隐藏，**自动翻页暂停**（和 CONFIG 一样），舞台的翻页键不起作用。
- **画面**：压暗的舞台上一张居中、不透明的阅读页，标题「履历 BACKLOG」，右上角 ✕。打开时最下面一行就是当前这一页，列表拿到键盘焦点（方向键、翻页键滚动）。Esc、L、✕、右键，或滚轮向下滚到底再向下，关闭；用按钮打开的，关闭后焦点回到「履历」。关闭它的那一下滚轮不会顺带翻页。只用舞台的 UI 令牌（`--gal-ui-*`）画；手机（宽 ≤ 640）列宽 94%、头像缩小。
- **内容**：舞台已经读到的轮次（castStage `turns`，最近 5 轮），每轮一条「第 N 轮」分隔线，最新一轮标「· 本轮」，且只列到当前这一页，没读到的页不出现。台词一行是说话人的头像（这一句情绪的头像）、名字和正文，名字后面是聊天里同一个「朗读这句」（配音开着时才有），点它重念这一句（念引号里的话，和舞台一样），不跳页、不关履历；旁白占整行、用次要墨色，没有头像、名字和朗读。
- **跳页**：最新一轮的每一行可以点（或 Tab 到它按 Enter / 空格），舞台回到那一页、自动翻页关闭、履历关闭；当前这一页的那一行点了就是回到舞台。更早的轮次只读。
- **长列表**：只渲染看得见的行和上下各 20 行，量过的行用实际高度；新的一轮到来、最早一轮移出时，正在看的那一行留在原处。
- **滚轮**：舞台上滚轮向上打开履历，向下翻到下一句；一次手势只翻一页，触控板的小增量累计到一格再算。
- 不改宿主 RPC、存档、提示词、导演或插件接口；履历只读舞台已有的数据，不写正文、变量或提示词。
- **不在本步**（之后各自加入）：皮肤自己的履历外观（皮肤文档的 `backlog` 字段：列表、气泡、横幅等版式，角色样式，画出来的关闭键和滚动条）；玩家每轮的输入（上游舞台拿不到聊天快照）；比舞台最近 5 轮更早的轮次（滚到顶时向前分页读取）；跳到更早一轮的页（上游舞台只在最新一轮里翻页）；物品、音效等演出在履历里的记录行；「回到最新」按钮；履历选段导出。

设计理由：这是参考实现的履历本身，不是另一套设计：行的结构（轮分隔、当前页标记、只列到当前页）、虚拟列表和测量、关闭方式、焦点和文案都照搬，只在上游缺依赖的地方改：朗读用聊天里已有的「朗读这句」，头像和名字颜色用角色素材的头像和名字色相，内容是舞台已经读到的最近几轮。履历只读舞台已有的数据，所以它不改任何存档；开着时暂停自动翻页，和 CONFIG 一样，正在回看的人不该被翻走。

## 舞台 core（25/N）：逐字显示

参考实现的打字机效果和 CONFIG 的「文字速度」：舞台的文字框以前整句一下子出现，现在逐字打出，快慢由读的人自己定。

- **逐字**：每一页的这句话按「文字速度」一个字一个字出现（按字素算，一个带修饰的表情或带附加符号的字母是一步），刚出现的字淡入并稍稍上浮（减少动态时只淡入）。句号、问号、感叹号、省略号和换行后多停 5 步，逗号、顿号、冒号、分号后多停 2 步，破折号后 1 步；闭引号（。」）跟着它前面的句末一起停，连在一起的标点只在最后停一次。整句从一开始就排好版，没出现的字是透明的，所以打字时不会重新换行，读屏软件读到的是整句。
- **翻页**：点舞台、→ / 空格 / Enter、滚轮向下：控制栏的「›」：这句还在打就先打完，再按一次才翻页。皮肤的翻页提示等整句出完才出现。
- **自动翻页**：等这句打完再开始等待（念完配音或按字数），和 CONFIG / 履历开着时一样。
- **整句直接出现**：「跳过」、重新打开舞台回到的那一页、回退后重读、从履历跳到的那一页、插件的舞台画面，以及文字速度拉到最快（0）。
- **CONFIG › 文字**：「阅读」一组第一行「文字速度」，左慢右快，最右「瞬间」；默认 28 毫秒每字，范围 0–80、步长 2，和其它阅读节奏一样只记在本机（`textSpeed`）。下面一块「预览」用当前设置逐字打一句示例，打完按自动模式的等待停一会儿（末尾一枚翻页三角），再重新打；改任何一个阅读设置都立刻从头再打。
- 不改宿主 RPC、存档、提示词、导演或插件接口。
- **不在本步**（之后各自加入）：皮肤自己的文字出现方式（皮肤文档 `textFx` 的分步跳字和逐字音效）、旁白逐行淡入、正文流式到达时边到边打、字体和字号、跳过改为逐页快进（按住 Ctrl）。

设计理由：这是参考实现的打字机本身，不是另一套设计：字素切分、标点停顿表、透明的后半句、只有正在淡入的字单独成节点、第一次点击先打完、自动翻页等打完、CONFIG 的滑条方向和文案、预览都照搬，只在上游缺依赖的地方改：计时用浏览器的定时器（参考实现另有窗口在后台时暂停的前台时钟），没有皮肤的分步跳字和流式正文，所以只留匀速淡入这一种。整句先排好版，是为了打字时不跳行；第一次点击先打完而不是直接翻页，是因为读得快的人只想看全这一句，不该因此错过它。

## 舞台 core（26/N）：分页

参考实现的文字框分页：一句话超出文字框时，以前在框里滚动（打字时后面几行打在框外看不见），现在切成几张「卡」，一张一张读完再翻页。

- **量真实的框**：用舞台文字框本身的样式和宽度（一个看不见的副本）量每张卡放不放得下；一张卡最多 3 行，框放不下 3 行时（手机 375 宽的经典框是 2 行）按框能放的整行数。皮肤把翻页提示接在句末时，每张卡都给它留位置。只量当前页和前后各一页，按「文字 + 宽度 + 字体」缓存；窗口变宽变窄、换皮肤、字体加载完都会重量，量完才画，读到的位置（这张卡从第几个字开始）不变。
- **怎么切**：优先在句末断（句号、问号、感叹号、省略号，连同后面的闭引号），其次逗号、顿号等，再次任意处；卡不以闭标点开头、不以开括号结尾（」！、?!、……、”。不拆开）。括号里的一段放得下就整段留在一张卡上；放不下时每张卡各自补上开、闭括号。除最后一张外每张至少占满框的三分之一；最后一张太短（不到一整张的三分之一）时，同样张数重新均分，但不会因此断在词中间。
- **翻页**：点舞台、→ / 空格 / Enter、滚轮向下、「›」：卡还在打就先打完，再按一次是下一张卡，最后一张之后才翻页。「‹」/ ← 先一张张往回，再到上一页的最后一张。页码（2 / 4）仍按页算；输入框和「›」变灰都等最后一页的最后一张。
- **逐字**：每张卡各自从头打；翻页提示等这张卡打完才出现。
- **自动翻页**：每张卡按自己的字数等待；有配音的页，前面的卡在配音念到这张卡所占的比例时翻（按字数分配，念到哪张显示哪张），最后一张等配音念完再按「自动等待」翻页；系统朗读等拿不到进度的配音，念完后其余的卡按字数等待。翻卡不重新念这句。
- **整张直接出现**：「跳过」落在最后一页的最后一张；重新打开舞台、回退后重读、从履历跳到的那一页落在第一张。之后再翻的卡照常逐字。
- 不改宿主 RPC、存档、提示词、导演、履历或插件接口；卡只是显示，页号、配音、演出、履历都还是按页。插件的舞台画面拿到的仍是整页。
- **不在本步**（之后各自加入）：正文流式到达时已经显示的卡保持不动、皮肤文字框按行数伸缩（`art.textbox.height`）、文字大小、玩家输入页的分页。

设计理由：这是参考实现的分页本身，不是另一套设计：用真实文字框的副本量、最多 3 行、断行优先级和禁则、括号补全、短尾卡均分、按字符位置记住读到哪张、翻卡先打完、往回翻进上一页的最后一张、配音按比例翻卡都照搬，只在上游缺依赖的地方改：上游没有文字大小设置和随行数伸缩的皮肤文字框，所以行数只看框能放几行；上游的跳过是直接跳到最后一页，所以落在最后一张卡上而不是逐张快进。卡只在显示层，因为一页还是导演、配音、演出和履历共同的单位，分页不能改它们。

## 舞台 core（27/N）：皮肤的文字出现方式

参考实现的皮肤分步跳字：皮肤文档必填的 `textFx` 以前只被校验、不起作用，现在舞台按它把字打出来。

- **`type`**（经典和大多数皮肤）：仍是 25/N 的逐字淡入。皮肤写了 `cps` 时按它放慢，但最多慢到读者「文字速度」的 1.2 倍。
- **分步跳字**（`ink`、`pop`、`stutter`、`stamp`、`cut`、`scan`、`scrawl`）：像剪纸动画一样每秒 12 步（60 Hz 下正好 5 帧一步，120/144 Hz 也是整帧），每步出现一小组字（`charsPerStep`）。整句用时仍由「文字速度」决定：读得慢的人得到的是停顿的步，不是更慢的时钟；`stutter` 会犹豫（固定种子，重读一样），但不超过普通速度的 1.2 倍。
- **姿势**：每个字先摆入场姿势、下一步落地（或皮肤自己的 `poses`，1–4 个：位移、旋转、缩放、斜切、模糊、墨色），每个姿势保持整步（`stepFps` 换算成几步），之后并入普通文字。入场墨色是 `flash`（没写就用强调色）；`from` 决定 `stamp` 从上还是从下落；`emphasis`：`jitter` 给每个字一个固定的小偏移（`jitter` 倍），`none` 用正文墨色入场，`ink` 用闪色。原字一直占着行里的位置，摆姿势的是它上面的副本，所以不会重新换行，也不改文字框的滚动。
- **翻页**：和 25/N 一样，第一下先打完（整句立刻是普通文字）；最后几个字落地后才算打完，翻页提示和自动翻页等它。跳过、重新打开、履历跳回、文字速度 0 仍是整句直接出现。
- **安全**：标了 `photosensitive` 的皮肤改为普通逐字（上游没有「光敏保护」开关，按打开处理）。系统「减少动态」时照常分步出现，只是不摆姿势。
- 不改皮肤合同（这些字段早就在）、宿主 RPC、存档或插件接口。CONFIG 的预览仍是普通逐字。
- **不在本步**：皮肤的逐字音效（`sfx` 里的打字音，上游还没有界面音效）、旁白逐行、流式边到边打。

设计理由：这是参考实现的分步跳字本身：12/s 的「一拍二」时钟、以文字速度为预算的步数、姿势按整步保持、字的副本上摆姿势、每种出现方式自带的两个姿势都照搬。时钟对齐到帧而不是按 `stepFps` 字面计时，是因为 8/s 在 60 Hz 上会 7/8 帧交替，看起来像卡顿。只在上游缺依赖的地方改：没有应用内的「减少动态」和「光敏保护」设置，所以前者只看系统设置、后者当作打开；没有界面音效，所以不带逐字音。

## 舞台 core（28/N）：跳过改为快进

参考实现的「跳过」：以前一下子跳到本轮最后一页，中间写了什么读者完全看不到；现在是快进，一张张卡闪过。

- **快进**：每 150 毫秒显示下一张卡（长句的每张卡也一张张过），每张都整张出现、不逐字；60 Hz 下每张停 9 帧，看得见每一张，40 张卡的一轮约 6 秒。翻到下一页时是一次「跳过」访问，和以前的跳过一样不念配音、不播演出和音效。到本轮最后一页的最后一张卡自动停下，输入框出现。
- **两种开法**：控制栏的「跳过」按一下开始、再按一下停（快进时它亮着，`aria-pressed`）；按住 Ctrl 快进、松开就停（先等 160 毫秒才开始，所以 Ctrl+C 这类快捷键、短按 Ctrl 不会跳；输入框里按 Ctrl 不算；已经在最后一张卡时不启动）。开始快进会关掉自动翻页，打开自动翻页也会停掉快进。
- **任何输入都停**：快进时按任何其它键、点任何地方（「跳过」本身除外）、滚一下滚轮，都会停下（按住 Ctrl 的快进在窗口失去焦点或切到后台时也停）；停下它的那一下只用来停，不顺带翻卡。停在哪张卡，那张卡保持整张显示。CONFIG 或履历打开时不快进。
- 不改宿主 RPC、存档、导演、履历或插件接口；快进只是翻卡翻页，和手动翻的路径相同。

设计理由：这是参考实现的跳过本身：固定 150 毫秒一步、控制钮锁定和按住 Ctrl 共用一条快进路径、160 毫秒的启动延迟、任何输入都停且那一下只用来停、到本轮结尾自动停都照搬。快进而不是直接跳，是因为读者想跳过的是等待（逐字、配音、演出），不是内容；每张卡闪过一下，想看的地方随手一按就停在那里。参考实现没有「只跳已读」：每一轮都是现写的，没有已读可言。只在上游缺依赖的地方改：控制钮沿用上游「自动」的写法（名字不变、开着时 `is-on` 与 `aria-pressed`），并且一直可按（在结尾按下立刻停）；计时用浏览器定时器（参考实现另有窗口在后台时暂停快进的前台时钟，上游没有）。

## 舞台 core（29/N）：旁白逐行与旁白带

参考实现的无框旁白：皮肤合同里的 `art.narration`（字号、行距、压暗、位置、字幕带、逐行入场）以前只被校验、不起作用，现在舞台按它画旁白页。

- **只对声明了 `art.narration` 的皮肤**：经典和没写它的皮肤，旁白仍在自己的文本框里；台词页不变。它不需要图片，只有 `art.screen`、没有 `art.textbox` 的皮肤也生效。设计像素按舞台高度换算（`art.screen`），宽度不够时按宽度（`art.screenWidth`，没写就是 16:9）。
- **屏幕中央**（本页没有图）：不画框、名牌、头像窗、翻页提示和 AUTO 灯，文字居中在 `y`（默认设计屏正中），字号 `font`、行距 `pitch`（手机上至少 17px）；背景和人物压暗到 `1 − veil` 的亮度。
- **旁白带**（本页的物品有图，而且这次访问会播它：翻页或新正文，不含跳过和重新打开）：改用底部一条通栏字幕带，只压暗字幕带自己（`band.veil`），场景保持原来的亮度，图不被字盖住；字号、行距、离底边的距离是 `band` 的 `font` / `pitch` / `bottom`（默认 30 / 43 / 0，压暗 80/255）。一页的版式在这次访问里不变。
- **字与控件**：压暗层是黑色的，所以字是浅色带深色光晕（和字幕一样），不随皮肤的框色；控制栏跟在文字下面、靠右，用同一种墨色。分页不变：一张卡仍最多 3 行。
- **逐行**（`lines`）：旁白的每张卡不再逐字，而是按排版后的视觉行一行行淡入：每行 `fade` 秒，后一行晚 `stagger` 秒，从下方 `rise` 设计像素升起。行在字体就绪后量，文字、字体或宽度变化时重量，不在动画帧里量；重量不重新计时。最后一行淡入完才算打完，翻页和自动翻页等它；第一下点击先全部显示。跳过、重新打开、履历跳回、文字速度 0 和系统「减少动态」时整张直接出现。
- **跳过中**不切换版式：快进时旁白留在文本框里，每 150 毫秒一张卡不会在压暗和字幕带之间来回闪；停下的那一页恢复。
- 不改皮肤合同（这些字段早就在）、宿主 RPC、存档、导演、履历或插件接口。
- **不在本步**：皮肤自己画在舞台上的按钮（旁白页仍用控制栏）、文字卡、手机等其它占画面的演出触发字幕带、旁白带在流式正文中的保持。

设计理由：这是参考实现的无框旁白本身：只对声明了 `art.narration` 的皮肤生效、两种版式由舞台按「本页有没有图」决定（皮肤只给数值，不自己推断物品或演出）、一句话内版式不变、跳过中不切换、字幕式的墨色、逐行的量法和时钟都照搬。两种版式一起搬，是因为居中的旁白会盖住物品的图；只接 `lines` 而不接版式，`font` / `pitch` / `veil` 就仍然无效。只在上游缺依赖的地方改：上游会占画面的只有物品的图（参考实现还有 CG、手机和带图的演出）；上游没有应用内的「减少动态」开关，只看系统设置；计时用浏览器定时器。

## 舞台 core（30/N）：正文模型直接写说话人

参考实现的对白格式：说话人由正文模型在写台词时一并写出，代替后台结算的引号标注（见「地基：对白格式」）。

- **提示词**：参考实现的对白格式说明与说话人名单，原样搬来；只把差分换成上游的 28 个情绪中文名，所有人物共用一组，名单外的人物也从里面选。经 Context Planner 的正文计划给出，和人物卡系统指令更新一样作为更新消息送达：内容不变就不重发。
- **解析**：参考实现的行解析，宿主和浏览器共用一份。舞台的页：一行气泡就是那个人的一页台词（`kind: 'line'`、`speaker`、`emotion`，心声加括号），页号仍按非空行；导演读到的这一页是「名字：台词」。
- **聊天**：正文写完后，每行气泡是一个说话人行（复用对话头像的行和朗读按钮）；生成中是「名字：“台词”」。
- **删除**：结算里的 `cast_submit` 工具、「本轮台词」说明和提交校验；只开「对话气泡」时不再为它跑后台结算。旧轮次的已存标注照常读取，引号匹配的显示留到流式说话人行一起改。
- 不改存档、导演工具、舞台运行时或插件接口的形状。

设计理由：后台标注要等正文写完、再跑一次结算，所有气泡才一起出现。同一张卡、同一段开场、同样 4 条输入的实测（正文与结算都用同一个模型）：首个说话人行平均在按下回车后 32.1 秒出现（20.1–41.9 秒），其中正文写完后还要再等 4.6–9.0 秒；每轮多 2 次请求、平均多 $0.053（$0.032–0.082），而且结算会话跨轮累积，越玩越贵；路人喊的话漏标 3.3 句/百句；一句台词嵌在旁白里时，整段旁白都画进了说话人行。正文直接写说话人后，没有额外请求，只多出标记的输出 token（实测每轮 ≤ $0.013），漏掉说话人 0 句；说话人行在正文写完时就出现。参考实现边写边出说话人行，首个气泡平均 4.9 秒（3.8–6.2 秒）；流式说话人行是下一步，本步先把说话人交给正文模型。

## 舞台 core（31/N）：皮肤决定旁白的样子

29/N 里旁白的墨色、压暗颜色和版式还写死在舞台里（浅色字带深色光晕、黑色压暗、按「本页物品有没有图」选屏幕中央或字幕带）。现在都由皮肤声明；不写的皮肤保持 29/N 的样子。

- **版式** `art.narration.layout`：
  - `box`：旁白留在文本框里，和没写 `art.narration` 的皮肤一样（框图 `art.textbox.images.narration`、墨色 `textStyle.narration`），不压暗；写了 `lines` 仍逐行入场；
  - `free`：总是屏幕中央、无框、整屏压暗；
  - `band`：总是底部字幕带，场景不压暗。
  - **不写**：舞台的规则不变——屏幕中央，本页物品有图且这次访问会播它时改用字幕带。
  - **和物品图的关系**：只有不写 `layout` 时物品图才参与选择。写了就以皮肤为准：`free` 时物品照常出现在压暗层上面（不被压暗，但文字可能压在图上），`band` 时没图也用字幕带，`box` 时物品和台词页一样出现在框上方。快进中、台词页一律保留文本框，不受 `layout` 影响。
- **墨色** `art.narration.ink`（无框旁白的字和控制栏，默认 `#fbf8ff`）与 `art.narration.halo`（光晕：对象同 `art.textbox.halo` 的 `{x, y, blur, color, alpha}`，按设计像素换算成一层阴影；`false` 不要光晕；不写是默认的深色三层光晕）。控制栏的悬停与按下底色取同一墨色的 14% / 24%。
- **压暗颜色** `art.narration.veilColor`（默认黑色），屏幕中央用 `veil`、字幕带用 `band.veil` 的强度。屏幕中央的压暗是盖在背景和人物上的一层，黑色时与原来的 `1 − veil` 亮度相同。
- **框内旁白的墨色** `textStyle.narration`：任何皮肤都可写，只在文本框里的旁白生效（包括 `box` 版式和快进中的旁白），对框底色至少 7:1。
- **校验**（写入皮肤时，和其它皮肤颜色一样）：无框旁白的墨色对它可能站上去的每一种底都至少 4.5:1——版式会用到的每个压暗（屏幕中央 `veil`、字幕带 `band.veil`，默认 80/255）按 `veilColor` 盖在纯黑和纯白场景上；有光晕时再把光晕按它的 `alpha` 盖在这些底上，以光晕为底。`box` 版式没有压暗，不检查。所以深色字配浅色压暗时要写 `halo: false` 或浅色光晕，压暗也要够厚。已有皮肤的默认值（浅色字、黑色光晕）总能通过。
- 不改宿主 RPC、存档、导演、履历或插件接口；JSON Schema 镜像同步加了这些字段。

设计理由：引擎只提供能力，具体样子由皮肤的数据决定；皮肤作者能合理想选的东西不应写死成引擎里的是或否。字段名沿用已有的：`art.narration` 与它的 `--art-nar-*` 令牌、框图 `art.textbox.images.narration`、框内墨色 `textStyle.narration`（参考实现里已有，同样 ≥ 7:1）；版式词用 `box` / `free` / `band`，舞台根上的 `data-narration-layout` 仍是 29/N 的 `screen` / `band`。对比度沿用文本框外底板的检查法（盖在纯黑与纯白场景上），因为旁白背后是任意场景。

## 舞台 core（32/N）：边生成边出说话人行

30/N 把说话人交给正文模型后，聊天仍要等整段写完才把「名字：“台词”」换成说话人行。现在和参考实现一样边流边出。

- **生成中**：同一份行解析按「最后一行可能没写完」读正在流的正文。一行气泡写到 `[` 后的第一个字就是那个人的行，台词边写边长；没写完的心声先不加右括号。还没写到台词的末行（`@bub`、`@bubble:handle|名字|差分|`）什么也不显示，不露标记。正在写的行没有朗读按钮，写完才有。
- **写完时**：行的位置和样子不变，不再整段重排。
- **开关与头像**：正在生成的一轮只向宿主要一次本局的「对话气泡」开关和人物（`castForTurns`，不带轮次）；宿主答复前和关着时仍是「名字：“台词”」。正文提交后的刷新保留上次的答复，说话人行不闪。
- **删除**：聊天里按已存标注匹配引号、把整段画成说话人行的显示。聊天只从正文读行；30/N 之前的轮次在聊天里按旁白显示，已存标注仍给舞台、插件（`getCast`、`registerTurnView` 的 `lines`）和编辑携带。
- 不改宿主 RPC、存档、舞台、配音或插件接口的形状。

设计理由：参考实现实测，按下回车后首个说话人行平均 4.9 秒出现（3.8–6.2 秒），与正文长短无关；等整段写完则要正文的全部时长。一句话的说话人在它的开头就已写出，没有理由再等。按引号匹配标注的显示会把整段旁白画进说话人行，又只剩旧轮次在用，留着就是第二套显示。

## 舞台 core（33/N）：双语配音

到 32/N 为止，朗读念的就是显示的台词：用日语声音的人物只能按着中文台词念。现在和参考实现一样，正文模型为这样的人物把配音要念的话写在同一行里。

- **一条规则**：正文是中文，没有「正文语言」设置。人物的配音语言是中文（或没选）时，正文模型只写一个文字字段，照原样念；是其他语言时写两个字段：中文显示台词 + 这门语言的配音台词。
- **配音语言**：人物自己的声音设置，在「舞台素材」人物的配音来源旁边选（日语、中文、英语、韩语、粤语，以及「其他语言…」：填任意 BCP 47 代码，保存时校验一次）；没选过时显示中文，选中文就存为没选，所以没有单独的「未设置」状态（`effectiveVoiceLanguage`，`bubble-line.cjs`，显示和规则读同一个函数）。角色素材的人物带 `voiceLanguage`（BCP 47 语言代码），只存这一处；没选过时不写。它随卡导出、导入。RPC `castSetVoiceLanguage({ name, language })`（`language: ''` 清除）。
- **对白格式**：配音开着时，配音语言不是中文的人物（按主语言子标签比较，`zh-CN` 算中文；`voiceTranslates`）在名单里带 `[Voice language: Japanese]`，格式里加一节 `<voiced_bubbles>`：这些人物的每行（心声也是）写两个文字字段 `@bubble:handle|name|variant|[显示台词]|[配音台词]`，配音台词是同一句话在配音语言里的自然说法，写成语音合成不会读错的样子。其余人物（没选过配音语言，或选了中文）照旧用一个字段。没有人需要另写配音（或配音关着）时，格式与 32/N 逐字节相同；改了配音语言或配音开关，下一轮按 30/N 的更新消息重发一次。
- **读**：同一份行解析读出第五个字段（`voice`）；显示、导演读到的页和插件的 `lines` 都只有显示台词。配音字段还在生成时只显示显示台词；回复结束时配音字段没写完，这行照常显示、不念。
- **念什么**（`bubbleSpeech`，聊天的朗读按钮、舞台和履历共用）：有配音字段就念它；没有时念显示台词，但说话人的配音语言不是中文时不念（不会用日语声音念中文），也没有朗读按钮。浏览器从随行的人物（`castForTurns`、舞台数据的 `cast`）读配音语言。宿主照旧只合成浏览器送来的那句话。
- 不改渠道的合成参数；各渠道按自己的方式识别文字语言。

设计理由：配音要念的话由写正文的模型一起写出，不必再发一次后台翻译；模型写这句话时知道语气和上下文。语言是人物声音的属性，所以放在人物自己的声音设置里，名单、朗读都读这一处。缺配音字段时宁可不念，也不换成显示台词：用另一种语言的声音念中文，比不念更突兀。

## 舞台 core（34/N）：回合末的选项菜单

参考实现的回合末选项：舞台最后一页以前只有一个输入框，候选项只在聊天侧；现在本轮最后一张卡上出现选项菜单，选一项就是下一轮的输入。

- **同一份候选项**：菜单读写聊天侧的候选项面板（`interactions.candidates`）和同一个候选项任务（`submitCandidateTask`，含宿主的「自动生成候选项」）；舞台不自己发起生成，也不另存一份。舞台里生成的候选项回到聊天里也在，反过来也一样。
- **出现时机**：只在本轮最后一页的最后一张卡上，下一轮正文生成中不出现；履历打开时和文本框一起隐藏。每条回复的菜单只播一次入场动画，翻回来、重开舞台时直接出现。
- **几种状态**（文字和本地一致）：
  - 没有候选项：「生成选项」和「自由输入」；
  - 生成中：文本框里换成等待行（几句短语轮流淡入淡出，两侧各一条细线），「自由输入」暂时收起；
  - 生成失败：「选项生成失败」和「重试」（悬停可看原因），任务被取消时回到「生成选项」；
  - 有候选项：每个行动一条，场景变化也是一条（不加标签，发送时才带「【场景变化】」），最后是「自由输入」。
  - 下一轮正文生成中，文本框里同样是等待行。
- **操作**：点一条、或用 Tab 选中后按 Enter / 空格就发送；每条右侧的 ✎ 把它变成同位置的输入框（原文在里面），改完 Enter 发送、Shift+Enter 换行、Esc 还原；「自由输入」同样就地打开输入框。菜单里的 Enter、空格不翻页。
- **默认样子**：屏幕中央一列通栏的半透明条，两端渐隐，用皮肤的 UI 颜色（`--gal-ui-*`），点选立刻发送；手机上占满舞台宽度。系统「减少动态」时不播动画、立即发送。
- **皮肤的条图** `art.choices`（字段早就在皮肤合同里，现在接上）：每条画成皮肤的九宫格条图（`images.plain`，不可点时 `off`，偶数行 `alt`），聚焦时 `focus` 的图、墨色和位移；`anchor` 决定菜单的垂直中心（`stage` 舞台正中，`above-box` 框图上方的空间中央，或直接写 `center` 设计像素），`x` / `align` / `tilt` / `stagger` / `band` 调位置和倾斜。条图出现时文本框让开；条图点选后等 0.233 秒的点击动画再发送。图片没有全部解码前，整个美术层不启用（和其它 `art.*` 一样）。
- **入场与点选动画** `transitions.choices`（新字段）：`enter` 是条目出现（后一条晚 `stagger` 毫秒）、`leave` 是点选后离开（其它条先走，点中的最后）；各自是 `{ms, ease, delay, stagger, wipe, pose, fade}`，至少有 `wipe`、`pose`、`fade` 之一。`ease` 是命名曲线（`linear` / `out` / `in-out` / `back` / `snap` / `expo-out` / `quint-out` / `emphasized` / `emphasized-out` / `emphasized-in` / `spring`）或四个数的贝塞尔；`wipe` 是遮罩形状（`circle` / `rect` / `diamond` / `triangle` 从中心 `at` 长大，或 `left` / `right` / `up` / `down` 按边擦开）；`pose` 是起点（`dx` / `dy` 百分比、`rot` 度、`scale`）。写了 `leave` 时，发送等到它的 `delay + ms` 之后。不写就是上面的默认动画。
- **等待行** `waitLines`（新字段）：1–64 句、每句不超过 24 个字、不以空白开头或结尾、不换行；不写用引擎的默认等待行。本卡想换等待行时，在本卡皮肤里写。
- **校验**：和其它皮肤字段一样，只在写入皮肤时检查；JSON Schema 镜像同步加了 `transitions` 与 `waitLines`。
- 不改宿主 RPC、存档、导演、候选项任务或插件接口；聊天侧的候选项面板不变。

设计理由：这是参考实现的回合末面板本身：只在最后一张卡、同一套候选项、行动与场景同列、✎ 就地改写、生成中把等待放进文本框、点选后等点击动画再发送、每条回复只入场一次，都照搬，默认外观和动画也沿用参考实现。候选项已经有一条完整的管线（聊天侧面板、后台任务、自动生成），舞台只是它的另一个出口，所以复用而不新写。动画和等待行是皮肤作者会想自己选的东西，所以做成皮肤的声明数据，引擎只提供能力和默认值；`transitions` 先只开放 `choices` 一个界面，以后其它界面按需加。只在上游缺依赖的地方改：等待行在参考实现里是固定的一组，这里成了可替换的默认值；上游没有应用内的「减少动态」开关，只看系统设置。

## 舞台 core（35/N）：导演点名、皮肤来画的画面效果

参考实现的画面效果目录：导演以前只有 `shake-1` 一种震屏，皮肤合同里的 `effects` 只被校验、不起作用。

- **目录**：`screen.play` 的 `effect` 是九个名字之一——`flash` 白闪、`flash-red` 红闪、`blackout` 眼前一黑、`shake-1/2/3` 震屏（小/中/大）、`shock` 冲击（白闪慢慢退去、从中心扩散的一圈波、一次小震屏）、`glitch` 故障、`heartbeat` 心跳（两下暗红暗角和轻微放大）。导演只点名，不给参数；记录里只存名字，播放时才解析。每轮上限、可用演出开关、按页播一次、跳过和重新打开不播，都和 `shake-1` 一样。
- **外观**：`stage-effects.cjs` 是唯一出处，每个名字一份引擎默认值；皮肤的 `effects[名字]` 逐字段合并在上面（字段和写入时的校验早就在合同里：闪光 `{color, peak, in, hold, out, tail, cycles, ease}`，震屏 `{amp, ms}` 或步进路径 `{path, step}` 与 `target`，`shock {flash, wave, waveMs, shake}`，`glitch {ms}`，`heartbeat {color, vignette, zoom, ms}`）。震幅是舞台高度的比例，步进路径按皮肤的设计屏 `art.screen`（没写就是 576）换算。
- **画在哪里**：场景上、文本框下一层效果层（闪光、暗角、冲击波）。震屏移动背景、人物、物品和效果层，文本框跟着动一半；`target: background` 只动背景。用属性 `translate` / `scale` 动画，不覆盖各层自己的 `transform`。插件的舞台样式不画。
- **安全**：闪光一律按光敏保护处理（上游没有开关，按打开）：保留颜色、降低强度，白至多 .5、进出各至少 80 ms，饱和红变暗红、至多 .4，重复合并为一次；全舞台任何一秒内至多开始 3 次闪光，第 4 次不播。变暗（`blackout`）不算闪光。系统「减少动态」时不震屏、不放大、不播故障和冲击波：冲击只留白闪，心跳只留暗角，闪光和变暗照常。
- **提交工具**（只在提交时读一次）：同一个名字的不同写法（大小写、全半角、空格或下划线、少了连字符）、上面的中文名、族名（`shake`/`震屏` → `shake-2`）直接接受，结果里带 `normalized`；近义词（`red-flash`、`explosion` 等）和把效果名写进命令名（`screen.flash`）会被拒绝，并返回一条可以原样重发的 `didYouMean`；都不像时列出九个名字。中文名和近义词不进 schema 和提示词。
- **字节**：工具 schema +81 B，系统提示 +30 B。不改宿主 RPC、存档、皮肤合同或插件接口。
- **不在本步**：冲击波从说话人头部发出（`screen.play` 没有人物字段）、文本框跟着闪光变亮变暗、画面状态 `screen.set`（`effects` 里的 `blur` 等五种）、背景转场 `effects.transition`、心声底图 `effects.thinking`。

设计理由：这是参考实现的画面效果本身：九个名字、引擎默认数值、合并顺序、光敏规则和每秒三次的门、提交工具的两级修正都照搬。只在上游缺依赖的地方改：参考实现在 WebGL 场景里画，这里用 DOM 层和 Web Animations（故障是人物和物品横向撕开加红青分离，背景不动以免露出边缘；冲击波是一圈按实际大小绘制的扩散光环）；没有应用内的「减少动态」和「光敏保护」开关，前者看系统设置、后者当作打开（和 27/N、29/N 一致）；参考实现还有按卡的覆盖层，上游没有按卡的效果表，不带。

## 字体库（舞台 core 36/N 的前置）

皮肤合同的 `font.body` / `name` / `ui` 和字面的 `fallback` 写的是「字体库 id」，但上游一直没有字体库。现在插件自带一个开源中文字体库，按 id 提供字体文件；舞台怎么用它见 36/N。

- **目录**：每个字体家族一个文件夹 `<id>/`，含 `index.json`（`id`、`label`、`family`、`category` 取 `sans|serif|rounded|hand|display`、`files [{weight, style, file, format: "woff2"|"truetype"|"opentype"}]`、`license`、`source`、`coverage`）、字体文件（WOFF2 / TTF / OTF）和许可证全文。插件自带的在 `tavern-plugin/fonts/`；数据目录 `fonts/` 下装了同 id 的家族时整体用装的那份，不混用两边的字重。
- **自带的家族**（都是完整字形，不做子集）：

  | id | 名称 | 字重 | 许可证 | 大小 |
  | --- | --- | --- | --- | ---: |
  | `neo-xihei-screen` | 霞鹜新晰黑 屏幕阅读版 | 400 | IPA Font License 1.0 | 7.3 MiB |
  | `neo-zhisong-screen` | 霞鹜新致宋 屏幕阅读版 | 400 | IPA Font License 1.0 | 11.4 MiB |
  | `resource-han-rounded` | Resource Han Rounded CN | 400 / 500 / 700 | SIL OFL 1.1 | 14.3 MiB |
  | `noto-sans-sc` | Noto Sans SC | 400 / 500 / 700 | SIL OFL 1.1 | 12.2 MiB |
  | `noto-serif-sc` | Noto Serif SC | 400 / 500 / 700 | SIL OFL 1.1 | 16.7 MiB |

  共 61.8 MiB（2 个 IPA 官方原始 TTF、9 个 OFL WOFF2）。IPA 两款逐字节原样分发，不转换或修改，附 IPA 许可证全文；OFL 三款保留 WOFF2 和 OFL 全文。来源、版本和下载摘要见 `tavern-plugin/fonts/README.md`。只收开源许可证允许再分发的字体，商业字体和改过字形的字体不进字体库。
- **接口**：RPC `listFonts()` 返回 `{fonts: [{id, label, family, category, weights, files: [{weight, style, file, format, bytes, url}], url, license, source, coverage}]}`；一个家族的 `index.json` 坏了只隐藏它自己。`GET` / `HEAD /api/dsh-tavern/fonts/<id>/<file>` 只给 `index.json` 列出的字体（WOFF2 为 `font/woff2`、TTF 为 `font/ttf`、OTF 为 `font/otf`，支持 ETag / 304、单段 Range / 206、`If-Range` 和 416）；文件名带内容哈希（`400-<16 位十六进制>.woff2|ttf|otf`）的缓存一年，其余一小时；拒绝路径穿越、编码分隔符、未列出的文件和指向字体库之外的链接。
- 不改存档、皮肤合同或插件接口；字体只在页面用到时才下载。

设计理由：这是参考实现的字体库：同一个目录格式、同一个 RPC 和路由、装的家族优先于自带的。字体文件很大，所以单独成一个 PR，舞台使用放在 36/N。

## 舞台 core（36/N）：舞台用皮肤声明的字体

皮肤合同里的 `font` 早就是必填项，`font.body/name/ui` 和 `font.faces` 也在写入时检查，但舞台一直不读，所有文字都用宿主的界面字体。现在舞台按皮肤的字体声明画字。

- **三个角色**：`font.body` 是舞台正文；`font.name` 是说话人名字（名牌和头像框上的名字）；`font.ui` 是舞台其余文字——控制栏、回合末选项、履历、CONFIG 和它们的控件。`name`、`ui` 没写时跟随 `body`。
- **值**：每个角色写一个 id，是皮肤自己的字面（`font.faces` 的键）或字体库的家族（上一节）。依次试本角色、再试 `body`，用第一个找得到的：字面总能找到；字体库 id 要字体库里有这个家族，没有就跳过这一层。
- **字面**：`font.faces` 以 id 为键，最多 4 个 WOFF2 `{file, weight, fallback?}`，随皮肤条目上传、从皮肤租约按 `weight` 注册（`FontFace`，`font-display: swap`），换皮肤或关闭舞台时移除。可选的 `fallback` 是字体库 id：字面缺的字（例如日文字体遇到简体专用字）先用它，再用舞台字体栈；它与字面一起注册。
- **字体栈**：每个角色最后都接舞台的内置字体栈 `"Noto Sans SC", "Source Han Sans SC", "PingFang SC", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif`。皮肤没有可用的字体时就是这个栈；字体载入前或载入失败时也先用它。
- **经典**：内置的经典皮肤声明 `font: {body: "neo-xihei-screen"}`（霞鹜新晰黑），名字和界面跟随正文。
- 字体库的家族只在舞台用到时注册 `@font-face`，浏览器只下载实际出现的字重。
- 不改存档、皮肤合同或插件接口；宿主只用字体库的 `listFonts` 和字体路由。

设计理由：这是参考实现的舞台字体：同样三个角色、同样「本角色 → body → 内置栈」的顺序、字面优先于同名字体库 id、字面的 `fallback` 紧跟字面，经典的默认字体和内置栈都一样。参考实现另有玩家在 CONFIG 里的本机字体覆盖和电影字幕角色；上游舞台没有这两项，不带。没有字体库这一层时皮肤只能自带字面，所以字体库先单独成一个 PR。

## 舞台 core（37/N）：配音和音效时压低背景

以前配音响起时 BGM 和环境音照常响，台词常被盖住。现在配音或音效响着的时候，比它低的声音层自动轻一些，响完就回来（避让，ducking）。

- **优先级**：配音 > 音效 > 环境音 > BGM。响着的声音只压低比自己低的层；配音和音效同时响时，每层取两者中压得更深的一个，不叠加。
- **默认量（dB）**：配音响时 BGM −4、环境音 −4、音效 −2；音效响时 BGM −2、环境音 −3。压下和回升都是平滑的：配音起音 50 ms、结束后保持 250 ms 再用 200 ms 时间常数回升（翻页间隙里的下一句不会先把 BGM 放上来再压下去）；音效起音 20 ms、保持 50 ms、回升 150 ms。中途反转从当前值继续，不跳变。每次避让在结束后 0.7 秒内回到 0.5 dB 以内。
- **什么算「响着」**：配音从听得到的那一刻（音频开始播放、或系统朗读开始出声）到念完或被停下，合成中的等待不算；舞台、聊天的「朗读这句」和插件的朗读是同一个播放器，都算。音效从第一个开始到最后一个结束（含 10 秒上限后的淡出）。关闭舞台时配音和音效停下，避让随之结束，聊天里继续的 BGM 回到原来的音量。
- **在哪里**：BGM、音效、环境音各自的层增益后面多一个避让增益，再进总音量：一层听到的响度 = 条目「音量」× 本层 × 避让 × 总音量。滑条、静音和总音量的含义不变；配音自己优先级最高，不被压。
- **玩家开关**：CONFIG › 声音 多一组「混音」，一行「自动混音」开关（`role=switch`），不加副标签或说明行，**默认开启**。关闭后各层保持滑条的音量，正在压低的层平滑回升。和音量一样只记在本机浏览器：`dsh-tavern-stage-audio` 里关闭时多一项 `duck: false`，开启时没有这一项（记录和以前逐字相同）。
- **皮肤调量**：皮肤文档的新字段 `duck`（可选），按「触发 → 被压的层 → dB」写，只能写比触发低的层：`{"voice": {"music", "ambience", "sfx"}, "sfx": {"music", "ambience"}}`，每格 −24–0（0 = 不压）。写了的格子盖在引擎默认上，没写的照默认；只在打开的舞台生效，关闭舞台回到引擎默认。例如 `"duck": {"voice": {"music": -10}}` 让对白时 BGM 压得更深。和其它皮肤字段一样只在写入时检查；JSON Schema 镜像同步加了 `duck`。玩家关掉开关时皮肤的量也不起作用。
- 不改宿主 RPC、存档、导演、提示词或插件接口；经典皮肤不写 `duck`。
- **不在本步**：响度均衡（写入时测一次响度、按层目标播放）、界面音效层和它的避让、通话等新声源。

设计理由：这是参考实现的避让矩阵本身：同样的优先级、「只压低比自己低的层、取最深不叠加」、同样的数值和起音 / 保持 / 释放时间，避让增益接在层增益之后，所以滑条只代表玩家的偏好。只在上游缺依赖的地方改：参考实现还有通话和界面音效两个声源，上游没有，不带；参考实现的配音走 Web Audio 的配音层，上游配音是浏览器播放的音频（或系统朗读），所以由播放器告诉混音器「正在出声」，配音不经过避让增益。开关默认开启是主人定的：避让是对白听得清的基本混音，而不是特效。量由皮肤声明而不是写死，是因为不同风格（安静的文艺片、热闹的战斗）想要的压低程度不同。

## 第三步：配音

- **一个全局开关**：「舞台设置 › 基础设置 › 配音」，和「配音」页（也在「设置 › 配音」）顶部的「开启配音」是同一个开关，默认关。打开前要在「配音」页选好渠道并填齐设置。
- **渠道**：浏览器朗读（系统语音，零配置）、OpenAI 兼容 `/audio/speech`（OpenAI、硅基流动 CosyVoice、中转）、GPT-SoVITS（api_v2）、MiniMax T2A v2、火山引擎（豆包语音 V3，APP ID + Access Token，音色按 ID 填，复刻音色用 `icl_` 前缀）、Fish 协议（21/N）；插件可用 `speechProvider` 再加。各渠道分别保存设置，Key 存在 DSH 凭据库，改地址必须重填 Key。
- **声音**：每个渠道有默认声音和旁白声音（旁白留空则不念）；每个人物在「舞台素材」里按渠道单独选声音，跟着人物卡走，换渠道不丢。
- **情绪**：gpt-4o 系列把标注的情绪写成语气要求；MiniMax 映射到它的 7 种情绪；火山引擎映射到它的情感枚举（2.0 音色、1.0 多情感音色才认，其余保留音色默认语气）；插件渠道拿到情绪名自己处理。
- **合成与缓存**：宿主侧合成，按「渠道 + 非密钥设置 + 声音（或人物的参考音频，22/N） + 情绪 + 文字」内容寻址存进 `speech-cache/`，同一句只付费一次；浏览器朗读在浏览器里合成，不经宿主。
- **在哪里听**：带头像的台词行有朗读按钮（念这行的台词，有配音字段时念配音字段，33/N）；配音开着时全屏舞台翻到哪句念哪句，自动播放时念完再翻页；控制栏的「♪」是 BGM 面板。
- **还没做**：缓存不会自动清理；正文写完自动念整轮。

## 插件接口

已开放（见[插件接口](../plugin-api.md)「演出」与 `registerStageView`）：

- 宿主侧：`getCast({ gameId, turn })` 读某一轮当前版本的台词标注；`onCastAnnotated` 标注保存时通知；`getCastAssets({ gameId })` 读角色素材；`speechProvider` 加配音渠道；`synthesizeSpeech` 按人物声音合成一句。
- 浏览器侧：`getStage`、`watchStage` 读舞台数据；`registerStageView` 换舞台画面，Tavern 保留阅读流程，插件失败时退回内置画面；`speak`、`stopSpeech` 朗读。
