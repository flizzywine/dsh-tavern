# 单会话可追溯压缩备忘

> 状态：后续方向，暂不实现。当前先复用 DSH 原生压缩机制，并为游玩／剧本会话使用 Tavern 剧情摘要提示词。

## 当前决定

- 目前只解决单个 Tavern 对话的上下文长度，不建设跨对话长期记忆。
- 不引入 TencentDB Agent Memory 的 Proxy、向量检索或 L0–L3 记忆流水线。
- 卡片模式继续使用 DSH 原生工程摘要；游玩和剧本模式使用剧情摘要。
- 原始 Tavern 对话仍由 `chat.messages` 完整保存，压缩只改变模型看到的 DSH Session Surface。

## 后续目标

参考 TencentDB Agent Memory“高层摘要可以回到低层原文”的体验，为 DSH 原生压缩增加单会话下钻查看：

```text
当前上下文
├─ 压缩检查点
│  └─ 展开被压缩的原始消息
│     └─ 如包含更早检查点，可继续下钻
└─ 近期未压缩原文
```

DSH 已在追加式 Session 日志中保留原始事件，并通过 `compactionId`、`shadowedSeqs` 和压缩范围记录摘要与原文的关系。未来只需建立读取投影和 UI，不应复制一套压缩或存储机制。

## 边界

- 下钻只用于查看、审计和判断摘要是否遗漏，不把展开的原文重新注入模型。
- 权威剧情原文仍来自 Tavern Chat；DSH 事件用于还原压缩时模型实际看到的上下文。
- 多次压缩形成递归检查点，但 UI 默认只展示当前有效上下文，旧层级按需展开。
- 开发前需要验证 DSH 对完整 Session 事件和压缩元数据的稳定读取接口。
