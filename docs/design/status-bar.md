# 回复展示与状态栏兼容

> 状态栏的长期生命周期与性能改造见[持久化状态视图 Runtime 改造方案](persistent-status-view-runtime.md)。本文继续定义回复投影与状态栏兼容语义。

目标是无缝承接 SillyTavern 人物卡的前端表现，同时把格式、代码和前端生成从正文写作中逐步拆出。用户只需导入人物卡并开始游玩，不需要选择内部处理方式。

## 统一展示接口

原始回复始终作为内部源文本保存。展示模块接收原始回复和人物卡携带的展示规则，将正则命中的片段移出可见正文，返回剩余正文、可渲染区块和诊断信息：

```text
projectReply({ rawText, cardPresentation })
  -> { bodyText, blocks, warnings }
```

前端只消费这一个接口，不关心结果来自正则还是独立生成。解析失败时必须完整显示原文；任何展示结果都不能覆盖内部源文本或成为权威剧情状态。命中成功后，命中片段只出现在独立展示区，不再重复出现在可见正文中；后台连续性仍读取内部源文本。展示区只接收正则替换产物，不复制未命中的正文；如果多条正则累计覆盖整轮正文，则视为本轮解析失败，撤销全部展示结果并保留完整原文。

## 第一阶段：正则兼容

先支持常见酒馆标签、状态块、选项和人物卡携带的可兼容正则，将模型已经输出的格式转换成美观 UI。识别成功就渲染，失败就显示完整原文。生成的 HTML 必须过滤，人物卡中的任意脚本不能直接执行。

正则来源是可编辑人物卡工作 raw 中的 `data.extensions.regex_scripts`（V1 卡为 `extensions.regex_scripts`）。原版 PNG/JSON 只用于恢复；UI 和展示模块通过人物卡投影读取正则，不直接修改原版，也不依赖缩水后的字段副本。

这一阶段优先解决生态兼容和立即可用，不要求正文之外再增加模型调用。正则只属于展示 Adapter，不负责保存状态，也不能为了前端要求继续扩大正文提示词。

## 第二阶段：独立生成

后续在人物卡导入或准备阶段，由独立任务分析卡片、正则和脚本，生成并缓存该卡的展示 Adapter。游玩时直接使用缓存结果，不让正文模型同时承担故事创作、格式控制和前端代码生成。

两阶段使用同一个展示接口，自动回退顺序为：

```text
卡片专属展示 Adapter
  -> 通用正则 Adapter
  -> 未命中的可见正文 + 内部原始源文本
```

## 权威状态

人物姿势、地点、时间等权威状态仍由正文后的独立状态结算维护，并随正文替代和回退恢复。正文中的状态块可以用于兼容展示，但不能反向覆盖已经校验的权威状态。这样既保持酒馆人物卡的原有观感，也不让正文重新承担状态协议。
