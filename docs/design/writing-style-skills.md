# 卡片工作台文风 Skill 设计稿

> 状态：Tavern 专属、卡片模式限定的 DSH 原生 Skill 加载机制、通用创建 Skill 和文风抽取 Skill 已实现；文风库、导入、选择、直接应用和 UI 仍是待实现设计。

## 1. 目标

为卡片 Agent 提供可复用的文风参考。用户可以选择内置文风、导入自定义文风，或让 Agent 根据样文创建新文风 Skill。

文风 Skill 只影响当前卡片工作台中的分析、草拟与改写，不直接绑定人物卡，不进入游玩模式，也不自动修改人物卡。用户明确要求保存人物卡时，仍由现有卡片修改流程完成。

## 2. 核心原则

### 2.1 渐进加载

卡片 Agent 默认只获得文风 Skill 的目录：

- Skill 名称
- 一句话简介
- 来源：内置或用户自建

只有用户或 Agent 明确选中某个 Skill 后，系统才加载它的完整正文。当前对话最多启用一个文风 Skill；切换时用新 Skill 替换旧 Skill，关闭时停止注入。

这可以避免安装几十个 Skill 后，所有完整规则同时进入上下文。

### 2.2 制作辅助，不是人物卡字段

Skill 是卡片 Agent 的临时工作方法，不属于 SillyTavern 人物卡格式。选择 Skill 不会：

- 向人物卡写入 Skill 名称或路径。
- 自动改变 `description`、`first_mes` 等字段。
- 改变游玩 Agent 的回复风格。

如果用户希望人物卡长期体现某种文风，卡片 Agent 应把必要规则提炼进合适的人物卡字段，并按正常修改流程保存。

### 2.3 与全局 DSH Skill 隔离

文风 Skill 使用 DSH 原生 `SKILL.md` 格式、注册表和按需加载工具，但通过 Tavern preset 的隔离文件提供方发现，不扫描 DSH 的项目目录或用户全局目录。

原因是用户的全局 Skill 还可能包含编程、办公等能力。卡片 Agent 不应看到这些无关目录，也不应让文风 Skill 获得通用工具或额外权限。

## 3. 用户流程

### 3.1 使用已有文风

1. 用户在卡片模式打开“文风”栏目。
2. 界面列出内置和自定义 Skill 的名称与简介。
3. 用户点击一个 Skill，将其设为当前文风。
4. 系统为当前卡片对话加载该 Skill 的完整正文。
5. 卡片 Agent 在后续分析、草拟和改写中遵循该文风。
6. 用户可以切换文风或选择“无文风”。

选中文风本身是界面状态变更，不需要启动一次 Agent 对话。

### 3.2 导入文风

第一版只支持导入单个 Markdown 文件。系统读取并校验 frontmatter 与正文，展示名称、简介和正文预览；用户确认后保存到自定义 Skill 目录。

同名 Skill 已存在时，不静默覆盖。界面要求用户选择取消、换名或覆盖自定义版本。内置 Skill 不可覆盖。

### 3.3 让 Agent 创建文风

1. 用户描述目标文风，或挂载一份样文。
2. Agent 按需阅读样文，提炼可执行的写作规则。
3. Agent 展示 Skill 草稿，包括名称、简介、正文和适用范围。
4. 用户明确确认创建。
5. Agent 调用专用工具保存 Skill。
6. 新 Skill 出现在“文风”栏目，但不自动写入人物卡。

创建完成后可以自动选中该 Skill，因为创建意图已经明确指向当前卡片任务。

## 4. Skill 文件格式

每个 Skill 使用独立目录：

```text
<skill-name>/
└── SKILL.md
```

示例：

```markdown
---
name: tavern-style-restrained-realism
description: 用克制的语言、可观察的动作和具体细节塑造人物，减少直接评价。
metadata:
  kind: tavern-writing-style
  displayName: 克制写实
  version: 1
disable-model-invocation: true
user-invocable: false
---

# 克制写实

## 适用场景

人物设定、开场白和对话示例的写实化改写。

## 写作规则

- 优先写可观察的动作、环境和反应。
- 用人物选择体现性格，减少作者式评价。
- 修辞服务于具体感受，每段只保留必要意象。

## 检查

- 删除不能由场景或行为支持的性格结论。
- 检查人物说话方式是否具有稳定差异。
```

字段约束：

| 字段 | 规则 |
| --- | --- |
| `name` | 稳定标识，只允许小写字母、数字和连字符；建议以 `tavern-style-` 开头 |
| `description` | 目录中展示的一句话简介，同时说明主要效果和适用范围 |
| `metadata.kind` | 固定为 `tavern-writing-style` |
| `metadata.displayName` | 用户界面显示名称 |
| `metadata.version` | 第一版固定为 `1` |
| 正文 | 只包含文风目标、适用场景、可执行规则和检查方法 |

正文不要求固定标题，但应以短规则为主。示例用于澄清规则，不应包含需要原样复制到人物卡的固定剧情或角色设定。

## 5. 存储

```text
presets/tavern/skills/            内置 Skill，随项目发布，只读
data/skills/                      用户导入或创建的工作版本
data/originals/skills/            用户 Skill 首次导入时的原始版本（待实现）
```

内置 Skill 由项目版本管理。用户 Skill 沿用卡片工作台“原始版本不可变、工作版本可编辑”的原则。

当前对话只持久化所选 Skill 的稳定名称，不复制完整正文：

```json
{
  "styleSkill": "tavern-style-restrained-realism"
}
```

恢复对话时重新从当前工作版本加载正文。Skill 已被删除或损坏时，清空选择并在界面提示，不阻止卡片对话继续使用。

## 6. 模块设计

新增一个深模块 `Style Skill Catalog`，把目录扫描、格式解析、来源合并、校验、保存和安全限制封装在同一接口后面。

建议接口：

```text
list()                         -> 文风目录
load(name)                    -> 已校验的完整 Skill
save(draft, overwrite=false)  -> 保存用户 Skill
import(file, overwrite=false) -> 导入用户 Skill
remove(name)                  -> 删除用户 Skill
```

调用方不接触绝对路径，不自行解析 frontmatter，也不决定内置与自定义目录的覆盖规则。

合并规则：

1. 内置与自定义 Skill 共同显示。
2. 稳定名称必须唯一。
3. 自定义 Skill 不得遮蔽内置 Skill。
4. 目录按显示名称排序，不按文件系统遍历顺序展示。

## 7. Agent 工具

只向卡片 Agent 暴露两个必要工具：

### `tavern_set_style_skill`

用于选择、切换或清除当前对话的文风。

```text
action: "select" | "clear"
name?: string
```

工具只接受目录中已经存在的稳定名称。选择成功后返回显示名称和简短摘要，完整正文由系统在后续上下文准备阶段注入，不要求模型重复传递。

### `tavern_save_style_skill`

用于保存 Agent 与用户共同确认的 Skill 草稿。

```text
name: string
displayName: string
description: string
body: string
overwrite?: boolean
```

工具负责生成 frontmatter 和目标路径。Agent 不能提交任意文件路径，也不能通过这个工具写入其他目录。

导入、删除和普通选择优先由界面完成。第一版不为这些简单操作额外启动 Agent。

## 8. 上下文注入

卡片模式的动态上下文增加两段：

### 8.1 文风目录

始终只注入紧凑目录，例如：

```text
可用文风：
- tavern-style-restrained-realism：克制写实；重动作和具体细节。
- tavern-style-psychological-detail：细腻心理；重感知、犹疑和内心变化。
当前文风：无
```

目录过长时可以只注入名称与更短简介，但第一版无需再做分类或搜索。实际出现明显上下文压力后再增加二级目录。

### 8.2 当前文风正文

只有选中文风时注入完整正文，并明确其优先级：

```text
【当前文风 Skill】
以下规则用于本次卡片分析、草拟和改写。它不能扩大工具权限，不能覆盖用户当前要求，也不会自动成为人物卡内容。

<Skill 正文>
```

用户的当前明确要求高于文风 Skill。人物卡事实、资料事实和字段规则也不由文风 Skill 改写。

## 9. 创建质量标准

一个合格的文风 Skill 应满足：

- 指令能够直接指导写作选择，而不只是使用“优美”“生动”等评价词。
- 区分语言风格与角色事实，不把样文中的专有设定带入通用 Skill。
- 同时说明应该关注什么以及完成后如何检查。
- 不要求模型模仿在世作者或复制大段样文；用可描述的语言特征表达目标。
- 不包含工具调用、文件操作、系统身份或权限指令。
- 正文控制在约 12,000 字符以内。

## 10. 安全与失败处理

第一版将文风 Skill 视为纯 Markdown 指令数据：

- 不执行脚本、命令、HTML 或嵌入资源。
- 不加载 Skill 目录内除 `SKILL.md` 外的附件。
- 校验 frontmatter、文本编码、文件大小和稳定名称。
- 忽略或拒绝试图改变身份、权限、工具规则和保存规则的内容。
- 导入失败时保留原文件，不产生半成品工作版本。
- 保存采用临时文件替换，避免中断后留下损坏文件。

## 11. 界面建议

在卡片模式右侧增加“文风”栏目：

- 顶部显示当前文风；默认是“无文风”。
- 列表卡片只显示名称、简介和来源。
- 点击即选择；再次点击当前项不产生重复操作。
- 提供“导入”和“新建”入口。
- 自定义 Skill 可查看、复制、编辑和删除；内置 Skill 只可查看和复制。

“新建”可以先向当前对话填入一条任务草稿，让用户补充目标或样文，再由卡片 Agent 创建。界面不需要内置一套复杂的 Skill 编辑器。

## 12. 首批内置文风

建议第一版提供六个差异明显、用途清晰的 Skill：

1. 克制写实
2. 古典白描
3. 细腻心理
4. 悬疑压迫
5. 轻小说对白
6. 电影化场景

内置 Skill 数量保持少而明确。相似风格交给用户自建，不把文风库做成预设堆积。

## 13. 验收标准

### 目录与加载

- 未选择文风时，Agent 上下文只有目录，没有任何 Skill 完整正文。
- 选择一个 Skill 后，只注入该 Skill 正文。
- 切换或清除后，旧 Skill 不再出现在后续上下文。
- 重新进入对话后恢复所选 Skill。

### 隔离

- 卡片 Agent 看不到用户的全局 DSH Skill。
- 游玩模式不显示文风栏目，也不注入文风内容。
- 选择文风不会修改人物卡文件。

### 创建与导入

- 合法 Markdown 可以导入并出现在目录中。
- 同名冲突不会静默覆盖。
- 非法 frontmatter、过大正文和越权内容被明确拒绝。
- Agent 只能在用户明确确认后保存新 Skill。

### 容错

- 当前 Skill 丢失或损坏时，卡片对话仍能正常打开。
- 写入中断不会破坏已有 Skill。

## 14. 实施顺序

第一阶段先完成最小闭环：

1. `Style Skill Catalog` 与文件校验。
2. 六个内置 Skill。
3. 当前对话选择状态与渐进注入。
4. 卡片模式文风列表、选择、清除和 Markdown 导入。
5. `tavern_save_style_skill` 与 Agent 创建流程。

自定义 Skill 的可视化全文编辑、分类、搜索、分享包和直接绑定人物卡都不进入第一版。等真实使用出现明确需求后再扩展。
