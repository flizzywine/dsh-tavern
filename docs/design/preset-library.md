# 预设库

> 核心决定：产品只提供一个“预设库（实验性）”。用户自行导入外部预设，并明确勾选需要启用的条目；系统不提供独立的方案资源库，也不直接运行整份外部预设。

## 目标

SillyTavern 预设通常同时包含流程控制、内容偏好、格式要求、正则和模型配置。DSH Tavern 有自己的运行流程，不能把整份预设无条件接管为系统规则。

预设库只解决三个问题：

1. 保存和查看用户导入的外部预设；
2. 让用户逐条选择需要参与请求的提示词与正则；
3. 在兼容模式中按 SillyTavern 语义编译这些已选条目。

程序不判断条目用途，不自动修改条目，也不承诺任何模型或供应商上的特定输出效果。

## 用户模型

```text
导入外部预设
  → 查看提示词与正则
  → 手动勾选条目
  → 启用所选条目
  → 或停用全部预设条目
```

右侧面板只注册：

- 标题：`预设库（实验性）`；
- 主操作：`导入外部预设`；
- 单份预设操作：`选择条目`、`导出`、`重命名`、`删除`；
- 选择页操作：`启用所选条目`、`停用预设条目`。

不提供独立的运行方案列表、方案导入导出、方案复制或适配模型标注。

## 选择规则

- 提示词默认不选，由用户逐条勾选；
- 正则默认按外部预设原状态选择，用户可以取消；
- marker、空条目和运行时托管占位不能手动启用；
- 同一时间只使用一份外部预设的已选条目；
- 启用新的预设条目会替换当前选择；
- 用户可以停用全部外部预设条目；
- 启用的条目可能与 DSH Tavern 自身规则冲突，界面必须明确提示风险。

当前只有兼容模式完成外部预设条目适配。游玩模式和卡片模式尚未完成适配，请勿启用外部预设条目。

## 内部保存

底层继续使用自包含的选择快照保存已选提示词、正则、来源信息和必要兼容设置。这是为了：

- 保持每轮请求稳定；
- 兼容已有用户数据；
- 避免来源文件临时变化影响正在运行的请求；
- 让运行时统一生成 DSH 三段投影或 SillyTavern 顺序消息。

该快照是内部实现，不是用户产品对象。旧版本留下的快照文件不删除，但新版界面不再显示独立入口。

## 删除与旧数据

- 删除正在使用的来源预设时，先停用其条目；
- 删除来源预设不主动删除旧内部快照，避免不可逆的数据损失；
- 重新导入同一路径的预设后，可以继续更新对应内部快照；
- 旧的独立方案入口在启动时从 Better Sidebar 中关闭；
- 升级不自动激活任何旧配置。

## 发布边界

发布包不自带、也不自动安装第三方外部预设或预先选择的运行配置。用户需要自行导入预设并决定启用哪些条目。

## 请求与日志

普通 DSH 请求可将内部选择快照投影为稳定前缀、每轮注入和后带内容；兼容模式按 SillyTavern 的顺序、角色和 marker 规则编译。普通用户不接触这些内部结构。

每次真实模型请求仍保存完整诊断日志，包括最终消息顺序、选中条目来源、正则、模型响应和错误。日志用于解释真实行为，不改变请求结果。

## 验收

- 侧栏只出现一个“预设库（实验性）”；
- 用户可以导入预设、查看内容并勾选提示词与正则；
- 点击“启用所选条目”后，从下一次请求开始生效；
- 点击“停用预设条目”后，不再注入外部预设内容；
- 产品界面和使用说明不出现独立方案功能；
- 发布包不包含或自动导入第三方外部预设；
- 旧数据不被删除，现有请求投影仍可读取内部快照。
