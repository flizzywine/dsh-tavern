# 预设库实验模块

> 当前状态：用户只管理一种“预设”，详情分为“酒馆原始预设”和“DSH 预设预览”。用户标注破限提示词，程序自动分为前、中、后；对话绑定预设路径，每次请求读取当前工作版，正则开关实时生效。

## 1. 目标

dsh-tavern 应当直接兼容 SillyTavern 预设，避免要求用户完成以下多步转换：

```text
导入预设
  → 挂载到卡片工作台
  → Agent 提取破限提示词
  → 保存为破甲 Markdown
  → 打开破甲库
  → 选择文件并启用
```

新的用户流程为：

```text
导入预设
  → 选择一份当前启用预设
  → 标注其中与破限有关的提示词
  → 查看自动生成的 DSH 前、中、后与正则
  → dsh-tavern 全局直接使用
```

预设的存储格式、条目名称、顺序和原始启用状态完整保留；阅读和转换均以酒馆预设自己的设置作为默认状态。运行时处理方式可以不同，但用户不需要理解内部转换过程。

## 2. 产品原则

### 2.1 无缝导入

- 原始 JSON 保存到 `data/originals/presets/`，不得修改；
- 工作文件保存到 `data/resources/presets/`，保留所有已知和未知字段；
- 导入不再生成破甲文件、中间 Markdown 或新的方案实体；
- 导入完成后直接打开预设详情，并按酒馆预设自身设置显示开关状态；
- 导入和管理预设不依赖当前会话，也不隐式创建会话。

### 2.2 过滤与开关分离

酒馆预设的普通条目可能是破限、写作控制、流程控制、输出任务或示例，程序无法可靠自动分类。首次导入时提示词默认全部未标注；只有用户明确标为“破限相关”的条目才进入 DSH 预设。

过滤标注与条目开关互不替代：

- “破限相关”决定条目是否进入 DSH 预设；
- `enabled` 决定进入 DSH 预设后的条目是否实际注入；
- 已标注但默认关闭的条目仍显示在 DSH 预览中；
- 开启状态继承有效 `prompt_order`，用户可在 DSH 预览中调整；
- 正则无需标注，继承脚本自身的 `disabled`。

系统已原生提供的空占位条目不参与标注；无法映射的内容只进入折叠的“兼容信息”。

### 2.3 选择属于系统

“当前启用预设”是 Profile 级单选状态，可以选择任意一份已导入预设，也可以选择“不启用外部预设”。提示词和正则的勾选不是编辑预设 JSON；它们分别保存在每份预设的运行配置中。

同一时间只有当前启用预设用于绑定新对话。切换预设不清空各自内部勾选，切换回来后可以继续使用原配置。已经开始的对话继续绑定原预设路径：前、后修改后下一次请求立即生效，中段修改后从下一轮生效。正则修改会立即重新处理绑定该预设的已有对话展示。普通 DSH Profile 和其他插件不受影响。

### 2.4 注入失败必须明确中止

只要系统中存在已启用内容，预设缺失、JSON 损坏、条目或正则失效、组合失败或注入失败时，就必须明确提示“预设注入失败”。前台初始化失败时终止新对话创建；后台 Agent 初始化失败时终止该后台任务。错误需要说明具体预设、内容和原因，并在预设管理器中持续保留，直到用户修复、删除或关闭问题内容。

系统不得静默跳过预设后继续生成，也不得让界面显示“已启用”而实际没有注入。所有条目均关闭时，模型任务正常运行，不视为错误。

## 3. 预设管理器

预设库升级为预设管理器，继续提供：

- 导入、列出、查看、重命名和删除预设；
- 修改提示词条目的名称、角色、正文和开关状态，保留其他已知与未知字段；
- 单选当前启用预设，或选择“不启用外部预设”；
- 在“酒馆原始预设”中展示全部提示词、角色、源开关和完整正文，并标注破限相关；
- 在“DSH 预设预览”中只展示已标注条目的自动前、中、后分段及继承的开启状态；
- 展示 SPreset 正则，并允许逐项决定是否处理使用该预设的对话展示；
- 在卡片模式中通过“在对话中引用”把预设作为分析素材。

新增运行时操作：

- 逐项标注或取消标注破限提示词，并独立调整已保留条目的开启状态；
- 一键关闭某份预设的全部内容；
- 分别显示提示词与正则的总数和已启用数量；
- 显示当前全局启用提示词数、合计字符数、正则数和最近一次持久错误；
- 对空条目、占位条目和未识别结构说明为什么不能直接注入。
- 把当前预设及其提示词、正则勾选保存为可重复应用的命名配置方案；
- 应用、覆盖、重命名和删除配置方案。

删除预设时同步移除它的全局开关状态。重命名预设时同步迁移全局状态，不得误开、误关或复制条目。

### 3.1 预设配置方案

配置方案是当前运行配置的轻量快照，只保存预设路径、已勾选提示词键、已勾选正则键和预设结构摘要，不复制预设正文，也不形成新的资源库。应用方案会一次恢复对应预设及全部勾选状态：正则立即生效；绑定该预设的对话在下一次请求读取新的前、后，在下一轮读取新的中段。

预设重命名时同步迁移方案路径；预设被删除或方案引用的条目消失时保留方案并明确标记失效，不静默忽略缺失内容。原预设结构变化但方案引用仍完整时允许应用，同时显示变化提醒。

### 3.2 内置使用说明

预设管理器必须提供随时可展开的“如何使用”说明。用户第一次打开管理器时默认展开，之后可以收起。说明使用以下核心文案：

> 当前预设模块是实验功能，支持前、中、后与正则，但不承诺完整复现所有外部脚本和采样环境。
>
> 新对话绑定当前预设；已绑定对话会实时读取当前工作版，正则开关也会影响已有展示投影。

界面还应提供以下即时提示：

- 没有启用内容：显示“推荐状态：使用 dsh-tavern 内置能力”；
- 启用第一项时：确认用户知道外部预设可能改变系统行为；
- 启用内容持续增加时：提示“建议只保留解决当前问题所必需的少量内容”；
- 提供“不启用外部预设”，作为最直接的恢复方式；另提供清空勾选操作；
- 不使用恐吓式弹窗，不阻止用户自行选择。

## 4. 数据模型

原始预设和工作预设不保存 dsh-tavern 的运行开关。最小运行状态单独保存在当前 Tavern Profile 的全局数据中：

```text
RuntimePresetState {
  activePreset: PresetPath | ''
  presetOrder: string[]
  entries: Record<PresetPath, Record<EntryKey, boolean>>
  regexes: Record<PresetPath, Record<RegexKey, boolean>>
  plans: RuntimePresetPlan[]
}

RuntimePresetPlan {
  id: string
  name: string
  presetPath: PresetPath
  entryKeys: EntryKey[]
  regexKeys: RegexKey[]
  presetDigest: string
  createdAt: number
  updatedAt: number
}
```

`RuntimePresetState` 保存当前实际选择。`entries` 记录用户标注后保留的条目键，不代表条目的开启状态；开启状态仍来自酒馆工作预设的有效 `prompt_order`。首次注册时 `entries` 为空，正则沿用酒馆源预设默认开关。阅读与转换仍以酒馆源预设为结构来源；`EntryKey` 与 `RegexKey` 由解析器生成，同名标识重复出现时加入稳定序号。

- 仍存在的条目保留全局选择；
- 已消失的条目从运行状态中忽略；
- 新条目保持关闭；
- 不静默修改原始或工作 JSON。

旧会话的 `boundaryPrompt` 字段不再参与运行。迁移不尝试把破甲 Markdown 反向伪造成酒馆预设，因为两者缺少可靠的条目、顺序和来源映射。

每个 Tavern 对话保存绑定预设路径，并记录最近一次解析结果用于诊断：

```text
RuntimePresetSnapshot {
  presetPath: PresetPath
  front: { entries, text }
  middle: { entries, text }
  back: { entries, text }
  sources: Array<{ path, entryKey, phase }>
  regexScripts: RegexScript[]
  digest: string
  createdAt: number
}
```

`presetPath` 是运行权威引用。每次请求根据它读取当前启用条目并解析宏；`RuntimePresetSnapshot` 只是最近一次解析结果和来源的诊断记录，不再是冻结配置。前、后请求结束后从有效 Session 遮蔽，中段每轮第一步写入 Session。完整真实请求另存为不可回注的诊断日志。

## 5. 模块设计

### 5.1 Preset Reading

`Preset Reading` 继续负责把不同 SillyTavern JSON 投影为稳定结构：

```text
inspectPreset(text, filename)
  -> PresetInspection
```

它隐藏 `prompts`、`prompt_order`、角色、启用状态和扩展字段差异，并为每个条目生成稳定 `EntryKey`。它只解析，不读取会话，也不决定当前启用组合。

### 5.2 Runtime Preset

新建一个深的 `Runtime Preset` 模块，外部只需要以下 Interface：

```text
state()
  -> 全部预设的全局条目状态

toggle({ path, entryKey, enabled })
  -> 更新一个条目的系统级开关

snapshot(path?)
  -> { front, middle, back, sources, regexScripts } | null
```

文件读取、转换映射、全局状态存储、组合和错误处理全部隐藏在模块实现中。正文、候选和状态结算在每次模型请求前按对话绑定路径读取当前投影；正则开关也通过同一模块实时读取。

这条 seam 取代现有 `Boundary Prompts` 模块；不能在旧模块外再叠一层预设适配器，否则仍会保留两套选择和注入状态。

## 6. 提示词组合规则

`snapshot` 按以下顺序生成三段运行时提示词与正则：

1. 读取系统级运行状态；
2. 只读取 `activePreset` 指向的预设；
3. 使用转换协议按有效 `prompt_order` 恢复顺序并划分前、中、后；
4. 排除未启用、空内容、DSH 原生接管 marker 和未编排条目；
5. 每段内部按原顺序用两个换行连接正文；
6. 保留启用正则，并返回条目来源和诊断供 UI 与日志审计。

除连接条目所需的两个换行外，正文保持逐字不变：不添加条目名称，不总结、不润色、不清洗、不截断。每次模型请求按前、中、后顺序解析兼容宏；前、后立刻采用新结果，中段只在新一轮第一步写入。

以下内容不作为提示词正文直接注入：

- `Persona Description`、`Chat History`、`World Info` 等空占位条目；
- 正则脚本、HTML 模板和 Tavern Helper 脚本；
- temperature、top_p、max_tokens 等模型参数；
- 无法识别的二进制或非文本扩展字段。

启用的预设正则不进入提示词三段。它们与人物卡正则一起处理前台输入和模型回复，并分别生成 Session 与展示投影；权威模型原文保持不变。后台结算、候选协议和日志不执行预设正则。读取前台历史时从原文重新生成展示，因此正则开关能立即影响已有回复。HTML 模板、Tavern Helper 脚本和模型参数仍由各自兼容模块处理。

## 7. 注入时机与范围

新建 Tavern 对话时保存预设路径；每次前台和后台请求重新读取该路径的当前三段内容。

三段按不同生命周期生效：

- 前段作为保留角色的请求前缀消息，前台与后台沿用同一稳定快照；
- 中段在前台每个玩家回合注入一次，在后台每个候选或结算任务注入一次，不累积；
- 后段在每次前台或后台模型请求末尾临时附加，包括工具循环的后续 step；请求结束后从有效 Session Surface 遮蔽，不进入下一次请求上下文；
- 提示词开关变化只影响之后新建的 Tavern 对话；已有对话如需使用新提示词组合，应新建对话。

正则属于实时投影配置：

- 每次处理输入、新回复或读取历史时，按该对话绑定的预设读取当前正则开关；
- 正则修改立即重新处理已有展示和之后的新输入、新回复，不需要创建新 Session；
- 原始回复作为权威数据保留，正则生成可追踪、可重建的模型与展示投影；
- 早期版本已经破坏性清理且未保留原始回复的历史内容无法恢复。

三段均以请求投影消息表达，不写入人物卡、世界书或权威聊天历史。后台把自身的结算／候选任务放在预设消息之后，保证 DSH 输出协议不被预设改写。

界面显示选中条目的总字符数。第一版不静默裁剪提示词；如果组合过大，只给出明确警告，由用户自行关闭条目。

## 8. 删除旧破甲模块

实施时删除以下产品与代码入口：

- Better Sidebar 中的“破甲库”；
- `Boundary Prompts` 领域模块及相关 RPC；
- `tavern_read_boundary_prompt`、`tavern_update_boundary_prompt` 工具；
- “从预设提取破甲”卡片工作台入口和任务提示词；
- `tavern-extract-boundary-prompt` Skill；
- 内置破甲 Markdown 和首次安装逻辑；
- 仅验证旧破甲文件制作、选择和注入的测试。

用户目录中已经存在的 `data/boundary-prompts/` 文件不自动删除。它们只是停止被程序读取，用户可以自行备份或清理。升级不得以“移除模块”为由删除用户创作的数据。

旧破甲设计文档随代码迁移一并删除，避免两套设计同时被视为当前方案。

## 9. 非目标

当前阶段不实现：

- 拖拽排序、添加、复制或删除提示词条目；
- 自动识别哪些条目属于破限；
- 自动根据模型选择预设或条目；
- 执行预设附带的 Tavern Helper 脚本或模型参数；
- 自动测试和承诺某份预设对特定模型有效；
- 把外部预设改写为 dsh-tavern 原生正文、候选或状态协议。

用户选择什么就注入什么；dsh-tavern 负责可靠保存选择、确定性组合、统一注入和明确诊断，不负责替用户判断提示词质量。

## 10. 验收标准

### 导入与管理

- 导入后原始 JSON 与所有未知字段保持不变；
- 有 `prompt_order` 和无 `prompt_order` 的预设都能得到确定顺序；
- 新导入预设的提示词默认全部未标注，正则按自身 `disabled` 显示默认状态；
- 标注后的提示词继承自身 `prompt_order.enabled`，已标注但关闭的条目仍出现在 DSH 预览；
- 已有对话继续绑定原预设路径；前、后修改后下一次请求生效，中段修改后下一轮生效；
- 正则开关变化立即影响绑定该预设的已有对话展示，不改写底层回复；
- 同一时间只能启用一份预设，也可以明确选择不启用；
- 切换预设时，各预设内部勾选配置保持不变；
- 重命名、删除或损坏预设不会留下无提示的失效引用。

### 注入

- 没有任何启用内容时，新对话不创建外部预设快照；
- 标注并开启提示词后，请求按前、中、后得到保留角色和顺序的消息；
- 启用正则后，绑定该预设的已有对话和新对话都在回复展示阶段执行；
- 前段稳定复用，中段每轮一次，后段每次请求一次且不留在后续有效上下文；
- 每次请求按三段顺序读取当前预设并解析宏；
- 前台与后台使用同一当前预设，实时正则只作用前台；
- 每次前台和后台真实请求都完整持久化，可按轮次分页读取，但不会进入之后的模型上下文；
- 条目正文不被总结、润色、截断或重新排序；
- 存在已启用内容时，任何组合或初始化失败都会中止对应的对话创建或后台任务，并给出持久、可复制的明确错误；不得降级为无预设运行。

### 清理

- UI 不再出现破甲库和“从预设提取破甲”；
- 卡片 Agent 不再获得破甲文件读写工具和提取 Skill；
- 新运行时不再创建或读取 `boundary-prompts` 文件；
- 已有用户文件仍留在磁盘；
- 完整测试覆盖源预设默认状态、`prompt_order` 顺序、多预设顺序、重命名、删除和转换诊断。

## 11. 已完成的实施顺序

1. 先为 `Runtime Preset` Interface 编写行为测试；
2. 扩展 `Preset Reading`，生成稳定条目标识和默认运行状态；
3. 实现系统级选择、逐字组合和不可变快照；
4. 将前台和持久后台 Agent 的初始化流程切换到新 `snapshot`；
5. 把预设库升级为可操作的预设管理器；
6. 删除旧 UI、模块、工具、Skill、默认文件和测试；
7. 更新架构、翻译设计、TODO 和文档索引；
8. 用真实 SillyTavern 预设完成浏览器端到端验证。
