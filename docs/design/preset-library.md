# 预设库实验模块

> 当前状态：只支持导入、阅读和研究预设。提示词注入与预设正则匹配均已禁用，不产生任何运行时效果。旧对话中保存的预设快照也不再执行。本文件其余内容是历史设计记录，不代表当前功能。

## 1. 目标

dsh-tavern 应当直接兼容 SillyTavern 预设，避免要求用户完成以下多步转换：

```text
导入预设
  → 挂载到卡片工作台
  → Agent 提取破限提示词
  → 保存为破甲 Markdown
  → 打开破甲库
  → 选择文件并启用
```

新的用户流程为：

```text
导入预设
  → 选择一份当前启用预设
  → 勾选其中需要的提示词或正则
  → dsh-tavern 全局直接使用
```

预设的存储格式、条目名称、顺序和原始启用状态完整保留；dsh-tavern 的全局开关独立存在且默认全关。运行时处理方式可以不同，但用户不需要理解内部转换过程。

## 2. 产品原则

### 2.1 无缝导入

- 原始 JSON 保存到 `data/originals/presets/`，不得修改；
- 工作文件保存到 `data/resources/presets/`，保留所有已知和未知字段；
- 导入不再生成破甲文件、中间 Markdown 或新的方案实体；
- 导入完成后直接打开预设详情，但所有可执行内容默认关闭；
- 导入和管理预设不依赖当前会话，也不隐式创建会话。

### 2.2 所见即所得

预设管理器按有效 `prompt_order` 展示提示词条目，并在下方展示正则脚本。每个可注入提示词和可执行正则都提供全局开关，不再要求额外点击“保存方案”或前往其他侧栏激活。提示词配置用于之后新建的 Tavern 对话；正则配置作为展示规则立即作用于使用该预设的已有对话。

预设导入后：

- 所有提示词和正则的 dsh-tavern 全局开关一律默认为关闭；
- 不继承预设原本的启用状态；
- 用户必须逐项手动开启需要的内容；
- 空内容和纯占位条目不可开启。

### 2.3 选择属于系统

“当前启用预设”是 Profile 级单选状态，可以选择任意一份已导入预设，也可以选择“不启用外部预设”。提示词和正则的勾选不是编辑预设 JSON；它们分别保存在每份预设的运行配置中。

同一时间只有当前启用预设用于创建新对话。切换预设不清空各自内部勾选，切换回来后可以继续使用原配置。提示词修改只影响当前 Profile 后续新建的 Tavern 对话；已经开始的对话保持创建时的提示词快照。正则不固定在提示词快照中，修改后会立即重新处理绑定该预设的已有对话展示。普通 DSH Profile 和其他插件不受影响。

### 2.4 注入失败必须明确中止

只要系统中存在已启用内容，预设缺失、JSON 损坏、条目或正则失效、组合失败或注入失败时，就必须明确提示“预设注入失败”。前台初始化失败时终止新对话创建；后台 Agent 初始化失败时终止该后台任务。错误需要说明具体预设、内容和原因，并在预设管理器中持续保留，直到用户修复、删除或关闭问题内容。

系统不得静默跳过预设后继续生成，也不得让界面显示“已启用”而实际没有注入。所有条目均关闭时，模型任务正常运行，不视为错误。

## 3. 预设管理器

预设库升级为预设管理器，继续提供：

- 导入、列出、查看、重命名和删除预设；
- 单选当前启用预设，或选择“不启用外部预设”；
- 展示提示词条目、角色、顺序、启用状态和完整正文；
- 展示 SPreset 正则，并允许逐项决定是否处理使用该预设的对话展示；
- 在卡片模式中通过“在对话中引用”把预设作为分析素材。

新增运行时操作：

- 逐项全局启用或停用可注入提示词和正则；
- 一键关闭某份预设的全部内容；
- 分别显示提示词与正则的总数和已启用数量；
- 显示当前全局启用提示词数、合计字符数、正则数和最近一次持久错误；
- 对空条目、占位条目和未识别结构说明为什么不能直接注入。
- 把当前预设及其提示词、正则勾选保存为可重复应用的命名配置方案；
- 应用、覆盖、重命名和删除配置方案。

删除预设时同步移除它的全局开关状态。重命名预设时同步迁移全局状态，不得误开、误关或复制条目。

### 3.1 预设配置方案

配置方案是当前运行配置的轻量快照，只保存预设路径、已勾选提示词键、已勾选正则键和预设结构摘要，不复制预设正文，也不形成新的资源库。应用方案会一次恢复对应预设及全部勾选状态：正则立即生效，提示词仍需新建对话后生效。

预设重命名时同步迁移方案路径；预设被删除或方案引用的条目消失时保留方案并明确标记失效，不静默忽略缺失内容。原预设结构变化但方案引用仍完整时允许应用，同时显示变化提醒。

### 3.2 内置使用说明

预设管理器必须提供随时可展开的“如何使用”说明。用户第一次打开管理器时默认展开，之后可以收起。说明使用以下核心文案：

> 当前预设模块是实验功能，只支持导入和阅读，不能复现 SillyTavern 的预设编译、请求结构或破限效果。
>
> 提示词注入和预设正则匹配均已禁用，不产生任何运行时效果。
>
> 后续将先通过独立兼容模式复刻真实的酒馆预设编译能力，验证成功后再研究如何迁移到 DSH 原生架构。

界面还应提供以下即时提示：

- 没有启用内容：显示“推荐状态：使用 dsh-tavern 内置能力”；
- 启用第一项时：确认用户知道外部预设可能改变系统行为；
- 启用内容持续增加时：提示“建议只保留解决当前问题所必需的少量内容”；
- 提供“不启用外部预设”，作为最直接的恢复方式；另提供清空勾选操作；
- 不使用恐吓式弹窗，不阻止用户自行选择。

## 4. 数据模型

原始预设和工作预设不保存 dsh-tavern 的运行开关。最小运行状态单独保存在当前 Tavern Profile 的全局数据中：

```text
RuntimePresetState {
  activePreset: PresetPath | ''
  presetOrder: string[]
  entries: Record<PresetPath, Record<EntryKey, boolean>>
  regexes: Record<PresetPath, Record<RegexKey, boolean>>
  plans: RuntimePresetPlan[]
}

RuntimePresetPlan {
  id: string
  name: string
  presetPath: PresetPath
  entryKeys: EntryKey[]
  regexKeys: RegexKey[]
  presetDigest: string
  createdAt: number
  updatedAt: number
}
```

`activePreset` 为空表示不启用外部预设；同一时间只允许一个路径。所有新提示词和正则在该状态中都以 `false` 开始，不读取预设自身的启用值作为运行默认值。`EntryKey` 与 `RegexKey` 由预设解析器生成；同名标识重复出现时必须加入稳定序号，避免一个开关意外控制多个内容。预设文件变化后：

- 仍存在的条目保留全局选择；
- 已消失的条目从运行状态中忽略；
- 新条目保持关闭；
- 不静默修改原始或工作 JSON。

旧会话的 `boundaryPrompt` 字段不再参与运行。迁移不尝试把破甲 Markdown 反向伪造成酒馆预设，因为两者缺少可靠的条目、顺序和来源映射。

每个新 Tavern 对话在创建时保存一份不可变运行快照：

```text
RuntimePresetSnapshot {
  presetPath: PresetPath
  text: string
  sources: Array<{ path, entryKey }>
  digest: string
  createdAt: number
}
```

快照保存该对话创建时实际注入的提示词及其来源。全局提示词配置之后发生变化时，旧对话不更新、不追加，也不重新注入。`presetPath` 同时标记对话绑定的预设，使展示层能够读取这份预设当前启用的正则，而不改变提示词快照。

## 5. 模块设计

### 5.1 Preset Reading

`Preset Reading` 继续负责把不同 SillyTavern JSON 投影为稳定结构：

```text
inspectPreset(text, filename)
  -> PresetInspection
```

它隐藏 `prompts`、`prompt_order`、角色、启用状态和扩展字段差异，并为每个条目生成稳定 `EntryKey`。它只解析，不读取会话，也不决定当前启用组合。

### 5.2 Runtime Preset

新建一个深的 `Runtime Preset` 模块，外部只需要以下 Interface：

```text
state()
  -> 全部预设的全局条目状态

toggle({ path, entryKey, enabled })
  -> 更新一个条目的系统级开关

snapshot()
  -> { text, sources } | null
```

文件读取、预设解析、全局状态存储、组合和错误处理全部隐藏在模块实现中。对话创建流程只调用一次 `snapshot`；正文、候选、状态结算和卡片 Agent 不得在后续轮次重新解析或追加预设。

这条 seam 取代现有 `Boundary Prompts` 模块；不能在旧模块外再叠一层预设适配器，否则仍会保留两套选择和注入状态。

## 6. 提示词组合规则

`snapshot` 按以下顺序生成唯一的运行时提示词区块：

1. 读取系统级运行状态；
2. 只读取 `activePreset` 指向的预设；
3. 使用 `Preset Reading` 恢复该预设内部的有效条目顺序；
4. 排除未启用、空内容和纯占位条目；
5. 按原顺序用两个换行连接正文；
6. 返回条目来源和诊断，供 UI 与日志审计。

除连接条目所需的两个换行外，正文保持逐字不变：不执行宏解析，不添加条目名称或角色标签，不总结、不润色、不清洗、不截断，也不伪造 `user` 或 `assistant` 历史消息。原始角色只在管理器中展示。

以下内容不作为提示词正文直接注入：

- `Persona Description`、`Chat History`、`World Info` 等空占位条目；
- 正则脚本、HTML 模板和 Tavern Helper 脚本；
- temperature、top_p、max_tokens 等模型参数；
- 无法识别的二进制或非文本扩展字段。

启用的预设正则是独立展示规则，不进入系统提示词。它们在模型回复完成后与人物卡正则一起执行；命中内容从可见正文移入独立展示区。读取历史时，展示层从保留的原始回复重新生成投影，因此正则开关能立即影响已有回复，但不会改写底层 Session。HTML 模板、Tavern Helper 脚本和模型参数仍由各自兼容模块处理。

## 7. 注入时机与范围

新建 Tavern 对话时保存预设路径，并为当时启用的提示词生成一次快照。提示词组合结果作为 `tavern:runtime-preset` 系统区块放在初始系统提示词最前面。

提示词注入只发生在对话初始化阶段：

- 前台主 Agent 创建时注入一次；
- 该对话后续所有轮次沿用初始系统上下文，不再次解析、追加或重复注入；
- 持久后台 Agent 创建时使用所属 Tavern 对话的同一份快照并注入一次，后续后台轮次不重复；
- 提示词开关变化只影响之后新建的 Tavern 对话；已有对话如需使用新提示词组合，应新建对话。

正则属于展示配置：

- 每次处理新回复或读取历史时，按该对话绑定的预设读取当前正则开关；
- 正则修改立即重新处理已有回复和之后的新回复，不需要创建新 Session；
- 原始回复作为权威数据保留，正则只生成可随时重建的展示投影；
- 早期版本已经破坏性清理且未保留原始回复的历史内容无法恢复。

除在初始系统提示词最前面增加这一块外，不调整任何现有提示词的内容、顺序、工具权限或输出协议。预设内容不写入人物卡或世界书，也不作为普通消息追加到聊天历史。

界面显示选中条目的总字符数。第一版不静默裁剪提示词；如果组合过大，只给出明确警告，由用户自行关闭条目。

## 8. 删除旧破甲模块

实施时删除以下产品与代码入口：

- Better Sidebar 中的“破甲库”；
- `Boundary Prompts` 领域模块及相关 RPC；
- `tavern_read_boundary_prompt`、`tavern_update_boundary_prompt` 工具；
- “从预设提取破甲”卡片工作台入口和任务提示词；
- `tavern-extract-boundary-prompt` Skill；
- 内置破甲 Markdown 和首次安装逻辑；
- 仅验证旧破甲文件制作、选择和注入的测试。

用户目录中已经存在的 `data/boundary-prompts/` 文件不自动删除。它们只是停止被程序读取，用户可以自行备份或清理。升级不得以“移除模块”为由删除用户创作的数据。

旧破甲设计文档随代码迁移一并删除，避免两套设计同时被视为当前方案。

## 9. 非目标

第一版不实现：

- 在预设管理器中编辑条目正文或拖拽排序；
- 自动识别哪些条目属于破限；
- 自动根据模型选择预设或条目；
- 执行预设附带的 Tavern Helper 脚本或模型参数；
- 自动测试和承诺某份预设对特定模型有效；
- 把外部预设改写为 dsh-tavern 原生正文、候选或状态协议。

用户选择什么就注入什么；dsh-tavern 负责可靠保存选择、确定性组合、统一注入和明确诊断，不负责替用户判断提示词质量。

## 10. 验收标准

### 导入与管理

- 导入后原始 JSON 与所有未知字段保持不变；
- 有 `prompt_order` 和无 `prompt_order` 的预设都能得到确定顺序；
- 新导入预设的全部提示词和正则默认关闭；
- 条目开关不依赖会话，并成为之后所有新建 Tavern 对话的全局默认值；
- 已有对话始终使用创建时的提示词快照，不受之后的提示词开关变化影响；
- 正则开关变化立即影响绑定该预设的已有对话展示，不改写底层回复；
- 同一时间只能启用一份预设，也可以明确选择不启用；
- 切换预设时，各预设内部勾选配置保持不变；
- 重命名、删除或损坏预设不会留下无提示的失效引用。

### 注入

- 没有任何启用内容时，新对话不创建外部预设快照；
- 启用提示词后，新对话在初始系统提示词最前面得到一份有序组合；
- 启用正则后，绑定该预设的已有对话和新对话都在回复展示阶段执行；
- 同一前台或后台 Agent 的后续轮次不重复注入；
- 选中条目逐字进入系统提示词最前面，宏和其他文本保持原样；
- 条目正文不被总结、润色、截断或重新排序；
- 存在已启用内容时，任何组合或初始化失败都会中止对应的对话创建或后台任务，并给出持久、可复制的明确错误；不得降级为无预设运行。

### 清理

- UI 不再出现破甲库和“从预设提取破甲”；
- 卡片 Agent 不再获得破甲文件读写工具和提取 Skill；
- 新运行时不再创建或读取 `boundary-prompts` 文件；
- 已有用户文件仍留在磁盘；
- 完整测试覆盖默认全关、全局逐项开关、多预设顺序、新对话提示词快照、前后台只注入一次、旧对话提示词不变、历史正则重投影、重命名、删除和注入失败中止。

## 11. 已完成的实施顺序

1. 先为 `Runtime Preset` Interface 编写行为测试；
2. 扩展 `Preset Reading`，生成稳定条目标识和默认运行状态；
3. 实现系统级选择、逐字组合和不可变快照；
4. 将前台和持久后台 Agent 的初始化流程切换到新 `snapshot`；
5. 把预设库升级为可操作的预设管理器；
6. 删除旧 UI、模块、工具、Skill、默认文件和测试；
7. 更新架构、翻译设计、TODO 和文档索引；
8. 用真实 SillyTavern 预设完成浏览器端到端验证。
