# 外部预设库与破限方案库

> 文档状态：记录当前实现，并定义下一阶段产品模型。新模型尚未全部实现。
>
> 核心决定：用户只接触“外部预设”和“破限方案”。所谓 DSH 预设只是内部请求投影，不再作为用户需要理解、编辑或激活的产品对象。

## 1. 为什么重新划分

SillyTavern 预设通常同时包含身份设定、流程控制、写作要求、输出格式、示例文本、占位符、正则和模型参数。把整份预设直接叠加到 dsh-tavern，会与前台正文、后台结算和候选生成等 DSH 原生任务发生冲突。

兼容模式已经在固定案例中复现真实 SillyTavern 的破限能力，也证明真正需要运行的往往只是外部预设中的少量条目。产品不应要求普通用户理解酒馆预设与 DSH 前、中、后的转换关系，而应让用户从外部预设中明确抽取自己需要的破限内容。

新的产品关系是：

```text
外部预设（只读来源）
  → 抽取破限方案（用户选择）
  → 激活破限方案（唯一运行入口）
  → 内部请求投影（用户不可见）
```

## 2. 统一术语

### 2.1 外部预设

从 SillyTavern 等外部系统导入的源文件。它用于查看、比较和抽取，不直接参与模型请求，也不存在“启用外部预设”。

外部预设保留：

- 原始提示词条目、角色、顺序和默认开关；
- `prompt_order`、marker、正则及未知扩展字段；
- 原始 JSON 和可恢复的工作副本；
- 来源摘要，用于判断抽取方案是否过期。

### 2.2 破限方案

用户从一份外部预设中明确抽取出的可运行配置。它独立保存被选中的提示词条目和迁移过来的正则；来源预设只作为出处信息，不是运行依赖。

破限方案是唯一允许被激活并进入模型请求的用户对象。同一时间最多激活一份，也可以不激活任何方案。当前激活方案是 Tavern 全局状态，不绑定单个对话。

### 2.3 内部预设投影

运行时从破限方案和来源外部预设确定性生成的内部结构。普通 DSH Tavern 请求使用“稳定前缀、每轮注入、后带内容”三段；开发者兼容模式使用 SillyTavern 顺序、marker、角色和 `strict_tools` 语义。

它不是资源库，不单独激活，不要求用户查看或维护。代码中可以继续沿用 `RuntimePresetSnapshot` 等内部名称，但 UI 和用户文档不再出现“DSH 预设”。

## 3. 当前实现快照

截至 `383c113`，产品对象已经完成拆分：

- 外部 JSON 原文保存到 `data/originals/presets/`，工作文件保存到 `data/resources/presets/`；
- `Preset Reading` 解析提示词、`prompt_order`、角色、marker、正则和未知字段；
- 外部预设库只负责导入、只读查看、导出、重命名、删除和抽取；
- `BypassPlan` 独立保存所选提示词、酒馆运行正则和必要兼容设置；
- Profile 只激活破限方案，不再激活外部预设；
- Profile 保存唯一的 `activePlanId`，每次请求从当前全局方案生成最新内部投影；
- 普通 DSH 模式从方案内已开启条目生成前、中、后三段，并保留条目角色；
- 开发者兼容模式按 SillyTavern 顺序编译消息，处理人物卡占位、宏、正则、marker 和 `strict_tools`；
- 真实模型请求日志保存方案 ID、名称、摘要、三段和最终请求；
- 旧 `RuntimePresetPlan` 与旧对话会在启动时迁移为未激活的自包含方案；
- 固定测试案例中，兼容模式已经连续复现真实 SillyTavern 的破限输出。

当前用户流程为：

```text
导入外部预设
  → 勾选需要的提示词，默认带上全部酒馆运行正则
  → 保存为独立破限方案
  → 在破限方案库激活
  → 下一次 Tavern 请求全局生效
```

方案保存后不再读取来源文件。删除、重命名或修改外部预设不会改变已有方案。

## 4. 用户流程

### 4.1 导入和查看

```text
打开外部预设库
  → 导入外部预设 JSON
  → 查看原始条目、角色、顺序、默认状态、正则和兼容信息
```

外部预设详情是只读检查界面。允许重命名文件、导出和删除，但不提供“启用预设”“使用预设”或直接修改运行开关。

### 4.2 抽取破限方案

```text
在外部预设详情点击“抽取破限方案”
  → 勾选需要的提示词条目
  → 默认迁移全部正则，并按需取消或调整
  → 输入方案名称
  → 保存到破限方案库
```

抽取页必须同时显示：

- 条目名称、角色、完整正文和原预设默认状态；
- 条目在 `prompt_order` 中的位置；
- marker、空占位和系统托管内容的说明；
- 已选条目数、字符数和预计上下文体积；
- 配套正则的名称、作用位置和原始启用状态。

提示词默认由用户自行勾选。正则默认全部迁移到方案中，并继承外部预设里的启用或关闭状态；用户可以在保存前逐条取消迁移或调整状态。

第一版不自动判断哪些提示词条目属于破限，也不替用户修改正文。程序只提供完整信息、选择机会和确定性抽取。

### 4.3 管理和激活

```text
打开破限方案库
  → 查看方案来源与条目摘要
  → 导入、导出、编辑、重命名、复制或删除方案
  → 激活一份方案，或选择“不使用破限方案”
```

对话框上方显示“破限方案：名称”或“破限方案：无”。不再显示“当前预设”。

导出的 `.dsh-bypass-plan.json` 是自包含交换文件，保存提示词、正则、开关状态、来源追溯信息和必要兼容设置；不保存内部方案 ID、激活状态或对话绑定。导入会校验格式并创建新的方案，同名方案不会被静默覆盖。

## 5. 用户界面

右侧资源库增加两个并列入口：

### 5.1 外部预设库

- 标题：`外部预设库`；
- 说明：`导入和查看外部预设，并从中抽取破限方案`；
- 操作：导入、查看、重命名文件、导出、删除；
- 详情主操作：`抽取破限方案`；
- 不显示全局激活选择器；
- 不显示“DSH 预设预览”；
- 不允许直接驱动对话请求。

### 5.2 破限方案库

- 标题：`破限方案库`；
- 说明：`管理从外部预设中抽取的可运行方案`；
- 顶部提供当前激活方案单选器；
- 每张方案卡显示名称、来源信息、提示词数量、字符数和正则数量；
- 操作：导入、导出、激活、编辑选择、重命名、复制、删除；
- 删除外部预设不会影响已经保存的方案；
- 方案自身内容损坏时显示“方案已失效”，不得静默跳过缺失内容。

## 6. 目标数据模型

```text
BypassPlanState {
  activePlanId: BypassPlanId | ''
  plans: BypassPlan[]
  lastError: RuntimeError | null
}

BypassPlan {
  id: BypassPlanId
  name: string
  source: {
    presetName: string
    presetPath?: PresetPath
    presetDigest: string
  }
  entries: PromptEntry[]
  regexScripts: RegexScript[]
  createdAt: number
  updatedAt: number
}
```

破限方案是自包含的运行资源，因此：

- 提示词条目保存完整正文、角色、顺序、启用状态和内部标识；
- 正则保存完整脚本、作用范围、启用状态和执行顺序；
- 来源名称、路径和摘要只用于追溯，不参与运行时解析；
- 删除或修改来源外部预设不会改变已经保存的方案；
- 用户希望同步外部预设的新版本时，需要重新抽取，或在方案编辑器中手动更新；
- 删除外部预设和删除破限方案是两个互不级联的操作。

内部投影不作为用户数据长期维护：

```text
InternalPresetProjection {
  planId: BypassPlanId
  front: PromptEntry[]
  middle: PromptEntry[]
  back: PromptEntry[]
  regexScripts: RegexScript[]
  sources: ProjectionSource[]
  digest: string
  createdAt: number
}
```

## 7. 运行规则

### 7.1 激活和绑定

- Profile 同一时间最多激活一份破限方案；
- Tavern 每次请求读取 Profile 当前的 `activePlanId`；
- 切换全局激活方案后，从下一次请求开始立即生效；
- 游玩前台、游玩后台、卡片 Agent 和兼容模式统一读取当前全局方案；
- 已经写入 Session 的历史中段不会追溯改写，但后续请求不再继续使用旧方案；
- 编辑当前方案后，后续请求读取最新选择：稳定前缀和后带内容从下一次请求生效，每轮注入从下一轮生效；
- 没有激活方案时，Tavern 使用自己的内置提示词，不注入外部破限内容。

### 7.2 普通 DSH Tavern 请求

运行时直接读取绑定方案中的独立条目，把已启用条目自动映射为内部三段：

```text
稳定前缀
  → DSH 原生对话和任务上下文
  → 每轮注入
  → 后带内容
```

- 稳定前缀和后带内容只拼入真实请求，不写入权威 Session 历史；
- 每轮注入在新一轮生效；
- 三段保留条目原始角色和 `prompt_order` 相对顺序；
- DSH 原生人物卡、世界书、前台正文、后台结算和候选协议继续由各自模块负责；
- marker、人物信息占位和聊天历史占位由系统消费，不重复注入正文。

### 7.3 开发者兼容模式

兼容模式也必须从当前全局破限方案读取独立条目，不能绕过方案直接使用整份外部预设。编译器仍按 SillyTavern 语义处理方案内条目、系统托管 marker、人物卡、世界书、宏、正则和 `strict_tools`，用于差异测试和兼容验证。

兼容模式是开发工具，不向普通发布用户展示，也不改变“只有破限方案可以运行”的产品规则。

### 7.4 正则

正则不是提示词，但可能是方案不可缺少的配套行为，因此直接复制进破限方案：

- 抽取时默认迁移外部预设 `extensions.regex_scripts` 中酒馆真正执行的全部正则，并继承每条正则原有的启用状态；
- `extensions.SPreset.RegexBinding` 只作为 SPreset 编辑器元数据保留，不与运行正则合并，也不进入方案；
- 用户可以取消迁移某条正则，也可以在方案中单独启用或关闭；
- 方案保存后，正则与外部预设彻底分离；
- 正则执行仍遵循 `promptOnly`、`markdownOnly`、角色、深度和原预设启用语义；
- Session 保存模型层权威文本，展示层可以实时重新投影；
- 正则失败不得拖垮整轮对话，但必须保存逐项诊断；
- HTML 展示继续由安全 iframe 渲染，不进入模型上下文。

## 8. 失败与诊断

以下情况必须阻止方案激活或模型请求，并给出明确错误：

- 方案自身 JSON 损坏，或内部提示词、正则结构不完整；
- 宏解析、顺序恢复或内部三段投影失败；
- UI 显示已激活，但运行时没有读取到方案；
- 当前全局方案与模型请求日志记录不一致。

每次真实模型请求日志至少保存：

```text
planId / planName
sourcePresetName / sourcePresetDigest（仅用于追溯）
selectedEntryKeys / selectedRegexKeys / enabled states
internalProjectionDigest
最终 messages、角色、顺序和模型参数
响应正文、finish reason、错误和耗时
```

## 9. 迁移方案

现有 `RuntimePresetPlan` 只保存来源引用和开关快照，不能满足删除外部预设后继续使用的要求。迁移时需要升级为自包含的 `BypassPlan`：

1. `RuntimePresetPlan` 重命名为 `BypassPlan`；
2. 创建方案时，把被选提示词的完整内容复制到 `entries`；
3. 默认把全部正则及其原启用状态复制到 `regexScripts`；
4. 原路径和摘要只保存在 `source` 追溯信息中；
5. 新增 `activePlanId`；
6. 删除“应用方案后回写 `activePreset + entries + regexes`”的行为；
7. 旧对话的 `runtimePresetPath` / `bypassPlanId` 只保留迁移和最近一次实际请求的诊断用途，不再作为运行权威；
8. 运行时只从方案自身生成内部投影，不重新读取外部预设；
9. UI 删除“当前启用预设”和“DSH 预设预览”。

如果升级时存在 `activePreset` 和已选择条目，但没有对应旧方案，可创建一份未激活的“迁移方案”，让用户检查后自行激活。不得自动把整份外部预设投入运行。

## 10. 非目标

当前阶段不实现：

- 自动判断哪些提示词属于破限；
- 自动修改、总结或优化外部预设正文；
- 向普通用户解释或暴露前、中、后三段；
- 直接运行一整份外部预设；
- 承诺某份方案对所有模型和供应商都有效；
- 执行 Tavern Helper、同步 EJS 或未纳入兼容层的脚本；
- 把人物卡、世界书、写作风格和剧情控制自动塞入破限方案。

## 11. 验收标准

### 外部预设库

- 可以导入、查看、导出、重命名和删除外部预设；
- 详情完整展示原始条目、角色、顺序、默认状态和正则；
- 没有任何“启用预设”或直接使用入口；
- 只能通过“抽取破限方案”进入运行配置流程。

### 破限方案库

- 可以从一份外部预设选择提示词，并默认迁移全部正则后命名保存；
- 可以导入、导出、查看、编辑、重命名、复制、删除和单选激活方案；
- 导入不会自动激活或覆盖同名方案；
- 激活对象始终是方案 ID，不是预设路径；
- 删除或修改来源外部预设后，已保存方案仍可独立运行；
- 没有激活方案时不注入任何外部破限内容。

### 运行时

- 普通用户界面不出现“DSH 预设”、前、中、后等内部术语；
- 普通 DSH 请求从方案生成内部三段，兼容模式从同一方案生成 SillyTavern 请求；
- 两条运行链路使用相同的方案选择，不会回退到整份外部预设；
- 请求日志能追溯方案、来源、条目、正则、最终消息和结果；
- 固定兼容案例继续保持连续成功，不因产品模型迁移退化。

## 12. 建议实施顺序

1. 先把 `RuntimePresetPlan` 升级为自包含的运行权威 `BypassPlan`，增加 `activePlanId`；
2. 让普通 DSH 和兼容编译器都从方案读取条目；
3. 把全局激活状态迁移为方案 ID，并让对话字段退化为请求诊断快照；
4. 新增破限方案库和抽取界面；
5. 把现有预设库改为只读外部预设库；
6. 删除“当前启用预设”“DSH 预设预览”和旧配置方案文案；
7. 完成迁移测试与固定案例回归后，再移除旧状态字段和兼容 RPC。
