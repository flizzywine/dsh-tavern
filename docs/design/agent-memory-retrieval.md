# Agent 记忆检索

## 问题本质

长程游玩中，历史信息会不断增长，最终超过模型可用的上下文窗口和注意力容量。因此，记忆系统要解决的不是“持续向模型灌入更多信息”，而是“在当前任务需要时，找回正确的历史信息”。

最好的方式是向 Agent 提供检索工具，让 Agent 在任务明确后自主决定查什么、读什么；而不是由系统预测 Agent 将来的需求，提前抽取、压缩并注入信息。这是 Claude Code 类编码 Agent 展示出的重要架构经验：对于可搜索、可反复读取的资料，给 Agent 搜索与阅读能力，往往比提前替它决定上下文更可靠。

## 核心原则

1. **完整保存正文**：历史原文是权威信息源，不用变量、摘要或数据库记录取代它。
2. **不预测未来需求**：系统不在每轮预先猜测哪些记忆将来有用，也不把大量摘要固定回灌上下文。
3. **把检索权交给 Agent**：系统只提供检索与阅读能力；Agent 根据当前剧情或任务，自主决定要查找什么。
4. **渐进式披露**：先搜索关键词或语义线索，只返回简短命中目录；Agent 选中后，再读取附近完整正文。
5. **最小充分上下文**：只把支撑当前判断所必需的片段放回本轮上下文。

## 一句话原则

> 记忆不是预测需求并持续注入，而是完整保存信息，把检索工具交给 Agent，由它按需查找。

## 实现方案

> 状态：已实现。第一版只做当前对话内的历史正文检索，不引入向量数据库、模型摘要或跨对话记忆。

### 产品行为

- 前台 Agent 与后台 Agent 都在稳定前缀中长期拥有同一个 `tavern_recall_history` 工具。
- 后台的变量结算、姿势结算和候选生成只是不同的末尾任务指令，不切换工具集或 Skill 集。
- 工具只在 Agent 主动调用时返回资料；普通回合不自动检索，也不向上下文回灌历史摘要。
- 检索范围仅限当前对话已经正式提交的历史 Round。
- 历史正文只是回忆证据：只能用于确认已经发生的细节、关系和剧情，不得把旧场景当作当前场景，不得重复演绎历史正文。

### 权威数据

直接读取 Tavern Chat 的 `messages`，不另建一份事实数据库。

纳入检索：

- 已提交的玩家输入；
- 已提交且当前有效的助手 Session 正文；
- 开场白。

排除检索：

- 模型隐藏推理、工具调用和后台轨迹；
- 调试信息、错误信息、状态栏展示和 iframe 内容；
- 重新生成期间尚未完成的候选 Round；
- 已被重新生成替换或回退删除的正文；
- 人物卡中仅为兼容读取而保留的非当前 Swipe。

助手正文优先读取已经提交的 `message.text`，即模型后续续写实际使用的 Session 文本；不要重新采用 `sourceText` 或 `displayText` 建立另一套剧情事实。

### 深模块

新增 `History Recall` 模块，复杂性全部留在模块内部。调用者只需要一个查询接口：

```js
recall({ chat, query, turn, radius, limit })
```

参数规则：

- `query` 与 `turn` 必须且只能提供一个；
- `query` 搜索人物名、地点、物品、承诺或事件等线索，返回少量命中目录；
- `turn` 读取指定轮次及相邻 Round 的完整原文；
- `radius` 默认 `1`，限制为较小范围；
- `limit` 默认 `5`，限制搜索结果数量。

返回值统一包含 `found`、当前对话标识、命中轮次、角色、简短片段和可继续读取的轮次范围。工具层只负责解析参数和渲染结果，不自行拼装或搜索消息。

删除这个模块后，正文筛选、轮次归并、搜索排序、分页和重新生成一致性会重新散落到前台工具、后台工具及测试中，因此该模块具有足够深度。

### 检索方式

第一版采用本地确定性扫描，不建立持久索引：

1. 每次调用时从当前 Chat 构造有效 Round；
2. 统一大小写、空白和常见标点；
3. 完整短语命中优先，其次按查询词覆盖率排序；
4. 同分时较新的轮次优先；
5. 搜索阶段只返回短片段，Agent 再按轮次读取附近原文。

这样实现最简单，也天然跟随重新生成、回退和旧对话迁移。只有真实长对话扫描出现可测量的性能问题后，才增加派生索引；索引即使损坏也必须能从 Chat 原文重建，不能成为权威数据。

### 工具与提示词

模型只看到一个稳定工具：

```text
tavern_recall_history
检索或读取当前对话已经正式发生的历史正文，仅用于回忆细节和剧情。
检索结果不是当前场景，不得重复演绎、照搬旧台词或让已经发生的事件再次发生。
```

工具每次返回内容时，在结果最前面附加尾部提醒：

```text
【历史回忆资料】
以下是已经发生的历史，只用于确认和回忆；不得当作当前场景继续输出，不得重复演绎。
```

工具描述位于稳定工具目录中，只出现一次；结果提醒仅在实际调用时出现，利用末尾位置效应约束本轮使用方式。

### 前台接入

在现有 Tavern 工具注册处注册 `tavern_recall_history`：

- 根据执行中的 Session 找到当前 Chat；
- 仅允许 `story` 与 `script` 游玩模式；
- 调用 `History Recall` 模块；
- 以短目录或指定 Round 原文渲染工具结果。

工具定义始终存在，不随自由故事、剧本模式或当前轮次变化，保持前台请求前缀稳定。

### 后台接入

把同一个工具定义加入后台 Agent 的稳定工具目录，并把它设为所有非生图后台任务的共享只读工具：

- 共享工具由后台 Runner 统一执行，通过当前后台任务携带的前台 `sessionId` 找到 Chat；
- 不要求变量结算、姿势结算和候选生成分别声明该工具；
- 任务专用的提交工具仍由当前任务协议控制；
- 切换后台任务只追加新的任务指令，不注册、撤下或改写历史检索工具。

这会顺带消除“每个后台调用点重复配置历史工具”的浅层实现，确保工具目录和缓存前缀稳定。

### 并发一致性

- 检索只读取已经写入 Chat 的提交态，因此运行中的新正文不可见。
- 普通 Round 在前台正文提交后即可成为历史；后台结算结果不改变正文检索内容。
- 重新生成按照现有原子替换流程执行：新正文及后台结算全部成功前，检索仍看到旧 Round；整体提交后只看到新 Round。
- 回退完成后直接从最新 Chat 重建有效 Round，因此被回退内容立即不可检索。
- 工具调用期间若 Chat revision 变化，可以返回本次读取的 revision；不尝试把两版结果混合。

### 实施顺序

1. 新增 `History Recall` 模块及纯内存测试，覆盖正文筛选、查询排序、按轮读取和结果上限。
2. 注册前台工具，验证自由故事和剧本模式都能检索同一对话，而卡片工作台不能误用。
3. 为后台 Runner 增加共享只读工具能力，并接入同一个模块。
4. 增加前后台工具目录稳定性测试，确认切换候选、结算和姿势任务时工具集合不变。
5. 增加重新生成、回退和运行中 Round 的一致性测试。
6. 使用真实长程游玩记录验证中文关键词、相邻轮读取、宏解析结果以及不会召回状态栏。

### 验收标准

- 前台和后台均可按关键词找到久远的已提交正文，并继续读取命中轮次附近原文；
- 未调用工具时，请求中不增加任何历史正文或自动摘要；
- 返回内容不包含隐藏推理、后台轨迹、状态栏、已替换正文或未完成 Round；
- 后台任务切换不会改变稳定工具目录；
- 重新生成提交前后分别只检索到旧正文和新正文，不出现两版并存；
- 回退后的正文不可再检索；
- 提示词明确约束历史只用于回忆，不得重复演绎；
- 第一版不新增持久数据库，旧对话无需迁移即可使用。
