# 从酒馆到 Galgame：四层演出

2026-10-17 备忘。目标：不另做一个 Galgame 程序，而是让同一局故事从酒馆的文字游玩，一层一层过渡到 Galgame 式的演出。玩家停在哪一层都完整可用，往上加一层只是多一种看法。

实现细节见 [角色演出](cast-presentation.md)。

## 四层

| 层 | 是什么 | 加什么 | 变不变 |
|---|---|---|---|
| 1. 故事正文 | 正文、变量、回退、重新生成、存档 | — | 不变。所有演出都不改它，模型上下文也不受影响 |
| 2. 正文渲染 | 聊天里的正文，附上一份标注后渲染 | 台词的说话人与情绪、人物头像、差分小图、逐句配音（TTS） | 可选，默认关 |
| 3. 右侧舞台 | 右侧栏的一个窗口，和聊天并排 | 立绘、背景图、音乐 | 可选，打开才有 |
| 4. 全屏舞台 | 第 3 层放大，把对话框和舞台合在一起铺满页面 | 逐句翻页、自动播放、在舞台里直接输入下一轮 | Galgame 模式，随时退回聊天 |

要点：

- **第 1 层永远是唯一的真相**。第 2–4 层只读第 1 层和演出数据，不写回正文、变量或提示词。
- **演出数据是附在故事上的标注**：每轮台词标注（谁说、什么情绪）跟着正文版本走，回退、重新生成、编辑后自然失效；角色素材（头像、立绘、背景、声音、音乐）跟着人物卡走。
- **缺什么退一步**：没有标注就当旁白；没有立绘用头像，没有头像用首字；没有背景用卡图虚化；没有声音就不念。普通人物卡在每一层都能用，只是朴素一些。
- **入口由 Tavern 提供**，不借用人物卡自己的状态栏：状态栏是卡作者写的界面，每张卡都不一样。第 3 层由顶栏「舞台」打开，第 4 层由第 3 层的「全屏舞台」放大。
- **特化做多深交给插件**：本体保证每一层的基础版本能用；Live2D、镜头、特效这类更重的演出，通过插件接口替换第 3、4 层的呈现（例如 Galgame 分支的导演 AI）。

## 人物卡格式：沿用 CCv3，不另起新格式

新形态的游戏需要卡里带上演出素材，但不需要一个孤立的新格式。SillyTavern 系的 Character Card V3（`chara_card_v3`）已经留了位置：

- `data.assets`：素材列表，类型有 `icon`（头像）、`background`（背景）、`emotion`（表情立绘）、`user_icon`、`other`，`uri` 可以指向网址或卡包内的文件。
- **CHARX**：一个 ZIP，里面是 `card.json` 加素材文件（`embeded://` 指向包内路径），RisuAI 等前端已经在用。
- `data.extensions`：任意命名空间的扩展字段，ST 会原样保留不认识的内容。

所以第 2–4 层需要的东西大多有现成位置：主角头像 → `icon`，立绘 → `emotion`（名字就是情绪），背景 → `background`。CCv3 没有的部分放进 `extensions.dsh_tavern.cast`，例如：

- 多个人物的名单与别名，以及每个人物各自的头像和立绘（`emotion` 资产默认只属于主角）；
- 每个人物的声音；
- 背景、音乐与场景的对应关系。

这样做的好处：

- **向下兼容**：同一张卡在 ST、RisuAI 里还是一张能玩的文字卡，多出来的素材它们要么能用（头像、背景、表情），要么原样保留。
- **向上完整**：在 Tavern 里，同一张卡能直接点亮第 2–4 层，不用另外配素材包。
- **不孤立**：卡作者用熟悉的格式做卡，玩家用熟悉的方式分享卡；Galgame 化只是在同一种卡里多放一些素材。

已实现（2026-10-17）：

1. **导入**（`lib/domain/card-assets.js`）：读 CCv3 `data.assets` 的三种来源：CHARX 包内的 `embeded://`、RisuAI PNG 的 `chara-ext-asset_:N`（`__asset:N`）、JSON 里的 `data:`，以及 RisuAI 的 `extensions.risuai.emotions` 和 Tavern 自己的 `extensions.dsh_tavern.cast`。
   - 表情名按对照表对到 ST 的 28 种情绪（英文、中文、带编号的都认），进主角立绘。
   - 背景进角色素材，舞台用主背景（名叫 `main` 的，否则第一张）。
   - 对不上的表情、其他类型的素材原样保存，不使用，导出时写回。规范要求不能静默丢弃。
   - CHARX 本身存成 PNG（卡面是 PNG 时，把卡数据写进卡面）或 JSON；卡面不是 PNG 时没有封面，卡面图作为主角头像。
2. **导出**：人物卡库「导出 CHARX」。按 CCv3 写 `card.json` 和素材，主角立绘放在 `emotion`，背景放在 `background`（主背景名 `main`），保留的素材放回原类型；其他人物的头像、立绘和每个人物的配音声音写进 `extensions.dsh_tavern.cast`。v2 卡导出时补上 v3 的写法，内容不变。
3. **`extensions.dsh_tavern.cast` 结构**：`{ version: 1, characters: [{ name, aliases, avatar, sprites: { 情绪名: uri }, voices: { 配音渠道: 声音 } }] }`，uri 是包内的 `embeded://`。只放 CCv3 放不下的东西。

还没做：CHARX 超过 50 MB 时拒绝导入（Live2D 等大素材）；RisuAI 的附加素材（`x-risu-asset`，正文里 `{{img::名字}}` 引用的图）只保存不显示。
