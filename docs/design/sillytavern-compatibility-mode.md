# 酒馆兼容模式

> 这是默认关闭的实验性游玩能力。普通用户可以在 DSH 设置的“DSH Tavern”页面手动开启；开启后，左侧顶层导航最右侧显示“兼容（实验性）”。

## 目标

在 dsh-tavern 内尽可能复刻 SillyTavern 的真实请求构造，使依赖酒馆消息结构的人物卡和用户自行选择的外部预设条目可以继续使用。

它不是第二套应用。两种模式共用资源库、对话展示、模型适配器和日志，只在“如何构造本轮模型请求”这一处形成 seam。

## 两种请求模式

- **DSH 模式**：保留前台 Agent、后台 Agent、状态结算、候选项和 DSH 原生提示词。
- **酒馆兼容模式**：清空 DSH 系统提示和工具，停用后台状态结算，只发送按酒馆语义编译的前台消息；候选项可以按需手动生成。

默认入口仍是左侧 Tavern 顶层“游玩 / 卡片”。用户在设置中开启实验功能后，导航变为“游玩 / 卡片 / 兼容（实验性）”。游玩与兼容模式拥有独立的历史列表；切换入口只打开对应列表，不会把已有对话改成另一种请求模式。新建对话固定继承当前入口模式。关闭设置只隐藏兼容入口和历史，不改写已有兼容对话。

## 兼容请求编译

当前编译器负责：

1. 读取用户在预设库中启用的条目，并按来源预设的 `prompt_order` 还原顺序，不使用 DSH 前中后投影结果。
2. 保留每条提示词的 `system`、`user`、`assistant` 角色。
3. 展开人物描述、性格、场景、玩家设定、示例对话、聊天历史和世界书 Marker。
4. 支持人物卡 `system_prompt`、`post_history_instructions` 覆盖。
5. 按顺序执行变量与注释宏；宏处理后为空的条目不进入请求。
6. 正则运行时以原生 `extensions.regex_scripts` 为准，不执行 SPreset 编辑器副本；提示词正则只投影真实聊天消息，历史深度从最新消息倒序计算。
7. 执行绝对深度注入，再按 SillyTavern 1.18.0 的 `strict_tools` 语义展开示例名称、合并连续同角色消息、把中途 `system` 改成 `user`、补齐交替占位，并保留工具调用字段。
8. 复用模型适配器发送后处理完成的消息数组。

完全复刻仍是持续目标。世界书递归、概率、粘滞、预算裁剪、多模态、工具调用及不同供应商的消息合并规则，需要继续依据固定版本的 SillyTavern 源码逐项补齐，并通过同素材请求日志比对确认。

## 日志

每次真实请求保存到 `model-requests/<chatId>/`，包括：

- 请求模式、人物卡与预设引用；
- 宏、世界书、正则及选中条目追踪；
- 模型适配器收到的最终请求；
- 完整模型文本、终止原因、错误和耗时。

日志描述真实发生的请求，不把静态预览当成运行证据。
