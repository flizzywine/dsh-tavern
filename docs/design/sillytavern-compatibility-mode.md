# 酒馆兼容模式

> 这是开发调试能力，不属于普通用户的游玩设置。只有以 `DSH_TAVERN_DEV_MODE=1` 启动时，左侧顶层导航才显示“兼容”入口；发布环境默认隐藏，服务端也拒绝开启。

## 目标

在 dsh-tavern 内复刻 SillyTavern 的真实请求构造，用同一份人物卡、预设、世界书和模型配置，对比 DSH Agent 模式与酒馆原生语义。

它不是第二套应用。两种模式共用资源库、对话展示、模型适配器和日志，只在“如何构造本轮模型请求”这一处形成 seam。

## 两种请求模式

- **DSH 模式**：保留前台 Agent、后台 Agent、状态结算、候选项和 DSH 原生提示词。
- **酒馆兼容模式**：清空 DSH 系统提示和工具，停用后台 Agent、状态结算与候选项，只发送按酒馆语义编译的前台消息。

切换入口位于左侧 Tavern 顶层“游玩 / 兼容 / 卡片”导航。它影响当前游玩对话的下一轮，也作为之后新建游玩对话的默认值；不会重写已有历史。游戏准备弹窗和对话标题栏不再重复展示这一设置。

模式可在创建游玩对话时选择，也可在已有游玩对话顶部切换。切换从下一轮生效，不重写历史。

## 兼容请求编译

当前编译器负责：

1. 读取酒馆预设原始 `prompt_order` 和默认开关，不使用 DSH 前中后过滤结果。
2. 保留每条提示词的 `system`、`user`、`assistant` 角色。
3. 展开人物描述、性格、场景、玩家设定、示例对话、聊天历史和世界书 Marker。
4. 支持人物卡 `system_prompt`、`post_history_instructions` 覆盖。
5. 执行宏、提示词正则和绝对深度注入。
6. 复用模型适配器发送最终消息数组。

完全复刻仍是持续目标。世界书递归、概率、粘滞、预算裁剪、多模态、工具调用及不同供应商的消息合并规则，需要继续依据固定版本的 SillyTavern 源码逐项补齐，并通过同素材请求日志比对确认。

## 日志

每次真实请求保存到 `model-requests/<chatId>/`，包括：

- 请求模式、人物卡与预设引用；
- 宏、世界书、正则及选中条目追踪；
- 模型适配器收到的最终请求；
- 完整模型文本、终止原因、错误和耗时。

日志描述真实发生的请求，不把静态预览当成运行证据。
