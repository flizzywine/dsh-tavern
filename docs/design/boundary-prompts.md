# 破甲提示词设计

> 状态：预设库、破甲库、全局注入和 `tavern-extract-boundary-prompt` 已实现。Skill 负责分析与提取，用户明确要求保存时仍通过现有破甲写入工具落盘；有效性由用户按模型和案例验证。系统性实测暂缓，见[破限模块测试计划](boundary-module-testing.md)。

## 1. 产品定位

破甲提示词属于游玩前的准备内容。它与人物卡、世界书、素材和剧本一样，应在卡片工作台中通过对话完成阅读、分析、提取和修改，而不是发展成一套孤立的制作界面。

破甲库只负责运行时调控：查看已有文件、为当前会话选择一个文件、开启或关闭注入，并显示最近一次模型任务是否完成注入。

具体提示词是否有效仍需用户自行验证。dsh-tavern 可以随项目提供一到两个推荐配置，推荐模型只通过文件名表达，例如 `DeepSeek-推荐.md`。推荐配置默认关闭；推荐只代表项目当前测试结果，不承诺在模型、渠道或审核策略变化后仍然有效。

## 2. 核心原则

### 2.1 制作归卡片工作台

卡片工作台是统一的游玩准备空间。以下工作都由同一个卡片 Agent 完成：

- 新建和修改人物卡；
- 阅读、提炼和整理素材；
- 修改世界书和参考剧本；
- 阅读酒馆预设并提取破甲提示词；
- 新建和修改破甲提示词文件。

破甲不是另一种 Agent 模式。它只是卡片工作台中的一种起始任务，复用相同的会话、系统提示词、资源挂载和长程上下文能力。

### 2.2 预设归预设库

酒馆预设首先作为原始 JSON 导入预设库，保留原始文件和工作文件，并提供结构化只读阅读。导入时不运行正则筛选，不自动判断哪些条目属于破甲，也不直接生成破甲方案。

用户把预设挂载到卡片工作台后，由 Agent 根据预设结构、上下文和用户要求进行阅读与讨论。只有用户明确要求保存时，Agent 才把确认后的结果写入破甲目录。

这样可以复用统一的素材流程，也避免破甲模块承担不断变化的酒馆预设格式兼容工作。

### 2.3 文件就是方案

破甲提示词保存在专用目录中，每个 Markdown 文件就是一个可选方案：

```text
data/boundary-prompts/
├── deepseek.md
├── claude.md
└── 自用方案.md
```

- 文件名就是显示名称；
- 文件正文就是实际注入内容；
- 不建立方案数据库、内部 ID、模型映射或额外元数据；
- 用户可以通过卡片 Agent 修改，也可以直接编辑文件；
- 文件删除后，引用它的会话自动停止注入。

项目内置推荐配置也使用完全相同的 Markdown 文件格式，并作为普通文件出现在该目录中。系统不保存或解析“推荐模型”属性，不做模型自动匹配；文件名就是全部说明。首次安装时仅在同名文件不存在时创建，后续更新不得覆盖用户已经修改或删除的内容。

### 2.4 调控归侧栏

破甲库不承担预设导入、智能提取或复杂编辑。它只提供：

- 列出破甲目录中的文件；
- 查看文件正文；
- 为当前会话选择一个文件；
- 开启或关闭注入；
- 显示当前选择和最近一次注入状态；
- 删除不再需要的文件。

复杂的新建、分析、组合和改写通过卡片工作台完成。侧栏可以提供“进入卡片工作台制作破甲提示词”的入口，但不复制一套制作流程。

## 3. 卡片模式整合

### 3.1 新的起始任务

卡片工作台增加第四个起始入口：`从预设提取破甲`。

完整入口为：

1. 修改人物卡；
2. 从资料新建人物卡；
3. 从预设提取破甲；
4. 空白开始。

新入口只提供认知上的任务起点，不创建新的 Agent 模式。它与其他入口一样创建 `card` 会话，使用同一个卡片 Agent、工具和固定系统提示词，只额外追加一段破甲提取任务说明。

用户也可以从“空白开始”进入工作台，再挂载预设并要求 Agent 提取破甲提示词。

### 3.2 预设导入流程

1. 用户选择“从预设提取破甲”；
2. 用户从预设库选择已有预设，或导入新的酒馆预设；
3. 原始预设进入 `data/originals/materials/`，工作文件进入 `data/resources/materials/`；
4. 预设作为结构化资源挂载到当前卡片工作台；
5. Agent 按需阅读原始条目、顺序、角色和启用状态；
6. Agent 与用户讨论哪些内容需要保留、组合或修改；
7. 用户明确要求保存后，Agent 使用专用工具写入一个 Markdown 文件；
8. 新文件立即出现在破甲库中，但默认不为任何会话开启。

预设始终是素材，破甲文件始终是 Agent 和用户共同确认后的产物。二者不能在导入阶段被隐式等同。

### 3.3 卡片 Agent 工具

卡片 Agent 增加专用写入工具：

```text
tavern_update_boundary_prompt({
  name,
  text
})
```

Interface 约束：

- `name` 映射为破甲目录中的安全 Markdown 文件名；
- `text` 按 Agent 提交的正文原样保存，不再自动总结、润色或加工；
- 同名文件已存在时必须明确作为修改目标，不能静默覆盖；
- 拒绝目录逃逸和非 Markdown 目标；
- 写入失败时保留旧文件，并向 Agent 返回明确错误；
- 工具只写破甲目录，不修改人物卡、世界书、剧本或导入的预设素材。

读取现有破甲文件使用专用的 `tavern_read_boundary_prompt`：不传文件名时只列目录，传入文件名时读取完整正文。工具只读专用目录，不扩大其他文件权限。

## 4. 运行时注入

当前会话只保存最小选择状态：

```text
BoundaryPromptSelection {
  enabled
  filename?
}
```

所有模型生成流程只需要调用一个小 Interface：

```text
resolve({ sessionId, operation })
  -> { filename, text } | null
```

Interface 约束：

- 未开启、未选择、文件不存在或文件为空时返回 `null`；
- 一次最多解析一个文件；
- 返回正文必须与文件内容一致；
- 调用方不需要理解文件来源或制作过程；
- 读取或注入失败不得阻止原任务，应回退为不注入并记录明确错误。

启用后，选中文件作为独立系统提示词区块注入当前会话的所有模型任务，包括游玩正文、候选项、状态结算、世界书模型任务和卡片 Agent。它不拼入人物卡，也不覆盖各任务原有的系统提示词、工具权限和输出格式。

## 5. 信息架构

```text
资料库
  └── 导入酒馆预设原文件
          ↓ 挂载
卡片工作台
  └── Agent 阅读、讨论、提取、修改
          ↓ tavern_update_boundary_prompt
data/boundary-prompts/*.md
          ↓ 侧栏选择与开关
当前会话的全部模型任务
```

这里有两个清晰的 seam：

- 制作 seam：卡片 Agent 只通过专用工具写破甲文件，不直接操作运行时选择；
- 运行 seam：模型任务只通过 `resolve` 取得当前文件，不理解预设和卡片工作台。

## 6. 第一版范围

- 建立 `data/boundary-prompts/` 文件目录；
- 酒馆预设通过预设库按原始 JSON 导入；
- 卡片工作台增加“从预设提取破甲”起始任务；
- 卡片 Agent 可以创建和修改破甲 Markdown 文件；
- 破甲库可以查看、选择、开启、关闭和删除文件；
- 当前会话启用后，文件内容注入全部模型任务；
- 界面显示当前文件和最近一次注入状态。

## 7. 暂不支持

- 在破甲库直接导入酒馆预设；
- 在导入阶段用正则自动筛选破甲条目；
- 建立方案数据库、标签系统或模型自动匹配；
- 内置大规模方案库，或维护无法实际测试的模型适配列表；
- 普通用户运行时自动测试、评分或切换方案；开发阶段的批量验证由独立的本地测试框架承担；
- 根据敏感内容自动开启；
- 将破甲内容写入人物卡、世界书、剧本或原始预设；
- 绕过模型之外的渠道审核或外部审核。

## 8. 验收标准

### 8.1 卡片工作台

- 酒馆预设能够导入预设库并保留原始版本；
- “从预设提取破甲”进入的是统一 `card` 会话，而不是独立模式；
- Agent 可以读取挂载的预设，并在用户明确要求后写入破甲文件；
- Agent 不会在只读、分析或讨论阶段修改破甲目录；
- 现有破甲文件可以在卡片工作台中继续讨论和修改；
- 写入结果立即出现在侧栏，但不会自动启用。

### 8.2 文件与侧栏

- 一个 Markdown 文件对应一个方案，不存在额外方案数据库；
- 项目最多提供一到两个推荐配置，推荐模型只写在文件名中，首次安装后默认关闭；
- 用户直接修改文件后，侧栏和下一次注入读取最新正文；
- 侧栏不再出现“导入酒馆预设”或自动提取界面；
- 用户可以为当前会话选择一个文件并独立开启或关闭；
- 删除已选择文件后，该会话自动停止注入。

### 8.3 注入

- 开关关闭时，任何模型任务都不存在破甲内容；
- 开关开启时，所有模型任务只注入当前选择的一个文件；
- 文件正文原样进入独立系统提示词区块；
- 各任务原有提示词、工具权限和输出格式不受影响；
- 破甲目录异常时，原模型任务仍可在不注入的情况下继续。

## 9. 实施顺序

1. 先把现有方案 JSON 存储迁移为 `data/boundary-prompts/*.md`，保留当前会话选择与全局注入能力；
2. 删除破甲库中的预设导入、正则候选和复杂编辑流程，只保留运行时调控；
3. 新增预设库，把酒馆预设作为原始 JSON 导入并结构化只读展示；
4. 为卡片工作台增加“从预设提取破甲”任务提示词和入口；
5. 为卡片 Agent 增加安全的破甲文件写入工具；
6. 验证“导入预设 → Agent 提取 → 文件出现 → 侧栏选择 → 全任务注入”的完整流程；
7. 最后删除旧的预设解析器、方案数据结构和迁移期间的兼容代码。
