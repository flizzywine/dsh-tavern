# ADR 0005：重新生成替换最后一轮，不建立 Swipe 分支

- 状态：接受
- 日期：2026-09-02

## 背景

酒馆 Swipe 可以在同一消息楼层保存并切换多个版本；DSH Agent Session 则是只追加轨迹。把 Swipe 直接映射进持续 Session，会让 Chat 当前选择、模型可见 Surface 和后台结算状态发生分叉，并产生跨前后台的并发一致性问题。

## 决定

删除产品级 Swipe 切换。正文重新生成只替换最后一个已完成 Round：保留玩家输入，重新执行前台正文和后台状态结算，全部成功后才采用新整轮；失败时恢复旧整轮。已有后续剧情时不允许改写更早轮次。

## 结果

- Story Timeline 保持单一路径，与 Agent 的追加式执行模型一致。
- 前台正文、后台状态、checkpoint、revision 和模型 Surface 以同一个成功边界提交。
- 用户失去多个正文候选间来回切换的能力，但仍保留一键重新生成和带意见重新生成。
- 人物卡兼容数据可以继续带有 Swipe 字段，但它们不再形成可交互剧情分支。
