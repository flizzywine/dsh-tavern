# ADR 0005：重新生成替换最后一轮，不建立 Swipe 分支

- 状态：接受
- 日期：2026-09-02

## 背景

酒馆 Swipe 可以在同一消息楼层保存并切换多个版本；DSH Agent Session 则是只追加轨迹。把 Swipe 直接映射进持续 Session，会让 Chat 当前选择、模型可见 Surface 和后台结算状态发生分叉，并产生跨前后台的并发一致性问题。

## 决定

删除产品级 Swipe 切换。正文重新生成只替换最后一个已提交 Foreground Turn。保留玩家输入，开始生成时撤下旧正文。提交前失败、取消或中断恢复后，旧正文保持撤下，原正文只供重试使用。新正文成功提交后立即采用，再异步执行后台状态结算。结算失败时保留新正文并允许继续。已有后续剧情时不允许改写更早轮次。

## 结果

- Story Timeline 保持单一路径，与 Agent 的追加式执行模型一致。
- 前台正文、checkpoint 和 revision 一起提交。模型 Surface 从持久投影记录接续，后台状态按绑定版本单独提交。
- 用户失去多个正文候选间来回切换的能力，但仍可从统一入口重新生成正文，指导意见可留空。
- 人物卡兼容数据可以继续带有 Swipe 字段，但它们不再形成可交互剧情分支。
