# 多世界书真实界面游玩验证

日期：2026-09-12。分支：`experiment/multi-worldbook-merge`。

## 环境与方法

使用已安装的 DSH CLI 0.1.2-rc.1、实验分支插件、独立临时 Profile 和有界面的 Chromium。通过实际界面导入、绑定、开局、输入并发送消息；不修改用户原有卡片或存档。不是独立组件 fixture，也不是用户正式 Desktop Profile 的覆盖安装测试。

人物卡来自公开 `demo/cards/avra-before.json`，测试副本名为“阿芙拉 · 多书手测”。仅给开场白增加两个关键词。全部前台与后台请求使用 `deepseek-official / deepseek-v4-flash`。

两本独立 JSON 世界书均使用 UID 0、1：

- 主书：常驻“麦酒三枚铜币、木牌蓝色”；关键词“铜铃渡口”对应“萤火照潮、鱼纹铜片”。
- 附加书：常驻“免费银柄雨伞、木牌红色”；关键词“星砂信箱”对应“黄昏开启、七角星封口”。

蓝色与红色是故意制造的语义冲突。测试输入只问设定，不直接提供秘密答案。

## 已观察结果

- 在世界书库通过文件选择器分别导入两本书，从书详情绑定同一人物卡。人物卡详情显示两本。
- 上移附加书后正确成为主书；移回后恢复原顺序。逐本解绑后显示一本，重新添加后恢复两本。
- 冲突提示正常显示，不阻止开局。两本源文件与导入原件逐字节一致。
- 初次两轮游玩中，两本常驻都进入真实请求的 system。模型既使用酒价，也使用银柄雨伞；把蓝红冲突解释成木牌正反两面。此行为是本次模型生成，不是产品的冲突裁决策略。
- 第二轮请求与正文都包含两本动态条目的秘密。`preparedWorldBook.refs` 为 `entry:1`、`entry:3`；再下一轮准备因现有冷却规则而为空。
- 修复后重新开局，第一轮真实请求及正文就包含两本动态条目，回答正确给出四项秘密；没有额外开场结算模型请求。
- 修复后普通卡开局快照包含四个条目，UID 为 0、1、2、3。主书编号保持，附加书撞号重编号，内容无丢失。
- 再从人物卡详情解绑附加书，绑定索引只剩主书。修复后已开的双书局快照逐字比较不变，仍为四条；新开局快照仅两条。
- 单书新局实际发送一轮后，请求 system 只有主书酒价与蓝色木牌；messages 中只有主书口令，无七角星。请求任何字段均不含附加书的银柄雨伞、红色木牌或七角星，验证没有跨局残留。
- 合计三局、四轮前台对话、四次后台结算全部完成。第一局第一轮因模型主动调用一次工具共两步；其余前台各一步。九份请求记录均为 Flash，无 Pro。

本地证据保存在 `output/playwright/worldbook-manual/`（忽略目录）：测试卡、两本测试书、`merged-opening.json`、只保留模型/状态/标记计数的 `request-evidence.json`、解绑截图 `unbound-extra.png`。完整测试内容只存在隔离临时 Profile；文档不收录凭据或认证 URL。

## 本次手测发现并修复

- `7b0b207`：worktree 的 `.git` 是文件，版本读取把它当目录，界面反复报 ENOTDIR。现在支持 gitdir、commondir、共享 loose/packed refs 与 detached HEAD。
- `8981360`：直接输入第一轮绕过候选项准备，导致开场白关键词未召回。发送第一轮前本地准备开场世界书，不扫描玩家输入，不启动额外模型调用，已有准备不重复计算。
- `3583ecf`：无交互脚本的普通开场没有准备草稿，因此没保存世界书快照。开局入口补建草稿，让普通卡和脚本卡都保存本局合并书。

## SillyTavern 对照

[官方 World Info 文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)允许人物卡配置主书及附加书，常驻条目与关键词条目有不同激活方式；官方人物卡导出只携带主书。

同时核对本机 SillyTavern `d7adfdb61` 的 `public/scripts/world-info.js`：`getCharacterLore()` 收集主书和 `extraBooks`，用 Set 去重书名；条目携带来源书名；激活 Map 用 `${entry.world}.${entry.uid}` 区分编号。它没有对全部常驻设定做语义冲突分析。

本产品继续采用已确认的本局单份合并快照：附加条目撞号重编号，导出包含全部合并条目；脚本通过主书名称或 current 访问。并未实现 SillyTavern 任意书名的多命名空间脚本 API。
