# 潜令 V1.7 宿主面板手测

日期：2026-09-12。原卡为用户提供的 `V1.7-r4.20.18---1.png`。按用户要求，在当前运行的 Tavern 环境中新建测试局，未改原卡或已有游戏。未把卡片或脚本正文加入仓库。

## 复现

从原卡提取 `qlPanelDocumentScore` / `qlPanelParentDocument`，在生产 `installTavernTrustedHostFacade` 的宿主环境执行：只有窗口与文档基础分 40，低于阈值 60，返回 null。实际浏览器选择原卡、切换到第一个故事开场并点击“开始新游戏”，随后重复出现“酒馆主界面尚不可访问”。同时出现 `initializeGlobal is not defined`，使控制器初始化在发布全局对象处中断。

## 修复

- Trusted Host Facade 提供可见的 `#chat` 兼容挂载容器，仅在宿主没有同名节点时创建；多个脚本共用，最后一个持有者退出时移除，不移除已有节点。
- 不提供隐藏的假 `#send_textarea`。原卡确实会读写输入框，假输入框会截走真实交互。
- 补齐脚本沙箱 `initializeGlobal`，先写入当前 window 对象，再通过现有事件总线通知 `waitGlobalInitialized` 等待者。

原卡探针修改后得分 90，选中宿主；原卡面板实际挂在 documentElement，而非聊天挂载容器内。

## 实际浏览器结果

当前服务加载实验 worktree，修复同步到其源文件与生成客户端后重启服务，再从历史打开本次测试局：

- 变量结构注册成功，MVU 加载成功；未再出现上述两条阻断错误。
- 右下角出现“潜”悬浮球；点击后显示控制中心。

- 在实际共享脚本 iframe 中先等待再调用 initializeGlobal，等待者收到同一对象；测试全局键随后删除。

相关界面、模块加载、脚本生命周期测试：93 项通过；生成客户端一致性、diff 检查通过。

本次未调用文字模型、独立群聊 API 或生图服务，未验证全部玩法、输入框回退写入以及正文后续生成。两个真实 textarea 存在于当前宿主，未把其中任意一个冒充为原生酒馆输入框。控制中心显示与页签交互通过，不等于整张卡所有功能已兼容。
