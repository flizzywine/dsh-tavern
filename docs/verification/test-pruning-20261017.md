先记录候选用例的实际执行范围，再按边际生产分支、函数与代码范围筛选；源码文本、固定文案和重复配置断言优先考虑。保留持久化、回滚、损坏恢复、凭据保护和平台安装的关键回归。对某些路径重复的行为用例仍有删除，执行覆盖重叠不表示断言完全等价。

## 测量口径

- 遵守相关文件验证范围，没有运行全量测试。固定快照对照以 284 个候选/保留测试文件为基础，加入 58 个按实际导入模块选出的未改动相关文件；这 58 个文件在同一生产快照上的记录前后复用。另对最后一次替换涉及的两个文件做了独立验证。这里的百分比是该相关集合的测量值，不是全量测试覆盖率。
- 行覆盖使用 Node 22 原生实际行命中；文件集合与行分母固定为基线。函数按源码起止偏移匹配；分支使用基线范围，在同一函数内映射到删除后最窄的包围范围，缺失函数/文件按未命中处理。基线分支、函数分母保持不变，避免 V8 运行时少发现分支而抬高比例。原生未归一化结果也保留在 JSON 中。
- 包含 Tavern 自有运行代码、启动器、内置包及 testsets/lib；排除 node_modules、vendor。动态 eval/VM 脚本与非匹配文件不在该原生生产覆盖率中。逐用例采集另记录了动态脚本范围，用于筛选。
- 起始代码以记录内的 baselineCommit 为版本指针，叠加采集时已有改动；精确源码由生产哈希界定，不声称其他聊天同期新增生产功能通过该固定快照验证。
- 主测试 worker 覆盖记录完整。基线一条 0 字节 loader 记录未计入，最终对照没有损坏记录。快照最初缺 Git 元数据，导致 4 条运行包测试失败；补齐元数据后，该文件重新验证全部通过，其记录并入基线。删除方案的相关集合验证没有失败。
- 当前工作区有同期修改，应用时逐条匹配原测试内容；保留六个文件里的新内容，尤其保留了同期加强的插件面板 API v2 回归，改删一个纯源码链接一致性检查。该替换前后仅出现相同的宿主 preload 生产覆盖，未改变表中的指标。
