# 原生 Swipe 开场选择兼容

2026-09-12：针对用户提供的开场选择台诊断与原卡做共享层修复，未改写原卡。

## 原因与行为

- 选择台调用 `SillyTavern.getContext().swipe.to(null, 'right', { forceMesId: 0, forceSwipeId: index })`，原桥接未提供该接口，预览也未识别这类选择台。
- 主开场为空时，SillyTavern 的 `getFirstMessage()` 会先移除空主开场再分配 swipe 编号。原有预览与会话开场描述保留空位置，导致编号错位。
- 预览与未推进的正式开场现在共用编号映射；保留资源本身的 `alternate:N` 标识。预览选择已有开场，正式开场通过已有准备流程进入新会话，不修改旧会话历史。
- 只支持开场消息及已有有效开场编号。没有增加任意历史消息切换或生成新 swipe 的功能。
