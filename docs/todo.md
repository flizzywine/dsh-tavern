## P2：人物卡专属 UI 工具

正则是兼容层，不能根治横线、块头或字段缺失等掉格式问题。长期方案是在人物卡导入或准备阶段生成并缓存专属 UI Adapter：

- [ ] 分析人物卡的正则、HTML 模板和字段协议，生成结构化 schema 与专属 UI 工具；模板只生成一次。
- [ ] 前台主 Agent 只生成纯正文，不再输出状态块、HTML、分隔符或其他 UI 协议。
- [ ] 正文完成后启动独立 UI 任务，只提交本轮结构化变量，并调用人物卡专属工具。
- [ ] 工具校验参数并确定性渲染 UI；校验失败时返回具体错误并限次重试 UI 任务，不重新生成正文。
- [ ] UI 结果绑定当前剧情 revision；任务失败时保留上一版有效界面，不影响正文、候选和状态结算。
- [ ] 不同人物卡可以使用不同 schema，但统一接入回复展示接口。
- [ ] 后续支持差量更新已有界面，进一步减少 token 和格式错误。
- [ ] 正则在过渡期继续承担旧卡兼容；专属工具稳定后只作为导入时的模板来源，不再参与每轮正文删除和替换。
