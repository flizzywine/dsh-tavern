## 2026-09-01：显式启用与输入框上方入口

- 后台：旧配置缺少 `enabled` 时关闭；先保存完整配置才能启用，部分保存不会丢其他字段；并发保存串行。关闭或前台生成中拒绝新任务，已保存图片仍可读取。
- 前台：主按钮注册在原有 `conversation.input.dock` 操作栏，正文 renderer 不再放生成按钮；读取真实规划/生成/保存阶段；保存后单独启用，未保存的配置不能直接启用。
- 测试：`scene-illustration.test.mjs` 覆盖上述后台行为；`play-controls-chat-snapshot.test.mjs` 验证实际 dock 的目标轮次、Chat/Session 选择和卡片模式隔离；本机真实 DSH Agent loop + 附件测试通过。
- 浏览器：使用生产 renderer、生产 dock 注册和设置函数，测试宿主仅提供会话元数据、脚本文字模型和本地图片 HTTP 接口。保存与启用时调用数均为 0；点击后 2 次文字请求（工具提交及收尾）、1 次图片请求、前台 0 条新增消息；关掉后按钮消失但图片、下载保留；重启仍可见。390px 窄屏下图片与操作栏未撑出正文，页面可滚动，无浏览器错误。
- 这不是完整部署的 Desktop/CLI 端到端验收，不证明商业渠道可用，也不代表后续重画、调整、取消等尚未实现流程已经通过。整个规格仍在开发中。

## 2026-09-01：方案与标签的持久化主流程

- 新增 `scene-plan.js`，按游戏、正文有效历史和表达版本保存人物事实版本、标签块及画面方案；同一个原子写入发布一致版本，不逐字段写半成品。人物事实不含渠道标签，换表达配置不改变相同事实的版本。
- 子代理工具改为 `submit_scene_plan`，只提交有变化的字段、标签及必要来源引用。宿主验证字段、重复身份和原文引用，允许一次格式修正；成功保存后才由宿主单独请求图片。保存成功不依赖 Agent 最后一条确认成功。
- 通过 `scene-plan.test.mjs` 验证：只改动作时其他标签版本不变、清除不残留、场景不连续时不继承旧动态信息、同名人物分别持久化、未来/其他分支不串入、过期提交拒绝、切换表达不改人物事实版本。
- `scene-illustration.test.mjs` 增加实际主流程测试：格式修复发生于付费请求前，失败图片复用方案，历史正文不借最新姿态，两次绘图之间的剧情进入输入。只取目标及上次方案之后的正文，以完整段落预算裁剪，记录缺失和字符预算（不冒充 token）；裁剪后不能确认连续性。
- 全套回归 976 项通过，包含本机真实 DSH Agent loop / 工具 / 附件测试；测试宿主浏览器验证方案提交→图片生成→展示，仍为 2 次文字请求、1 次图片请求、前台无新增消息。供应商和文字模型返回仍使用本地夹具，不是商业渠道或真实语义/画质验收。
- 未完成项仍包括：相关原始卡片/世界书设定提取、重画与调整、风格、多渠道、参考图、图片版本浏览、取消与恢复、完整日志导出。以上不因基础模块通过测试而标为完成。
