# 卡片工作台产品设计

## 1. 定位

卡片工作台是游玩前的对话式准备空间。用户可以修改人物卡、从资料制作人物卡、修改资料，或从空白任务开始；四个入口共用同一个 `card` Agent、工具和系统提示词，只追加不同的起始任务说明。

工作台不负责角色扮演或续写剧情。剧本绑定仍由人物卡详情页直接管理；外部预设的运行时开关由预设管理器负责。

## 2. 四个起始任务

### 修改人物卡

先选择一张人物卡，再进入工作台。Agent 通过 Tavern 专属读取和更新工具渐进读取字段、世界书与 raw 扩展；只有用户明确要求或确认后才提交最小变更。

### 从资料新建人物卡

先从资料库选择至少一项资料。工作台创建后自动引用所选资料，由 Agent 分批阅读并与用户确认角色名、玩家身份和需要保存的设定，再创建正式人物卡。

### 修改资料

先从资料库选择至少一项资料。Agent 读取资料工作版，理解修改目标；信息不足时先讨论或提问，用户明确要求或确认后才使用原生文件工具修改工作文件。导入时保存的原版不被改写。

### 空白开始

不预设任务或资源，直接进入同一个卡片 Agent。用户可以之后引用人物卡、预设或资料并说明任务。

## 3. 资源与存储

Better Sidebar 提供三个职责分离的库：

- 人物卡库：导入、查看、编辑、删除人物卡，管理世界书和剧本绑定；
- 预设库：原样保存、结构化阅读 SillyTavern JSON，并管理全局运行时提示词条目；
- 资料库：保存素材、剧本、设定和其他普通参考文件。

资源首次导入时，原版进入 `data/originals/`，可编辑工作版进入 `data/resources/`。Agent 默认读取工作版；人物卡只能通过 Tavern 专属工具修改，资料工作版可以在用户确认后通过原生文件工具修改。删除整个资源时，工作版和原版一并删除；从对话中移除引用不等于删除资源。

人物卡、预设和资料通过相对路径成为结构化 `@资源` 引用。引用只挂载路径，不自动把全文塞入上下文，也不自动建立剧本绑定。

## 4. Agent 能力边界

卡片 Agent 复用 DSH 极简模式，获得当前平台的 Shell、`str_replace_editor` 和 Tavern 专属工具：

- `tavern_read_card`：按字段渐进读取稳定人物卡投影；
- `tavern_read_card_raw`：按 JSON Pointer 读取正则、脚本、MVU 和未知扩展；
- `tavern_read_worldbook`：按编号、关键词或分页读取世界书；
- `tavern_update_card`：暂存并在本轮最终回复后提交已确认的人物卡最小变更；
- `tavern_restore_card`：仅在灾难性损坏且用户再次确认后从原版恢复；
- `skill` 与 `tavern_save_skill`：按需使用或创建 Tavern 专属 Skill。

预设工作文件只读。预设条目的运行时启停是确定性的产品功能，不交给 Agent 操作。游玩 Agent 和后台 Agent 不获得卡片工作区文件工具或 Skill。

## 5. 写入规则

1. 阅读、搜索、比较和讨论不产生写入。
2. 用户目标或可写对象不明确时，先确认，不猜测。
3. 人物卡只提交已确认的最小字段、世界书条目或 raw 路径变化。
4. 资料修改只作用于已引用的工作文件，保持未要求修改的内容不变。
5. 初始原版在资源存续期间保持不变；系统不因此创建逐轮版本历史。
6. 修改完成后直接说明实际改动，不要求用户再点击一次保存。

## 6. 渐进读取

初始上下文只提供资源地图、文件路径和必要状态，不注入全部资源正文。Agent 先查看文件规模、结构或检索结果，再读取当前任务所需的最小范围。没有实际读取的内容不得声称已经读过。

对话历史、压缩和一般记忆复用 DSH；人物卡路径、挂载资源、工作草稿和已经落盘的修改属于 Tavern 权威产品状态。

## 7. Skill

卡片 Agent 只扫描项目内置和 Tavern 用户目录中的 Skill。当前内置 `tavern-create-skill` 与 `tavern-extract-writing-style`，分别用于制作通用 Tavern Skill 和从样文提炼文风规则。旧的预设破甲抽取 Skill 已删除。

Skill 是工作方法，不是人物卡字段，不自动写入资源，也不进入游玩模式。

## 8. 验收标准

- 四个入口都创建同一种 `card` 会话，没有额外 Agent 模式；
- “修改资料”必须先选择资料，创建后自动引用所选工作文件并追加任务说明；
- UI 不再出现“从预设提取破甲”或破甲库；
- 人物卡、预设、资料三个库职责清晰，预设管理器独立处理全局条目开关；
- 普通讨论不会写文件，确认后的资料修改只改变工作版；
- 人物卡更新继续经过结构化工具校验和最终回复提交；
- 大型资源按需读取，不因挂载而自动进入完整上下文；
- 完整测试覆盖四入口、资源引用、工具可见性、原版保护和修改提交。
