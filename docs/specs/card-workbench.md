# 卡片工作台产品设计

## 1. 定位

卡片工作台是游玩前的对话式资源准备空间。用户可以修改人物卡、从剧本制作人物卡、修改剧本、修改世界书、修改预设，或从空白任务开始；六个入口共用同一个 `card` Agent、工具和系统提示词，只追加不同的起始任务说明。

工作台不负责角色扮演或续写剧情。剧本绑定由剧本库或人物卡详情页直接管理，不通过 Agent；预设可以安全编辑，但不会应用到当前 Agent，运行时效果仍然禁用。

## 2. 六个起始任务

### 修改人物卡

先选择一张人物卡，再进入工作台。Agent 通过 Tavern 专属读取和更新工具渐进读取字段、世界书与 raw 扩展；只有用户明确要求或确认后才提交最小变更。

### 从剧本新建人物卡

先从剧本库选择至少一份剧本。工作台创建后自动引用所选剧本，由 Agent 分批阅读并与用户确认角色名、玩家身份和需要保存的设定，再创建正式人物卡。

### 修改剧本

先从剧本库选择一份剧本。Agent 读取剧本工作版，理解修改目标；信息不足时先讨论或提问，用户明确要求或确认后才使用原生文件工具修改工作文件。导入时保存的原版不被改写。

### 修改世界书

先从世界书库选择一个独立世界书或人物卡内置世界书。工作台自动添加有明确类型的世界书引用；Agent 按编号、关键词或分页读取相关条目，用户确认后通过世界书 Library interface 提交条目级最小修改。

### 修改预设

先从预设库选择一个预设。Agent 按 JSON Pointer 渐进读取原始工作 JSON，用户确认后提交 `set` 或 `delete` 最小路径操作。保存时重新校验 JSON 与可识别的 SillyTavern 结构，未知字段保持不变。目标预设不会应用到当前 Agent，也不能在此任务中测试运行效果。

### 空白开始

不预设任务或资源，直接进入同一个卡片 Agent。用户可以之后引用人物卡、预设、世界书或剧本并说明任务。

### 调试游玩对话

“酒馆状态”侧栏提供人物卡调试区，用户可从最近的游玩回复中选择目标轮次并点击“交给卡片 Agent 调试”。系统为同一人物卡新建卡片工作台，并只读挂载用户选中的游玩轮次；不会在正文消息中插入调试控件，也不会复制、修改或自动注入整段游玩历史。

卡片 Agent 先按需读取该轮概览，再分别查看模型原文、进入 Session 的文本、展示文本或按当前人物卡重新计算的正则诊断。历史展示结果与当前诊断必须明确区分：前者是该轮保存内容，后者用于验证当前工作版人物卡。Agent 先说明问题位于模型输出、Session 投影、展示正则还是人物卡规则；只有用户明确确认后才能修改人物卡。

## 3. 资源与存储

Better Sidebar 提供四个职责分离的库：

- 人物卡库：导入、查看、编辑、删除人物卡，并显示或调整当前世界书和剧本绑定；
- 预设库：原样保存、结构化阅读和编辑 SillyTavern JSON；运行时效果保持禁用；
- 世界书库：统一管理独立世界书与人物卡内置世界书；
- 剧本库：保存小说、剧情大纲和故事素材，查看工作版，并与人物卡一对一绑定；剧本和人物卡都允许暂未绑定。

资源首次导入时，原版进入 `data/originals/`，可编辑工作版进入 `data/resources/`。Agent 默认读取工作版；人物卡只能通过 Tavern 专属工具修改，剧本工作版可以在用户确认后通过原生文件工具修改。删除整个资源时，工作版和原版一并删除；从对话中移除引用不等于删除资源。

人物卡、预设、世界书和剧本通过结构化引用挂载到对话。独立世界书引用 `worldbooks/...`，人物卡内置世界书保留“世界书 + cards/... 来源”语义，不会退化为整张人物卡。引用只挂载目标，不自动把全文塞入上下文，也不自动建立剧本绑定。

## 4. Agent 能力边界

卡片 Agent 复用 DSH 极简模式，获得当前平台的 Shell、`str_replace_editor` 和 Tavern 专属工具：

- `tavern_read_card`：按字段渐进读取稳定人物卡投影；
- `tavern_read_card_raw`：按 JSON Pointer 读取正则、脚本、MVU 和未知扩展；
- `tavern_read_play_chat`：按轮次和层次只读查看已挂载的游玩记录，并用当前人物卡重新检查正则命中；
- `tavern_read_worldbook`：按编号、关键词或分页读取世界书；
- `tavern_update_worldbook`：通过现有世界书 Library interface 保存已确认的条目级修改；
- `tavern_read_preset`：按 JSON Pointer 分段读取预设工作 JSON；
- `tavern_update_preset`：按 JSON Pointer 保存已确认的最小修改并重新校验；
- `tavern_update_card`：暂存并在本轮最终回复后提交已确认的人物卡最小变更；
- `tavern_restore_card`：仅在灾难性损坏且用户再次确认后从原版恢复；
- `skill` 与 `tavern_save_skill`：按需使用或创建 Tavern 专属 Skill。

目标预设只作为待编辑数据，不成为当前 Agent 的提示词，也不启用预设提示词或正则效果。游玩 Agent 和后台 Agent 不获得卡片工作区文件工具或 Skill。

## 5. 写入规则

1. 阅读、搜索、比较和讨论不产生写入。
2. 用户目标或可写对象不明确时，先确认，不猜测。
3. 人物卡只提交已确认的最小字段或 raw 路径变化。
4. 世界书和预设只通过专用工具修改已引用目标；剧本修改只作用于已引用的工作文件。
5. 初始原版在资源存续期间保持不变；系统不因此创建逐轮版本历史。
6. 修改完成后直接说明实际改动，不要求用户再点击一次保存。

## 6. 渐进读取

初始上下文只提供资源地图、文件路径和必要状态，不注入全部资源正文。Agent 先查看文件规模、结构或检索结果，再读取当前任务所需的最小范围。没有实际读取的内容不得声称已经读过。

对话历史、压缩和一般记忆复用 DSH；人物卡路径、挂载资源、工作草稿和已经落盘的修改属于 Tavern 权威产品状态。

## 7. Skill

卡片 Agent 只扫描项目内置和 Tavern 用户目录中的 Skill。当前内置 `tavern-create-skill` 与 `tavern-extract-writing-style`，分别用于制作通用 Tavern Skill 和从样文提炼文风规则。旧的预设破甲抽取 Skill 已删除。

Skill 是工作方法，不是人物卡字段，不自动写入资源，也不进入游玩模式。

## 8. 验收标准

- 六个入口都创建同一种 `card` 会话，没有额外 Agent 模式；
- 任意已完成的游玩回复可以交给同人物卡的卡片 Agent 调试；挂载记录只读，不自动修改人物卡或游玩历史；
- 卡片 Agent 可分别读取模型原文、Session 文本、展示文本和当前正则诊断，不自动注入整段游玩记录；
- “修改剧本”必须先选择一份剧本，创建后自动引用所选工作文件并追加任务说明；
- “修改世界书”和“修改预设”必须先选择一个目标，并自动追加类型正确的引用；
- 世界书库在卡片对话中为独立和内置世界书提供“在对话中引用”；
- UI 不再出现“从预设提取破甲”或破甲库；
- 人物卡、预设、世界书、剧本四个库职责清晰；预设可编辑但不可应用；
- 普通讨论不会写文件，确认后的剧本修改只改变工作版；
- 人物卡更新继续经过结构化工具校验和最终回复提交；
- 大型资源按需读取，不因挂载而自动进入完整上下文；
- 完整测试覆盖六入口、资源引用、工具可见性、原版保护和修改提交。
