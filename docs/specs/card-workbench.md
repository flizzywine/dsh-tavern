# 卡片工作台产品设计 Spec

## 1. 产品定位

卡片工作台是一个以任务入口启动、以持续对话承载的游玩准备空间。用户可以从修改人物卡、从资料新建人物卡、从预设提取破甲或空白任务开始，再随时向对话中添加人物卡、小说、剧本、酒馆预设和设定文档等任意文件，由 Agent 根据用户意图进行阅读、分析、新建、编辑和整理。

四个入口共享同一个卡片 Agent、工具和系统提示词，只追加不同的起始任务提示词。入口提供认知上的任务起点，不形成互相隔离的模式；进入对话后可以随时调整任务。剧本绑定是人物卡详情页中的纯手动操作，破甲提示词的运行时选择与开关由破甲库负责。

## 2. 要解决的问题

此前为了追求逻辑统一，只保留一个无差别入口，导致用户开始任务时缺少明确的认知锚点；更早的独立模式又会限制对话中途转向。

这会带来以下问题：

- 单一入口无法直观表达用户准备修改、抽取还是自由探索。
- 对话中无法自然增加新的参考文件。
- 人物卡、世界书、素材和剧本的 Agent 操作方式不一致。
- 大型人物卡或世界书容易让 Agent 将“按需阅读”误解为内容缺失。
- 用户担心 Agent 一次错误修改会严重损坏人物卡。

## 3. 产品目标

1. 用户可以不选任何文件，直接开始一次卡片工作台对话。
2. 对话开始后，用户可以随时添加或移除任意文件。
3. 新建人物卡、编辑人物卡、修改世界书、参考剧本和制作破甲提示词都由同一个卡片 Agent 完成；绑定剧本使用人物卡详情页的手动操作。
4. 卡片 Agent 以 DSH 极简模式为能力底座，并叠加 Tavern 专属工具。
5. 初始导入的资源保留不可变原始版本，后续编辑只改变工作版本。
6. 用户不需要理解底层文件结构、工具协议或上下文限制。

## 4. 非目标

- 不提供完整版本历史。
- 不提供多步撤销树或分支管理。
- 不建设 Tavern 专属的长期记忆、向量召回、自动摘要、上下文压缩或记忆 Agent。
- 第一阶段不建设虚拟文件空间、连续自动备份、撤销／重做或外部变更冲突检测。保留一份不可变初始版本不属于连续备份或版本历史。
- 不要求用户在对话开始前区分“编辑”、“抽取”或“剧本”任务。
- 不将文件被选入对话视为剧本绑定。
- 不重新设计游玩模式、剧情时间线或候选项。
- 本 Spec 不规定技术架构、数据结构、工具参数或存储方案。

## 5. 核心概念

### 5.1 卡片工作台

用于人物卡准备的持续对话空间。工作台可以在没有任何文件时建立，并在对话过程中持续增减文件。

### 5.2 资源文件

被添加到当前工作台的文件。它可以是人物卡、素材、剧本候选文本、酒馆预设、设定文档或其他参考资料。酒馆预设从独立预设库导入并原样保留，不在导入阶段自动提取或生成破甲提示词。

文件的用途由用户当前任务决定，而不是在选择文件时预先锁定。同一份文本既可以作为人物卡提炼素材，也可以作为修改现有人物卡的参考。

游玩准备资源在界面中分为四个库：

- “人物卡库”只展示人物卡；
- “预设库”只展示原始 SillyTavern JSON 预设，并提供结构化只读阅读；
- “破甲库”只展示用户确认后保存的 Markdown 破甲方案；
- “资料库”只展示素材、剧本、设定和其他普通参考文件；
- “资料库”是原“资源库”的新名称，不再重复展示人物卡。

### 5.3 破甲提示词文件

卡片 Agent 根据用户明确要求制作的系统提示词文件。每个 Markdown 文件就是一个方案，统一保存在 `data/boundary-prompts/`，不建立额外方案数据库。破甲文件的制作和修改属于卡片工作台；当前会话选择哪个文件、是否启用以及是否完成注入，由破甲库负责。

### 5.4 文件挂载

将资源加入当前工作台，使用户和 Agent 可以在当前对话中使用它。Better Sidebar 的“人物卡库”“预设库”和“资料库”分别通过 `@` 挂载人物卡、预设和普通资料；破甲库用于选择全局注入方案，不以普通资料方式挂载。通用“文件”入口独立保留。发送后只持久化资源相对路径，不自动注入正文。资源重命名会真实移动文件，并同步更新已经建立的对话引用。

挂载不会自动修改、复制、删除或绑定文件。从工作台移除文件只表示当前对话不再使用该文件，不会删除原文件。

### 5.5 剧本绑定

将某份文本明确设为某张人物卡的游玩剧本。

在对话中选入或参考某份文本，不等于将其绑定为剧本。只有用户明确表达绑定、替换或解绑意图时，才改变人物卡与剧本的关系。

### 5.6 初始版本与工作版本

资源首次导入卡片工作台时，原始文件保存在 `data/originals/`，可编辑文件保存在 `data/resources/`。两边都按 `cards`、`presets`、`materials`、`scripts` 分类，资源相对路径就是身份，不建立内部资源 ID。Agent 的读取、编辑和保存默认作用于工作版本，不能覆盖、改写或删除原版。用户明确点击删除资源时，视为删除整个资源，工作版与原版一并删除。

这不是连续版本历史：系统不为每轮修改生成新备份，也不因此提供多步撤销。对于从空白创建的人物卡，用户首次明确保存的正式内容成为初始版本，此后的修改进入工作版本。

## 6. 产品原则

以下六条是当前已经确认的基础原则。具体 UI、资源呈现方式和操作布局尚未确定，后续设计不得反过来破坏这些原则。

### 6.1 空白对话与资源挂载

用户可以直接建立空白对话，再把人物卡、剧本、小说、素材和设定文档作为资源挂载到当前对话。文件选择不再是进入卡片工作台的前置条件，资源也不预先决定任务类型。

工作台应允许资源自由组合。同一份文本既可以作为人物卡提炼素材，也可以作为修改人物卡或世界书的参考；挂载剧本不等于绑定剧本。

### 6.2 完整的 Agent 能力上限

卡片 Agent 以 DSH 极简模式的完整工具能力为底座，再叠加 Tavern 特化工具。极简模式负责通用文件搜索、阅读、比较和编辑；特化工具负责人物卡、世界书和剧本绑定等 Tavern 内部资源操作。

游玩 Agent 与卡片 Agent 保持隔离，不因为卡片工作台开放工具而获得文件操作能力。

### 6.3 一套统一的系统提示词

卡片工作台只使用一套精心设计的系统提示词，统一容纳新建人物卡、编辑人物卡、素材提炼、世界书审查、剧本参考和剧本绑定等功能，不再按任务拆成“编辑模式”或“抽取模式”。

系统提示词分为两层：

- 固定层：Agent 身份、能力边界、工具选择、阅读原则、写入规则和结果反馈。
- 动态层：当前挂载资源目录、正式人物卡或新卡草稿、世界书目录、剧本绑定状态及本轮必要上下文。

动态层只提供当前任务需要的信息，不默认注入全部资源正文。

### 6.4 独立的卡片工作台右侧面板

卡片工作台需要根据功能适配自己的右侧面板。它与游玩模式的“酒馆状态”侧栏是两个不同面板，不复用同一个界面承担两类职责。

该面板具体展示什么、提供哪些操作、如何组织资源与修改结果，目前尚未明确。在真实功能流程稳定前暂不实现，也不提前锁定 UI 结构。

### 6.5 对话中的渐进式披露

人物卡、世界书、剧本和参考素材都可能非常大。资源一旦挂载，不等于它的全部内容应立即进入模型上下文。

对话初始阶段只披露资源地图和完成当前任务所需的最少状态，例如已挂载 Tavern 资源的类型与相对路径、人物卡字段目录及长度、世界书条目目录和剧本绑定关系。人物卡字段通过 `tavern_read_card` 按字段、字符窗口读取；素材通过 `tavern_read_source` 检索或分块读取；世界书和剧本通过各自的 Tavern 只读工具按需读取。只有当前判断或修改确实需要的内容才进入上下文。

渐进式披露必须保持可追踪：Agent 应区分“已挂载”“已定位”“已读取”和“尚未读取”，不得把尚未加载的内容描述为不存在，也不得声称已经通读实际未完整读取的资源。任务转移时，应重新评估所需上下文，不长期携带已经无关的大段正文。

### 6.6 初始版本不可变

初始导入的人物卡、预设和资料必须保留原貌。无论 Agent 后续进行多少次修改，都只能更新工作版本，不能覆盖初始版本；只有用户从界面明确删除整个资源时，才删除两份版本。

初始版本用于保留来源、对照差异和必要时重新开始，不等于自动备份系统。是否在 UI 中提供查看、比较或从初始版本重新生成工作副本，留到卡片工作台面板设计时决定；底层不可变边界不能依赖 UI 实现。

### 6.7 多资源与目标确认

工作台不限制同时选入的文件类型和数量。用户可以同时选入多张人物卡、多份素材和多份剧本候选文本。

当用户的修改目标、新建目标或剧本绑定对象不唯一时，Agent 必须在写入前请用户确认。

### 6.8 阅读与写入分离

Agent 可以为了理解任务主动查找和阅读文件。新建、修改、删除、绑定、替换和解绑都必须有用户明确意图。

### 6.9 大文件按需阅读

Agent 应通过检索、分段和按需阅读理解大型文件。Agent 应准确区分已读取内容和尚待读取内容，不得将按需阅读表述为文件丢失。

### 6.10 修改结果可见

每轮修改完成后，Agent 应说明修改了哪些文件和什么内容。UI 应同步显示最新结果。

### 6.11 复用 DSH 的长程上下文管理

卡片工作台不建立独立记忆系统。对话历史、长程工作管理、上下文压缩与压缩后的回忆完全复用 DSH 原生能力，不在 Tavern 内重复实现召回算法、向量库、自动摘要、上下文压缩或额外的记忆 Agent。

Tavern 只持久保存可验证的客观状态，例如当前人物卡路径、工作草稿、挂载资源路径、剧本绑定和已经落盘的修改结果。这些状态是产品数据，不是 Agent 记忆。讨论过程、分析思路、已读取内容和一般用户偏好交给 DSH 管理；压缩后缺少资源细节时，Agent 通过人物卡、素材、世界书或剧本工具重新读取，以当前资源内容为准。

因此，任何必须保证正确性的业务状态都不得只存在于对话文本中；任何可以从资源重新取得的信息，也不应额外复制进 Tavern 记忆层。

### 6.12 Tavern 专属 Skill

卡片 Agent 复用 DSH 原生 Skill 机制：初始上下文只出现 Skill 名称与简介，任务需要时再通过原生 `skill` 工具读取完整 `SKILL.md`。Skill 来源与用户的全局 DSH 目录隔离，只扫描随项目发布的 `presets/tavern/skills/` 和用户数据目录 `data/skills/`。

Skill 只是一种卡片准备方法，不是人物卡字段，也不自动写入人物卡。游玩 Agent 和后台任务不获得 Skill 目录或加载工具。当前内置 `tavern-create-skill`、`tavern-extract-writing-style` 和 `tavern-extract-boundary-prompt`：分别负责创建通用 Tavern Skill、从样文提炼文风规则，以及从酒馆预设提取可迁移的破甲提示词。

用户 Skill 通过受限的 `tavern_save_skill` 写入 `data/skills/<name>/SKILL.md`。它只接受结构化名称、简介与正文；同名覆盖需要明确修改意图，内置 Skill 不可覆盖。

## 7. 界面与信息架构

### 7.1 入口

点击“新建卡片工作台对话”后显示四个起始入口：“修改人物卡”“从资料新建人物卡”“从预设提取破甲”“空白开始”。修改入口从人物卡库选择人物卡；人物卡抽取从资料库选择资料；破甲抽取从预设库选择预设；空白入口不要求预选资源。四者都进入同一种 `card` 会话，使用完全相同的 Agent、工具和系统提示词，只额外追加对应任务提示词。

旧的工作台对话仍保留在卡片历史中，重新进入时恢复上次挂载的资源状态。

### 7.2 卡片工作台右侧面板（待设计）

右侧面板不复用“酒馆状态”。以下问题保留到功能流程稳定后再决定：

- 当前挂载资源如何展示和切换。
- 资源添加、移除和搜索入口放在哪里。
- 正式人物卡、草稿、世界书和剧本状态如何组织。
- Agent 本轮读取、修改和失败结果如何反馈。
- 哪些操作适合直接按钮，哪些应继续通过对话完成。

### 7.3 当前阶段的 UI 边界

卡片工作台在 Better Sidebar 中使用四个职责分离的 Tavern 专属库：

- “人物卡库”只列出人物卡，负责导入、搜索、查看、编辑、删除、世界书、剧本绑定和“加入当前对话”；
- “预设库”只列出 SillyTavern JSON 预设，负责导入、结构化只读阅读、重命名、删除和通过结构化 `@预设` 加入对话；
- “破甲库”只列出 `data/boundary-prompts/` 中的文件，负责当前会话的选择、开关和注入状态；
- “资料库”只列出素材、剧本、设定和其他普通参考文件，负责导入、查看、重命名、删除和通过结构化 `@资料` 加入对话。

人物卡不再出现在资料库中。DSH 通用“文件”入口同时保留；“酒馆状态”继续只服务游玩模式。

卡片对话框上方不再放置任务按钮。用户在创建对话时选择人物卡修改、人物卡抽取、破甲抽取或空白入口；前三种入口把对应任务模板写入输入草稿，用户可以继续补充要求和挂载资源后再发送，不会自动提交消息。任务模板独立保存在 `prompts/` 并按创建实时读取。剧本只在人物卡详情页手动绑定；预设库负责原文件导入与阅读，破甲库不负责智能提取。

## 8. Agent 交互模型

### 8.1 通用能力

卡片 Agent 以 DSH 极简模式为底座，首先获得：

- 持久 Shell：macOS / Linux 使用 `bash`，Windows 原生环境使用 DSH rc.8 的 `pwsh`，在当前 DSH 工作区列出、检索、比较和整理文件。
- `str_replace_editor`：读取、新建和精确编辑当前工作区文件。

在此基础上只叠加必要的 Tavern 专属工具：`tavern_read_card` 按字段分段读取人物卡，世界书和剧本读取工具处理内部大资源，`tavern_update_card` 保存明确的人物卡变更，`tavern_update_boundary_prompt` 把用户确认的结果写入专用破甲目录。游玩 Agent 不暴露工作区文件工具。

第一阶段直接复用 DSH 当前工作区与权限机制，不额外建设受限虚拟文件空间。等人物卡、素材和剧本操作完成统一后，再根据实际问题决定是否引入虚拟文件投影。

### 8.2 Agent 工作说明

Agent 应获得一份简短、稳定的卡片工作台说明，至少覆盖：

- 如何识别当前可用文件。
- 如何搜索和分批阅读大型文件。
- 何时优先使用 `edit`，何时才使用 `write`。
- 如何区分“仅作参考”与“绑定为剧本”。
- 修改前如何确认目标文件和用户意图。
- 修改后如何向用户说明实际变更。
- 如何避免宣称已经通读尚未完整阅读的文件。

### 8.3 用户确认

Agent 可以主动进行不改变状态的阅读、搜索、分析和比较。

以下行为必须基于用户明确意图：

- 新建或覆盖文件。
- 修改或删除文件内容。
- 创建、替换或解除剧本绑定。
- 对多个可能目标中的某一个进行写入。

当用户的当前消息已经清楚表达上述意图时，Agent 可以直接执行，不需要重复要求用户再确认一次。

## 9. 核心用户流程

### 9.1 空白对话起步

1. 用户点击“新建卡片工作台对话”。
2. 系统打开不预载人物卡正文的空白对话。
3. Agent 简短提示用户可以直接说明目标，也可以挂载参考资料；具体 UI 入口待后续设计。
4. 用户可以先说明需求，再挂载资源；也可以先挂载资源，再说明需求。

### 9.2 从素材新建人物卡

1. 用户向当前对话挂载一份或多份素材。
2. 用户说明准备提炼的角色和玩家身份。
3. Agent 搜索、分批阅读素材，并与用户讨论方案。
4. 用户明确要求生成或保存后，Agent 创建新人物卡。
5. 新人物卡进入人物卡库并挂载到当前对话；未来的工作台面板同步显示这一结果。

### 9.3 编辑现有人物卡

1. 用户将现有人物卡添加到当前对话。
2. Agent 读取卡片结构，并在需要时按条目阅读大型世界书。
3. Agent 与用户讨论问题和可选方案。
4. 用户明确要求修改后，Agent 使用局部编辑保留未涉及内容。
5. 修改成功后，UI 显示最新人物卡状态。

### 9.4 同时参考多份文件

1. 用户从人物卡库加入一张或多张人物卡，再从资料库加入原著、角色设定和剧本。
2. 用户可以要求 Agent 交叉对照、补全或统一其中的设定。
3. Agent 可以自由搜索和阅读全部已挂载文件。
4. 如果存在多个可写目标而用户没有指明，Agent 先请用户确认。
5. 修改完成后，Agent 明确说明实际改动的目标文件。

### 9.5 参考剧本

1. 用户将某份文本添加当前对话。
2. 用户要求 Agent 参考它修改人物卡、世界书或开场白。
3. Agent 阅读相关部分并执行用户要求。
4. 该文本仍然只是当前任务的参考文件，不自动成为游玩剧本。

### 9.6 绑定、替换或解绑剧本

1. 用户进入人物卡详情页。
2. 用户在显眼的“剧本模式”区域选择绑定、替换或解绑。
3. 系统直接完成文件操作并刷新绑定状态，不启动 Agent 对话。
4. 绑定关系影响此后使用该人物卡新建的游玩对话。

### 9.7 从预设提取破甲提示词

1. 用户选择“从预设提取破甲”，并从预设库选择已有预设或导入新的酒馆预设；
2. 预设在 `presets/` 中保存原始版本和工作版本，再挂载到统一卡片工作台；
3. Agent 按需阅读预设结构、条目顺序、角色和正文，与用户讨论需要保留、组合或修改的部分；
4. 用户明确要求保存后，Agent 使用 `tavern_update_boundary_prompt` 创建或修改一个 Markdown 文件；
5. 文件立即出现在破甲库中，但不会自动为任何会话启用；
6. 用户进入准备游玩的会话，在破甲库选择文件并开启注入。

预设导入阶段不运行正则候选、自动摘要或自动写入。预设是保留原貌的输入资源，破甲文件是卡片 Agent 与用户确认后的产物。

## 10. 状态与反馈

### 10.1 需要表达的资源状态

卡片工作台需要让用户和 Agent 区分以下状态，但由右侧面板、对话反馈或其他方式呈现，暂不锁定：

- 已挂载。
- 初始版本受保护；用户明确删除整个资源时，初始版本随工作版本一同删除。
- 已定位。
- 已读取或部分读取。
- 尚未读取。
- 阅读中或分批检查中。
- 已修改。
- 新建。
- 绑定剧本。
- 存在校验失败。

### 10.2 修改反馈

一轮修改成功后：

- Agent 在回复中简要说明改了什么。
- 未来的工作台 UI 应让本轮变更目标可见；具体形式待设计。

### 10.3 失败反馈

当修改无法安全保存时：

- 保留修改前的正式内容。
- 用户能看到哪个文件失败以及失败原因。
- Agent 不得将失败的修改描述为已保存。

## 11. 边界情况

### 11.1 对话中没有文件

Agent 根据用户消息开始讨论，并在需要引用现有内容时提示用户挂载资源。用户仍可以要求 Agent 从空白状态新建人物卡。

### 11.2 同时存在多张人物卡

Agent 可以进行比较和交叉参考。当用户要求修改但未说明目标时，Agent 先请用户指定人物卡。

### 11.3 同名文件

系统必须能帮助用户和 Agent 区分同名文件，不得仅依赖显示名称确定写入目标；具体呈现方式待右侧面板设计时决定。

### 11.4 大文件和大型世界书

Agent 优先搜索、定位和按需阅读。当用户要求全面审查时，Agent 按批说明进度，并只对已完成阅读的范围下结论。

### 11.5 移除已修改文件

如果文件的修改已经成功保存，从对话移除它不会撤销修改。如果存在尚未完成的操作，UI 在移除前提示用户。

### 11.6 不支持的文件

不支持的资源仍可以保留在挂载列表中，但系统需要明确说明 Agent 无法读取或修改的原因。

## 12. 验收标准

### 12.1 当前基础能力

- 用户可以在不选文件的情况下直接进入卡片工作台。
- 用户也可以从现有人物卡进入同一种卡片工作台，不产生第二种任务模式。
- 编辑、素材提炼、破甲提取和从空白新建共用一个卡片 Agent 和一套系统提示词。
- 卡片工作台不打开或复用游玩模式的“酒馆状态”侧栏。

### 12.2 Agent 能力

- 卡片 Agent 具备 DSH 极简模式的持久 Shell（macOS / Linux 为 `bash`，Windows 为 `pwsh`）与 `str_replace_editor`。
- 游玩 Agent 不暴露工作区文件工具。
- 卡片 Agent 同时具备完成 Tavern 内部资源操作所需的专属工具。
- 卡片 Agent 可以发现 Tavern 专属 Skill，并通过 DSH 原生工具按需加载完整说明；全局 Skills、游玩 Agent 和后台任务不可见。
- Agent 可以从任意组合的已选文件中读取、搜索和比较内容。
- 人物卡只能从人物卡库管理和加入对话，不会在资料库重复出现。
- 酒馆预设从预设库管理和加入对话；素材、剧本和设定从资料库管理和加入对话。
- Agent 可以新建人物卡、编辑现有人物卡和修改世界书。
- Agent 可以读取预设库中的酒馆预设，并把用户确认的结果写入 `data/boundary-prompts/*.md`。
- Agent 可以参考剧本而不建立绑定。
- Agent 可在用户意图明确时建立、替换或解除剧本绑定。
- 存在多个可写目标时，Agent 不会自行猜测。
- 初始上下文只包含资源地图和当前任务的必要状态，不自动注入全部资源正文。
- Agent 根据任务检索和分段读取大型资源，并准确说明已读与未读范围。
- 任务转移后，无关的大段资源正文不会被持续带入后续上下文。

### 12.3 写入安全

- 普通讨论、搜索、阅读和比较不会修改文件。
- 导入酒馆预设不会自动创建或修改破甲提示词文件。
- 用户意图不明确时，Agent 不执行写入、删除或剧本绑定。
- 校验失败时，正式人物卡内容保持不变。
- 资源首次导入后，初始版本不可被 Agent 或后续保存覆盖。
- 所有后续修改只作用于工作版本。
- 从空白创建的人物卡以首次正式保存的内容建立初始版本。
- 系统不因初始版本保护而生成逐轮备份或多步版本历史。
- 用户明确点击删除人物卡、素材或剧本时，同时删除其工作版本和初始版本；从对话中移除挂载不等于删除资源。

### 12.4 用户体验

- 用户无需在开始时选择任务类型。
- Agent 对大文件的解释是“按需阅读”，而不是“内容缺失”。
- 修改成功后，用户能明确知道修改了哪些文件。

### 12.5 后续资源与面板验收（UI 方案确定后）

以下目标保留，但不作为当前阶段 UI 的完成条件：

- 用户可在同一对话中多次挂载和移除资源，且不中断当前对话。
- 重新打开历史对话时，已挂载资源保持不变。
- 挂载资源不会自动建立剧本绑定。
- 用户能区分资源的已挂载、已定位、已读取、部分读取、尚未读取和已修改状态。
- 用户能识别初始版本与当前工作版本；具体查看和比较方式待定。
- 卡片工作台通过独立面板呈现必要状态，不占用“酒馆状态”侧栏。
- 面板具体布局、入口和交互方式另行确认后再加入验收。

## 13. 实施顺序

1. 先把当前卡片 Agent 改为真正的“DSH 极简模式＋Tavern 专属工具”，提高基础能力上限。
2. 已统一人物卡编辑与素材提炼能力：卡片工作台使用单一 `card` 模式和同一个 Agent；在此基础上增加“从预设提取破甲”入口，四个入口只追加不同任务提示词，不产生新的模式。
3. 为导入资源建立不可变初始版本，后续编辑只写入工作版本，不扩展成连续备份或版本历史。
4. 功能跑通后再改善文件选择、状态展示和其他 UI 操作。
5. 受限虚拟文件空间、连续备份和冲突检测不进入第一阶段；以后只在真实使用问题证明必要时再设计。

## 14. 产品决策摘要

- 卡片模式改为会话优先的卡片工作台。
- 用户从修改人物卡、人物卡抽取、破甲抽取或空白入口开始，再在对话中随时选择文件和调整任务。
- 破甲提示词制作也进入同一个卡片工作台；酒馆预设先进入预设库，再由 Agent 提取并写入专用目录。
- 预设库负责原始预设的导入和只读阅读；破甲库只负责查看文件、选择方案、开关和注入状态。
- 人物卡库、预设库、破甲库和资料库职责分离；人物卡、预设和资料都可以按任务加入当前工作台。
- 人物卡、素材和剧本可以在同一对话中自由组合。
- 文件用途由当前任务决定，不在选入时预先锁定。
- 参考文本与绑定剧本保持明确区分。
- 卡片 Agent 先以 DSH 极简模式为底座，再增加 Tavern 专属工具。
- 对话采用渐进式披露：先给资源地图，再按当前任务检索和读取正文。
- 初始导入版本在资源存续期间保持不变，Agent 只修改工作版本；用户明确删除整个资源时两者一并删除。这不扩展为连续版本历史。
- 先提升 Agent 能力和打通功能，再进行入口与 UI 整合。
- 卡片工作台需要独立面板，不复用“酒馆状态”侧边栏；具体 UI 方案暂缓。
- 第一阶段不建设虚拟文件空间或连续自动备份。
