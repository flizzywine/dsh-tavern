# 卡片工作台产品设计 Spec

## 1. 产品定位

卡片工作台是一个以对话为入口的人物卡准备空间。用户先进入对话，再随时向对话中添加人物卡、小说、剧本、设定文档等任意文件，由 Agent 根据用户意图进行阅读、分析、新建、编辑和整理。

工作台取代“先选人物卡再进入编辑”、“先选素材再开始抽取”、“单独绑定剧本”等分散流程，将它们统一为同一种产品体验：在一次持续对话中，随时选择文件，随时调整任务。

## 2. 要解决的问题

当前人物卡准备流程被拆成多个独立入口，用户需要先理解“编辑人物卡”、“从素材抽取”、“绑定剧本”之间的区别，才能选择正确入口。

这会带来以下问题：

- 用户必须在开始对话前预先确定任务类型。
- 对话中无法自然增加新的参考文件。
- 人物卡、世界书、素材和剧本的 Agent 操作方式不一致。
- 大型人物卡或世界书容易让 Agent 将“按需阅读”误解为内容缺失。
- 用户担心 Agent 一次错误修改会严重损坏人物卡。

## 3. 产品目标

1. 用户可以不选任何文件，直接开始一次卡片工作台对话。
2. 对话开始后，用户可以随时添加或移除任意文件。
3. 新建人物卡、编辑人物卡、修改世界书、参考剧本和绑定剧本都在同一对话模型中完成。
4. Agent 只使用 Pi 式的 `read`、`write`、`edit`、`bash` 四种通用能力。
5. 所有修改均可自动回退一步，防止极端毁卡。
6. 用户不需要理解底层文件结构、工具协议或上下文限制。

## 4. 非目标

- 不提供完整版本历史。
- 不提供多步撤销树或分支管理。
- 不要求用户在对话开始前区分“编辑”、“抽取”或“剧本”任务。
- 不将文件被选入对话视为剧本绑定。
- 不重新设计游玩模式、剧情时间线或候选项。
- 本 Spec 不规定技术架构、数据结构、工具参数或存储方案。

## 5. 核心概念

### 5.1 卡片工作台

用于人物卡准备的持续对话空间。工作台可以在没有任何文件时建立，并在对话过程中持续增减文件。

### 5.2 资源文件

被添加到当前工作台的文件。它可以是人物卡、素材、剧本候选文本、设定文档或其他参考资料。

文件的用途由用户当前任务决定，而不是在选择文件时预先锁定。同一份文本既可以作为人物卡提炼素材，也可以作为修改现有人物卡的参考。

### 5.3 文件挂载

将文件加入当前工作台，使用户和 Agent 可以在当前对话中使用它。

挂载不会自动修改、复制、删除或绑定文件。从工作台移除文件只表示当前对话不再使用该文件，不会删除原文件。

### 5.4 剧本绑定

将某份文本明确设为某张人物卡的游玩剧本。

在对话中选入或参考某份文本，不等于将其绑定为剧本。只有用户明确表达绑定、替换或解绑意图时，才改变人物卡与剧本的关系。

### 5.5 上一步备份

最近一次成功修改之前的完整状态。它只用于防止 Agent 在一轮修改中极端损坏文件，不承担完整版本管理职责。

### 5.6 变更批次

一轮对话中经校验后一起生效的全部文件修改和关系修改。同一轮内 Agent 即使进行多次操作，也只产生一个变更批次。

## 6. 产品原则

### 6.1 对话优先

用户先建立对话，再决定使用哪些文件。文件选择不再是进入卡片工作台的前置条件。

### 6.2 文件自由组合

工作台不限制同时选入的文件类型和数量。用户可以同时选入多张人物卡、多份素材和多份剧本候选文本。

当用户的修改目标、新建目标或剧本绑定对象不唯一时，Agent 必须在写入前请用户确认。

### 6.3 阅读与写入分离

Agent 可以为了理解任务主动查找和阅读文件。新建、修改、删除、绑定、替换和解绑都必须有用户明确意图。

### 6.4 大文件按需阅读

Agent 应通过检索、分段和按需阅读理解大型文件。Agent 应准确区分已读取内容和尚待读取内容，不得将按需阅读表述为文件丢失。

### 6.5 修改结果可见

每轮修改完成后，Agent 应说明修改了哪些文件和什么内容。UI 应显示修改结果以及当前是否可回退。

## 7. 界面与信息架构

### 7.1 入口

卡片模式主入口只保留“新建卡片工作台对话”。点击后直接进入空白对话，不弹出前置文件选择器。

旧的工作台对话仍保留在卡片历史中，重新进入时恢复上次挂载的文件。

### 7.2 文件栏

对话顶部或输入区附近展示持续可见的文件栏，包含：

- “添加文件”入口。
- 当前已挂载文件的名称、类型和状态。
- 移除单个文件的操作。
- 文件刚刚被修改、新建或与人物卡建立绑定时的状态提示。

### 7.3 文件选择器

文件选择器在对话内打开，而不是在对话建立前打开。

用户可以：

- 从已有文件库中选择一个或多个文件。
- 上传新文件并立即加入当前对话。
- 搜索、筛选和多选文件。
- 在不中断对话的情况下多次重新打开选择器。

### 7.4 上一步回退

当当前工作台存在上一步备份时，UI 显示“回退上一步”。

回退作用于最近一个变更批次，同时恢复该批次中涉及的所有文件和关系。回退后，用户可以再次使用同一入口恢复回退前的状态，形成一步撤销／重做。

## 8. Agent 交互模型

### 8.1 通用能力

Agent 在卡片工作台中只使用四种通用能力：

- `read`：阅读文件或其中的指定范围。
- `write`：新建文件，或在用户明确要求时整体重写文件。
- `edit`：对现有文件进行局部、精确修改。
- `bash`：列出、检索、比较和整理当前工作台内的文件。

这四种能力是 Agent 的统一操作入口。产品不再要求 Agent 学习人物卡修改、世界书阅读、素材抽取和剧本绑定的多套独立工具。

### 8.2 Agent 工作说明

Agent 应获得一份简短、稳定的卡片工作台说明，至少覆盖：

- 如何识别当前可用文件。
- 如何搜索和分批阅读大型文件。
- 何时优先使用 `edit`，何时才使用 `write`。
- 如何区分“仅作参考”与“绑定为剧本”。
- 修改前如何确认目标文件和用户意图。
- 修改后如何向用户说明实际变更。
- 如何避免宣称已经通读尚未完整阅读的文件。

### 8.3 用户确认

Agent 可以主动进行不改变状态的阅读、搜索、分析和比较。

以下行为必须基于用户明确意图：

- 新建或覆盖文件。
- 修改或删除文件内容。
- 创建、替换或解除剧本绑定。
- 对多个可能目标中的某一个进行写入。

当用户的当前消息已经清楚表达上述意图时，Agent 可以直接执行，不需要重复要求用户再确认一次。

## 9. 核心用户流程

### 9.1 空白对话起步

1. 用户点击“新建卡片工作台对话”。
2. 系统直接打开空白对话。
3. Agent 简短提示用户可以直接说明目标，或使用“添加文件”选入参考资料。
4. 用户可以先说明需求，再添加文件；也可以先添加文件，再说明需求。

### 9.2 从素材新建人物卡

1. 用户向当前对话添加一份或多份素材。
2. 用户说明准备提炼的角色和玩家身份。
3. Agent 搜索、分批阅读素材，并与用户讨论方案。
4. 用户明确要求生成或保存后，Agent 创建新人物卡。
5. 新人物卡自动出现在文件栏和人物卡库中，并可在当前对话中继续修改。

### 9.3 编辑现有人物卡

1. 用户将现有人物卡添加到当前对话。
2. Agent 读取卡片结构，并在需要时按条目阅读大型世界书。
3. Agent 与用户讨论问题和可选方案。
4. 用户明确要求修改后，Agent 使用局部编辑保留未涉及内容。
5. 修改成功后，UI 显示已修改状态和“回退上一步”。

### 9.4 同时参考多份文件

1. 用户同时添加人物卡、原著、角色设定和剧本。
2. 用户可以要求 Agent 交叉对照、补全或统一其中的设定。
3. Agent 可以自由搜索和阅读全部已挂载文件。
4. 如果存在多个可写目标而用户没有指明，Agent 先请用户确认。
5. 一轮内修改的多个文件作为同一变更批次一起生效。

### 9.5 参考剧本

1. 用户将某份文本添加当前对话。
2. 用户要求 Agent 参考它修改人物卡、世界书或开场白。
3. Agent 阅读相关部分并执行用户要求。
4. 该文本仍然只是当前任务的参考文件，不自动成为游玩剧本。

### 9.6 绑定、替换或解绑剧本

1. 用户选入人物卡和剧本候选文本。
2. 用户明确表达“将这份文本绑定给这张卡”等意图。
3. 如果只有一张卡和一份候选文本，Agent 可以直接执行。
4. 如果目标不唯一，Agent 必须先请用户指定。
5. 替换或解绑已有剧本时，Agent 明确说明影响。
6. 操作成功后，文件栏和人物卡状态中都显示最新绑定关系。

## 10. 上一步备份与回退

### 10.1 生成时机

只有当一轮对话产生并成功保存变更批次时，才更新上一步备份。

以下情况不覆盖已有备份：

- 普通讨论、搜索、阅读或分析。
- Agent 尝试修改，但校验失败。
- 本轮没有产生实际变化。

### 10.2 备份范围

备份覆盖最近变更批次中涉及的全部文件和文件关系。如果同一轮同时修改人物卡、世界书和剧本绑定，回退时必须将它们整体恢复。

### 10.3 一步撤销／重做

回退成功后，回退前的状态成为新的上一步备份。用户可以再次执行同一操作，恢复回退前的状态。

### 10.4 外部变更冲突

如果备份中的文件已经被其他对话或界面操作修改，系统不直接覆盖新内容。UI 应告诉用户存在外部变更，并禁用一键回退，避免恢复旧状态时损坏新修改。

## 11. 状态与反馈

### 11.1 文件状态

文件栏至少区分：

- 已挂载。
- 阅读中或分批检查中。
- 已修改。
- 新建。
- 绑定剧本。
- 存在冲突或校验失败。

### 11.2 修改反馈

一轮修改成功后：

- Agent 在回复中简要说明改了什么。
- UI 高亮本轮变更的文件。
- UI 显示“可回退上一步”。

### 11.3 失败反馈

当修改无法安全保存时：

- 保留修改前的正式内容。
- 保留原有上一步备份。
- 用户能看到哪个文件失败以及失败原因。
- Agent 不得将失败的修改描述为已保存。

## 12. 边界情况

### 12.1 对话中没有文件

Agent 根据用户消息开始讨论，并在需要引用现有内容时提示用户添加文件。用户仍可以要求 Agent 从空白状态新建人物卡。

### 12.2 同时存在多张人物卡

Agent 可以进行比较和交叉参考。当用户要求修改但未说明目标时，Agent 先请用户指定人物卡。

### 12.3 同名文件

文件栏必须能帮助用户和 Agent 区分同名文件，不得仅依赖显示名称确定写入目标。

### 12.4 大文件和大型世界书

Agent 优先搜索、定位和按需阅读。当用户要求全面审查时，Agent 按批说明进度，并只对已完成阅读的范围下结论。

### 12.5 移除已修改文件

如果文件的修改已经成功保存，从对话移除它不会撤销修改。如果存在尚未完成的操作，UI 在移除前提示用户。

### 12.6 不支持的文件

不支持的文件仍可以显示在文件栏中，但 UI 需要明确说明 Agent 无法读取或修改的原因。

## 13. 验收标准

### 13.1 会话与文件选择

- 用户可以在不选文件的情况下直接进入卡片工作台。
- 用户可在同一对话中多次添加和移除文件。
- 重新打开历史对话时，已挂载文件保持不变。
- 选入文件不会自动建立剧本绑定。

### 13.2 Agent 能力

- Agent 只使用 `read`、`write`、`edit`、`bash` 完成人物卡准备任务。
- Agent 可以从任意组合的已选文件中读取、搜索和比较内容。
- Agent 可以新建人物卡、编辑现有人物卡和修改世界书。
- Agent 可以参考剧本而不建立绑定。
- Agent 可在用户意图明确时建立、替换或解除剧本绑定。
- 存在多个可写目标时，Agent 不会自行猜测。

### 13.3 安全与回退

- 普通对话和阅读操作不会更新上一步备份。
- 一轮内的多次修改只生成一份上一步备份。
- 校验失败时，正式文件和旧备份保持不变。
- 一步回退同时恢复同一变更批次中的全部文件和关系。
- 回退后可再次恢复回退前状态。
- 存在外部变更冲突时，系统不盲目覆盖新内容。

### 13.4 用户体验

- 用户无需在开始时选择任务类型。
- 文件选择、添加和移除不中断当前对话。
- Agent 对大文件的解释是“按需阅读”，而不是“内容缺失”。
- 修改成功后，用户能明确知道修改了哪些文件，以及是否可回退。

## 14. 产品决策摘要

- 卡片模式改为会话优先的卡片工作台。
- 用户先进入对话，再随时选择文件。
- 人物卡、素材和剧本可以在同一对话中自由组合。
- 文件用途由当前任务决定，不在选入时预先锁定。
- 参考文本与绑定剧本保持明确区分。
- Agent 只使用 Pi 式的 `read`、`write`、`edit`、`bash` 四种通用能力。
- 每轮成功修改只保留一份上一步备份。
- 一步回退覆盖整个变更批次，并支持一步重做。
