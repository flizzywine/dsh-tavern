# 世界书读取机制

游玩前后台使用 `list_lorebook` 分页浏览标题、`read_lorebook` 按关键词读正文、`grep_lorebook` 搜索原文片段。卡片工作台使用 `tavern_read_lorebook` 和 `tavern_update_lorebook` 查看、编辑原始世界书。旧会话工具回执仍可读取。

## 自动注入 + 主动检索

内置策略「自动注入 + 主动检索」沿用原「主动检索」的设置标识，已使用内置策略的对局无需改设置。原始世界书 JSON 仍是唯一事实来源；派生索引不改写正文、不运行模板、不调用模型或 embedding 服务。

- 默认扫描最近 **2 条**玩家或助手消息，通常是本轮输入和上一条剧情正文。整本世界书可以设置扫描深度，单条可以覆盖。扫描跳过开场白和占位消息，并包含脚本或插件显式提供的扫描文本。普通触发词默认忽略大小写并按子串匹配，单个汉字须独立出现，也支持整词匹配和 `/正则/`。
- 有效的非常驻静态条目先匹配主触发词和启用的二级条件，再按条目标题、触发词和正文与扫描文本的 BM25 相关性排序，在世界书 Token 预算内最多注入 **5 条**正文。中文使用单字与双字组合，英文和数字按词计分。没选上的条目仍可主动检索，其中至多 3 个命中标题作为线索。常驻、显式前缀与尾部、动态和 MVU 规则沿用各自通道。
- 正文完成后，该版本条目在接下来的 **10 个剧情回合**不重复自动注入，Agent 仍可随时查阅。失败或未完成的回合不计；成功替换上下文的压缩重置冷却，条目改写后也可重新匹配。历史导入不补写自动注入。

- 仅启用的非常驻静态资料进入 Skill；初始化、MVU 规则、EJS、宏、预处理与可识别的脚本代码保留各自处理链。分类与转换均为纯程序处理，不调用 LLM。
- 静态常驻条目每次请求在固定前部读取最新原文，不写入聊天历史。
- 静态非常驻条目优先按原始标题的重复父分类（如“功法·…”或“[王国-城镇-地点]”）分组；缺少明确分类的条目通过字符 2/3-gram、TF-IDF、余弦稀疏图和 Leiden 分组（默认 CPM 分辨率 0.02）。世界书 Skill 最多 29 类；超出时，以本地 TF-IDF 质心相似度把小类合并到最接近的类别，保留全部原文。不因正文长度拆分更多 Skill。每类生成实体 `SKILL.md`：整组原文合计本地估算不超过 2000 token 时，按条目分节直接内联；超过阈值时整组外置到 `references/中文标题.md`（去除控制标签；只有重名时加 `--2` 等数字后缀），由原生 `read` 按需读取，不做部分内联。阈值只估算原文（ASCII 约 4 字符/token，其他字符约 0.6 token/字符），不是模型账单计量。所有外置条目的名称和原文相对链接直接列在 `SKILL.md` 中，不另设资料目录文件；原文支持原生分页读取。布局随资料版本切换，不生成根级 `INDEX.md`。
- 发现阶段仅展示 Skill 名称与至多 100 字符的描述，不加载全部 `SKILL.md` 正文。按需展开 Skill（含条目目录）→ 原文；短小资料仍在调用 Skill 时直接内联。
- 对外名称与描述不用聚类词片：清理标题中的机械编号与已知控制标签，以完整标题的共同分段命名；只有全部成员明确声明同一类别时才采用该类别。描述列出成员名称和原文共有字段，没有结构时直接列资料名。调用名由中文主题在本地转为无声调拼音（如 `ke-ju`），无 `wb-` 前缀；重名加短数字后缀。全过程不调用 LLM，不翻译或改写条目正文。
- 动态常驻条目首次渲染后，在依赖或执行时机变化时重新评估。动态非常驻条目先检查激活条件。参与前台注入的 EJS 或提示词模板在首次生效或渲染结果变化时，向本轮上下文追加一次更新，保留已有消息和缓存前缀。系统保存最新有效快照，压缩或冷启动后按实际上下文判断是否需要恢复。显式选用「每轮尾部」的条目在生效时逐轮提供。
- 无法证明纯读取的 EJS、装饰器和宏保留原生执行时机，不能把静态分析当作副作用安全证明。同一执行轮缓存结果，不为检测变化重复执行或重新抽样。

派生文件位于酒馆数据目录的 `worldbook-skills/<人物卡文件名>/<中文主题>/`，无人物卡时使用世界书名称；目录按人物卡绑定的世界书及有效内容版本共享，不包含对局身份；相同资料的多个对局共用文件，删局不删除共享文件。不同快照或可见条目集合使用“资料版本2”等可读后缀，防止互相覆盖，重启保留已分配路径。内部归属信息保存在隐藏元数据中，旧哈希目录在生成成功后清理。主题目录不附加内部 ID，仅重名时添加短数字后缀；不放进全局 Skill 扫描目录。仍由 Provider 按当前对局绑定和可见性注册到原生 Skill 系统；后台仅在任务运行期间按所属前台对局访问相同有效资料；任务结束即撤销授权，手机私聊和舞台导演保持隔离，其他对局不可读取。编辑后以 worker 构建新资料版本；停用条目或换卡立即撤销当前局对旧路径的读取权限，旧版本文件保留供其他快照使用。它们是世界书的派生副本，不作为独立编辑来源；下次读取时修复生成文件中的手工改动。该策略在游玩局中以 `read` 替换旧 `worldbook_search`，仅开放当前局生成文件。读取钩子只做同步和范围校验，文件 IO、分页和结果格式均由原生工具完成。卡片工作台和旧策略保持原有工具行为。原生 read 的按行、单行长度及输出量上限仍适用；原始正文资源本身没有截断或改写。宿主没有兼容原生 `read` 工具时不公布无法读取的目录。

同一执行轮内，未知副作用的批量预处理结果保持冻结；新增或修改的预处理控制器会留下诊断并在下一明确执行轮生效，删除和禁用立即撤销。带预处理控制器的书只有在原生运行时确认当前版本的条目可见性后才公布静态目录；编译阶段不会为此执行脚本。

### 脚本修改与 Skill 同步

酒馆脚本仍修改原始世界书；每个模型步骤开始前以及读取 Skill 时校验最新有效资料。增删改后重新分类：只有启用、非常驻的静态条目进入 Skill，其余继续走原运行链。内嵌条目用来源与 UID 匹配，避免删除数组元素造成后续条目错位。

已有条目尽量保留分类和 Skill 名称；正文修改、删除不重新构建全量相似度图。新增条目优先加入同源标题分类，必要时以本地相似度分配，仍最多 29 类。后续构建使用 750ms 防抖，并在发布前复查源版本，过期结果不授权读取。分类和名称的延续信息保存在会话元数据中，重启可恢复。

每次观察到新版本，在模型上下文追加一条合并通知，列出新增、改写和移出静态库的条目，提醒旧正文失效并重新按需读取。通知基线持久化，同版本不反复注入。已经产生的历史回答不会被追溯改写。资料版本根目录变化时提示旧绝对路径失效；主题名称尽量稳定，旧版本文件继续服务仍使用旧快照的对局。

世界书模型筛选已停用，不再提供开关；旧配置即使保存为开启也不执行筛选，历史模型排除产生的冷却不再限制召回。关键词匹配、常规读取冷却及动态处理继续按各自规则运行。

后台结算、候选生成和人物设计也可通过原生 `skill` / `read` 按需读取所属对局的静态资料；后台 `read` 仅允许该对局生成的世界书文件。常驻、动态条目和 MVU 更新规则仍沿原处理链提供，不依赖主动检索。
