# 合成数据压缩边界测试

验证日期：2026-09-20。测试代码：`tests/compaction-boundaries-native.test.mjs`。

使用已安装 DSH 的真实 Session、Token Meter、Agent Loop 和 BasicCompactionEngine，复用 Tavern 剧情压缩提示词。模型返回文本和窗口拒绝由测试桩提供，无付费请求，不修改用户存档或生产配置。窗口缩小至 2,000 tokens；部分测试调低触发比例，以较小历史覆盖临界值。

测试桩按当前 DSH 的字符估算规则计算消息、系统背景、工具和输出预留，然后返回 `CONTEXT_WINDOW_EXCEEDED`。这验证的是机制边界，不代表真实模型的分词精度、摘要质量或某个第三方服务的行为。

## 实测结果

28 个用例全部符合断言，包含预期失败，不表示所有输入均可压缩。

| 场景 | 实测结果 |
| --- | --- |
| 占用 864，阈值 865 / 864 / 863 | 分别不压缩 / 压缩 / 压缩；后两种降至 430 |
| 2k 窗口，占用恰为 1,600（80%），摘要输出预留 128 | 摘要输入 1,234，加输出共 1,362，成功 |
| 相同历史，摘要输出预留改为 1,024 | 共需 2,258，摘要请求超限，失败且不替换原历史 |
| 摘要请求容量恰差 1 / 刚好够 / 多 1 token | 手动、普通容量、超限恢复三条路径均分别失败 / 成功 / 成功 |
| 空摘要、比原文更长的摘要 | 三条路径均拒绝替换，压缩标记成对闭合；改为有效摘要后可重试成功 |
| 历史约 11,016，摘要窗口 2,000 | 普通容量摘要需要约 10,260；手动和强制摘要约 11,168，均超限 |
| 固定系统背景本身约 3,004，窗口 2,000 | 压缩不能删除固定背景，摘要请求失败 |
| 单轮历史本身过长 | 普通容量路径保留近期原文，可能没有可压缩区间；强制路径尝试后，摘要仍可能超限 |
| 模拟摘要能生成，但固定前缀仍超过窗口 | 允许已成功摘要落盘，但不能降至阈值，有限尝试后报错；原始事件仍在 |
| 真实 Agent，新玩家输入本身过大 | 一次历史摘要成功，但新输入仍放不下；正文请求共两次后停止，无无限重试 |
| 真实 Agent，摘要请求本身过大 | 正文一次、摘要一次后失败，原历史仍在 Surface；放宽测试窗口后可继续会话 |

失败后的检查区分两类情况：摘要未提交时 Surface 完全不变；已有部分摘要成功时允许 Surface 有进展，但原始事件保留，压缩生命周期闭合。

## 结论与后续范围

原生 80% 保护有助于提前压缩，但不保证摘要请求一定放得下。摘要有自己的提示词和输出预留，窗口还可能被固定背景、工具或单条超长输入占满。

本轮没有改动生产算法。若要让已严重超长的旧历史可压缩，需要单独设计摘要请求预算和分块摘要；固定背景或当前输入本身超过窗口则还需要缩减内容或使用更大的模型窗口。不能只增加重试次数，也不能通过吞掉超限错误宣称成功。

## 运行

先将 `DSH_BOOT_MODULE` 设为本机 `@deepseek-ai/dsh-app-boot/lib/index.js` 的绝对路径，再运行：

```sh
node --test tests/compaction-boundaries-native.test.mjs
```

未设置该环境变量时，原生测试会跳过；需检查输出的 skipped 数，不能把跳过当作验证通过。
