# 项目范围：做什么，不做什么

DSH Tavern 已进入稳定阶段。接下来的重心是**维护人物卡的可玩性**：让现有的人物卡，在现有的游玩流程里跑得更好。不盲目扩张功能；新功能只在维护可玩性所必需时才做。

提需求前请先看这份清单。清单里的方向不是“暂时没空”，而是有意不做：每多一个方向，维护成本和出错的组合就多一层，最终伤害的是已有功能的稳定。

## 做

- **人物卡兼容**：卡在原版酒馆能用、在这里不能用，就是我们的问题。我们改程序适配卡，不要求卡作者改卡。
- **稳定性**：安装、更新、回滚，以及桌面、命令行、安卓三端行为一致。
- **性能**：长对话、存档体积、启动与响应速度。
- **可诊断性**：出错时说清是哪一步、为什么失败，一次就能定位。
- **安装与更新体验**：少步骤、少等待、失败可恢复。
- **逐步开放插件接口**：清单里不内置的功能，尽量开放稳定的[插件接口](plugin-api.md)，让需要的人自己做成插件。接口只允许插件「添加」内容（提示词段落、世界书条目、结算工具、媒体等），不允许替换 Tavern 自己的流程；接口带版本号、只加不改。缺接口请提[插件接口需求](https://github.com/flizzywine/dsh-tavern/issues/new?template=plugin-api.yml)。

判断标准：**它是否让“现有的卡在现有的流程里跑得更好”？** 是就考虑，否则默认不做。

## 不做

### 换赛道的

| 不做 | 原因 |
| --- | --- |
| 群聊、多角色同场 | 上下文、发言轮次和结算都要重做，等于另一个产品。 |
| 写小说、长篇创作模式 | 已有专门的写作工具；这里专注角色扮演。 |
| 通用的酒馆插件兼容 | 等于再造一个 SillyTavern。已支持的酒馆助手、MVU、提示词模板（EJS）、正则、状态栏与前端卡到此为止。 |
| 其他前端的卡片和存档格式（Risu、Agnai 等） | 只认 SillyTavern 人物卡。 |
| 语音朗读、语音输入、视频或动图生成 | 多媒体不是文字游玩的核心。交给第三方 DSH 插件，通过[插件接口](plugin-api.md)挂到正文里。 |

### 做平台的

| 不做 | 原因 |
| --- | --- |
| 账号、云同步、多用户 | 数据始终只在你自己的设备上。 |
| 卡片市场、社区分享、在线排行 | 内容分发不是本项目的职责。 |
| iOS、Mac 安装包、Linux 桌面版等新平台 | 维持现有的 Windows 安装包、命令行与安卓三端。 |
| 跟进每个新版 DSH | 固定在已适配的 DSH 版本（当前 0.1.5-rc.2）。等 DSH 真正稳定后，再集中适配一次。 |

### 做了停不下来的

| 不做 | 原因 |
| --- | --- |
| 接入更多生图服务、ComfyUI 工作流编辑、内置生图的新能力 | 内置生图只做小改进，不加新能力。新的生图方式请做成插件，见[插件接口](plugin-api.md)。 |
| 主题或皮肤编辑器、自定义界面布局 | 外观维持现有皮肤。 |
| 世界书与预设的高级可视化编辑 | 能导入、能做基本编辑即可；复杂编辑请用专门工具。 |
| 玩法系统（成就、好感度、背包、地图等） | 这些属于人物卡自己；我们负责把卡跑对。 |
| 新的记忆或总结算法试验 | 维持现有机制，只修问题。 |
| 联网搜索以外的新工具（代码执行、文件操作等） | 工具越多，前台越容易跑偏。 |
| 界面多语言 | 用户以中文为主，翻译维护是长期成本。 |

## 那我遇到问题怎么办

- **某张卡在原版酒馆正常、在这里不正常**：这正是我们要修的，请附上人物卡文件和日志反馈。
- **想要清单里的功能**：可以在 [Discussions](https://github.com/flizzywine/dsh-tavern/discussions) 交流，或寻找、编写对应的 DSH 插件；本项目不会内置。
