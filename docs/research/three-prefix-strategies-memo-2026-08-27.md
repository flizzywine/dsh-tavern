# Agent 多调用场景的三种前缀实验备忘录

> 日期：2026-08-27
>
> 状态：待实验验证
>
> 目标：验证三种前缀策略能否让多次模型调用保持稳定的虚构创作轨道。本文记录实验假说和对应原理，不把尚未验证的机制写成结论。

## 背景判断

酒馆通常在一次模型调用中连续生成一整段回答。开头一旦进入某种叙事轨道，后续 token 会持续以已经生成的内容为条件。

Agent 会把一个任务拆成多次模型调用。上一轮输出在下一轮会变成输入历史，而新一轮 `assistant` 输出仍从首 token 重新开始。因此，每次调用都可能重新出现一次任务识别、指令竞争和安全对齐的路由过程。

本轮计划分别测试三个位置不同、机制不同的变量：

```text
输入最前面：稳定无害内容
      ↓
每次调用：简短的虚构创作指令
      ↓
输出最前面：固定的正常安全内容
      ↓
正则仅在展示层隐藏固定内容
```

## 方案一：在输入最前面加入稳定无害内容

### 做法

在每次最终模型请求的输入前部放置一段固定、稳定、完全无害的文本，例如原创小说片段或其他普通叙事内容。实验期间保持文本、消息角色和插入位置不变。

### 对应原理

1. **任务分布定位**：固定小说或叙事文本可能让模型把当前上下文识别为文学续写、角色扮演或虚构创作，而不是孤立的问答请求。
2. **输入端位置效应**：长上下文研究发现，模型经常更容易利用输入开头和末尾的信息，而忽略中部信息。放在最前面可能形成持续的上下文锚点。
3. **上下文学习**：稳定文体可能充当示范，让模型临时调整对当前任务类型、文风和预期输出的判断。
4. **跨调用稳定性**：Agent 每次都会重新调用模型；固定重新注入可以保证每次请求仍包含相同的任务分布信号。

### 证据边界

- 现有研究支持输入内容、位置和示范会影响行为，但没有证明某篇小说是跨模型通用的特殊开关。
- 无关文本过长可能稀释当前任务、占用上下文，或者被模型忽略。
- KV cache 只减少重复计算，不会让这段文本失去输入条件作用。

## 方案二：每轮注入简短的虚构创作指令

### 做法

每一次模型调用都注入一条简短、固定的虚构创作框架，明确当前任务属于虚构故事、角色扮演或文学续写。它不只出现在 Session 第一轮，而是进入每一次实际发送给供应商的请求。

### 对应原理

1. **调用边界会重置解码轨迹**：上一轮生成结束后，下一轮输出重新从首 token 开始。每轮重申虚构任务，是为了重新建立同一种局部任务轨道。
2. **竞争目标**：模型同时受到指令遵循、叙事连贯、角色一致性和安全目标影响。虚构创作框架可能提高“继续完成故事”的相对权重。
3. **泛化错配**：安全后训练不一定均匀覆盖所有虚构、嵌套叙事和角色表达方式。DeepInception 等研究说明，场景、角色、层级和分步生成的组合会显著改变模型行为。
4. **靠近当前任务的近因信号**：与只在很早位置放一次长预设相比，每轮短提示更靠近本轮任务，较不容易在长历史中被弱化。

### 证据边界

- 虚构创作不是通用开关；不同模型和版本可能专门覆盖过角色扮演场景。
- 提示过长或过于强调安全、审核、拒绝等概念，可能反而激活安全审查轨道。
- 每轮注入是否有效，取决于最终消息角色、顺序、system 指令和本轮局部任务，不能只看预设原文。

## 方案三：要求每次调用先输出固定的正常安全内容，再由正则隐藏

### 做法

要求模型在每次回答开头先生成一小段固定、正常、无害的内容，再继续完成真正的本轮任务。前端或渲染层用正则移除这段固定内容，使用户只看到其后的正文；原始模型输出仍应保留，便于诊断。

### 对应原理

1. **浅层安全对齐**：研究表明，一些模型的安全行为过度集中在最初几个输出 token；拒绝或正常回答的开头可能迅速把后续生成带入不同轨迹。
2. **自回归轨迹依赖**：一旦模型已经生成正常、连贯的开头，后续 token 会以该开头为条件继续生成：

   \[
   P(y_t\mid x,y_{<t})
   \]

3. **输出端前缀锚定**：固定开头尝试让每次新调用先进入正常生成轨道，再继续本轮内容。这一变量针对的是 Agent 每次调用都会产生新的输出首 token。
4. **展示与生成分离**：正则只负责不向用户展示固定开头；真正可能影响模型的是模型已经生成并继续读取了这些 token，而不是正则本身。

### 重要区别

“要求模型先输出固定内容”仍然是一条输入指令，模型可以不遵循；它不等于供应商 API 直接预填的 `assistant prefill`。后者把指定 token 作为当前 assistant 回答已经存在的开头，控制更直接。实验记录中必须将两者分开命名。

### 证据边界

- 浅层安全对齐不等于安全只存在于前几个 token；模型仍可能在后续位置拒绝、中止或转向。
- 固定安全开头也可能强化安全解释或拒绝轨道，效果方向需要实测。
- 正则过滤不能改变供应商输入审核、输出审核、停止原因或模型内部判断。
- 必须保存未经过正则的 `sourceText`；否则无法判断模型真实生成了什么以及在哪里中止。
- 正则处理后，下一次调用究竟收到哪一种历史非常关键：若回传原始输出，固定开头仍存在于后续上下文；若只回传过滤后的展示文本，它只影响当前调用，不会作为下一轮历史继续存在。

## 三种策略的关系

| 策略 | 作用位置 | 主要假说 | 当前证据等级 | Agent 中为什么重复 |
| --- | --- | --- | --- | --- |
| 稳定无害内容 | 输入最前部 | 任务分布、文体锚定、位置效应 | 弱，探索性假设 | 保证每次请求都有相同全局背景 |
| 简短虚构创作指令 | 每轮任务附近 | 指令遵循、竞争目标、虚构表达域 | 中等；完整结构有实验，极简版待测 | 每次调用重新建立局部任务轨道 |
| 固定正常输出开头 | 每轮输出最前部 | 浅层安全对齐、自回归轨迹依赖 | 要求模型自行输出的证据弱；真正 prefill 的证据强 | 每次调用都有新的输出首 token |

三者不是同一种“前缀”，也不能假定效果会简单相加：

- 方案一主要改变输入的全局背景。
- 方案二主要改变本轮局部任务的解释。
- 方案三试图改变当前回答已经开始后的生成轨迹。

## 实验记录要求

当前计划可以组合测试，但必须保留单变量基线，才能知道最终是哪一种机制在起作用：

| 编号 | 条件 |
| --- | --- |
| C0 | 三种策略都不启用 |
| C1 | 只启用稳定无害内容 |
| C2 | 只启用每轮虚构创作指令 |
| C3 | 只启用固定正常输出开头 |
| C4 | 三种策略全部启用 |

每次实验至少记录：

- 模型、供应商、版本、采样参数和流式设置；
- 每次调用最终序列化后的消息角色、顺序和文本哈希；
- 未经正则处理的完整原始输出；
- 正则处理后的展示输出；
- `finish_reason`、服务端审核错误、断流、重试和自行停止；
- 每个 Agent 阶段分别成功或失败，不能只记录整轮最终结果。

只有当同一条件重复多次仍稳定出现差异时，才能把结果暂时归因于相应策略。
