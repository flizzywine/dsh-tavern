# 梨园架构研究与借鉴范围

本文记录 [Liyuan](https://github.com/weidu12123/Liyuan) v1.5 对 dsh-tavern 的架构启发。它是研究参考，不是兼容承诺，也不表示 dsh-tavern 将采用梨园的运行时。

## 核心结论

梨园最值得借鉴的不是某个单独功能，而是它对权威剧情、模型上下文和派生状态的分离：完整过程可以保留，但正文 Agent 每轮只看到当前分支需要的剧情投影；账本、摘要、面板和召回结果则作为各自独立的领域状态，随剧情分支一起演进和回退。

dsh-tavern 应继续坚持 DSH 原生架构，把这些经验转化为 DSH 上的深模块，而不是复制梨园的 RP Harness。

## 值得借鉴的原则

### 1. 权威记录与模型上下文分离

完整事件记录用于审计、回退和恢复，模型上下文只是由当前剧情分支生成的临时投影。工具过程、调试信息、废弃分支和其他非正文内容不应因为存在于记录中，就自动进入正文 Agent 的上下文。

dsh-tavern 已经拥有剧情 Timeline、checkpoint 和 DSH Agent Surface。后续可以进一步收束为统一的“剧情上下文投影”模块：预设、世界书、摘要、正则和动态状态都通过同一个 Interface 影响模型输入，不直接修改权威历史。

### 2. 摘要负责连续性，原文归档负责细节

长局压缩不应只有一种产物：

- 接力摘要保留关键事件、人物关系、承诺、伏笔和当前场景，用于继续演出；
- 被裁掉的原文进入可检索档案，用于找回对白和具体细节；
- 最近剧情继续保留原文，避免续演点失真；
- 摘要必须记录明确的覆盖位置，并绑定生成它的剧情版本。

因此，摘要与向量记忆不是竞争关系。前者解决“剧情接得上”，后者解决“细节找得回”。

### 3. 派生状态必须绑定剧情版本

世界状态、候选项、世界书召回、摘要、状态栏和未来的地图、装备栏等面板，都属于某个明确的剧情 `branch/revision`。异步任务完成时如果剧情已经回退、替换或分叉，迟到结果必须作废。

磁盘文件和界面缓存只能是投影，不应成为另一份权威来源。回退剧情时，相关派生状态也必须恢复到同一 checkpoint。

dsh-tavern 当前的 `revision + checkpoint + stale result rejection` 已经具备这一基础，后续能力应继续复用它，而不是各自建立时间线。

### 4. 多 Agent 通过窄接口协作

剧情 Agent、后台 Agent 和面向用户的系统助手不应共享一锅上下文，也不应默认继承同一份预设：

- 剧情 Agent 负责正文演出；
- 世界书模块负责确定性的常驻与关键词投影；后台 Agent 负责候选分析和状态结算；
- 系统助手可负责配置、诊断、素材处理和其他戏外事务。

协作应表现为明确的任务委托和结构化结果交回，而不是把另一个 Agent 的完整思考与工具过程追加进剧情。各 Agent 可以共享经过校验的领域事实，但拥有不同的 Kernel、工具集合和上下文投影。

### 5. 领域工具统一定义，按运行面投影

世界书、记忆、人物卡、时间线和面板等能力可以由统一领域模块提供，再根据正文 Agent、后台 Agent、系统助手或界面的职责投影出不同工具集合。

工具是否出现应取决于当前运行面和依赖是否真实可用。读取、临时写入和持久写入应采用不同权限；模型写入用户长期资料时，必须遵守明确的用户授权规则。

这种设计能够提高模块的 Depth：调用方只学习稳定 Interface，兼容格式、存储、权限、错误隔离和具体实现集中在模块内部。

## 与 dsh-tavern 当前方向的关系

| 梨园经验 | dsh-tavern 的对应方向 | 判断 |
| --- | --- | --- |
| 每轮重建干净剧情投影 | DSH Surface + Tavern Timeline | 值得统一成一个深模块 |
| 状态快照随会话树回退 | checkpoint + 单调 revision | 已经同向，DSH 方案更完整 |
| 动态世界书独立召回 | 本地关键词匹配与冷却状态 | 借鉴独立领域边界，不引入 Agent 分析 |
| 世界线基于现有会话树形成 | Tavern branch/checkpoint | 借鉴领域语义，不另建存档系统 |
| 面板状态随剧情分支恢复 | 状态栏与未来可视化投影 | 可作为未来扩展原则 |
| 剧情 Agent 与系统助手分治 | 主 Agent + 后台 Agent | 可进一步区分用户可见的戏外助手 |
| 摘要与原文检索双轨 | 尚未形成完整长局记忆模块 | 最值得后续研究 |

## 不应照搬的部分

- 不复制梨园的生成循环、会话树或进程内 Agent 网关；DSH 继续是唯一 Agent 运行平台。
- 不强制采用“计划、分段续写、稿纸、封笔”的正文仪式。它可能增加模型轮次并影响游玩节奏。
- 不把世界书升级为独立 Agent 或生成流程；常驻和关键词激活继续作为确定性兼容机制。
- 不接受“正文只能是模型原始输出”作为共同原则。dsh-tavern 可以按照既定生命周期，将 `AI_OUTPUT` 正则处理后的结果确立为规范正文。
- 不把梨园的具体实现直接复制进项目。其代码采用 [PolyForm Noncommercial License](https://github.com/weidu12123/Liyuan/blob/master/LICENSE)，研究架构与复制代码是两件事。

## 建议优先级

1. 先明确统一的剧情上下文投影 Interface。
2. 在现有 Timeline 上建立摘要覆盖点与原文归档双轨模型。
3. 要求新增派生状态全部绑定 `branch/revision`。
4. 多 Agent 发展到需要用户可见的系统助手时，再建立任务委托与结果交回协议。
5. 工具种类明显增多后，再统一工具定义及不同运行面的投影。

总体原则是：借鉴梨园如何划分状态与责任，不迁移它的主体架构。所有经验最终都应转化为 DSH 原生能力，并由 Tavern 的权威剧情时间线统一约束。
