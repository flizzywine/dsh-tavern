# 《灯火阑珊》MVU 兼容链路验收

> 验收日期：2026-08-28
>
> dsh-tavern 分支：`MVU`
>
> 最近一次运行时验收提交：`e46f344`

## 结论

《灯火阑珊》已经能够在 dsh-tavern 的纯前台兼容模式中完成一轮真实运行：人物卡初始化 MVU 状态，前台请求携带变量快照，模型同时输出正文和标准变量补丁，Host 将补丁结算到当前消息及 Swipe，随后显示正则与状态栏读取新状态并重新渲染。

这证明当前实现已经形成可运行的 MVU 主链路，并能常驻执行本卡的变量结构、动态世界书、开场白索引和变量守卫脚本。它仍不等于完整复刻 SillyTavern、MagVarUpdate、ST Prompt Template 和 Tavern Helper；没有完成固定输入下的 SillyTavern 差分验证，因此当前不能标记为“完整支持”。

## 验收环境

- 人物卡：本机导入的《灯火阑珊》，不提交人物卡和 CG。
- 外部预设：`Kemini Dramatron 陨落的天才 v1.26`。
- 前台模型：Google Gemini 3.7 Flash。
- 测试动作：依次发送 `向前一步，观察四周。`、`我先停在路边，向赶车少年拱手问路。`、`我婉拒搭车，继续徒步前往临安坊市。`。
- 运行模式：兼容模式，纯前台 MVU；没有后台变量模型。
- 自动化测试：`625/625` 通过，`git diff --check` 通过。

本轮模型输入和输出具有随机性，只证明该次真实链路可运行；它不是同输入、同输出的差分基准。

## 可观察证据

### 1. 人物卡资产

人物卡中检测到五个 Tavern Helper 脚本入口：

1. `MVU`
2. `灯火阑珊-变量结构`
3. `灯火阑珊-动态世界书管理`
4. `开场白索引`
5. `变量守卫`

卡内还有发送侧变量清理、变量更新显示美化和状态栏加载正则。

### 2. 初始化与 Swipe

- 开场消息包含 15 个 Swipe。
- 15 个 Swipe 均建立了独立变量快照。
- 每个快照包含 `stat_data`、`schema`、`display_data`、`delta_data` 和 `initialized_lorebooks`。
- 某条开场白存在 YAML 缩进错误时，仅该 Swipe 产生诊断，其他开场白仍可使用。

### 3. 最终请求

本轮真实模型请求记录为 `mtcp19k9-b80d6eb1-dbe2-45e5-9c39-8e0ee1046e5c`：

- 请求模式为 `sillytavern`；
- 最终装配为 3 条消息；
- 发送内容约 8.4 万字符；
- `{{format_message_variable::stat_data}}` 已被实际 YAML 替换；
- 请求中包含 `世界时钟` 等当前 MVU 状态；
- 请求中没有遗留 EJS 标记；
- 本卡本轮没有 EJS 模板，因此 EJS 求值次数为 0。

### 4. 回复结算

前台模型在正文后输出 `<UpdateVariable>` 和 JSON Patch。兼容运行时成功把变更写入当前助手消息的变量快照，包括：

- `世界时钟/时辰`：`子时` → `丑时`；
- `本尊/行踪/当前区域`：更新为 `神州·青石古道·晨雾岔口`；
- 当前处境与可参与机遇同步更新。

状态栏远程 UI 随后继续通过 Helper bridge 写入派生字段，说明消息 iframe 到 Host 的变量 mutation 链路已经实际工作。

后续两轮还验证了：

- 人物卡自带的 MVU bundle 被 Host 明确接管，避免同一补丁结算两次；其余四个 Helper 脚本在独立常驻 iframe 中加载；
- 变量结构和变量守卫均完成注册，动态世界书读取了 105 条卡内世界书；
- 动态世界书首次把 14 条 selective 条目转成 constant，世界书从 `47 constant / 58 selective` 持久化为 `61 constant / 44 selective`；
- 第三轮的 `MESSAGE_SENT` 在模型请求前触发，脚本已经能读取尚未正式落库的用户输入并完成世界书检查；
- Host 在执行补丁前同步发出 `VARIABLE_UPDATE_STARTED`、`COMMAND_PARSED`，在应用后发出 `VARIABLE_UPDATE_ENDED`，浏览器脚本对变量和命令的修改会回传 Host；
- `COMMAND_PARSED` 使用上游兼容的完整 `args` 路径形式，自动化用例证明守卫把错误路径改写为 `stat_data.体力` 后，实际落库值随之改变；
- 第三轮状态继续推进为 `卯时`、`神州·临安坊市·外围山梁`，并成功插入 `青玉柰` 背包项；上一楼层快照未被污染。
- 同一《灯火阑珊》会话同时在桌面窗口与自动化浏览器打开时，服务端只向一个窗口授予 Helper 执行租约；另一个窗口只保留消息状态栏 iframe，不再重复启动 4 个常驻脚本，避免动态世界书竞争写入。
- 卡内无版本的 `MagVarUpdate` 入口被锁定到 `0a730cd4a9b99689d1135a49b542c780b977c24c`；`Apeiria@main` 的 4 个 Helper 入口与状态栏替换均被锁定到 `4b8f897b7fa07d1eb851018e98893a86f42be6b6`。固定映射已经写入 Profile，原人物卡仍保留原始 CDN 文本。

### 5. 显示结果

- 完整变量更新没有以原始协议裸露给用户，而是被显示正则折叠为“天道推演”。
- 《灯火阑珊》状态栏成功加载。
- 状态栏显示更新后的地点、危险度、时代和时段。
- 正文、MVU 结算和状态栏 UI 可同时存在，未互相覆盖。

默认隔离 iframe 会拒绝卡片脚本直接访问父页面。状态栏仍可加载和读取 Host 提供的变量；用户在设置中明确确认后，可以启用“受信任人物卡模式”。实测开启后，状态栏消息 iframe 与 4 个常驻 Helper iframe 均从 `allow-scripts` 切换为 `allow-scripts allow-same-origin`，关闭后又恢复隔离。

## 当前兼容矩阵

| 能力 | 当前等级 | 说明 |
| --- | --- | --- |
| `<initvar>` 与开场 Swipe 快照 | 受限支持 | 真实卡 15 个 Swipe 已建立快照；错误 Swipe 可局部隔离，尚未完成官方 MVU 全量差分 |
| 标准 MVU 补丁结算 | 受限支持 | 本轮 JSON Patch 已结算；支持核心操作和失败隔离，尚非官方 MagVarUpdate 整包运行 |
| 下一轮变量宏注入 | 受限支持 | `format_message_variable` 已在真实最终请求中展开，Helper 全部宏/API 尚未补齐 |
| ST Prompt Template / EJS | 受限支持 | 核心模板、变量和控制流在 QuickJS 中执行；《灯火阑珊》本轮未使用 EJS，完整上游 API 仍有缺口 |
| 发送侧与显示侧正则 | 受限支持 | 本轮变量宏、变量更新折叠和状态栏替换均工作；尚未与固定 SillyTavern 版本全量差分 |
| Tavern Helper 消息/变量桥 | 受限支持 | 常驻人物卡脚本可读写消息、三类变量与人物卡世界书；广泛生成、取消、父页面 DOM 和完整 API 尚未补齐 |
| 卡片专属动态世界书 | 受限支持 | 真实脚本已在加载、回复后和发送前运行，世界书修改可持久化；当前只开放绑定人物卡世界书，尚非通用多世界书 API |
| 变量守卫 | 受限支持 | 真实脚本已加载，Host 的 MVU 阶段通过前端握手交付完整事件；命令可被改写后再执行，但尚未完成固定官方 MVU 差分 |
| 状态栏与远程 CG | 受限支持 | 默认隔离下可加载 HTTPS 资源和 UI；显式受信任模式可开放同源父页面访问；卡内 GitHub CDN 入口已固定提交，R2 图片及递归依赖尚未缓存 |
| MVU 额外模型解析 | 不支持 | 当前按已确认方案坚持纯前台 MVU |
| SillyTavern 同输入差分 | 不支持 | 尚未捕获同版本、同输入、固定模型输出的请求、事件和 UI 对照 |
