# DSH 0.1.2-rc.1 适配记录

## 版本与边界

2026-09-03 核对 npm 官方注册表和 [DSH 发布说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.2-rc.1)：候选版为 `0.1.2-rc.1`，位于 `next` 标签；`latest` 仍为 `0.1.1-rc.2`。本次从 `0.1.2-alpha.2` 升级到精确版本 `0.1.2-rc.1`。

Tavern 安装器继续复用当前宿主依赖，不替用户自动升级 DSH，也不固定安装另一份内部运行时。适配版本由 `config/dsh-compatibility.json` 统一提供。

## 确认的断点与修复

新版原生 Session 移除了 `events` 属性，改用 `snapshotEvents()` 读取不可变历史。原开局恢复在 `session.events.filter(...)` 报错；后台结果、回退定位、重试计数等容错读法则可能把历史误判为空。

新增 `domain/session-events.js` 作为唯一读取适配点：优先调用新版方法，旧宿主回退到 `events`。不修改 Session、不缓存跨追加失效的快照，也不吞掉宿主读取错误。覆盖：

- 开场追加和中断恢复、稳定背景读取。
- 前台回复提取、失败轮清理、回退和最后一轮重新生成。
- 后台持久会话校验、任务结果、错误、完成边界和消息面回退。
- 重试次数约束，以及排错日志和重生成定位诊断。

原生测试夹具同步保存 `inheritedEventCount` 并传给新版恢复接口。两项原生测试不再假定 DSH Session 恰好被提升到插件的 `node_modules`，改为从实际宿主依赖解析。

新版子 Agent 的公共通信接口有变化，但 Tavern 使用 Agent handle 和自己的任务队列，没有调用被移除的 `SubagentRuntime.followup/reportFrom`，无需替换通信架构。

## 验证

- 修改前在真实 rc.1 上复现开局失败；修改后开场部分写入、保存失败、恢复和继续下一轮均通过。
- 新版真实宿主专项 28 项通过：开局、预设共存、用户工具、移动端插件挂载、凭据语义、后台生图与附件保存。模型和图片服务使用本地脚本响应，不调用付费服务。
- 针对社区报告的卡片工作台 `filter` 报错，另补一项原生回归：空白工作台和带卡工作台都能创建、恢复，开场只追加一次；已在 rc.1 通过，未单独安装 alpha.5 实测。
- 全量常规回归通过；需要原生宿主的可选测试另行执行，不把跳过项算作验证。
- alpha.2 的开局和统一生图 7 项回归通过，保留旧接口兼容。
- 新增 snapshot-only 回归覆盖重生成、回退、前台结果和最多一次重试，验证原事件前缀不被改写。
- 生图子包 166 项测试通过。
- 独立 rc.1 Profile 完整安装和启动通过；Chrome 实际新建卡片工作台、导入测试卡、新建游玩并显示开场正文，右侧资源库与酒馆状态正常，未观察到前端错误。
- 本机升级后重新安装 Tavern Profile、启动原服务，验证带鉴权的页面及人物卡、历史列表、设置、生图设置接口正常。

未验证 Windows / Android 真机、DSH Desktop 自带运行时或外部真实模型端到端游玩。这里的移动端验证仅是插件在新版宿主的挂载与卸载，不能替代手机实测。
