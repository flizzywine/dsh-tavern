# “狐析”用户画像模块提示词摘录

来源：`[主预设] V14.5 狐神抚 · 毓忻.json` 中 `extensions.tavern_helper.scripts[1]`（`🦊玄狐~`）。

本文只抽取“狐析”的问卷维度、核心提示词和工作流，省略界面、预设读写、事件监听与其他“玄狐”模块代码。

## 一、调查维度

1. 故事基调：轻松日常、黑暗奇幻、史诗冒险、温馨治愈等。
2. 文笔偏好：华丽细腻或简洁直白，是否偏好某类作者文风。
3. 整体节奏：快节奏或慢热，情感线与剧情线比例。
4. 人物描写重心：外貌、神态、心理活动、动作描写的侧重。
5. NSFW：类型、尺度、频率，或完全不要。
6. 互动风格：人物与用户交流时的语气和关系感。
7. 世界观/设定：背景设定的详细程度。
8. 雷区：绝对不能出现的内容。
9. 用户角色形象：综合其他偏好，描述用户希望扮演的角色形象。

## 二、逐项访谈提示词

脚本每次只调查一个模块。核心提示词如下（删除了“狐神抚”的角色语气描述）：

```text
你的任务：引导用户完成写作偏好分析。你正在和用户对话，一个模块一个模块地问清楚。

当前正在分析的模块：【{当前模块}】
提示问题：{该模块的提示问题}

已经分析过的模块：{已完成模块列表或“暂无”}

你需要：
1. 根据用户刚才的回复，进行分析总结（简洁模式为 1-3 个要点；详细模式为 2-5 个要点，并限制字数）
2. 然后用一句自然过渡问下一个模块的问题，给出 3-4 个参考选项引导用户
3. 语气轻松自然，像在聊天
4. 禁止续写正文，禁止进入角色扮演剧情，禁止写小说正文
```

它的开场问题会明确告诉用户：选项只是参考，也可以自由回答。例如故事基调给出：

```text
A. 轻松日常，氛围温暖治愈，节奏缓慢
B. 黑暗奇幻，压抑沉重，充满冲突和挣扎
C. 史诗冒险，宏大世界观，波澜壮阔
D. 温馨恋爱，注重情感细腻和关系发展

也可以自行描述想要的氛围，不必从选项中选择。
```

## 三、单项偏好扩写提示词

```text
你是用户偏好分析师。请阅读用户对“{模块名}”的简要回答，将其展开为一份精准的偏好分析。

格式要求：
- 提炼出 1-3 个核心要点，每个要点用简短标题开头
- 每个要点写具体说明
- 语言精准、有洞察力、有层次感
- 总字数限制在配置范围内

不要添加开场白、总结语或任何超出要点的内容。
```

对于“用户角色形象”这个综合模块，它改用另一段提示词：

```text
你是用户画像深度分析师。请根据用户的所有偏好分析结果和额外输入，详细描绘用户角色或对应特征应该具备的核心特质。

要求：丰富、具体、有层次感。分点描述，每条展开说明原因和具体表现；遵守配置的字数范围。
```

## 四、全局总结提示词

```text
你是总结专家，请综合用户与助手的全部对话，进行一个彻底的用户偏好总结。

按固定模块顺序整理，每个模块用【模块名】开头：
【故事基调】
【文笔偏好】
【整体节奏】
【人物描写重心】
【NSFW】
【互动风格】
【世界观/设定】
【雷区】
【用户角色形象】

最后增加【综合用户偏好】，综合以上分析，描绘用户角色应具备的特质、形象，以及用户喜欢的风格、世界观和其他偏好。

只输出指定标签内的总结内容，不加其他说明。
```

生成后先进入可编辑的预览框；用户点击“注入用户偏好”后，脚本才把各模块拆开并写进对应预设条目。

## 五、原模块的完整工作流

```text
逐项提问
→ 每次回答后总结当前模块并询问下一模块
→ 允许编辑、重答和回退对话
→ 汇总全部对话
→ 用户在预览框手动修改
→ 用户点击确认注入
→ 按模块拆分并写入预设
→ 每个模块可单独启用、关闭、重生成或清空
```

## 六、值得借鉴与不宜照搬之处

值得借鉴：

- 一次只问一个主题，并给出参考选项和自由回答入口。
- 每次先复述、归纳用户刚才的回答，再自然进入下一题。
- 原始对话、单项分析和最终总结分阶段产生。
- 最终总结先预览、允许修改，用户主动确认后才生效。
- 各维度可独立管理，不要求一次把所有问题答完。

不宜直接照搬：

- 它把分析结果直接写进当前 SillyTavern 预设，和预设条目 UUID 强耦合；DSH 应保存为独立的用户画像数据。
- 它固定顺序遍历九项，缺少根据回答跳题、追问矛盾和标注不确定性的机制。
- “用户角色形象”混合了用户本人的长期偏好与某次游戏中的玩家角色设定，容易跨人物卡污染。
- 单项扩写容易把一句模糊回答放大为未经用户确认的确定结论。
- 最终注入内容较长；DSH 游玩前缀应只使用用户确认后的最小充分摘要。
