# 强烈而旺盛的角色扮演游戏需求备忘

> 状态：产品判断与待验证假设，记录于 2026-08-27。本文不等同于市场规模报告。

## 核心判断

沉浸式角色扮演游戏存在强烈而旺盛的真实需求。

最有力的信号不是某个仓库的 Star 数，而是大量用户为了获得好玩、持续、稳定的角色扮演体验，长期忍受了极高的学习、配置和调试成本。用户不是因为酒馆容易使用而留下，而是因为人物卡、预设、世界书、插件和社区内容难以替代，才愿意学习一整套复杂技术。

> **酒馆繁荣的 trick 生态，证明的不是用户热爱折腾，而是用户对沉浸式角色扮演的需求强烈到愿意忍受折腾。**

## 需求信号

### 1. 用户以实际成本表达需求

为了玩到理想内容，普通用户需要接触模型供应商、API、参数、预设、世界书、正则、插件、上下文、破限、版本冲突和错误排查。这些概念远超普通娱乐产品应有的上手成本，但社区仍持续创作、分享、安装和调试资源。

这是一种比口头问卷更强的“已付出成本”信号：用户已经用时间、学习和反复试错证明，他们在意最终体验。

### 2. 社区在聊天架构上手工模拟 Agent

酒馆的许多复杂技巧，本质上是在传统逐轮消息拼接架构中补出 Agent 能力：

| 酒馆技巧 | 试图获得的能力 |
| --- | --- |
| 预设、提示词排序、注入位置与深度 | 规则和上下文调度 |
| 世界书、关键词触发 | 检索与按需记忆 |
| 总结、压缩、递归摘要 | 长期记忆管理 |
| 变量、MVU、状态栏 | 结构化状态存储 |
| 正则、HTML 前端 | 输出协议与界面渲染 |
| 多次生成、插件联动 | 工作流与子任务分工 |
| 防截断、自动续写 | 生成生命周期管理 |

这些能力没有由统一运行时提供，于是创作者和用户发展出大量相互依赖的提示词、插件和操作惯例。复杂度能够长期存在，说明它所补偿的体验具有足够高的价值。

### 3. 内容生态比技术产品本身更接近用户

用户真正寻找的是好玩的人物、故事、玩法和表现形式，而不是某种聊天架构。人物卡、预设、世界书、正则和插件构成了内容生产与传播网络；技术本体只是承载这个网络的运行环境。

社区中热门的插件和预设的点赞数量可以达到1万，而酒馆本体的star才3万多。说明用户更在意内容，而不是技术架构。

## 对 dsh-tavern 的产品推论

### 1. 首要任务是消灭使用门槛

普通用户的理想路径应当只有三步：

**找到喜欢的内容 → 导入 → 开始玩。**

插件安装、预设组合、提示词结构、模型参数、上下文管理和错误诊断都应由系统承担。高级能力可以开放，但不能成为开始游玩的必修课。

### 2. 必须承接现有酒馆生态

新的 Agent 架构如果要求用户放弃已经存在的人物卡、预设、世界书和前端内容，就同时放弃了最重要的需求入口。生态兼容不是附加功能，而是用户迁移到新架构的桥梁。

### 3. 保留体验，不复制复杂性

dsh-tavern 不应逐项照搬所有 trick，而应识别它们试图实现的真实能力：

- 可以稳定翻译的能力，转成 DSH 原生 Agent、记忆、状态、工具或渲染能力；
- 必须依赖精确消息结构和运行时语义的资源，进入隔离、可诊断的兼容层；
- 无法可靠兼容的部分明确说明影响，不静默降级，也不要求普通用户理解内部原因。

### 4. Agent 是实现手段，不是用户需求

用户需要的是沉浸、连续、稳定、低门槛的角色扮演体验。Agent 架构的价值在于更自然地承载记忆、状态、工具和任务分工，但产品不能要求用户先理解 Agent 才能使用。

破限也不能简单归因于缺少 Agent。其效果还会受到消息结构、模型行为和提供商审核影响；Agent 架构可以替代大量上下文与状态 trick，但不能保证突破模型或供应商的外部限制。

## 仍需验证的假设

现有信号足以支持产品方向，但还不能直接证明市场规模、付费规模或长期留存。后续应重点记录：

- 首次安装到成功进入第一轮游玩的时间；
- 人物卡或预设导入后的直接可玩率；
- 完成首次游玩需要查看教程或求助的比例；
- 连续游玩 10 轮、30 轮和长期会话的成功率；
- 兼容问题导致的退出率；
- 周活跃玩家、活跃会话和回访率；
- 用户为内容、便利性和稳定性付费的真实意愿。

这些指标将把“需求非常强烈”的产品判断，逐步转化为可验证的市场结论。

## 一句话结论

> **角色扮演需求已经强烈到让大量用户忍受一整套民间 Agent 技术栈；dsh-tavern 的机会，是承接这套生态创造的体验，同时让普通用户彻底忘掉背后的技术复杂性。**
