# 破限实验备忘

## 2026-08-27

- 模式：DSH Tavern 游玩模式，已启用当前破限方案。
- 现象：模型流式输出了 167 个字符，随后供应商关闭连接，且没有返回 `finish_reason`。
- 判定：生成过程中触发了供应商内容审核，输出被中途截断；本轮破限实验失败。
- 结果口径：已经流出的部分文字只说明模型曾开始生成，不算完整、有效的回答，也不能将本轮记为成功。
- DSH 表现：由于响应没有正常结束，DSH 将本轮判定为失败，并撤回界面上短暂出现的半截输出。

## 2026-08-26

- 模式：SillyTavern 兼容模式。
- 模型：Gemini 3.7 Flash。
- 预设：当前测试预设。
- 观察结果：预设能够通过本次测试内容；但模型偶尔仍会拒绝，直接使用“重新生成”再次请求通常可以成功。
- 能力边界：对于过于露骨的内容，模型仍会持续拒绝，多次重新生成也无法通过。
- 当前结论：兼容模式下该预设对 Gemini 3.7 Flash 有效，但效果并非每次稳定复现。
- 未确认项：首次拒绝、重新生成后成功的原因尚不明确，暂不归因于预设、请求差异或模型侧随机性。

## 2026-08-23

- 模型：Gemini 3.7 Flash（Infron）。
- 案例：人物卡《段莹莹》，剧本《女儿吟之欲求.txt》。
- 预设：`Kemini Dramatron 陨落的天才 v1.26`，开启 4 个条目。
- 已确认：19,518 字预设完整位于前台系统提示词最前面，后台 Agent 也使用同一份对话快照。
- 结果：后台 Agent 能正常输出；前台读取约 1,757 字真实剧本后连续断流，报错 `Stream ended without finish_reason`。
- 对照：保持工具调用不变，只把剧本工具返回值替换为普通校园日常内容，前台成功输出。
- 结论：不是预设未注入，也不是工具调用本身导致拒绝；本次拒绝由真实剧本内容触发。当前预设对后台任务有效，但没有稳定突破前台正文任务。
- 待测：在 SillyTavern 中使用相同模型、预设和案例复测，比较预设条目角色与排列方式的影响。
- 收尾：实验结束后已移除剧本读取诊断开关，恢复真实剧本读取。
