# 人物卡展示正则掉格式问题备忘

日期：2026-08-25

状态：尚未修复

## 背景

人物卡通常要求模型按固定文本格式输出，再用 `markdownOnly` 展示正则替换成带样式的 HTML。只要模型输出与正则约定稍有偏差，正则就不会命中，最终只能显示普通文字。

这不是 HTML 渲染失败，而是人物卡没有生成对应的 HTML。

## 问题一：候选项标记漂移

人物卡的“选项-白伊甸校园”规则要求：

```text
/A选项：...
/B选项：...
/C选项：...
/D选项：...
```

模型实际输出：

```text
/A.答应美月，跟着她走向宿舍楼。
/B.拒绝两人，自己去宿舍楼。
/C.转向夏芽，问她关于单人间钥匙的事。
/D.什么都没说，只是站在原地。
```

真实重放结果：

- “选项-白伊甸校园”规则没有执行。
- `.options-container` HTML 没有生成。
- iframe 只能把候选项显示成普通文字。

### 待考虑方向

- 人物卡正则同时兼容 `/A选项：`、`/A：`、`/A.`、`/A、` 等形式。
- 不依靠把格式指令移到模型附近来保证命中。
- 不在 DSH 全局层强行改写所有人物卡的候选格式。
- 长期需要考虑比脆弱文本正则更可靠的结构化展示协议。

## 问题二：多个人物只有第一个被替换

人物卡配置了“在场女生-1”到“在场女生-15”多条规则，但每条规则都要求从以下标题开始：

```text
[在场女生]
【名字】：...
```

第一条规则替换第一个人物时已经消耗 `[在场女生]`。第二个人物前只有 `【名字】`，不再存在该标题，因此第 2～15 条规则全部无法命中。

这些规则虽然名称不同，匹配结构实际相同，并不能依次匹配第 1、2、3 个人物。

### 待考虑方向

- 合并为一条全局人物正则，连续匹配人物记录，不限制最多 15 人。
- 或让第一条规则负责消费 `[在场女生]`，后续规则只匹配没有标题的人物记录。
- 需要验证规则不会误匹配正文里的其他 `【名字】` 字段。

## 问题三：内嵌 JavaScript 的 `$1` 被外层正则提前替换

“正文-白伊甸校园”的 replacement 内嵌了 JavaScript：

```js
html.replace(/“([^”]+)”/g, '<span class="tsukihi-quote">“$1”</span>')
```

这段 JavaScript 尚未进入 iframe 时，`$1` 已经被外层人物卡正则解释为第一个捕获组，即时间 `16:47`。最终进入 iframe 的脚本变成固定替换：

```js
html.replace(/“([^”]+)”/g, '<span class="tsukihi-quote">“16:47”</span>')
```

因此正文中的不同引号内容都会被错误替换成“16:47”。

### 待考虑方向

- 在人物卡 replacement 中正确转义内层 replacement token。
- 需要按 Tavern 的真实 replacement 语义做回归验证，不能直接全局替换所有 `$1`。
- 应覆盖 `$1`、`$2`、`$&`、`$$` 等内外两层 replacement token 的冲突情况。

## 核心问题

目前人物卡把“模型必须严格输出固定文本格式”和“展示正则必须准确命中”绑在一起：

```text
模型格式稍有漂移
→ 展示正则不命中
→ HTML 不生成
→ 卡片样式失效
```

这类问题不能只靠反复强调格式指令解决。后续需要同时考虑：

1. 让人物卡正则对常见格式变化更宽容。
2. 避免多条规则依赖会被前一条消耗的公共标题。
3. 区分外层展示替换 token 与内嵌脚本自己的替换 token。
4. 长期设计更可靠的结构化输出与展示协议。
