# 工具约定移入稳定前缀：Flash 对照

2026-09-12。结论：移动规则不减少输入长度；本次观察到预热后更好的缓存复用，但未证明整个短会话费用下降，也没有稳定减少输出。

## 条件

沿用用户公开阿芙拉 demo 与前两次实验的两个场景，官方 DeepSeek V4 Flash、High、temperature 0.1、max_tokens 20000。两组均包含“合理即可”和同次提交协议，不包含额外停止句。

将五条固定约定组成同一个块：通过工具而非 XML 提交、无变化提交空数组、校验失败修正、回滚语义、成功后不重复提交。内容不删减。末尾组放在当前 user 消息末尾；前缀组移到最前面的 system 消息。两组均加相同的条件说明“执行变量结算任务时，遵守以下约定”。本轮任务选择、必须调用哪个工具、正文、变量、卡片规则不移动。工具 schema 相同。

每个场景各三组配对，共 12 次。三个批次的初始信任分别为 18、21、24，正文有两种，因此每组依次处理六个不同输入，避免把原样重跑的整段请求缓存误判为固定前缀收益。两组每个对应样本的初值完全相同，不把各组生成结果反馈到下一次。批次交替执行组别顺序。

复用正式结算模块处理工具/回执，使用实验 typed-field adapter 校验并隔离落盘；不是完整浏览器 MVU/DSH provider 链路。官方 cache usage 是观察值，实验不能清空或精确控制服务端缓存。

## 冷启动与后续请求

首个前缀请求命中 0，首个末尾请求命中 1280：末尾布局与此前实验有可复用前缀，而新 system 布局需要重新预热。这种初始条件不对等，必须保留并说明。

第二、三批次的四个不同输入中，前缀组每次多命中 256 token。四次合计输入均为 6498，缓存命中 3072 → 4096，未缓存输入 3426 → 2402（减少 29.9%）。这是预热后子集的结果，不是全部样本的结果，也不是账单节省比例。工具约定块 433 字符；前移让它位于动态变量之前，可复用跨度增加。实际产品若有更长稳定内容、不同 provider 或消息投影，缓存表现仍需实测。

规则从 user 尾部移到 system 同时改变了角色和位置，因此任何生成差异不能仅归因于缓存。输出没有稳定改善，耗时受网络/缓存影响，不作性能保证。

## 正确性与限制

- 保存的六对完整请求，将前缀块原样搬回末尾后逐字段完全相同。
- 12/12 单响应包含两项工具、无截断/重试、回执 updated；状态独立读回与结果一致，通过字段集合、信任整数范围和非空姿势检查。
- 估值与措辞存在差异，没有唯一正确增量；通过结构和范围校验不等于叙事质量完全一致。
- 本实验仅变量结算，未测试候选任务等其他后台用途。正式迁移仍需保留条件作用域，避免把变量提交要求强加给其他任务。
- 原卡和正式提示词未在本次修改。
