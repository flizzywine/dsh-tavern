# 工具说明迁移后的连续三回合实模游玩

2026-09-12，生产代码 `2e679cb`。用户要求连续玩三个回合、结算三次，而非独立重复样本。

## 方法与边界

用户公开 demo 阿芙拉，原始状态栏六字段投影为隔离变量副本。前台和后台均使用官方 DeepSeek V4 Flash、High；前台 temperature 0.8、后台 0.1。前台逐轮调用真实模型续写，保留开场、全部此前玩家行动与模型正文，每轮提供最新结算快照。后台使用本次真实生成正文与上轮从磁盘读回的状态，通过正式 createMvuSettlementModule 结算，再落盘作为下一轮输入。没有预写模型正文，没有重置每轮变量，没有注入失败或指定信任数值。

后台提示来自当前正式模块，固定重试/回滚说明仅存在于工具 description，没有额外塞回本轮提示。变量执行仍是实验 typed-field adapter，实际写入隔离文件，不是安装版 UI 或浏览器官方 MVU 引擎。因此这是连续三轮实模模块验证，不是完整产品端到端验收。

三轮分别调用一次 posture_submit 和一次 mvu_submit_update，均在同一个模型响应中完成，两项返回 ok=true，回执 updated。无丢工具、无重复提交、无重试、无输出截断。信任未被人为要求每轮上升。

独立核验：第 2/3 轮 baseline 与第 1/2 轮落盘结果完全相同；前台请求历史逐轮增长；后台使用对应实际正文；三份状态文件读回与结果一致。固定工具约定在 tools 中，而非本轮正文提示中。

## 内容层面的遗留问题

调用流程成功不等于结算内容完美。第三轮已经是次日再访，但时间字段仍保留“雨夜 · 二更”，线索字段中的旧“明日中午可碰面”也未清理，只追加了新线索。该 demo 时间是自然语言字符串，没有日期字段或过期线索规则；因此结构校验通过，时间/线索新旧语义仍可能不一致。没有把它描述成全部状态语义正确，也没有为让测试通过而改结果。
