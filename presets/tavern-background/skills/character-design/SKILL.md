# 人物设计

在当前后台 Agent 会话内完成，不创建另一个 Agent。档案属于当前对话；保存后自动补充绑定的原始世界书并同步本局，前台按世界书召回规则读取。人物设计独立保存，不是姿势字段或 MVU operations：保存档案不会替代、跳过或完成本轮的姿势与变量结算。

## 选人

先调用 `character_design_read` 读档案与本局世界书索引，按姓名/别名查询正文。已有完整世界书人物设定时用 `character_design_reuse` 提交姓名和已读 refs；复用即完成，不另建档案。零散提及不算完整设定；动态模板用 worldbook_search 读渲染结果。已有同名/别名条目时不能换名绕过重复保护，需要修改原条目则交由用户编辑世界书。用户给了设计意见就按意见来；没给时按当前剧情和已有档案自己选。

- 已有档案的人物：按索引里的姓名读完整档案，在上面补充或修订。姓名写法不同、暂时离场或状态变化都不是新建的理由。
- 新建档案只给重要人物：可能持续登场、能推动剧情，或值得提前储备的。路人、一次性功能角色不建档。
- 剧情确实需要多名重要人物时，可以都完整设计，没有数量上限。

## 档案内容

只有五项，各写各的重点，不互相重复：

- **身份**
- **性格**：面对选择、冲突和关系变化时会怎么做。
- **外貌**：含日常穿着。
- **说话方式**
- **剧情作用**：此人的作用和可能的发展方向。设计可能性，不预写尚未发生的剧情。

结合题材、世界设定、已有人物来写，人物之间要有鲜明差异。每项都给具体内容，不写「未知」「待定」「未明确」之类占位。

## 保存与收尾

用 `character_design_save` 保存整份档案（只接收人物设计字段，不接收变量路径或变量对象），以 ok:true 为成功。新人物成为以姓名/别名触发的非常驻世界书条目，多书写主书，未绑定时建内置书；只自动同步本次设计变更，其他资源仍需用户确认。内容校验失败按错误修正；本局正文已被手改的冲突要保留用户修改、结束任务，不换名重建。

全部读写完成后调用 `character_design_finish` 结束设计阶段；不调用它，后续的姿势、变量或候选项提交会被拒绝。用户手动发起的人物设计任务到此结束，不提交姿势、变量或候选项；结算或候选任务中顺带设计时，结束设计阶段后继续原任务。

档案不输出到回复文本，不生成 HTML，不向前台追加说明。
