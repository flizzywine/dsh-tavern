# 智能判断

界面位置：舞台设置 › 基础设置 ›「舞台模式 ›」→「判断模型」。

## 它做什么

导演每编排一段正文前，对"没有被正文召回的绿灯素材"逐条询问判断服务："这条素材适合这段剧情吗？"，概率达到阈值的按概率从高到低补入候选，每次每类最多 `capPerKind` 条。一轮正文较长时会分段判断多次。蓝灯和已被正文召回的绿灯不占名额，关灯的素材永不提问。人物当前穿着和默认服装不参与判断。判断失败、超时或没有配置时，蓝灯和正文召回照常，只是不补位；不会随机补位，也不重试。

发给判断服务的是 `preamble`、本段正文和每个问题（素材的种类、名称与使用情景；已启用的模组也可能加入自己的判断问题）；不发送玩家输入、旧轮次、变量、世界书或完整人物卡。

## 配置

`tavern_stage_read judge` 读取当前配置、revision 和凭据状态；`tavern_stage_patch judge` 保存，属于全局设置，每次写入都要经宿主批准。这里读写的是全局配置；玩家在「舞台模型」或本局设置里给判断模型另选的模型优先，所以本局实际用什么要以界面为准。

| 字段 | 说明 |
| --- | --- |
| `provider` | `unset`（默认，不发任何请求、零费用）、`jev`、`openai`、`openai-compatible` |
| `model`、`baseUrl` | 模型名；`baseUrl` 只用于 OpenAI 兼容，需要支持 Decisions 协议，只提供 chat 接口的代理不能用 |
| `keyName` | 凭据名称，例如 `OPENAI_API_KEY`。工具只保存名称并显示是否已配置，不接收密钥本身。密钥由用户自己填：「判断模型」的「API Key」里直接粘贴密钥（保存在本机凭据里，不回显），或填已有凭据的名称 |
| `threshold` | 0–1，默认 0.6；调高补位更少 |
| `capPerKind` | 每类最多补入的条数，默认 8 |
| `timeoutMs` | 默认 1500 毫秒 |
| `enabled` | 关闭时等同未配置 |
| `preamble` | 附加在问题前的说明，默认空 |

## 费用

设置了提供方以后，每轮导演都可能产生一次或几次（长正文分段）按量计费的判断请求；费用由提供方按 API 用量收取，通常不包含在聊天订阅里。配置前把这一点告诉用户。想省钱时，先把常用素材的名称和触发词调好（或改蓝灯），比开智能判断更可控。

## 测试连接

`tavern_stage_patch judge-test` 会尝试发出一次真实的极小请求，可能收费（凭据或地址不对时在发送前就会失败）。只在用户要求测试时调用；它属于付费操作，要经宿主批准。结果是 `{ok, latencyMs, error?}`：成功时说"能连通"和延迟；失败时按错误给出修法（凭据未配置、地址不对、超时），并提醒请求可能已经发出，不要自动重试。

## 例子

用户："绿灯素材总是用不上，帮我开智能判断，用 OpenAI。"
→ 说明会按轮计费 → 读取 judge 配置 → 告诉用户"这是全局设置，会影响所有卡片：智能判断提供方改为 OpenAI，模型和凭据名称为……" → 写入（经宿主批准）→ 回读并查看凭据状态；未配置时请用户在「判断模型」的「API Key」里粘贴密钥。用户同意后再测试连接。
