# 舞台导演

导演跟着正文编排舞台演出：正文还在生成时就按段落开始安排，正文写完后收尾，内容包括换背景、人物上下场、换装、音乐、音效等。它只能从候选目录里选素材，不能创建素材（候选怎么来见 stage-assets 的灯态与触发词说明；前台写作风格用 create-writing-skill）。本 Skill 调整导演的规则和说明。工具：`tavern_stage_read`、`tavern_stage_patch`（引擎、智能判断）、`tavern_assets_read`、`tavern_assets_patch`（演出风格和素材说明）。

## 调用格式

每个工具只有一个 `request` 参数。几个动作共用的字段放在外层，`action` 和这个动作其余的字段放进 `operation`，可以嵌套多层，层级以工具 schema 为准；下文的 `动作 {字段}` 只列出字段。例如：

- 改引擎设置：`tavern_stage_patch({request:{expectedRevision:'引擎 revision', patch:{actionCaps:{…}}, operation:{action:'engine'}}})`
- 读预览：`tavern_stage_read({request:{action:'director-preview', playRef:'play-chat:…', turn:3}})`

## 按问题选手段

| 用户的问题 | 手段 | 范围 |
| --- | --- | --- |
| "导演太频繁换背景""希望多用镜头" | 演出风格条目（`directions`） | 放在哪个包决定范围 |
| "下雨的场景要用这首曲子" | 该素材的 `directorNote` | 用到该包的卡 |
| "在中转站工作时穿工作服" | 服装的使用情景 `guidance` | 用到该人物的卡 |
| 关掉某类演出、限制每轮动作数 | 引擎 `dimensions`、`actionCaps` | 全局 |
| 换导演模型 | 界面：设置 ›「舞台」›「舞台模型」 | 全局（本局设置可只换这一局） |
| 绿灯素材该出现却没出现 | 先看预览，再考虑触发词或智能判断 | 见下文 |
| 模组演出，如手机、文字演出等的用法 | 模组设置，见 stage-mods | 按模组 |

## 演出风格

演出风格是素材包里 `kind:'directions'` 的条目：正文写在 `text`，最多 2000 字，只有启用和关闭（固定蓝灯，没有触发词，`directorNote` 留空）。所在包对本卡生效时，启用的条目会原样加进导演提示词；本卡包的条目在前，全局包的在后，可以多条叠加，系统不设优先级，互相矛盾时请用户取舍。

- 只想影响这张卡：写进只绑定给这张卡的包。写进全局启用的包会影响所有卡，按全局写入处理。
- 正文写具体做法，例如"多数段落不出指令；只在场景或时间真正变化时换背景"，不要写"演出要自然"这类空话。
- 导演规则写在演出风格或素材、服装的说明里；人物卡的人设和世界书是前台正文读的，不用来控制导演。

完整例子：用户要"没写换装就保持上一轮那套"。

1. `tavern_assets_read({request:{action:'bindings'}})` 列出这张卡绑定的包（`boundPackIds`）和全局启用的包（`globalEnabledPackIds`）；挑一个只绑定、不在全局启用里的包，再用 `dependencies {packId}` 确认没有别的卡在用。没有合适的包就按 stage-assets 新建并绑定一个。`item {kind:'directions', packId}` 列出现有风格和包的 `revision`，要看某条风格的正文再加 `id` 读取。
2. 调用：

   ```js
   tavern_assets_patch({request:{expectedRevision:'第 1 步的包 revision', operation:{packId:'…', operation:{action:'item', item:{
     kind:'directions', id:'outfit-keep', name:'保持服装连续', enabled:true,
     recall:{mode:'constant', keywords:[]}, directorNote:'',
     text:'正文没有明确写换装时，保持人物上一轮的服装。'
   }}}}})
   ```

3. 回执成功后再读 `item {kind:'directions', packId, id:'outfit-keep'}`，看到这条启用的风格才报告"已保存"，并说明它从下一轮起影响导演。

## 素材与服装说明

`directorNote`（最多 300 字）告诉导演这条素材适合什么情景，例如"用于雨夜的室外场景"。服装 `guidance`（最多 80 字）写什么时候换上，例如"在中转站工作时"；临时道具类服装写清何时恢复原装。说明写情景，不写"必须每轮使用"之类的指令，导演仍按剧情判断。通用规则：一两句说清它是什么、在什么情景或情绪下用；出处、源 ID、原作集数和待办写进备注 `remark`（不发给导演）。例：`directorNote:"有人在门外敲门；用于访客到来、深夜来访或打断屋内谈话。"`，`remark:"来源：通用SE door-knock"`。改这些字段要用读取得到的包 revision，修改的是共享素材。

## 引擎设置（全局）

先 `tavern_stage_read engine` 取值和 revision，`schema {section:'engine'}` 看可写字段。读取结果说明的是当前配置；用户问"为什么太吵"时，把全局上限、本卡风格和本轮实际演出分开说，没有预览时不断定原因。导演模型由用户在 设置 ›「舞台」›「舞台模型」›「导演模型」选（默认跟随前台，即和当前聊天用同一个模型），本局设置里可以只给这一局换；导演模型必须支持工具调用。引擎里的 `directorModel` 不决定实际使用的导演模型，不用它换模型。「可用演出」（`dimensions`）和「每轮上限」（`actionCaps`）在 舞台设置 › 基础设置 ›「舞台模式 ›」页。写入前告诉用户"这是全局设置，会影响所有卡片"及具体变化；写入要经宿主批准才执行。

## 智能判断

智能判断（界面叫「判断模型」，在「舞台模式」页）用一个付费的判断服务，为未命中触发词的绿灯素材补位；不配置也能正常玩。配置、费用和测试读 [智能判断](references/judge.md)。

## 检查导演看到了什么

工作台关联了游玩记录（`play-chat:` 引用）时，用 `tavern_stage_read director-preview {playRef, turn}` 读取那一轮的导演输入预览：先看分节目录和字节数，再按 `section` 取需要的部分。预览用那一轮的正文加上**现在**的素材和设置重新组装，适合确认新规则会不会生效，不代表导演当时看到的内容。预览只读，不调用模型。用户也可以自己看：舞台设置末尾折叠的「提示词」→「导演模型」。导演指令是「目标.动词」写法（如 `music.clear`、`cast.add`、`cg.set`），由导演生成；卡、世界书和演出风格用普通文字描述意图即可。没有关联游玩记录时，请用户从对应游玩对话进入工作台，不要猜测记录 ID。用预览确认某条素材是否在候选里、某条风格是否已注入，再决定改灯态、触发词还是说明。

## 不改写已有演出

规则和说明从下一次导演起生效（导演进行中改了素材或设置，这一次导演会停下）。背景、服装、站位、音乐等持久状态在导演没有改动时保持原样，只随导演的增量操作及其联动（换场、离场、到期）变化；改规则不会清空当前舞台，也不会重新导演或改写历史演出。不要为了"让新规则生效"去要求重导历史轮次。

## 用工具完成，按事实报告

- 导演设置和规则只通过本 Skill 的工具读写。报错里的 `example` 是最小合法骨架：占位符换成读到的值，空数组只表示类型、不代表清空。工具做不到的事，说明缺什么或界面位置。
- 智能判断的凭据状态只说明配置，测试连接成功后才说"能连通"。
- 报告只描述工具结果里出现的事，分清：计划（还没调用写工具）、已问你（等你回复）、等待宿主批准、未获批准没有改动（照审批错误的 `message` 转述，会话策略自动拒绝不说成用户拒绝）、已保存（回执成功且回读到目标值）。

## 完成标准

回执成功且回读显示新值。有关联游玩记录时，用预览确认新风格或说明出现在导演输入里；预览不是已经发生的演出。实际演出效果请用户在下一轮游玩中确认。
