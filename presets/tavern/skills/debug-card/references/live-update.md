# 修改后在原存档继续玩

用户改完资源后回到原游玩会话，点「应用变化到当前游戏」即可继续。状态栏、EJS、世界书与变量结构会一起预检，通过后原子应用；失败则保留上次已应用的定义与变量。应用不会重新执行开场初始化，游戏进度不会被覆盖。

## 修改要点

- 改状态栏 HTML/CSS、正则或 EJS 时，保留状态栏声明和正则的 id。EJS 展示读取当前变量；预览时的变量写入被隔离，外部写入与命令不在预览中执行。需要改变游戏状态的逻辑放在正常结算里。
- 新增变量要给默认值；已有数值继续保留，改默认值不会重置旧存档。
- 字段改名、移动、删除或改类型时，在同一次卡片修改里写迁移声明，并同步世界书初值和更新规则。
- 预检报告路径冲突时修正迁移声明后重试，不用重开游戏来掩盖迁移缺失。

## 变量迁移声明

写在人物卡 `extensions.dsh_tavern.stateMigrations`，用 `tavern_update_card` 的 rawOperations 修改。V2/V3 原始文件通常是 `/data/extensions/dsh_tavern/stateMigrations`，先读原始结构确认。保留已有声明，新迁移用新 id；已执行过的 id 内容不能再改。

```json
[
  {
    "id": "wallet-v2",
    "operations": [
      {"op": "move", "from": "/gold", "path": "/wallet/coins"},
      {"op": "convert", "path": "/rank", "type": "number"},
      {"op": "remove", "path": "/obsoleteFlag"}
    ]
  }
]
```

路径相对于 `stat_data`，JSON Pointer 中 `~1` 表示 `/`，`~0` 表示 `~`。支持对象字段和嵌套对象；数组内字段、数组重排和任意脚本转换不支持，遇到时保留旧结构，改展示或规则来继续玩。

- `move` 保留原值，目标已存在时拒绝，避免覆盖另一项进度。改名必须用 move：直接新增新名、删掉旧名会被预检拦截，否则玩家的数值会被当成新字段重置。
- `convert` 支持 string、number、boolean。数值字符串可转数值；布尔只接受 true/false 及其字符串，不猜单位或语义。
- `remove` 只用于用户明确不要的字段，并同时删除初值定义，否则会被当成新增字段补回。
- 迁移作用于所有已有 MVU 快照（历史回合、候选 swipe、回退检查点、撤销数据），历史数值保留。

## 验收

原 chat/session 不变、已有正文不变、当前数值延续、新状态栏出现、刷新不重复触发 EJS 副作用、新一轮结算成功、回退后数值正确。没有实际应用并继续一轮时，报告「资源已修改，待应用验证」。存档救援只用于旧对话本身无法继续的情况，不是普通改卡流程。
