# 卡片调试

采用 diagnosing-bugs 的证据闭环：确定具体症状，建立可判定的复现，验证假设，再修复复测。使用 Tavern 提供的工具，不假设卡片 Agent 有终端、浏览器或仓库访问能力。

## 1. 锁定现场

确认目标人物卡、已挂载的 `play-chat:` 引用、异常轮次，以及用户期待与实际结果。只有一个引用时可省略 ref；多个引用先确定目标。缺少引用时请用户从对应游玩对话进入卡片调试，不猜 chatId。

先调用 `tavern_read_play_chat` 读取小型 `overview`。用户指定轮次就读该轮，否则从最新一轮开始；需要定位首次异常时读取 `turns`，再选择相关轮次。按返回的分页信息补齐需要的片段，不把截断内容当成完整证据。

首次需要读取日志、请求、状态或关联资源时，通过 `tavern_read_skill_reference` 读取 [证据与文件位置](references/evidence.md)（name 为 `debug-card`，path 为 `references/evidence.md`）。不要一次加载全部正文和日志。

完成标准：能用具体输入、轮次和可观察结果描述问题，例如“该轮 source 有状态标签，但 display 中整段消失”，而非“卡有问题”。

## 2. 建立验证闭环

优先使用已保存的异常轮次做对照，确定什么证据能证明失败、什么结果算修复。对比相关输入、原文、Session、展示或后台状态，缩小到造成差异的最小字段或规则。

本 Skill 以已有现场的只读诊断为主，不自动启动测试或重新生成。确需新证据时，说明缺少什么、给出最短复现步骤，请用户在游玩页面操作后继续读取对应记录。一次模型输出成功不证明随机性问题已消失；报告实际观察次数与失败情况。

尚不能复现时可继续只读检查并明确证据缺口，不能把猜测当成原因或宣称修复。性能问题先记录具体阶段耗时，区分首轮与后续轮次、前台生成与后台结算。

## 3. 验证原因

对模糊问题提出少量可证伪的候选原因，每个说明“若成立，会在哪一层看到什么差异”，优先检验最有证据的一项；明确的直接错误无需凑足假设数量。一次只验证一个变量。

定位到模型输出、提示词组装、Session 投影、展示正则、iframe 运行、后台任务或人物卡规则中的具体环节。核对当前卡与游玩快照是否一致；当前规则重新计算的结果不能代表当时的处理过程。

遇到 iframe 太矮、长内容裁切、滚动或百分比高度问题时，通过 `tavern_read_skill_reference` 读取 [iframe 高度适配](references/frame-sizing.md)（name 为 `debug-card`，path 为 `references/frame-sizing.md`），根据实际布局证据选择模式；长正文优先撑高外框。

完成标准：给出支持原因的具体证据，并说明仍未排除的因素。发现宿主或提供方问题时报告边界，不通过篡改卡片来掩盖故障。

## 4. 最小修复与复测

先说明原因、拟改字段和影响范围。用户仅要求诊断时，给出方案；已明确授权修复时继续执行，无需重复确认。通过 `tavern_update_card` 等对应资源工具修改，保留无关设定；不得改写游玩历史或直接编辑运行中的持久化文件。

修复涉及状态栏、EJS、变量字段或世界书，且用户要继续原游戏时，先通过 `tavern_read_skill_reference` 读取 [原存档更新与迁移](references/live-update.md)（name 为 `debug-card`，path 为 `references/live-update.md`），同时维护变量迁移声明。

按原来的失败判据复测，并核对紧邻的正常场景。明确区分静态规则检查、保存记录对照和真实 Agent 试玩；没有执行的验证如实说明。临时诊断内容若已加入资源，收尾时清除。

结尾简短报告：原因、修改、验证结果、剩余限制。展示请求或日志片段前隐藏密钥、令牌和 Cookie，仅引用与故障相关的内容。
