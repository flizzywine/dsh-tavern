# 创建 DSH 人物卡

交付人物卡、声明和资源互相匹配的成品。卡保存成功、素材安装成功和舞台可运行分别核实。

## 独立建卡

本 Skill 从设定到交付独立执行，不先运行传统建卡流程。DSH 卡可以只用普通对话，舞台是可选能力。

- 新卡：从用户已给的想法提取角色、玩家身份、初始关系、世界、开场和文风，只问会影响成品的缺项。一次一个主题，可给少量 Markdown 参考选项，允许“你定”；用户已授权直接制作时按已有要求落成。
- 选择交互模式：普通对话、气泡对话或完整舞台。说明舞台依赖可用素材、导演可能产生模型调用；仅在用户需要时增加 MVU、模组或额外插件。
- 素材计划：核对已有角色、头像、立绘、背景、音乐与来源授权，确定哪些随包分发、哪些尚缺。先给出可交付范围，不把示例 UUID 或占位图片当作真实资源。
- 已有卡迁移：读取原卡，沿用其角色与开场，保留原件；只补齐用户要求的 DSH 声明和资源，不重新访谈或重写剧情。

## 工作流程

1. 已有卡用 `tavern_read_card` 读取原始格式和扩展；新卡整理已确定的设定与模式。需要参考长期偏好时可用 `tavern_user_profile_read`，本次指令优先。
2. 用 `tavern_read_skill_reference`（name 为 `create-dsh-card`）读取 [references/format-and-stage.md](references/format-and-stage.md)，确认目标格式版本、字段位置和舞台前置条件。
3. 用 `tavern_update_card.fields` 保存角色设定、玩家身份（新建同时提供 name 与 player）、场景、完整开场及必要的示例对话；需要世界书时用 `tavern_update_worldbook` 写入独立主题条目。扩展用 `rawOperations` 做最小修改。沿用已有素材包的真实 ID 和版本，保留其他扩展。人物与开场引用只能指向真实存在的素材。用户仅要求导出卡包时，保留原卡模式。
4. 缺少素材时明确缺项。可以先完成文字卡并报告舞台尚未就绪；生成收费素材、启用模型或运行额外插件须遵循用户当前授权。需要独立插件行为时，加载 `tavern-plugin` 查公开接口；舞台展示由内置舞台承担。
5. 查看保存回执的校验结果；直接改文件后用 `tavern_validate_card`。按参考中的交付要求检查版本、素材及导出。只有实际生成可下载文件，才能报告已导出；当前工具不能生成卡包时，说明已保存的卡路径，并引导用户从卡片库导出，不虚构工具或下载链接。

## 交付

列出卡路径、作品版本、格式版本、选择的模式、素材缺项、校验结果和实际导出文件。静态校验不等于真实试玩；用户要求试玩时使用测试对局验证，并报告正文、头像和舞台各自结果。

旧卡迁移保留原文件与原版本记录。读到未知格式时说明需要更新宿主或显式迁移，不通过改小版本号来绕过校验。
