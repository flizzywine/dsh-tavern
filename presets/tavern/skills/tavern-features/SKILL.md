# Tavern 功能分流

本 Skill 只负责选路：判断需求属于哪个功能，再用 `skill` 加载对应的功能 Skill。它本身不解锁工具，配置工具随功能 Skill 一起出现。只做选路或介绍时，回答用户该用哪项功能，不声称已经配置。

## 选哪个 Skill

| 用户想做的事 | Skill |
| --- | --- |
| 有哪些素材包、哪些全局启用、哪些绑定本卡；安装、更新或导出素材包；包的全局/本卡/关闭；背景、音乐、音效、环境音、光影、CG、皮肤条目及其蓝绿灯和触发词 | asset-library |
| 新建人物，人物的名字与别名、人物灯、服装、差分、头像裁切、立绘、Live2D/Spine 模型导入与运行库，上传已有图片 | figure-assets |
| 用应用内生图做设定图、立绘、头像、背景（按次付费） | asset-generation |
| 给卡开舞台、设置向导、开了看不到立绘、舞台设置各项在哪；galgame 舞台、舞台模式；四态开关（对话气泡、配音、舞台模式、BGM 等）、开场画面与人物站位、本卡皮肤与默认皮肤、正文语言，字体和阅读控制在哪里设置；配立绘与声音、本卡开模组、导入 Live2D、带素材分享的最短路线 | stage-setup |
| 导演模型、可用演出、演出风格、素材的导演说明与服装使用情景、智能判断、导演提示词预览 | stage-directing |
| 已安装模组（文字演出、手机、计时器等）的开关、授权、设置值和变量来源 | stage-mods |
| 导出或导入带素材包的人物卡 ZIP | card-sharing |

相邻能力："舞台"一词通常指 galgame 舞台，用 stage-setup；卡片文字、开场白正文、世界书、正则用 edit-card；加入 MVU 变量用 card-to-mvu；编写新插件或模组代码用 tavern-plugin；已有游玩记录里的异常用 debug-card。

## 成套配置

用户问"怎么给这张卡开舞台""怎么把一张普通卡做成舞台卡"时，加载 stage-setup，按它的「开舞台」参考给最短路线和排查表。不想改原卡时，先在人物卡库「另存副本」（「保存字段」会直接改原卡；副本与原卡共用素材包）。之后补人物、服装、差分或导入模型用 figure-assets、asset-generation，导出卡 ZIP 用 card-sharing。

替用户一次配完整演出时按依赖顺序推进，每一步加载对应 Skill：素材包与绑定 → 人物与服装 → 开场画面 → 导演与模组。前一步得到的包 ID、人物引用和 revision 是后一步的输入。某项功能没有可用素材时跳过并告诉用户缺什么，不为凑齐功能制造空条目。

## 共同规则

- **功能开关是四态。** 舞台功能和模组都有 全局开启 / 全局关闭 / 本卡开启 / 本卡关闭，按「本卡关闭 > 全局开启 > 本卡开启 > 全局关闭」生效。本卡两态由用户在舞台设置里选，工具只写全局层。开关生效后，功能还要这张卡能用到素材条目（包的全局/本卡范围、条目灯态）才会出现。
- **全局写入先说明。** 改全局设置前告诉用户"这是全局设置，会影响所有卡片"及具体改动；写工具调用时宿主请用户确认，用户同意后才写入。
- **用功能工具完成。** 这些设置只能通过功能 Skill 的工具修改。
- **按事实报告。** 分清计划、等你确认、已请求确认、没有改动、已保存（回读到目标值）；只描述工具结果里出现的事。配置状态（已配置、已启用、没有上限值）说明的是设置，不是实测结果。介绍功能时，界面位置只引用功能 Skill 里写明的。
- **保存不等于生效。** 报告时分开说：已保存并回读的内容、需要用户在游玩页或素材库里查看的效果、尚未验证的部分。
