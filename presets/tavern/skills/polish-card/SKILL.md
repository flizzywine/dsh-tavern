# 精修人物卡

像小说编辑审稿：先联想几段人写的小说当范本，再找出最值得改的问题，照范本的笔调逐处改好并保存，最后列出改了什么。写得好的地方不动，宁缺毋滥。

## 准备

1. 用 `tavern_read_skill_reference` 读取本 Skill 的 [references/review-standards.md](references/review-standards.md)。这是前台精修使用的同一份审稿标准，开场白和示例对话照它审。
2. 用 `tavern_read_card` 读取人物卡，用 `tavern_read_worldbook` 读取绑定的世界书。先通读设定，了解人物的性格、出身、口癖和世界观，再开始审。
3. 用户只点名了某一部分（例如“精修开场白”）时，只审那一部分。
4. 按下面「文风联想」找好范本，再开始改。

## 文风联想

模型写的文字人机味重：句式整齐、形容空泛、动不动下结论。改之前先找人写的小说当范本，替换的文字照它的笔调写。

- 凭你的阅读记忆，找笔调最贴近这张卡的小说，摘出原文：跟着题材、时代、人物和场面选，不必是名家名作，轻小说、网络小说和各类类型小说都可以。
- 要多少写多少：可以是一段，也可以是几大段、上千字；叙述、对白、环境层次多时，可以分别找几段。
- 记不清原文时，写成你记得的那种笔调的段落，并标明「凭记忆，可能不是原文」，不要冒充原文。
- 用户指定了书、作者，或指定「剧本与素材库」里的某份材料时，按指定的来；素材库的材料用 `tavern_read_script`（可带关键词检索）或直接读文件。用户没指定时不去翻素材库。
- 只借笔调：节奏、句子长短、用词质感、人物说话的口气、留白和克制。情节、人名、地名、原句不能进人物卡，卡里也不提这部作品。
- 动笔前先把范本贴给用户，说明出处（书名、作者，或「凭记忆」）。用户觉得不合适就换一本重新联想。

## 按文字类型审

**开场白**（`first_mes`、每个 `alternate_greetings`）：按审稿标准审。另外注意：

- 开场没有前文，“剧情衔接”改为检查它与人物设定、世界书是否矛盾。
- 每局都从开场开始，开场要交代清楚场面，并给玩家留出行动的余地；不在开场里替玩家角色做重要决定、说关键的话。
- 有多个开场时逐个审，各改各的，不要把它们改得千篇一律。

**示例对话**（`mes_example`）：重点看人物口吻是否符合设定、几段之间是否在重复同一种句式和动作，以及审稿标准里的套路写法。`<START>` 分隔和说话人标记保持原样。

**设定文字**（`description`、`personality`、`scenario`、世界书里写设定的条目正文）：它们是给模型读的资料，不按小说文笔审。只改这几类问题：

- 前后矛盾：字段之间、条目之间、设定与开场之间对不上（年龄、关系、地点、时间线、能力）。以多数处的写法为准统一；看不出哪个对时不改，在报告里列出让用户定。
- 同一件事在多处重复写。保留最完整的一处，其他地方删掉或改成一句话指过去。
- 含糊或空泛：只有“神秘”“强大”“温柔”之类的形容，没有具体表现。能从卡里其他地方找到依据就补具体，找不到就保持原样，不自行编造。
- 语病、错别字、翻译腔长句。
- 人机腔：满篇空泛形容、总结句、口号式排比。照范本的口吻改成具体的细节和人话；事实要写清楚，不为文采牺牲准确。

设定事实一律不改：人物经历、关系、能力、世界规则、数值都保持原样。

## 不要动的内容

- `<initvar>`、`<mvu-status/>` 等标签及其中的内容，开场里的 HTML 和状态栏标记。
- `{{user}}`、`{{char}}` 等宏，以及 `<START>` 等格式标记。
- 规则类内容：`system_prompt`、`post_history_instructions`，标题以 `[` 开头的条目（如 `[mvu_update]`），以及写给模型的指令、输出格式要求、变量更新规则。
- 正则、脚本和 MVU 面板。

用户明确要求时，这些内容也可以改，改法照 edit-card。

## 怎么改

- 一处一改。用 `tavern_replace_card_text` 提交：`find` 从原文一字不差地复制，长到在该位置唯一；`pointers` 限定到这一处的 JSON Pointer（`tavern_search_card` 可查位置），`expectedCount` 设为 1。数量不符时工具不会保存，换一段更长的原文重试。
- 卡外单独绑定的世界书不在 `tavern_replace_card_text` 的范围内，用 `tavern_update_worldbook` 改条目的 `content`，同样一处一改。
- `replace` 是改好的文字；要删就写空字符串。可以是一个短语、一句，也可以是一整段或连续几段。
- 措辞问题改短语或一句，替换要贴合人物和场面，不要换成另一个套话；拖沓的段落整段删去或压缩；需要调整顺序时，把涉及的整段作为 `find`，`replace` 写成调整好的版本。
- 可以补动作、细节、对白，但情节走向、人物关系、设定事实不变；改完的地方要和前后文接得上。
- 一整段都是人机腔时，可以照范本的笔调整段重写，作为一处修改提交；内容（发生了什么、交代了哪些设定）不变。
- 同一处不要改两次；已经整段删去或压缩的地方，不要再单独改其中的句子。
- 每个字段最多改 8 处，整张卡一次最多改 30 处。按开场白、示例对话、描述/性格/场景、世界书的顺序处理；没处理完的部分在报告里说明，问用户是否继续。
- 一个字段没有值得改的问题，就跳过它。

## 报告

全部改完后，先注明这次用的范本（出处），再按位置列出每处修改，从 1 起连续编号：位置（字段名或条目标题）、一句话理由、原文 → 改后（较长的只引开头和结尾）。最后附一句：要撤销某几处，告诉编号即可。

用户要求撤销时，用 `tavern_replace_card_text` 把对应位置的改后文字换回原文。
