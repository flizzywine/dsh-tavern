# 世界书条目的写法

游玩时世界书不再按关键词把正文塞进上下文，多数资料要靠正文模型自己去搜、去读。条目写得能被搜到、标题一看就懂，模型才用得上。新建和修改世界书条目时照这份写。

## 游玩时条目怎么被用到

| 条目 | 怎么进到模型手里 |
| --- | --- |
| 勾了常驻（`constant`）的纯文字条目 | 每轮原文放进系统提示 |
| 其余纯文字条目 | 不进上下文。每条变成一个以标题命名的文件，模型用 `worldbook_grep` 逐字搜索、`read` 读全文、`worldbook_list` 按标题翻目录 |
| 关键词 | 最近两楼和本轮输入里出现关键词时，只给模型一行「这些条目可能相关」的标题提醒，不放正文 |
| 正文里有 `{{user}}`、`{{char}}` 等宏、EJS 模板或脚本的条目 | 算动态条目：照旧在关键词命中后渲染并注入正文，占注入预算；渲染之前搜不到 |

所以一条资料能不能用上，取决于两件事：模型能不能从标题看出该查它，能不能用它想到的词搜到它。搜索只认原字，不认近义词。

## 写法

1. **标题写「类别·名称」**，例如「人物·沈砚秋」「地点·霞飞路事务所」「规则·受伤与死亡」「物品·铜怀表」。标题就是文件名，也是目录里看到的名字。同一张卡的类别用同一套词。
2. **一条讲一件事，正文开头写清它是什么。** 人物写全名和常用称呼，物品写正式名和俗称，地点写名字、外观和用途，规则写什么时候适用。只有一两句的小地点、小配角并进所属的条目，每处一行写名字和样子，例如虚拟世界里的入口、商店街、演唱会会场合成一条「地点·虚拟城各处」。
3. **会被搜的叫法都要写进正文。** 关键词里的别名、外号、外文名、玩家口语里的说法，正文里至少出现一次；只写在关键词里的词搜不到。别名多时在正文开头加一行「相关说法：……」。
4. **关键词照样填**，填玩家和正文里真会出现的词，用来出标题提醒。不要用「看见」「死」「买」「关系」这类天天出现的词，它们会让提醒失去意义。
5. **纯资料条目不用宏。** 称呼写「玩家」或具体人名。只有内容确实要随变量变化时才用宏或模板，并接受它走注入、占预算。
6. **每轮都要生效的东西勾常驻**：核心规则、输出格式、主角档案、资料索引。常驻越多每轮越长，只放必需的。要模型照做的规则不要写成靠关键词触发的普通条目：它现在只是一个文件，模型不读就不生效。
7. **资料多时加一条常驻「资料索引」**（可查的条目大约十条以上，或有模型不容易想到去查的规则时）：列出每条可查条目的标题和该查的时机，并写明先搜标题、再读全文。

## 正例

人物条目，别名都在正文里：

```text
标题：人物·沈砚秋
关键词：沈砚秋、沈老板、砚秋、Mr. Shen
正文：
【沈砚秋】霞飞路事务所的老板，熟人叫他「沈老板」，洋行的客户叫他 Mr. Shen。三十出头，常穿灰色长衫配西式马甲，左手戴一块铜怀表……
```

规则条目，开头写适用时机和玩家会说的叫法：

```text
标题：规则·受伤与死亡
关键词：受伤、重伤、死亡、断气、中枪
正文：
<injury_rules>
相关说法：重伤、死亡、断气、中枪
适用：有人即将受重伤或死亡时，先读本条再写结果。
……
</injury_rules>
```

常驻资料索引：

```text
标题：资料索引（勾常驻）
正文：
<lorebook_index>
下面这些资料平时不在上下文里。写到相关内容之前，先用 worldbook_grep 搜标题，再用 read 读全文，照读到的写，不凭印象补设定。
- 规则·受伤与死亡：有人即将受重伤或死亡时
- 人物·沈砚秋：沈老板出场或被提起时
- 地点·霞飞路事务所：角色进出事务所、提到沈老板的住处时
</lorebook_index>
```

## 反例

| 写法 | 问题 | 改成 |
| --- | --- | --- |
| 标题「条目3」「新条目」「## ===组织=== ##」 | 翻目录看不出是什么 | 「组织·码头商会」「设定·租界巡捕房」 |
| 关键词有「沈老板、Mr. Shen」，正文只写「沈砚秋」 | 模型搜「沈老板」搜不到 | 正文写出全部叫法 |
| 「{{user}}的青梅竹马小雪……」 | 一个宏就把整条变成动态条目：搜不到，还占注入预算 | 「玩家的青梅竹马小雪……」 |
| 普通条目「战斗描写：必须……」，靠关键词「战斗」触发 | 现在只出一行标题提醒，模型不读就不照做 | 勾常驻，或并进常驻的规则条目 |
| 常驻空条目「<人物档案>」「</人物档案>」包住一批普通条目 | 普通条目不再插进两者之间，常驻里只剩一对空标签 | 去掉包装条目，类别写进标题（「人物·沈砚秋」） |
| 几十条资料、没有常驻索引，标题也看不出类别 | 模型只能靠标题提醒碰运气 | 统一「类别·名称」标题并加资料索引 |
