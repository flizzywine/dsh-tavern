# 新建人物卡

交付可直接开局的卡片。先提取用户已给的信息，只询问会明显改变结果的缺项；一次一个小主题，可提供差异明确的选项，也允许自由回答、跳过或交由你决定。不为凑齐问题清单追问。

用户明确要求 DSH 原生卡、舞台卡或 .dshcard 卡包时，直接加载 `create-dsh-card`，由其独立处理；不先创建传统卡再转换。

参考选项固定写成 Markdown 列表：`- **A. 标签**：一句说明`，字母从 A 起连续；最后一项固定是「其他想法 / 你定」。工作台的桌宠会把它们变成按钮，格式不符时只按普通文字显示。

## 确定内容

按需覆盖题材与尺度、角色动机与说话方式、玩家身份及初始关系、世界设定、开场数量和切入点。设定较多时才建世界书。可参考 `tavern_user_profile_read` 的长期偏好，以用户本次要求为准。

功能取舍由用户决定：MVU 将随剧情变化的状态交给后台结算，会增加后台调用；不用 MVU 的状态美化依赖模型输出格式，可能失效。信息足够后展示卡名、玩家、角色、世界书、开场及功能摘要；已明确要求直接制作时不重复确认。

## 美化草图

选择美化但尚未确定风格时，展示风格不同的静态 HTML 草图，每种放进闭合的 html 代码块供工作台预览。使用本卡示例数据和内联样式，360px 窄屏及长文本可读；草图不运行脚本或加载外部图片、字体，不把静态预览当作成品验证。按用户选择实现正式样式与交互。

## 创建与校验

- 空白工作台用 `tavern_update_card` 创建正式卡，`fields` 同时提供 `name` 与 `player`；填写描述、性格、场景、开场、示例对话、玩法说明与标签。开场给玩家留下行动空间，不替玩家决定言行。
- 需要世界书时，`tavern_update_worldbook` 对新卡的 `cards/...` 路径添加条目；用 `comment`、`content`、`primaryKeys` 表达一个主题和准确关键词。粒度以「值得这次触发」为准：重要人物单独成条；只有一两句描写的小地点、小配角并进所属的条目，例如虚拟世界里的入口、商店街、城堡、演唱会场合成一条该世界的条目，每处一行；对剧情重要、有实质内容的地点（如主角的家）才单独成条。
- 选择 MVU 时加载 `card-to-mvu`，在新卡上加入初值、更新规则与面板；采用选定草图，未选美化则做简洁字段列表。
- 美化不用 MVU 时，开场主页放在开场 html 代码块；状态栏约定模型输出标签，通过 `/data/extensions/regex_scripts` 的展示正则替换为 HTML，并用 promptOnly 正则移除模型历史中的旧状态块。
- 检查保存结果附带的格式校验；直接编辑文件后调用 `tavern_validate_card`。修复本次引入的问题并重新保存或校验。

报告卡片路径、开场切入点、启用功能与校验结果。用户可在游玩模式选择新卡预览实际开场；未执行真实试玩或模型结算时如实说明，不自动发起付费调用。
