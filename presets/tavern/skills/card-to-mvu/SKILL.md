# 人物卡转 MVU

交付前台写剧情、后台更新变量、面板读取变量的卡片。用 `tavern_apply_mvu` 装配；自己写面板 HTML 或直接编辑文件时，用 `tavern_read_skill_reference` 读取 [MVU 格式约定](references/mvu-format.md)。

## 来源与目标

先用 `tavern_mvu_overview` 看开场首尾、文件结构、世界书、正则、脚本和可能的旧状态协议，再按需读取目标设定、每个开场、实际绑定的世界书，以及相关状态正则和脚本。列清旧显示项、变量路径、类型、初值与更新依据；固定设定留在原文。只读取必要的关联资料。

从 ERA 等旧状态协议迁移时，在卡里分清持久状态、更新命令和展示脚本：状态逐字段映射成 MVU 变量，计算和触发条件写进 `[mvu_update]` 规则，前台不再输出旧命令。用户还要舞台里的状态页时，另加载 `stage` 按它的卡页面参考（references/pages.md）做，它读同一份 MVU 变量。

新建任务中的卡直接修改；转换已有卡默认先用 `tavern_copy_card` 建独立副本，保留原卡。用户明确要求原地修改时按指定目标操作。独立世界书可能被多卡共享，不因复制人物卡就认为世界书已经隔离；先核对绑定，影响授权外资源时说明并确认。

## 编辑

- 用 `tavern_apply_mvu` 一次提交默认初值、各开场差异值、更新规则和面板；工具装配开场标记、世界书条目和正则，不必重写开场正文。后续可只传需调整的部分。标准字段也可用 `tavern_update_card.fields`，扩展用 `rawOperations`，世界书条目用 `tavern_update_lorebook`；直接编辑目标 JSON 的 `raw.data` 时保留其他内容。
- 标准面板可选主色、分组、字段及 `bar` / `list`。布尔字段可用 `yes` / `no` 指定显示词（如 在线 / 离线，默认 是 / 否）；未指定 `label` 的字段使用路径末段，同组重名时补上最短可区分的父路径（如「角色甲 · 地点」）；自定义或保留原美化时在 `panel.html` 提供完整 HTML。
- 每个开场末尾写 `<initvar>` 和 `<mvu-status/>`。字段结构一致，值按各自场景填写，不借其他开场补齐；根包含 `"$meta": {"strictSet": true}`，让数组按字面值写入。玩法中会增减的数组和对象要在初值里标成可扩展（数组放 `"$__META_EXTENSIBLE__$"` 元素，对象写 `"$meta": {"extensible": true}`），否则后台加不进元素。
- 世界书 `[mvu_update]` 条目定义字段变化依据，只根据已发生的事实结算；公式和机制来自原卡。增删改名时同步所有开场、规则与面板引用。
- 状态视图正则的 HTML 读取 MVU 变量并订阅更新事件。已有美化优先保留原观感并适配变量协议，脚本面板也可改造；没有原美化时按题材设计窄屏可读的面板。无法保留的显示项或交互要报告，不用基础列表掩盖缺失。
- 整条删除的旧说明、开场状态块和正则可通过同次 `tavern_apply_mvu.remove` 清理；局部改写用 `tavern_replace_card_text` 或 `tavern_update_lorebook`。只移除已替代的旧状态生成协议、相关正则以及候选项生成/展示逻辑。共享脚本只删相关部分，保留手机、开场主页、剧情选择、署名与其他无关美化。归属不明的逻辑保留并说明。

## 校验与交付

检查保存结果附带的格式校验；直接编辑文件后调用 `tavern_validate_card`。修正 errors，判断 warnings 是否影响本次交付。核对每个开场、变量、规则与展示引用。

报告目标路径、实际改动、删除与保留的位置、校验结果和未覆盖的原美化缺口。如需验证开场初值、变量结算或面板显示，请用户在游玩区用保存后的卡开新局。如果用户要验证旧存档迁移，请其在游玩区打开对应存档。
