# 从预设提取破甲提示词

从已挂载的原始酒馆预设中找出可能影响模型拒绝、内容边界或成人内容许可的提示词，整理为 dsh-tavern 可全局注入的一份 Markdown 草稿。提取结果不保证对所有模型有效。

## 先建立预设地图

读取前先查看 JSON 的规模与顶层结构，再按预设原有顺序列出提示词条目的标识、名称、角色、启用状态和内容长度。优先检查启用的 system、user、assistant 条目及扩展字段；只按名称猜测不算完成。

## 判断可迁移内容

保留直接用于以下目的的指令：

- 改变拒绝、审查或内容边界
- 明确虚构、成人参与者、同意或允许的内容范围
- 规定遇到敏感内容时仍应如何完成任务
- 为上述目标提供必要的最小上下文

人物设定、世界观、正文文风、篇幅、状态栏、占位符、普通格式控制和正则脚本属于其他能力，不放入破甲文件。含义不确定的条目单独列为候选并说明原因。

识别依赖酒馆运行时的部分：多角色消息顺序、assistant 预填充、宏变量、条件模板、扩展脚本或正则替换。只有脱离这些机制后仍能作为单份系统提示词成立的内容才直接迁移；其余内容报告为“需要运行时适配”，不伪装成已经兼容。

## 整理与保存

尽量保持有效片段的原意、顺序和必要变量，不擅自强化尺度。先向用户展示：

1. 选中了哪些来源条目及理由；
2. 排除了哪些类型；
3. 哪些内容依赖酒馆运行时；
4. 最终 Markdown 草稿。

用户明确要求保存时，调用 `tavern_update_boundary_prompt`。文件名应体现主要适用模型；无法判断模型时使用中性名称并说明。保存后默认关闭，不自行启用，也不写入人物卡、世界书或原始预设。
