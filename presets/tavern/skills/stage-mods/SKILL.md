# 舞台模组

模组是装在舞台上的扩展：第一方模组随应用提供，其他模组可以在 设置 ›「舞台」›「舞台模组」导入 `.dshmod` 安装。模组通过导演的结构化命令或自己的界面在舞台上演出，例如手机短信、文字演出卡片、倒计时。物品是舞台内置功能，不是模组（见 stage-setup）。MVU 变量本身用 card-to-mvu。

工具：`tavern_mods_read`、`tavern_mods_patch`，上传模组文件和媒体用 `tavern_media_upload`。先用 `tavern_mods_read({request:{action:'list'}})` 看已安装哪些模组、各自的开关和授权状态。读取失败时，先告诉用户读取没有成功及错误给出的原因，再说"下面只是功能介绍，还没核实本机是否安装、是否授权、这张卡有没有可用素材"。开关和授权状态说明的是配置，模组是否演出要看游玩中的实际情况。

## 各模组说明

每个模组一篇，写它做什么、什么时候出现、有哪些设置。以 `tavern_mods_read config {modId}` 返回的字段为准。

| 模组 | id | 说明 |
| --- | --- | --- |
| AI检定 | `dsh.dice` | [AI检定](references/dice.md) |
| 计时器 | `dsh.timer` | [计时器](references/timer.md) |
| 手机 | `dsh.phone` | [手机](references/phone.md) |
| 文字演出 | `dsh.textcard` | [文字演出](references/textcard.md) |
| 数据删除 | `dsh.redaction` | [数据删除](references/redaction.md) |

`list` 里出现、上表没有的模组，按它自己的设置字段和说明回答。

## 调用格式

每个工具只有一个 `request` 参数。几个动作共用的字段放在外层，其余字段放进 `operation`，可以嵌套多层，层级以工具 schema 为准；下文的 `动作 {字段}` 只列出字段。例如写本卡层设置值（`config` 和 `clear-config` 共用 `key`、`layer`）：

`tavern_mods_patch({request:{modId:'dsh.phone', expectedRevision:'读到的 revision', operation:{key:'…', layer:'card', operation:{action:'config', value:{…}}}}})`

## 开关、授权和素材是三件事

- **开关**：四态，全局开启 / 全局关闭 / 本卡开启 / 本卡关闭，按「本卡关闭 > 全局开启 > 本卡开启 > 全局关闭」生效。开关由用户在界面里选，工具只读取状态（`list` 的状态只区分全局开/关，本卡选择以界面为准）。
- **授权**：模组的执行许可，与开关独立；开关打开不会扩大权限。授权也由用户在界面里处理。
- **素材**：有的模组要用素材包里的条目（模组说明里写明），和其他素材一样有包的范围和条目的蓝绿灯；一轮里没有可用条目时，这个模组那一轮不启用，导演也收不到它的说明（舞台上还留着它的状态时，只收到维持或停止所需的一句）。不需要条目的模组，开关生效就可用。

界面位置：舞台设置 ›「模组」里每个模组一行，右侧的开关标签展开四个选项；在卡上选「全局…」会清掉这张卡的选择并改所有卡。点行或「›」打开模组设置页，页顶「全局 | 本卡」决定设置值写在哪一层。模组的安装和卸载在 设置 ›「舞台」›「舞台模组」。

模组素材包的范围也在界面里选：把一个模组素材包只给当前卡用，请用户在模组设置页的「素材包」里把它设为「本卡」。本卡层的设置值和本卡层的 `mod-file` 上传只影响这张卡；模组设置、模组包、全局层设置值、全局层文件和模组媒体（`mod-media`）都按全局写入处理：先告诉用户"这是全局设置，会影响所有卡片"和具体变化，写入要经宿主批准。

## "只给这张卡开"

请用户在这张卡的 舞台设置 ›「模组」里把该模组选成「本卡开启」，全局保持关闭，其他卡就不会用它；反过来「本卡关闭」让全局开着的模组在这张卡上停用。这是界面操作，工具写不了，告诉用户位置即可。

- 打开后是否出现仍由剧情决定；要用素材条目的模组还要这张卡能用到条目（包的范围、条目灯态，见 stage-assets）。
- 可以用本卡层的设置值调这张卡的外观或强度（下文「设置值」）。

## 设置值

用 `tavern_mods_read config {modId}` 读取该模组的设置字段、全局与本卡两层的值和最终解析结果，按 [设置值与变量来源](references/mod-config.md) 写入。本卡层只放数据和展示配置，不能当作本卡开关。写入用读取到的 revision；冲突时重新读取，只重做本次修改。

## 不制造状态

需要跟随剧情变化的数值，比如手机电量，要卡里真的有对应的状态：MVU 变量或台账。没有时不要写固定值冒充剧情状态，也不要在正文、世界书或开场白里加入模组专用的格式说明。卡还没有 MVU 而用户需要这类数值时，先加载 card-to-mvu 加入变量，再回来把设置引用到变量。

这些工具不提供运行时命令、改写历史或往正文里插入手机消息的动作。设置改动影响之后的演出，展示类设置在舞台上可能立即可见；改设置不会重新导演或改写已有演出。

## 用工具完成，按事实报告

- 模组只通过本 Skill 的工具读写。报错里的 `example` 是最小合法骨架：占位符换成读到的值，空数组只表示类型、不代表清空。工具做不到的事，说明缺什么或界面位置。
- 报告只描述工具结果里出现的事，分清：计划（还没调用写工具）、已问你（等你回复）、等待宿主批准、未获批准没有改动（照审批错误的 `message` 转述，会话策略自动拒绝不说成用户拒绝）、已保存（写入成功且回读到目标值）。

## 完成标准

写入成功后回读：设置值用 `config` 看目标字段的 `resolved` 没有错误、取值符合预期；模组设置和模组包改动用 `mod` 或 `packs` 回读。引用变量的字段在工作台里只能确认引用写对了，游玩中的实际数值请用户进游戏看。交付时说明哪些效果要等剧情触发才能在舞台上看到。
