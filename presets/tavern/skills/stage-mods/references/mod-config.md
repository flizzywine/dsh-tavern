# 设置值与变量来源

## 值的四种形状

| 形状 | 含义 | 例子 |
| --- | --- | --- |
| `{auto:true}` | 自动：字段声明了自动来源时按来源取值，否则（或没取到）用字段默认值 | 不设置时就是这种 |
| `{fixed: 值}` | 固定值，类型必须与字段一致 | 电量固定 `80` |
| `{ref:{source, path, fields?}}` | 引用变量；`path` 是 JSON Pointer，MVU 相对 `stat_data` | 背包引用 `/背包`，并映射名称和数量字段 |
| `{formula:"表达式"}` | 公式，仅数字字段等支持 | 由多个变量算出的数值 |

一个值只能是其中一种。只有声明了自动来源的字段才适合写 `auto`；没有自动来源的字段写 `fixed`、`ref` 或 `formula`，不设置时用默认值。

## 两层

- `layer:'global'` 对所有卡生效，写入需要全局确认。
- `layer:'card'` 只对当前卡，保存在这张卡里，随卡导出；本卡层上传的文件放在这张卡的素材包里。字段声明为只允许全局时不能写本卡层。
- 某层没有设置就继承上一层；`clear-config` 删除当前层的值，恢复继承。

## 写之前先验证

- `tavern_mods_read sources` 列出当前卡可用的状态来源及不可用原因。
- `formula {formula}` 试算公式，返回结果或出错位置，不会写任何变量。
- `resolve {modId, key}` 查看单个字段最终取到的值、来自哪一层、是哪种形状。

引用路径或公式出错时，解析结果会带错误，不会悄悄改用其他来源；按错误位置修正，或改回固定值。

## 状态来源

全局设置 `dsh.state.source` 决定模组设置引用和导演读取哪种状态：`auto`（卡有 MVU 就用 MVU）、`mvu`、`ledger`（台账）。明确选择后不会自动退到另一种。台账没有数据时是"不可用"，不是空值。改这项会影响所有卡，按全局写入处理。物品数量不受这项影响，固定读 MVU（见 stage-setup 的物品说明）。

## 例子

用户："手机电量跟着变量'手机.电量'走。"
→ `sources` 确认这张卡的 MVU 可用 → 用 `config` 在本卡层写 `battery` 为 `{ref:{source:'mvu', path:'/手机/电量'}}` → `resolve {modId:'dsh.phone', key:'battery'}` 回读来源层和形状。如果变量还不存在，先用 card-to-mvu 加变量。工作台读不到游玩中的变量值，实际电量请用户进游戏看。
