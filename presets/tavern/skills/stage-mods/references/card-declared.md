# 卡声明的引擎接口

AI检定（`dsh.dice`）、数据删除（`dsh.redaction`）、文字演出（`dsh.textcard`）、计时器（`dsh.timer`）是舞台引擎随应用提供的接口，没有玩家开关。一张卡要用，就在卡里声明。声明了，导演或写正文的模型才拿到它的说明和指令；没声明，它不占这张卡的上下文。声明随卡导出、导入。

这几项的效果都只在某类卡上合适：随机判定改变故事走向，盖住机密词要有档案口吻的文字，全屏文字卡是一种演出风格，倒计时要有时限的场面。所以要不要用由卡作者决定，不交给玩家逐张开关。手机对一大类卡都通用，仍然是玩家开关。

## 怎么声明

声明写在卡的 `data.extensions.dsh_tavern.modSystem` 里，和本卡的设置值放在一起：

```js
tavern_update_card({ rawOperations: [
  { op: 'set', path: '/data/extensions/dsh_tavern/modSystem', value: {
    version: 2,
    mods: { 'dsh.redaction': 'on' },
    packs: {},
    config: { 'dsh.redaction': { version: 1, values: { guidance: { fixed: '异常的真名、伤亡人数、机构内部代号' } } } }
  } }
] })
```

- 卡里已经有 `modSystem` 时，先读出来，只在 `mods` 里加这一项，`packs` 和 `config` 照原样留着，再整个 `set` 回去。不要整个 `set` `dsh_tavern`，它下面还有 `assetBindings`、`pages` 等字段。
- 不再用的接口，从 `mods` 里删掉这一项。
- 本卡的设置值（`config`）照各模组说明写，例如数据删除的 `guidance`（遮挡指引）、文字演出的 `intensity`。写法见 [设置值与变量来源](mod-config.md)。
- 皮肤也能声明：皮肤文档里写 `mods["dsh.timer"] = {enabled: true, options: {…}}`，用这款皮肤的卡就用上它。适合属于某种演出风格的接口，例如审判风格皮肤自带的倒计时。

## 各接口什么时候声明

| 接口 | 声明后谁拿到什么 | 什么卡该声明 | 还要什么 |
| --- | --- | --- | --- |
| AI检定 `dsh.dice` | 写正文的模型拿到通用 1d100 检定工具和掷骰说明 | 想让结果真的随机、会因失败分岔的卡（冒险、跑团、生存） | 卡写了自己的规则（`extensions["dsh.rules"]`，见 [AI检定](dice.md)）时，卡自带规则检定，不用声明，也不会再给通用骰子 |
| 数据删除 `dsh.redaction` | 导演拿到 `redact` 指令和遮挡说明，把档案、简报、系统通知里的机密词盖住 | 机构档案、调查、SCP 一类，正文会出现文件和通知的卡 | 写一句遮挡指引（`guidance`），说清这张卡里什么算机密 |
| 文字演出 `dsh.textcard` | 导演拿到全屏文字卡指令（章节标题、大字强调、倒计时、关系图等） | 要「物语」那种大字演出风格的卡 | 可用 `intensity` 调多少（克制 / 标准 / 浓烈） |
| 计时器 `dsh.timer` | 导演拿到 `timer` 指令，在舞台上放倒计时 | 有限时场面的卡（审判、辩论、拆弹） | 卡或皮肤的素材里要有「倒计时」条目；一轮里召回不到条目，那一轮导演不拿到计时器 |

## 我们的卡是怎么用的（正例）

- **三角机构**：在 `dsh.rules` 里写了自己的检定规则（6d4、混沌、素质保证），规则检定随卡自带；声明了数据删除，遮挡指引写的是档案腔段落里的异常真名与能力细节、伤亡人数、机构内部代号与楼层；皮肤给检定配了自己的骰子外观和音效（皮肤 `mods["dsh.dice"].options`）。
- **魔法少女的扣扣审判（剧本版）**：声明了计时器，倒计时条目来自它绑定的素材包，给审判限时。
- **月下六席 · 狼人杀**：卡里不声明，计时器由它用的皮肤带来（皮肤里 `mods["dsh.timer"].enabled`），换了皮肤就没有。

## 不要做的

- 不要在正文、世界书或开场白里教模型这些接口的格式：声明了，引擎会把用法交给模型；没声明，教了也用不上。
- 不要为了「以后可能用到」声明：每声明一项，这张卡每一轮都多一段说明。
