# 舞台模组

用户问装了哪些模组、某个模组怎么用、手机的开关和外观、模组的设置值和变量来源时读这篇。要让卡用上检定、数据删除、文字演出、计时器，读[卡声明的引擎接口](mod-card-declared.md)。

模组是装在舞台上的扩展：第一方模组随应用提供，其他模组可以在 侧栏首页 ›「舞台装置」›「舞台引擎」›「模组」导入 `.dshmod` 安装。模组通过导演的结构化命令、写正文的模型的工具或自己的界面在舞台上演出，例如手机短信、文字演出卡片、倒计时、掷骰。物品是舞台内置功能，不是模组（[开关与皮肤](setup-switches.md)「物品」）。MVU 变量本身用 `card-to-mvu`；只是像手机、点开看数值的整页用[卡页面](pages.md)。

工具：`tavern_mods_read`、`tavern_mods_patch`，上传模组文件和媒体用 `tavern_media_upload`。先用 `tavern_mods_read({request:{action:'list'}})` 看已安装哪些模组和各自的状态。读取失败时，先告诉用户读取没有成功及错误给出的原因，再说"下面只是功能介绍，还没核实本机是否安装、这张卡有没有声明或可用素材"。状态说明的是配置，模组是否演出要看游玩中的实际情况。

## 各模组说明

每个模组一篇，写它做什么、什么时候出现、有哪些设置。以 `tavern_mods_read config {modId}` 返回的字段为准。

| 模组 | id | 怎么启用 | 说明 |
| --- | --- | --- | --- |
| AI检定 | `dsh.dice` | 卡声明 | [AI检定](mod-dice.md) |
| 数据删除 | `dsh.redaction` | 卡声明 | [数据删除](mod-redaction.md) |
| 文字演出 | `dsh.textcard` | 卡声明 | [文字演出](mod-textcard.md) |
| 计时器 | `dsh.timer` | 卡或皮肤声明 | [计时器](mod-timer.md) |
| 手机 | `dsh.phone` | 玩家开关 | [手机](mod-phone.md) |

`list` 里出现、上表没有的模组，按它自己的设置字段和说明回答。

例：写本卡层设置值（`config` 和 `clear-config` 共用 `key`、`layer`）：`tavern_mods_patch({request:{modId:'dsh.phone', expectedRevision:'读到的 revision', operation:{key:'…', layer:'card', operation:{action:'config', value:{…}}}}})`。

## 两种模组：卡声明的引擎接口，和玩家开关

- **卡声明**（AI检定、数据删除、文字演出、计时器）：舞台引擎提供的接口，没有玩家开关，全局开关对它不起作用。卡（或它的皮肤）声明了才给模型说明和工具，没声明就不占上下文。舞台设置的「模组」区只在声明了它的卡上列出这一行，写明是卡还是皮肤声明的，点开仍是它的设置页。声明写法、正例和现有卡的用法见[卡声明的引擎接口](mod-card-declared.md)。
- **玩家开关**：手机是这一种，第三方模组默认也是。对一大类卡通用、由玩家自己决定的功能，四态开关：全局开启 / 全局关闭 / 本卡开启 / 本卡关闭，按「本卡关闭 > 全局开启 > 本卡开启 > 全局关闭」生效。开关由用户在 舞台设置 ›「模组」那一行右侧的标签里选，工具只读取状态（`list` 的状态只区分全局开/关，本卡选择以界面为准）；在卡上选「全局…」会清掉这张卡的选择并改所有卡。只给这张卡开：请用户选「本卡开启」、全局保持关闭；反过来「本卡关闭」让全局开着的模组在这张卡上停用。

## 授权和素材

- **授权**：模组的执行许可，与开关和声明独立；打开开关或声明不会扩大权限。授权由用户在界面里处理。
- **素材**：有的模组要用素材包里的条目（模组说明里写明，如计时器的「倒计时」），和其他素材一样有包的范围和条目的蓝绿灯（[灯态与触发词](asset-lamps-recall.md)）；一轮里没有可用条目时，这个模组那一轮不启用，导演也收不到它的说明（舞台上还留着它的状态时，只收到维持或停止所需的一句）。不需要条目的模组，启用了就可用。
- 启用后是否出现仍由剧情决定。

界面位置：舞台设置 ›「模组」里点行或「›」打开模组设置页，页顶「全局 | 本卡」决定设置值写在哪一层。模组的安装和卸载在 侧栏首页 ›「舞台装置」›「舞台引擎」›「模组」。

模组素材包的范围也在界面里选：把一个模组素材包只给当前卡用，请用户在模组设置页的「素材包」里把它设为「本卡」。本卡层的设置值和本卡层的 `mod-file` 上传只影响这张卡；模组设置、模组包、全局层设置值、全局层文件和模组媒体（`mod-media`）都按全局写入处理。

## 设置值

用 `tavern_mods_read config {modId}` 读取该模组的设置字段、全局与本卡两层的值和最终解析结果，按[设置值与变量来源](mod-config.md)写入。本卡层只放数据和展示配置，不能当作本卡开关或声明。写入用读取到的 revision；冲突时重新读取，只重做本次修改。

## 不制造状态

需要跟随剧情变化的数值，比如手机电量，要卡里真的有对应的状态：MVU 变量或台账。没有时不要写固定值冒充剧情状态，也不要在正文、世界书或开场白里加入模组专用的格式说明。卡还没有 MVU 而用户需要这类数值时，先用 `card-to-mvu` 加入变量，再回来把设置引用到变量。

这些工具不提供运行时命令、改写历史或往正文里插入手机消息的动作。设置改动影响之后的演出，展示类设置在舞台上可能立即可见。

## 完成标准

写入成功后回读：设置值用 `config` 看目标字段的 `resolved` 没有错误、取值符合预期；模组设置和模组包改动用 `mod` 或 `packs` 回读。引用变量的字段在工作台里只能确认引用写对了，游玩中的实际数值请用户进游戏看。交付时说明哪些效果要等剧情触发才能在舞台上看到。
