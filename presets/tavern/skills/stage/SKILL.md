# 舞台功能入口

本入口只选路：判断需求属于哪一项，再用 `skill` 加载对应子 Skill。单项需求直接进入，不必先读其他分支。本入口不解锁工具，工具随子 Skill 出现；只做介绍时回答该用哪项，不声称已经配置。

| 要做的事 | 子 Skill |
| --- | --- |
| 开舞台、设置向导、开了看不到画面；四态开关（对话气泡、配音、舞台模式、BGM、自动素材等）；开场画面；本卡皮肤；字体与阅读 | `stage-setup` |
| 素材包的安装、绑定、批量整理；人物、服装差分、设定图与立绘、Live2D/Spine；配音、声音克隆、读音、自动素材选声；背景、CG、音乐音效、皮肤条目与触发词 | `stage-assets` |
| 导演模型、可用演出和动作上限、演出风格、智能判断，或查导演为什么选了这个素材 | `stage-directing` |
| 已安装模组（检定骰子、剧情短信与来电、文字卡、计时器等）的开关、授权、设置值和变量来源 | `stage-mods` |
| 卡自带的整页 HTML：标题页、开场页、开局页、地图、MVU 状态页（含手机样式） | `stage-status-panel` |
| 导出或导入带素材包的人物卡 ZIP | `stage-sharing` |
| 导入或绑定游玩剧本、调整游玩进度，静音卡片的 Helper 脚本 | `script-play` |
| 给卡加 MVU 变量，或从 ERA 等旧状态协议迁到 MVU | `card-to-mvu`；还要做舞台状态页时再加载 `stage-status-panel` |

相邻能力：写 DSH 卡文件或迁移旧舞台声明用 `create-dsh-card`；卡片文字、开场白正文、世界书、正则用 `edit-card`；编写新插件或模组代码用 `tavern-plugin`；某一轮游玩里的异常用 `debug-card`。

## 一次配完整张卡

用户问「怎么把一张普通卡做成舞台卡」时，先按 `stage-setup` 的开舞台给最短路线。不想改原卡时，先在人物卡库「另存副本」（「保存字段」会直接改原卡；副本与原卡共用素材包）。

替用户配完整演出时按依赖顺序推进，每一步加载对应子 Skill：素材包与绑定 → 人物与服装 → 开场画面 → 配音 → 导演与模组。前一步得到的包 ID、人物引用和 revision 是后一步的输入，顺序不能颠倒。某项没有可用素材时跳过并告诉用户缺什么，不为凑齐功能制造空条目。

### 先清点，再给方案

旧卡（尤其是为文字模式写的卡）动手前先只读清点：世界书条目（开关、常驻、作用）、正则、卡内脚本（是否联网、做什么）、各开场（是否 HTML、里面的按钮调用什么）、`extensions.dsh_tavern`（绑定、舞台开关、皮肤、开场画面、卡页面、模组配置）。再把要做的事按块列给用户，每块写明删除、迁移还是保留，以及理由，用户确认后再改。两种做法里有一种会丢功能时，默认保留功能，并在同一块里写清保留的代价和兜底办法。

判断每一类内容：

| 内容 | 判断 |
| --- | --- |
| 台词格式要求（如「【名字】台词【/名字】」）和渲染它的正则、脚本 | 对话气泡已替代：关掉条目，删对应正则和脚本。舞台的气泡格式条目由插件维护，不手写；新会话或在界面点「立即生效」后的下一轮起用新格式 |
| 选项格式（如 `<xuan>`）和展示它的正则 | 本体「自动生成候选项」已替代（设置 › DSH Tavern › 剧情，全局开关）：关条目、删正则 |
| 每轮正文末尾的状态块（如 `<ztl>` JSON） | 有真实数据就迁：按 `card-to-mvu` 把字段变成 MVU 变量、由后台结算写，再按 `stage-status-panel` 做状态页读同一份变量；前台不再输出状态块。原状态栏的美化优先保留：把原 HTML 改成读 `stat_data`，同一份 HTML 既做卡页面，也作为 `tavern_apply_mvu` 的 `panel.html`，不让工具生成默认面板替掉它 |
| 只服务已删格式的配色、排版脚本 | 删 |
| 从作者网站检查更新、改卡的脚本 | 保留。更新会把本机的修改（含舞台配置）合并到新卡上，适配不会被冲掉；代价是本机改过的开场，作者以后再改同一段时，作者的改动进不来 |
| MVU 本体（变量、`[mvu_update]` 规则）、剧情设定、HTML 开场交互页 | 保留；开场画面在舞台里另配 |
| 设定玩家身份的条目（默认主角名、身份） | 对照用户自己的主角和已有存档；冲突时单独列一块问用户，常见做法是关掉条目 |

删脚本前先查开场和页面里有没有调用它（例如开场信件页的「开始」按钮靠脚本工作），有就保留，或者先把调用改掉。

已有存档要读到新加的状态字段，每个开场末尾都要写完整的 `<initvar>`：老存档读的是开局时冻结的世界书，只改 `[initvar]` 条目对它不生效。以后也不要删掉这些 `<initvar>`，否则存档更新时会把这些字段当成作者删掉的而清掉。初值里要由后台往里加元素的空数组写成 `["$__META_EXTENSIBLE__$"]`（MVU 的可扩展标记），写成 `[]` 时数组不可扩展，后台写不进去；读数组的页面跳过这个标记。

### 旧卡换新版、存档迁移和删卡

- 同一作品出了新版、用户想保留旧存档时，首选原地更新：人物卡库 › 批量管理，选中旧卡点「更新」，上传新版。卡的路径和 id 不变，存档留在原卡下；本机对卡的修改（舞台配置、绑定的包、皮肤、开场画面、卡页面、模组配置、关掉的正则、后加的开场）合并到新卡上，不用重新搬。最近一次更新可以「撤回」。之后各局打开时会自动套用新卡，MVU 新字段按初值补上。原地更新会立刻换掉旧卡内容，要先告诉用户并得到同意。
- 新旧卡差别太大、或只要正文能接着玩时，才把旧存档以聊天记录导入新卡：舞台演出记录、插件数据和场景图都会丢，只留正文和最后的变量。卡片编辑会话不是游戏存档，不迁。
- 认卡按路径和 id，不按卡名。原地更新后卡名会变成新版的名字，游玩历史里存档的分组名在下次打开那一局时跟着改；自动素材包按卡 id 跟着卡走，包名不随卡名变。这些都不需要另行改名。
- 原地更新前新版已另外导入过一张时，那张就成了重复卡，由用户在人物卡库删除。删任何卡之前确认它下面的存档都已迁走，并请用户先导出一份卡备份；删除要用户单独确认，不跟其他改动一起做。

完成标准：每一步都由对应子 Skill 回读确认；最后请用户进舞台发一轮消息看效果，没看过游玩页时只说「已保存」。改了已有存档的卡，再请用户打开一个旧存档玩一轮，确认旧回合还在、状态页随结算更新。
