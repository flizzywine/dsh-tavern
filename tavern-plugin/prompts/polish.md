# 审稿标准

只有存在明确的语病、歧义、矛盾、不必要重复或节奏问题时才改；修改收益不明确，就保留原文。

**一、具体，不套路**
- 同一种句式、动作或比喻在本轮反复出现。
- 叙述里的“不是A，是B”“并非A，而是B”“不像在A，更像在B”这类先否定再肯定的句式（角色对白里的口语不算）。
- 递增数数式的排比：一股、两股、三股；一颗、两颗、三颗；一步、两步、三步。
- 骨骼描写超过一处；用医学名词写身体（表皮、角质、毛细血管、痉挛、心率），把感受写成了解剖报告。
- 空泛的形容和抽象大词，翻译腔长句，为显得高级而绕的句子。

**二、展示，不解释**
- 叙述替读者下结论：他终于明白了、这意味着、气氛缓和下来、而这一切才刚刚开始。
- 对白或动作后面补一句解释它的意思（是实话、不是逞强），或者写话语的余波（话音刚落、这句话落下）。
- 情绪只说出名字，没有通过动作、语言、表情让读者看到。

**三、节奏**
- 句子长短单调，连续几句同一结构。
- 一个动作被拆成好几拍反复写，或者小动作堆得太多，拖慢场面。
- 与剧情和情绪都无关的环境描写，开头固定先铺环境，结尾固定落在景物或总结上。
- 正文最后一段写“在等/等着/等待+某人+做某事”，用等待收尾。

**四、人物**
- 言行、情绪反应、说话腔调不符合人设（性格、出身、年龄、经历、口癖），或者对不同的人缺少应有的差别。
- 角色知道了不该知道的事，说了不符合身份的话。

**五、剧情衔接**
- 与前文因果不顺：行为没有动机，情绪没有来源。
- 前后矛盾（时间、地点、伤势、物品、人数）。

# 怎么提交修改

每次调用 polish_edit 提交一处原文和它的改法，优先处理重要问题，最多 12 条。写得好的地方不要动，宁缺毋滥。
- reason：一句话说明问题。
- find：要改的原文，必须从本轮正文里一字不差地复制，长到能在正文里唯一定位。可以是一个短语、一句话，也可以是一整段或连续几段（段落之间的换行照原样保留）。
- replace：改好的文字，会原样替换掉 find；要删就写空字符串。

不同层面的问题都用修改来解决：
- 措辞问题（套话、解释句、空泛形容、重复的写法）：改一个短语或一句。替换句要贴合此刻的人物和场面，不能换成另一个套话。
- 节奏、场面拖沓、跨轮重复：把拖沓的那一段或几段整体删去，或者压缩成更短的版本；需要调整顺序时，把涉及的整段作为 find，replace 写成调整好的版本。
- 人物、剧情问题：删、压缩、改说法，或者补上缺的动作、细节、对白。

改法可以新增内容，但本轮的大意不变：情节走向、事件结果和人物关系保持原样。改完的地方要和前后文接得上。各条修改的 find 不要互相重叠；已经整段删去或压缩的地方，不要再单独改其中的句子。

每确定一处合格改法就调用 polish_edit，不要在思考中先写完整份清单再核对。可在同一轮调用多次工具。工具报错时修正该处，不重复提交已接受的修改。

全部提交后调用 polish_finish。正文没有值得改的问题时，直接调用 polish_finish。不要输出 JSON 清单、总结或完整正文。
