# 卡片工作台生图

1. 用 `read_image_config` 查看当前渠道、提示词格式、可选渠道和工作流，以及参考图、种子能力。配置查询只读本地，不会生成图片。
2. 需要已有角色时用 `read_character` 查询精确 ID、外貌和服装；通用服装用 `read_outfit`。只选本张镜头可见的字段，避免相互矛盾的视角与衣着。
3. 读取 `references/INDEX.md`，用 `tavern_read_skill_reference` 按索引读适用规则。`always` 在编写前读，`prescan` 在提交前读，`manual` 在改库前读；`lookup` 用 `find_prompt` 搜索。规则没有匹配条目时遵循当前用户要求，不反复找不存在的文件。
4. 根据返回的 `promptMode` 编写画面。标签模型保留其权重语法；自然语言模型用完整句子，中文或英文均可；结构化模式保留段落与分节。不要统一转成英文标签。
5. 用户已要求生成或给过直接出图授权时，用 `gen_image_submit` 提交。它返回任务号，不等出图；一次可以要几张（`count`），也可以在多个渠道分别提交，任务会并行推进。`channel` 只影响本次，可填精确渠道 ID，`comfyui` 使用本地工作流；不填沿用当前设置。不要靠试错猜渠道和模型。
6. 参考图模式用 `generation_mode: reference`，`subjects` 填 `read_character` 返回的精确人物和本张服装 ID。只在该渠道支持参考图时使用。多人物可用 `characters` 分别描述，NovelAI 使用原生角色参数，其他渠道由引擎合成。
7. 用 `gen_image_status` 按任务号取图，一次可传多个任务号；`wait` 是这次最多等几秒，已经有图就先返回那一批，剩下的下次只用未完成任务号再查。把返回的 `markdown` 原样写进回复，保留完整 HTTP(S) 地址、域名和端口，不改成相对路径。失败或结果待确认的任务会带原因和能否重提；不确定时先检查配图记录，不自动重发。

画风、负面词、尺寸、种子和参考图绑定均由共用引擎处理，不在提示词中重复写内部参数或未知字段。用户没有指定的画面事实不要补造。
