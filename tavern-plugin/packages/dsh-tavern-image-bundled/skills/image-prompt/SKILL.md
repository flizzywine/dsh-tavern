# 卡片工作台生图

1. `read_image_config` 查渠道、提示词格式、工作流、参考图与种子能力，以及画风清单。只读本地，不出图。画风清单只给名字和 ID；想知道某一套画风的具体正面词，再传 `preset`（名称或精确 ID）单独取。
2. 画面有库中角色时用 `read_character`：不传 `name` 列全部人物；传 `name` 拿 `macro`（已含常穿那套）和可选服装。人物外貌只以宏的形式出现，不再给 traits；用户要改这个角色的外貌时才加 `full: true`，那时给 traits 原文、不含宏。
3. 提示词写法以 `references` 里 `always` 条目为准，并按 `read_image_config` 返回的 `promptMode` 分渠道：标签类（NovelAI、SD WebUI、标签式 ComfyUI）和自然语言类要求不同，别把标签写法套到所有模型上。
4. 人物宏原样嵌进串里，展开成标签还是句子由引擎按渠道决定。**有宏就别再手动拼外貌块**：`references` 里那些拼 `face` / `bodySFW` 的旧做法，在有宏的角色身上不用重做一遍，两套说法会打架。
5. 衣服由宏的 `outfit` 决定，结构见「宏」。常规只填名字：宏里默认已经是常穿那套，不换装就别动它；换库里的填 `outfits` 里的 `name`，名字后面可以带这一刻的状态，写成 `校服（裙摆挽起）`。库装由引擎整块展开，上下身、权重、配件都在，**别把 `outfits` 的正文抄进串**。只有用户要改衣服时才用正文：库外衣服或换一种穿法，那时把英文描述填进 `outfit`。中文描述在标签渠道不生效，写描述一律用英文。
6. 多人：每人一个宏，描述里用各自外貌或 `the woman` / `the man` 分开做主语，不写 `they`、`the two of them`、"two girls"。每人至少两项可区分特征（发色发型、衣服、体型）。句尾写明人数。宏只属于它那个人，衣服各写各的。
7. 多形态角色（名字带后缀）在宏里写形态自己的英文名，不写短名。
8. 镜头和角度写明；画面看不到的部位不写对应 tag（背影不写瞳色，遮脸不写瞳色）。
9. 用 `tavern_read_skill_reference` 按 `references/INDEX.md` 读规则：`always` 编写前、`prescan` 提交前、`manual` 改库前，`lookup` 用 `find_prompt`。没匹配条目就按用户要求写，不反复找文件。
10. 用户授权后用 `gen_image_submit` 提交，立即返回任务号。`count` 要几张、`channel` 指定渠道、`preset` 指定画风，两者都只影响本次、不填沿用当前设置；`comfyui` 用本地工作流。画风名从第 1 步的清单里挑，不靠试错猜渠道和画风。
11. 参考图模式 `generation_mode: reference`，`subjects` 填 `read_character` 的精确人物与服装 ID。只在该渠道支持参考图时用，且**不要再用人物宏**，外貌会被写两遍。
12. `characters` 给每个入画人物单独写一段描述，跟 `generation_mode` 无关，纯出图也能用；NovelAI 走原生角色参数，其他渠道由引擎合成。
13. `gen_image_status` 按任务号取图，可传多个；`wait` 是最多等几秒，有图先返回那批。`markdown` 原样写进回复，保留完整地址。失败或待确认的带原因，不确定先查记录，不自动重发。

## 宏

一个完整的宏长这样，五个键都在：

```
${"name":"Chun Xue","angle":"from front","upperBody":"sfw","lowerBody":"sfw","outfit":"校服"}$
```

| 键 | 填什么 |
|---|---|
| `name` | 人物的英文别名，`read_character` 返回什么就照抄什么；别名有冲突时是 id |
| `angle` | 跟主干句的镜头一致 |
| `outfit` | **这一张穿什么**，库里的填 `outfits` 里的 `name`，库外的填英文描述 |
| `upperBody` / `lowerBody` | 外貌取哪套：`sfw` 有衣物 / `nsfw` 裸露 / `hidden` 不入画 |

**衣服只写在 `outfit` 里，不写在 `}$` 外面。** 写到串里就脱离了人物：引擎不会按它去取配件和权重，多人时分不清哪件是谁的。

**`outfit` 不能漏。** 漏了引擎会补常穿那套；这时串里再写一件衣服，两套会同时进提示词，图上就是两套衣服拼在一起。

成对闭合：`${` 开头、`}$` 结尾，漏了结尾 `$` 整段作废。

写错不报错：名字对不上库时宏被整段删掉或退化成普通称呼，图跟人物库无关且无提示。首次用某角色先确认返回的宏原样能用，再改 `angle`、`outfit` 和 `upperBody` / `lowerBody`。

`outfit` 写了个库里没有、又不像英文描述的值时，那套衣服会整个丢掉，日志里是 `outfitResult: not-found`。

宏写在工具参数里，参数是 JSON，宏里的引号要转义成 `\"`。宏越长越容易把参数写坏，能不写的键就不写。

## full: true 只有一种情况

**用户明确要求改这个角色的外貌或服装**——换发色、改体型、加衣服、重写 traits。其余一律不传：

- 觉得宏太短、想先看完整外貌再画：宏里该有的都在，不知道外貌长什么样一样能画对。
- 想核对宏写得对不对：宏由工具从库拼出，不需要校对。
- 出图不对、想读全量排查：多半是主干句或主语的问题，读全量只会遮住问题。
- 拿不准：不读。

读一次全量，省下的 token 全还回去。

## sfw / nsfw / hidden

人物宏的 `upperBody` / `lowerBody` 决定引擎从库取哪套外貌，不是"露多少"的修饰。

| 值 | 引擎做什么 |
|---|---|
| `sfw` | 取这套衣服下的外貌（`bodySFW` / `lowerSFW`） |
| `nsfw` | 取裸露状态的外貌（`bodyNSFW` / `lowerNSFW`），**且不再自动补常穿服装** |
| `hidden` | 该部位不入画，不取外貌 |

填了 `nsfw`，引擎不再自动补常穿那套，但 `outfit` 里写的衣服照常生效。半脱就是这种：`outfit` 照写（库里的名字或英文描述），露出来的部位填 `nsfw`。只填 `nsfw`、`outfit` 也空着，画面就是全裸。
